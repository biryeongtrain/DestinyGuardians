# W47 — 저장 탄약 무손실 이관

W46 개별 탄창 크기 축소 이전 저장값을 읽을 때 초과 장탄을 폐기하지 않는다.

- `WeaponAmmoMigration.normalize`: 순수 계산. 현재 장탄은 새 탄창 한도 이내, 남은 양은 예비 공간부터 채우고 초과분은 별도 보존한다. 탄창이 커져도 자동 장전하지 않는다.
- `destiny_weapon_overflow`: 음수가 아닌 **long NBT**. `WeaponItems.save`의 실제 탄약 변경 경계에서만 기록한다. 반복 읽기/HUD/상태 조회는 저장하지 않는다. 반복 저장은 이미 분배한 초과탄을 재가산하지 않는다.
- 유한 탄약 총량 = 장탄 + 예비 + 보존탄. 사격은 정확히 소비량만 감소, 장전은 이동만 한다. 장전 도중 취소하면 아직 이동하지 않은 탄약은 그대로다.
- 장전은 현재 예비부터 사용하고 보존탄으로 비워진 예비 공간을 채운다. 예비 용량이 0인 경우에도 보존탄에서 정상 장전할 수 있다. 줍기는 보존탄을 새로 지급하지 않는다.
- 무한 예비인 Primary는 예비값 0을 유지한다. 옛 `MAX_INT` 예비 표식은 무한 공급 정책값이지 실물 탄약으로 이관하지 않는다. 실제 초과 장탄은 보존하며 정상 장전 시 우선 사용한다.
- 정상 옛 int 2개는 `2 * Integer.MAX_VALUE`까지 손실 없이 이관한다. 음수/비정수/NaN NBT는 손상값으로 0 처리한다. 미래/손상 long 합이 표현 한계를 넘으면 `Long.MAX_VALUE`에서 포화한다. 표현 불가능한 초과까지 보장한다고 주장하지 않는다.
- HUD는 현재 탄창·예비 용량 이내 숫자만 표시한다. 보존탄은 OP `/destiny weapon status`의 별도 행으로 감사할 수 있다. 보존탄이 남는 동안 예비가 가득 차 보이는 것은 소비분을 기존 보존탄으로 보충한 결과다.
- 저장된 이름·모델·그립·다른 CustomData·사용자 lore는 보존한다. 기존 자동 생성 lore의 인식된 탄약 행만 갱신한다.

자동 검증: `WeaponAmmoMigrationW47Test` 11개 및 `WeaponAmmoMigrationW47GameTests` 6개.
실제 ItemStack NBT/JSON codec 왕복, MAX_INT/long 경계, 전 63종 읽기 전용 HUD,
실제 서버 사격·취소/교체·실제 마감 시점 장전을 검사한다. 실행 결과는 QA 보고서에 별도 기록한다.
