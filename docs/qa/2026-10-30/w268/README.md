# W268 초보자 무기군·능력 안내

무기군 선택 화면에 사용법과 탄약 안내를, 캐릭터 선택 화면에 능력의 행동·효과를 추가했다. 사용자 요청에 따라 [stop-slop 스킬](/Users/qf/.codex/skills/stop-slop/SKILL.md)의 문장 교정 기준을 적용했다.

## 표시 위치

- `/메뉴` → 새 무기 → 무기군에 커서를 올리면 사용법과 시련의 장 탄약 규칙을 읽을 수 있다.
- 개별 특수 화기 상세에는 시작·상자·게이지 지급량과 부활 규칙을 표시한다. 숫자는 현재 정책 함수에서 읽는다.
- 캐릭터 → 직업·하위직업·능력 선택 화면에는 각 선택지의 전투 방식과 효과를 표시한다.

무기군은 내부 ID 18개, 능력은 52개다. 원작에만 있고 서버에 없는 부가 효과는 설명에 넣지 않았다. 수치·게임 규칙은 바꾸지 않았다.

## 특수탄약 확인 결과

사용자는 확인 결과를 보고 **현재 규칙 유지, 설명만 추가**를 선택했다. 아래는 특수 화기 1개 장착 기준이다.

| 무기군 | 경기 시작 | 상자 보급 | 게이지 보급 | 사망 시 보존 상한 |
|---|---:|---:|---:|---:|
| 산탄총·융합소총 | 1 | 1 | 1 | 3 |
| 저격총 | 1 | 1 | 2 | 3 |
| 추적소총 | 29 | 29 | 29 | 87 |
| 특수 유탄 발사기 | 1 | 1 | 1 | 3 |
| 월도 | 2 | 2 | 2 | 6 |

경기 첫 입장에 시작탄을 준다. 부활하거나 같은 경기에 재입장해도 추가로 지급하지 않는다. 사망하면 남은 탄약 중 시작량의 3배까지만 보존한다. 이 값은 전투 중 보유 상한이 아니며, 전투 중에는 무기의 탄창·예비탄 한도까지 보급을 모을 수 있다.

특수 화기를 2개 장착하면 각 무기군의 지급량을 2로 나누고 내림하되 최소 1발을 준다. 추적소총은 14발로 시작하고 사망 시 최대 42발을 보존한다. 장착 무기 자체를 교체하면 유한 탄약을 회수하며, 핫바 선택만 바꾸면 회수하지 않는다.

확인한 경로는 `CrucibleAmmoRules`와 `CrucibleAmmo.arrive/died/reconcileInventory` 및 보급 지급부다. [W263 조사](../w263/README.md)는 원작 출처와 포팅 근사를 구분한다. 이번에는 공식 규칙 전체를 재조사하지 않았다.

## 작업 추적과 교정

1. 고정 worktree 두 슬롯의 새 `w268-delta`에서 무기군·능력 설명을 분리했다. master는 UI 연결·탄약 안내·통합을 담당했다. 기존 슬롯 파일과 미커밋 변경은 보존했다.
2. 무기군 1차 문구에서 반복 조언을 발견해 담당 agent에게 수정을 요청했다. 반환 문구는 73~100자다. 능력 조사가 길어져 담당 agent 종료를 확인하고 master가 현재 구현에 맞춰 52개 문구를 작성했다.
3. `stop-slop` 교정으로 추상적인 소개를 시전 행동과 효과로 바꿨다. 헌터 연막은 실제 억제 효과를 안내한다. 치유 균열에 없는 초과체력 효과를 설명하지 않고, 빛의 샘·수호물에는 현재 서버의 초과체력을 안내한다.
4. andlist 접속을 확인하고 재시작 시점을 물었다. 사용자의 테스트 종료 답변 뒤 운영 서버를 정상 종료했다(exit 0).

## 검증

- 관련 JUnit 29개 통과: 탄약 규칙 6개, 메뉴 레이아웃·입력 23개. `compileGametestJava` 통과.
- `CrucibleAmmo`와 `CrucibleAmmoRules`의 SHA가 작업 전과 같음을 확인했다. 새 숫자별 테스트나 전체 자산 검사를 추가하지 않았다.
- 근거와 문구: [무기군](weapon-help.md), [능력](ability-help.md).
- 빌드·검증한 환경은 기존 작업을 포함한 통합 checkout이다. 이번 delta만 커밋한다.

- Danmo 구성의 격리 Vision 클라이언트에서 실제 PNG를 확인했다. [무기군 설명](sniper-help.png), [특수 화기 상세](sniper-detail.png), [수류탄 설명](grenade-help.png) 모두 글자 잘림·겹침 없이 표시했다. 대표 화면 검수이며 52개 능력 전수 시전 검사는 아니다.
- 서버 명령으로 QA 계정의 메뉴를 연 뒤 Vision 네이티브 시야·점프 입력으로 메뉴를 탐색했다. OS 마우스 조작이나 새로운 전투 기능 검증으로 보고하지 않는다.
- 종료 전 leaseActive=false, heldKeys=[], pendingSteps=0, nativeInput 중립을 확인했다. QA 메뉴를 닫고 소유 클라이언트에 종료 신호를 보냈다. 격리 서버는 exit 0으로 종료했다.
