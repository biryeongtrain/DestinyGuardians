# W263 시련의 장 피해·탄약

## 1. 조사와 기준
- 기존 무기는 PvE용 로컬 피해량이며 플레이어가 정밀 대상 태그에서 빠져 있었다. 기존 AmmoEconomy는 몬스터 처치 전용이다.
- 사용자 지정 DDC Game Mechanics gid1800463143 C157(전체CSV 반환106행)을 2026-10-30 직접 조회: PvP 100 체력+130 보호막=230 HP. 원문 선택행/전체응답SHA는 ddc-selected-rows.json에 보존. XLSX export401은 CSV gviz로 해결.
- 원작230HP를 현재 플레이어 maxHealth(기본20)에 비례 환산한다. 추가 흡수 체력은 초과보호막으로 남으며 헤드샷을 막지 않는다. 거리의1m는 기존처럼1블록.
- 공식 [9.0.0.1](https://www.bungie.net/7/en/News/Article/destiny_update_9_0_0_1): 최초1회만1처치분 특수탄, 이후 생명/라운드에서 재지급 없음. 사망 시 시작량3배까지 보존. 최초 상자30초.
- [9.5.0](https://www.bungie.net/7/en/News/Article/destiny_update_9_5_0): 바닥 탄약60초.
- [9.1.0](https://www.bungie.net/7/en/News/Article/destiny_update_9_1_0): 저격총 brick2발. 같은 글의 Trials20초/게이지35%는 일반 점령에 적용하지 않는다.
- [9.7.0](https://www.bungie.net/7/en/News/Article/destiny_update_9_7_0): 일부 무기 피해량 변경 및 특수·중화기 처치/지원·궁극기 처치 게이지 감소. 현재 확인한 최신 기준.
- 최신 게이지 절대점수·Ammo Generation 곡선·상자 반복주기/공유·쌍특수 분배의 완전한 원작표는 미확인이다. 구현된 로컬 정책은 별도로 명시하며 과거2024표를 최신 원작값으로 사용하지 않는다.

## 2. 구현 추적
- 운영 서버 접속자0명 확인 후 정상stop. JVM4GB 설정 유지.
- PvP 피해 source를 분리해 바닐라 방어구/인챈트/Resistance 중복 경감을 제거. 기존 시련의장 아군·보호시간·능력 상태/가드는 유지.
- 플레이어 정밀 판정과 대상별 PvP 피해 어댑터 연결 완료. 한 발이 몬스터와 플레이어에 맞아도 같은 전역 수치를 바꾸지 않는다.
- 고정슬롯1 무기피해자료/loader, 슬롯2 탄약runtime, 슬롯3 서버GameTest를 배타 신규파일로 배정. stale worktree를 현재 전체 기준선으로 간주하지 않으며 현재 main 의존 소스를 읽고 신규파일만 통합한다.

## 3. 검증 상태
- CU 관찰: Mac 잠금. Vision 실행 전 수동 해제 요청 중. 동일 클라이언트 기동 반복 없음.
- 서버 자동 테스트 및 통합 검증 완료. 아래 최종 결과 참조.

- 첫 targeted 빌드는 탄약 클래스 통합 전 공유 훅이 먼저 들어가 `CrucibleAmmo` 미존재로 실패했다. 변경 순서를 바로잡고 반환본 통합 후 다시 검사한다. 서버가 실행 중인 상태에서 빌드하지 않았다.
- vanilla 음식 회복이 원작 TTK를 바꾸지 않도록 경기월드에만 자연 회복을 끄고 DDC 기본 Health<=100 회복을 연결: 체력35틱 지연/31.25HP초, 보호막106틱/39.5HP초. 표시 체력은 단일 MC 바에 합산하며 능력 회복·초과보호막은 별도 유지.

- DDC Void gid1907852650 D13(명칭B13, 개별cell 직접확인) 일반 약화 PvP7.5%를 적용했다. 개별 Shadowshot/경이의 강화 약화는 현재 공통 WEAKENED와 분리되지 않았으므로 전용50%까지 완료했다고 하지 않는다. 능력별 피해량·경이/퍽 전수 PvP재보정은 이 무기 기본피해 작업의 미완 범위다.

## 4. 로컬 정책과 알려진 한계
- 점령전 탄약 게이지: 기본 주무기4처치당1brick, 지원은 절반. 특수/중화기 처치·지원과 궁극기 처치에는9.7의0.67배, 월도 근접0.8배를 적용. 기준 절대점수는 원작이 아닌 서버 조정값이며 Ammo Generation/Finder 곡선은 아직 미적용이다.
- 조정은 JVM `destiny.crucible.ammo.kill`(기본.25), `.assist`(.125), `.crateRepeatTicks`(1200), `.heavyCrates`(true). 런타임Config의 값검증을 통과해야 한다.
- 특수탄 최초상자30초는 원작 기준. 반복60초, 스폰 근처 개인 근접획득, 중화기90초후120초반복, 사망시 개인brick삭제·중화기회수는 로컬 정책. 최신 공유상자 동작과 동일하다고 주장하지 않는다.
- 특수탄 시작: 일반1, 추적소총29, 월도2. 추적29외 무기군의1처치분 매핑 및 쌍특수 정수분배(최소1)는 포팅 기본값. 저격총은 meterbrick2, crate1을 분리했다.
- 실제 장비 아이템 교체는 장착/해제된 유한 탄약을 회수한다. 단순 핫바 전환은 회수하지 않는다. 새로 받은 무기·보관함 프리로드는 사격 전에도 검사. 동일 경기 재참가로 시작탄을 재지급하지 않는다.
- 무기피해50개는 DDC 연결 PvP chart(업데이트중 경고 보존)와 공식9.7 보정. 나머지15개는 기존 로컬값 유지. 특히 검5개와 유탄/로켓의 직격·폭발 분리, Coriolis3x4패턴은 최신 수치/동작을 함께 확인해야 하므로 억지 배율로 채우지 않았다.
- 기존 모든 능력/경이/퍽의PvP 전용 계수와 최신발사속도·거리곡선을 전수 포팅한 것은 아니다. 기존 거리감쇠의 출처·한계는W43/W44에 남아 있다.
- 단위 targeted57/57, compileGametestJava 통과. 통합 서버 테스트 2/2 통과 (`gametest-r2.json`, `gametest-r2.txt`).

## 5. 서버검증에서 발견한 리스폰 결함
첫 두 GameTest는 실제피해/갑옷무시/정밀처치 및 실제발사→게이지brick2발획득까지 통과했으나 리스폰 후 무기존재 검사에서 실패했다. `ServerPlayer.restoreFrom` 바이트코드를 확인하니 새 respawn level의 keep_inventory를 읽는다. arena는true여도 임시 오버월드는false이므로 장비가 복사되지 않았다. 확인된 경기원본 member의 AFTER_RESPAWN에서 사망회수 이후 인벤토리/XP/score를 native와 같은방식으로 넘기도록 수정했다. 일반 월드 리스폰은 변경하지 않는다. QA서버 정상종료 후 수정·재기동한다.

## 6. 최종 검증과 배포 범위

- r2 서버 통합 테스트 **2/2 통과**: 정밀/갑옷·인챈트·Resistance 우회, PvE 피해 유지, 실제 발사와 처치, 게이지 탄약 획득, 사망 보존 한도, 리스폰 무기 복원, 중복 시작탄 차단, 최초 상자 획득. 가상 연결 플레이어를 썼으며 실제 클라이언트 입력 검증과 구분한다.
- 전체 단위 테스트 2,301개 중 기존 자산 검사 4개 실패. 목록은 `full-gate.json`에 보존했다. 이번 변경의 관련 검사 57개는 모두 통과했다. 전체 gate 성공으로 보고하지 않는다.
- Mac 잠금 상태라 Vision PNG/네이티브 입력 검증은 미실행이다. 잠금 우회나 같은 클라이언트 반복 실행은 하지 않았다.
- 운영 서버는 QA 정상 종료 후 4GB, online-mode=true 설정으로 재개한다.
- 선택한 W263 파일만 커밋한다. 기존 untracked 지원 클래스 6개는 이번 연결 변경의 기반으로 포함하며, 다른 작업의 미커밋 파일은 유지한다. 현재 전체 작업 디렉터리를 검증한 결과이므로 clean clone 독립 빌드 성공을 주장하지 않는다.

- 리스폰·피해 표시 최종 수정 후 관련 단위 검사 57개와 GameTest 컴파일을 다시 확인했다 (`targeted-r2.json`).
- 커밋에는 기존 피해 분배·탄약 attribution 연결을 필요한 기반으로 포함했다. Cornered 등 관계없는 기존 변경은 index에서 제외하고 작업 디렉터리에 보존했다.
