# W269 능력 키 분리와 HUD 안내

## 변경

| 능력 | GCB 설치 | GCB 미설치 |
|---|---|---|
| 수류탄 | Z | F |
| 근접 | C | Shift+좌클릭 |
| 직업 | V | Shift+Shift |
| 궁극기 | F | Shift+F |

GCB 설치 시 Shift+F·Shift 두 번·Shift+좌클릭의 능력 발동을 차단한다. 공중 점프·사격·궁극기 기본 공격·Q 장전·Shift+Q 특수 장전은 유지한다. Ctrl+Q는 일반/특수 장전을 시작하지 않으며, 클라이언트가 예측한 무기 버리기를 취소하고 기존 슬롯 동기화로 복구한다. 이자나기 설명도 Shift+Q로 바꾼다.

현재 GCB 4.0.0과 GCB-server에는 별도 F 전용 이벤트가 없다. F 궁극기는 마인크래프트의 손 교환 입력을 GCB 사용자의 궁극기로 해석한다. 기본 키를 바꿨다면 F 대신 해당 손 교환 키가 작동한다. 서버는 클라이언트의 사용자 지정 키 이름을 알 수 없어 HUD에는 기본 키를 표시한다.

GCB 설치 여부와 버전은 GCB-server의 수신 상태를 조회한다. 죽음·차원 이동으로 수호자 실행 상태가 초기화돼도 입력 방식은 접속 세션 동안 유지한다. 로그아웃/새 로그인에서 초기화한다. 키가 먼저 오고 버전이 늦게 와도 접속당 방송은 한 번만 한다. 버전을 받지 못한 설치 감지는 100틱 뒤 ‘버전 미확인’으로 표시한다.

미설치자는 접속 후 100틱 동안 감지를 기다린 다음 설치 권장과 클릭 가능한 [배포 링크](https://github.com/eiqq/GCB-mod/releases)를 한 번 받는다. 설치 강제나 접속 차단은 없다. 설치자는 `이름 유저가 GCB 모드 버전 를 설치했습니다.`를 전체 방송하며 버전만 파란색이다.

HUD는 기존 능력 아이콘과 충전 막대 아래에 키를 표시한다. 미설치자용 긴 조합은 두 줄로 나눠 탄약 패널과 겹치지 않게 한다. 궁극기 키는 다이아몬드 아래에 표시한다. 메뉴·사망·관전자·직업 해제 시 기존 HUD 정리 경로에서 함께 제거한다.

## 작업 기록

1. 기존 코드와 GCB 프로토콜을 확인하고 현재 파일을 `/private/tmp/destiny-w269/before`에 보관했다. 기존 메인 미커밋 변경을 보존한다.
2. 고정 worktree의 새 `w269-delta` 두 곳에서 HUD와 게임테스트를 나눴다. master가 입력 라우터·접속 감지·방송·통합·실게임 검증을 담당한다. worktree 원본과 이전 delta는 덮어쓰지 않는다.
3. 운영 서버 접속자 0명을 확인하고 정상 종료한 뒤 빌드했다. 초기 제품 compileJava 통과. 새 단위 테스트는 26.3 색상 API 이름 차이로 처음 컴파일 실패했고, 표시해야 할 파란색 값 검증으로 수정하여 3개 통과했다.
4. 검증 중 자동 잠자기 방지는 소유한 1시간 bounded coordinator로 적용한다. 인증·잠금 설정과 일반 클라이언트 프로필은 바꾸지 않는다.

## 검증 진행

- 단위 테스트: 버전 텍스트·파란색·설치 링크 3개 통과.
- 게임테스트와 Vision: 완료. GCB 4.0.0이 있는 Danmo 격리 프로필과 이를 제외한 프로필에서 아래 검증을 수행했다.

### 중앙 검증 1차

- 컴파일: `compileJava`, `compileGametestJava` 통과.
- 게임테스트: GCB 입력5, 장전/예측 복구6, 이자나기 거래12, 표현8, 인벤토리 패킷4, 조준경3 = **38개 통과**. W84 첫 실행은 기존 QA 난이도가 평화로움이라 허스크 생성5건 실패했다. 난이도를 보통으로 바꾼 뒤 같은12개가 통과했다. 제품 수정으로 해결한 실패가 아니다.
- 최초 실클라이언트는 서버 준비 전 접속하여 연결 거절이 났다. 서버와 팩 완료를 확인하고 소유 클라이언트를 종료/재시작하여 접속했다.
- GCB4.0.0 실제 접속에서 버전 수신·접속당 방송1회·Z/C/V/F HUD를 확인했다. Vision native Shift+F·더블Shift 후 능력 쿨다운0을 확인했고, 준비된 황금총에 native F를 눌러 시전 소리/에너지 소모/실화면을 확인했다. Z/C/V 각각의 OS 키 입력은 검증하지 않았으며, 등록된 서버 콜백은 게임테스트로 확인했다.
- GCB 입력 종료 때 leaseActive=false, heldKeys=[], pendingSteps=0, nativeInput 중립을 확인했다. 미설치 프로필로 전환해 접속 안내와 fallback HUD를 검증한다.

### 화면 검수 수정

GCB 미설치 프로필에서는 재접속 뒤 기존 GCB 감지가 남지 않고 fallback HUD와 설치 권장이 표시됐다. 같은 F 네이티브 입력이 수류탄을 발동했다. 두 환경 모두 글자 겹침은 없었으나 12px 기준 글자가 작아 담당 HUD agent에게 실제 PNG를 전달했다. 반환 수정은 글자14px, 둘째 줄 y=1016이다. 최종 캡처를 위해 QA 서버/client를 정상적으로 정리한 뒤 다시 컴파일한다.

접속 감지는 입력 정책용 세션에 별도로 보관한다. 기존 디버그 카메라의 gcbClient 표시값은 미설치자 판정 때 강제로 지우지 않으므로, 카메라 검수 도구의 기존 동작을 보존한다. 입력 허용 여부는 그 디버그 값에 의존하지 않는다.

### 최종 화면

- [미설치자 키](vanilla-keys.png): F, Shift+좌클릭, Shift+Shift, Shift+F. 한글과 긴 조합이 탄약 패널에 겹치지 않는다.
- [GCB 키](gcb-keys.png): Z/C/V/F. 접속 전환 시 이전 모드의 둘째 줄이 남지 않는다.
- [보조 손](offhand-keys.png): 기존 above-hand 표시 경로에서 아이템 위로 키가 보인다.
- [메뉴](menu-keys-hidden.png): 메뉴 동안 전투 키가 숨겨진다.
- 두 최종 프로필 모두 동일 제품 바이트로 확인했다. 이후 변경은 기존 HUD 회귀 테스트의 예상 노드 수뿐이다.

기존 HUD 테스트는 총20개 이하를 기대하여 키 가이드 추가 후1개가 실패했다. 단순히 한도를 풀지 않고, 미설치 키6개의 정확한 ID·텍스트·기존 HUD20개 이하·전체26개 이하, 갱신/로드아웃 전환 시 엔티티 재사용, GCB 전환 시4개 키와 둘째 줄 제거, 직업 해제 시 정리를 검사하도록 고쳤다. 재검증 결과는 아래에 기록한다.

## 최종 결과

- 관련 게임테스트 **41개 통과**(입력·장전38개 + HUD3개), 단위 테스트3개 통과. 최종 감지 구현에서 GCB5개를 다시 실행해 통과했다. 반복 실행을 별도 테스트 수로 세지 않는다.
- 확대된14px HUD를 설치·미설치 두 실클라이언트에서 확인했다. 설치 권장 수신, 접속당 버전 방송, 네이티브 F의 모드별 동작, 보조 손 가림과 메뉴 정리를 확인했다. 전체 무기·능력 모션 재검증이나 Z/C/V의 OS 입력 검증은 아니다.
- 소유 client만 종료했고 매 입력 시퀀스의 lease/키/대기 입력은 중립이다. QA 계정 직업은 기존 타이탄·공허, 에너지는60%로 돌리고 테스트 손 아이템을 비웠다. QA 난이도는 기존 평화로움으로 복원했다.
- 기존 미커밋 코드가 있는 통합 checkout으로 검사했다. 커밋은 현재 작업의 변경만 HEAD 기준으로 분리하며 이전 미커밋 코드를 함께 넣지 않는다. 깨끗한 checkout 단독 빌드 확인은 아니다. 원격 push는 하지 않는다.
