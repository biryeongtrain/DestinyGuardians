# W271 GCB 포함·버전 인식·달리기 장전·장전 사운드

## 요구와 원인

1. 사용자는 구버전도 버전 문자열을 보내면 GCB 설치로 인식하도록 요청했다. 현행 소스에는 4.2.0 비교가 없었고 별도 presence flag에만 의존했다. 버전 문자열이 있으면 해당 flag 없이도 설치를 인정하도록 보완했다. 기본값 unknown·빈 응답은 설치 증거로 사용하지 않는다.
2. 사용자가 배포 서버에 GCB-server를 설치하지 않았음을 확인했다. 사용자 요청으로 기존 minigame-lib·BetterModel에 더해 GCB-server도 include한다.
3. 달리기 Ctrl+Q는 바닐라 DROP_ALL_ITEMS 패킷이다. 기존 예약키 차단이 이 입력을 막았다. 실제 sprint 상태일 때만 일반 장전으로 처리하고, 정지 상태 Ctrl+Q 예약 및 Shift+Q 특수 장전 규칙은 유지한다. 아이템 버리기는 계속 취소하고 슬롯 예측 복구를 유지한다.
4. 장전 사운드는 재사용 ikelos 작업자에게 별도 파일 소유권을 부여해 조사했다. master는 input·GCB·build·중앙 검증을 담당한다.

## 검증 진행

- ClientControls 단위 검사 5개 통과(구버전·개발 버전·무응답·기존 알림 색상/링크 포함).
- GCB version-only 서버 회귀 및 sprint Q/CtrlQ 장전·완료·예측 복구 검사를 추가했다.
- 모델/장전 모션 자산은 변경하지 않는다. 기존 미커밋 변경은 보존한다.

- GCB 서버 회귀6개 통과. 장전 입력 회귀 첫 실행은 기존6개 통과, 신규 sprint 완료 검사의 잘못된 탄약 합계 가정으로1개 실패했다. 주무기는 예비탄 무한이며 특수탄은 overflow까지 보존하므로 이 두 규칙을 반영해 검사를 수정했다. 제품 장전 취소나 탄약 유실로 판정한 실패는 아니다. 수정 후 같은 sprint 검사1개가 통과했다.

## 장전 소리 조사 결과

에이전트가 현재 JAR, 운영 생성 팩, GameTest 생성 팩에서 장전 이벤트98개 및 직접 참조 OGG99개의 누락0을 확인했다. W63/W102 음원 길이는 지정 ticks/20과 일치한다. Windows에 실제 적용된 팩·음량 설정·청취 결과는 미확인이다. 원인 근거 없이 재생 방식을 바꾸지 않았다. 에이전트의 선택적 취소 처리·trace delta는 이번 배포에 통합하지 않았다.

서버 패킷/게임 동작 회귀에서 장전 소리 검사16개가 최종 통과했다. 이벤트별 패킷 직렬화, emitter 생성 후 소리 전송, 이동 추종, 중복 입력, 탄약 부족, 다른 시전자 분리, 샷건 마지막 삽입 철컥과 중간 사격 취소를 포함한다. 첫 실행의 무법자 검사1개는 QA의 기존 peaceful 난이도로 허스크 생성에 실패했다. normal에서 해당1개를 재검사해 통과한 뒤 peaceful로 복원했다. 소리가 실제 Windows 스피커에서 나오는 것을 검증한 결과는 아니다.

## 최종 검증 및 정리

- 단위 검사5개 통과.
- 서버 GameTest는 중복 제외29개 통과: GCB6, 장전입력7, 장전소리16.
- 게임 클라이언트/OS 입력/청취를 새로 검증하지 않았다. 관련 서버 입력과 실제 패킷 검사 범위다.
- QA 서버를 정상 종료했고 운영 서버는 재시작하지 않았다. 사용자는 새 JAR로 교체 후 서버를 재시작해야 한다.
- 이번 변경으로 달리기 Ctrl+Q가 거절되어 장전과 소리가 모두 시작하지 않는 경로는 해소했다. 이미 정상 장전 중인데 무음인 Windows 현상은 아직 재현되지 않았으며 해결 완료로 표시하지 않는다.

최종 `jar` 빌드 성공. [artifact.json](artifact.json)에서 GCB-server·minigame-lib·BetterModel 내장 버전과 새 JAR 해시를 확인할 수 있다. 최종 JAR의 모든 장전 OGG 직접 참조도 누락 없이 확인했다.
