# W266 빛의 샘·새벽의 수호물 초과체력

## 규칙과 출처

- 사용자 요청에 따라 두 장판에서 시전자와 아군에게 실제 흡수체력을 충전한다. 현재 DDC의 빛의 샘에는 회복·피해 감소만 있으므로 빛의 샘 초과체력은 원작 수치가 아닌 사용자 요청 커스텀이다. 선택 질문에는 수호물과 동일한 충전 규칙을 기본안으로 제시했다.
- 수호물: DDC Void의 최대45HP, 초당15HP 충전, 기본 지속10초를 사용한다. 기존 체력 환산인 데스티니230HP = MC 최대체력과 같은 비율을 사용하므로 기본 MC20HP에서 최대3.913HP를 추가한다.
- 안에서는 피해로 줄어든 초과체력을 다시 채우고, 이탈 후 충전을 멈추며 마지막 갱신으로부터10초 뒤 남은 해당 초과체력을 제거한다. 재진입하면 다시 충전·갱신된다.
- 겹친 샘/수호물은 하나의45HP 지원 초과체력 풀을 공유한다. 적·관전자·죽은 플레이어·다른 차원에는 충전되지 않는다.
- 사망·로그아웃·직업변경·차원이동 cleanup에서 자신이 부여한 흡수체력과 임시 최대흡수 속성만 제거한다. 외부 흡수체력은 남긴다. 기존 체력바 위 청록색 흡수막대를 재사용한다.
- 이번 범위는 초과체력 생성·충전·만료이다. DDC의 별도 Void Overshield PvE70% 감소, FIFO 복수 초과체력 레이어, Persistence 연장은 추가하지 않았다. 이전 W265 궁극기/샘 피해감소는 유지한다.

## 단계 기록

1. 운영서버 접속자0명 확인 후 정상 종료. 기존 수정은 baseline으로 보존했다.
2. master가 지원 초과체력·능력 tick/cleanup·수호물 membership을 구현. 고정 슬롯1은 출처 JSON, 슬롯2는 실제 시전/lifecycle GameTest를 신규 파일로 작성한다. stale 슬롯의 전체 갱신/빌드로 주장하지 않는다.
3. 제품 컴파일 통과. Mac 데스크톱 확인 후 master QA에만 최대1시간 잠자기 방지를 적용했다.
4. 검증은 기존 minecraft-testing·Vision26.3 지침으로 진행한다. 수치별 전수 검사를 추가하지 않고 실제 장판·흡수·소멸·아군판정을 확인한다.

5. 전체 JUnit2,301개 중2,297개 통과. W265와 동일한 기존 모델/UV4개 실패만 남음. 제품 컴파일 성공.

6. 신규 GameTest2개 통과: 실제 시전 후 Well-only/Ward-only/중첩, 적 제외, 동일틱 중복 방지, 흡수피해 후 재충전, 199틱 유지/200틱 만료, 외부흡수량·속성 보존. 두 번째 테스트명 숫자부분은 `at200ticks`이며 최초 selector 오타는 실행 전에 수정했다.
7. 격리 Danmo+Vision에서 두 궁극기를 native sneak+swap_offhand로 시전하고 forward+sprint로 장판을 벗어났다. 각각 흡수량3.9130435→피해2후1.9130435→재충전3.9130435, 체력20 유지, 이탈 후0을 서버에서 확인했다. 콘솔 generic 피해 fixture이며 자연 AI공격·실제 PvP 대전 검사는 아니다.
8. PNG 직접 검수: 두 장판의 청록색 흡수막대 충전·피격감소·재충전·이탈소멸 확인. 최초 Well 관측은 시전47초 뒤여서 이미 소멸한 값0이었다. 이후 자동 타이밍으로 다시 시전해 유효 구간을 검증했다. 오디오 청취는 미실행.
9. 네이티브 입력 중립·lease해제 확인, 테스트 계정 탑 복귀, 소유 client/QA서버/awake 정상 정리. 사망·접속종료 이벤트를 실제 사용자 계정으로 반복하지 않고 공통 cleanup과 코드 연결을 확인했다.
