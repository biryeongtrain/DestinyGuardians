# W247 — 로드아웃 캐릭터 메뉴

1. 요구사항: 메뉴/로드아웃에 캐릭터 탭을 추가한다. 직업·하위직업·수류탄·근접능력·직업능력·궁극기를 고르되 선택한 직업과 하위직업에서만 조합한다. 기존 무기 선택 흐름은 보존한다.
2. 기존 모델은 직업별 Loadout을 저장하며 하위직업은 장착 궁극기의 Element에서 결정할 수 있다. 현재 구현된 하위직업은 아크·솔라·공허다. KINETIC 직업능력/점프는 해당 직업의 공통 능력으로 허용한다. 새 미구현 능력을 선택지로 만들지 않는다.
3. 고정 worktree slot1은 중앙 선택 서비스, slot4는 메뉴 controller/view/layout/HUD를 담당한다. master는 명령어 연결·회귀 및 Vision 검증을 담당한다. 파일 소유 범위를 분리하고 원격 push/reset/clean은 하지 않는다.

4. 재사용 슬롯4에는 W245에서 이미 통합한 타워 파일이 남아 있어 최초 refresh가 쓰기 전에 중단됐다. 해당 파일이 수락 커밋 b85bf810과 byte 단위로 같음을 확인해 이전 기준 메타데이터만 정합화했다. 재시도는 60ac7271 + 현재 dirty/untracked 입력 221,543파일을 포함해 두 슬롯 모두 완료했다. 제품 코드나 사용자 파일을 reset/clean하지 않았다.
5. 명령어 class/subclass/equip도 메뉴와 동일한 중앙 검증 서비스를 사용한다. equip 자동완성과 supers 목록은 현재 직업·하위직업으로 필터링해 우회 선택/혼동을 줄인다.
6. 회귀 범위: 3직업×3속성의 허용 조합, 잘못된 직업·원소·슬롯·ID 거부, 직업별 선택 복원, 저장 CODEC 왕복, 활성 궁극기 중 변경 차단, 동일 선택 no-op 및 쿨다운/에너지 우회 방지. 화면 테스트와 기존 무기 메뉴 회귀도 취합한다.
7. 운영 접속자0명을 확인하고 save-all flush→stop으로 정상 종료했다. Mac 데스크톱 잠금 해제와 8102/25611 빈 포트를 확인했으며 W247 전용 2시간 bounded awake coordinator를 시작했다. 기존48시간 assertion은 보존한다.

8. 통합 compileJava/compileTestJava/compileGametestJava 성공. 메뉴 관련 JUnit23개(기존 controls3·layout7+11·새 character2)가 통과했다. 기존 테스트의 고정 노드20개 가정을 legacy 기하 범위로 한정하고, 새 상단 탭 및 단계별 숨김/키보드 도달성은 새 기하 계약으로 검증했다.
9. 격리 일반 dev 서버에서 정확한 GameTest5개가 모두 통과했다. 신규4개는 허용·거부 조합/저장/에너지·쿨다운/실제 메뉴 controller 포인터 선택과 무기 복귀를 검사하며 기존W227 장비창 전투 차단·원본 아이템 보존·이동 복구 회귀1개를 함께 실행했다. 실제 클라이언트 입력/PNG 검증은 다음 단계다.
10. 두 worktree의 전체 입력 기준선 감사에서 소유 범위 밖 변경은0개였다. master는 소유파일만 이전/이후 hash를 확인해 통합했고 main의 기존 dirty/untracked 작업은 보존했다.

11. 1차 Danmo4GB/OpenGL native 클릭과 실제 PNG에서 미선택 root/직업 목록/헌터 태양6필드와 궁극기2종 표시를 확인했다. 그러나 최초 검증은 버튼 중앙으로 곧바로 이동해 빈 공간에 머무는 동작을 놓쳤다. 사용자가 마우스가 기본 영역으로 당겨지는 결함을 제보했다. 원인은 주기 refresh가 focus=-1(정상적인 빈 공간)을 잘못된 포커스로 판단해 controls.point로 되돌리는 경로였다.
12. 주기 갱신은 현재 포인터의 hover만 다시 계산하도록 바꿨다. 마우스 모드에서는 탭·항목·옵션 전환도 좌표를 유지하고, 명시적인 WASD/Space 조작에만 키보드 포커스 재배치를 허용한다. UI GameTest에 빈 공간31틱 유지(세 번 이상의 refresh)와 클릭 전후 좌표 불변 검증을 추가했다. 기존 QA 서버/client는 정상 종료하고 수정본으로 재검증한다.
13. fixture 준비 때 초기 fill은 인접 청크 미로딩으로 실패하여 명시적으로 격리 overworld9청크를 forceload하고 바닥289블록을 생성했다. 수집기는 성공 문구 block(s)를 blocks로 잘못 예상해 한 번 timeout했으나 실제 성공 로그를 확인해 재실행하지 않았다. 최종 정리 때 해당 임시 forceload를 해제한다.

14. 수정본에서도 JUnit23개와 정확한 서버 GameTest5개가 통과했다. 2차 Danmo4GB/OpenGL Vision은 빈 공간(600,230)에서42 client ticks 정지 후 hover=-1/좌표 불변을 확인했다. 이어24 client ticks의 분할 회전으로 빈 공간을 천천히 가로질러 캐릭터 탭에 도달했다. 매 클릭 직전에 서버 hover 노드를 확인하고 화면 전환 후 좌표 불변을 검증했다.
15. 마우스로 헌터6항목을 모두 선택하고 태양 궁극기 목록이 칼날 장전·황금 총만인지 확인했다. 타이탄 공허(기본 궁극기/새벽의 수호물), 워록 태양(기본 궁극기/빛의 샘)을 선택한 후 헌터 태양/칼날 장전의 이전 구성이 복원됨을 확인했다. 로드아웃 복귀→새 무기→무기군도 정상 동작했다. 실제 PNG를 master가 검수했고 UI worker에게1차 이미지와 수정 원인·회귀 시나리오를 전달해 검토받았다.
16. 마지막 WASD 포커스 이동과 native 우클릭 닫기가 통과했다. leaseActive=false/heldKeys=[]/pendingSteps=0 및 nativeInput 모두false를 확인했다. UI·모델을 바꾸지 않는 수치 퍽 테스트를 확대한 배치가 아니며, 전체 무기·능력 테스트 전부 통과로 보고하지 않는다. 사운드 청취나 물리 OS 마우스 동작 검증을 주장하지 않는다.
17. 격리QA의 임시 forceload9청크에 해제를 요청했고 이미 남은 항목이 없다는 서버 응답을 확인했다. 이어 save-all flush→client 종료→server stop을 완료했다. 외부 init을 이전 내용으로 복원했다. 원본 로그·입력 증거는 /private/tmp/destiny-w247 및 /private/tmp/destiny-w235/qa/w247에 보관한다. docs의 frames는 검수용 실제 PNG이며 커밋 대상에서 제외한다.

18. worker 종료 후 master의 최종 포인터 수정본만 슬롯4의 동일 소유파일에 hash 검증 복사했다. 두 고정 슬롯은 삭제하지 않고 다음 작업에 재사용할 idle-needs-refresh로 반환했다. 다른 슬롯2/3의 진행 상태는 변경하지 않았다.

19. 운영 runServer가192.168.35.237:25565에서 재기동했고 타워 준비·기존 재질0변경·리소스팩 생성 완료 로그를 확인했다. online-mode=true와andlist OP4는 유지한다. QA 전용 bounded awake coordinator는 종료했고 기존48시간 caffeinate PID79904는 살아 있다. 이번17개 관련 파일만 커밋하며 기존 GameTest 등록들과 슬롯2/3 진행 상태는 index의 분리된 blob을 통해 커밋에서 제외한다. 원격 push는 하지 않는다.
