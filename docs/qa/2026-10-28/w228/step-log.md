# W228 단계별 작업

1. 사용자 요청: 테스트 무기 슬롯별 선택과 데미지/유틸리티 퍽 자유 선택. W227 화면과 기존 원작 소켓/전투 연결을 확인했다. 원작 미지원 조합을 표시만 하고 효과가 있는 것처럼 꾸미지 않는다.
2. 고정 슬롯4·5를 재사용 갱신하고 서비스/화면을 분담한다. master는 컨트롤러·한국어 데이터·중앙 검증·실제 게임 입력을 맡는다.

3. 고정 슬롯4·5를 현재 통합본으로 갱신했다. 복구본을 외부 보존했고 기존 워크트리를 재생성하지 않았다. 서비스·퍽과 HUD를 분담하며 master는 컨트롤러·입력·중앙 검증을 맡는다.
4. 일반 소지 목록을 보존하고 명시적 테스트 진입·슬롯별 카탈로그·실제 장착 무기 퍽 모드를 컨트롤러에 연결한다. 카탈로그 미리보기는 ItemStack을 생성하지 않는다.
5. 한국어 구현 퍽77개를 공식 정의로 정리했다(데미지22·유틸리티55). 원작 설명과 Minecraft 적용 동등성을 구분했다.
6. Computer Use에서 Finder 창이 접근 가능한 상태를 확인했다.8102·25611 미점유와 사용자48시간 caffeinate PID79904 유지도 확인했다. 일반 앱 조작은 보내지 않았다.
7. 사용자 지시에 따라 직접 교체·실제 장착 퍽 편집 초안을 중단하고 슬롯→새 무기→무기군→무기→퍽→최종 추가 흐름으로 변경했다. 두 worker에게 변경 계약을 전달했다. 자동 기본 무기 지급은 UI에서 제거한다.
8. master가 작성 중 무기를 세션에만 보관하고 최종 확인에서만 서비스 add를 호출하도록 컨트롤러를 변경했다. 뒤로·닫기·슬롯 변경은 작성 중 선택만 버린다.
9. 두 worker의 최신 마법사 흐름 delta를 소유 경로·기준 hash·전체 워크트리 범위 밖 변경 여부를 확인해 통합했다. 서비스의 정확한 퍽 tuple·원본 객체 재사용·사전 거부, HUD의 단계별 hit/navigation과 최종 확정 버튼을 검토했다.
10. 중앙 관련 단위·assemble·GameTest 컴파일을 시작한다. 무기 모델·리그와 퍽 수치는 변경하지 않았다.
11. 관련 단위21/21과 assemble·GameTest 컴파일이 통과했다(target-1). 서버에서 확정·초안·원본 보존 동작을 검증한다. 새 격리 client에는 이전에 소유한 QA options만 복사해 첫 실행 안내를 피하며 일반 프로필은 보존한다.
12. 첫 서버 실행에서21개 중19개 통과했다. 새 W228 테스트1개의 장전 fixture가 준비되지 않아 담당자에게 수정 요청했고, 넓은 필터에 함께 걸린 W226 충전 마감 검사1개 실패도 별도 기록했다. 재실행은 W227·W228 정확 필터로 분리한다. 제품 단위 전체 검사는1회 진행한다.
13. 전체 단위2,072개 중2,066개 통과했다. 실패6개는 W227과 같은 검사 집합임을 비교했으며 음원·입자 자산은 변경하지 않았다.
14. 서비스 담당자가 실제7틱 준비 시간을 기다리도록 테스트 fixture만 수정했다. 반환 hash를 대조해 통합하고 정확한 W228 필터로 재실행한다.
15. 수정 후 정확한 W228 서버 검사8/8 통과했다. 제품 변경은 없었고 테스트의 실제 준비 마감 대기만 보정했다. W227 기존 장비·입력·소유권 회귀를 정확 필터로 실행한 뒤 한 격리 Vision 배치에서 확인한다.
16. 1차 native에서 무기군→무기→퍽 단계와 확정 전 실제 장비 미변경을 확인했다. 같은 위치의 다음 단계 클릭이 기존 armed 래치에 막힌 제품 문제를 발견해 제거하고 틱별 패킷 중복 방지는 유지한다. 실제 PNG4장을 HUD 담당자에게 전달했다. 클릭 유지로 단계가 자동 진행하지 않는지도 다음 native에서 확인한다.
17. 같은 좌표 클릭 수정 뒤 관련 단위21/21·빌드와 W227 서버11/11 재통과. HUD 담당자의 실제 PNG검수에서 초안 카드의 현재 적용 중 문구 모순을 찾아 초안에 저장됨으로 변경했다. 해시 대조 통합 후 관련 검사·컴파일을 진행하고 최종 native를 시작한다. 전체 수치/자산 검사는 반복하지 않는다.
18. 마지막 초안 문구 수정 후 관련 단위21/21·컴파일 통과(target-ui-3). 두 번째 격리 native에서는 같은 위치의 다음 클릭과24틱 클릭 유지가 정상 동작했다. 확정 전 Inventory=[]·확정 후 실제 소켓2개·취소 전후 인벤토리 payload 일치도 확인했다.
19. 물리 매사냥꾼·에너지 은둔자·파워 결투 규칙을 각 무기군에서 선택하고 최종 추가했다. 실제 PNG의 한글 가독성·설명·확정 버튼·세 슬롯 장착을 검수했다. 키/lease 중립, 소유 server/client 종료0, 포트 해제,48시간 assertion 보존을 확인했다. 최종 assemble만 별도로 진행한다.
20. 최종 assemble 성공(package-final). 이 단계는 패키징만 수행하며 단위 검사를 다시 실행한 것으로 세지 않는다. 작업 범위와 필요한 의존 파일·QA만 stage하고 기존 미커밋 작업은 보존한다. 고정 슬롯4·5는 W228 수락 뒤 idle-needs-refresh로 유지한다.
21. 두 worker 종료와 고정 슬롯 보존을 확인했다. stage된601개 경로가 지정 범위와 정확히 일치하고 diff whitespace 검사가 통과했다. 원본 log·중복 패키징 XML·내부 계약은 stage하지 않았으며, 공유 레지스트리의 기존 변경은 작업본에 보존했다.
