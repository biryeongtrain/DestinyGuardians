# W338 — R3 타이탄 달리기

별도 Sol6.1 high 에이전트 한 명이 R3-Titan-Running을 대혼란의 주먹·한손 망치(Hammer of Sol)·파수병의 방패에 적용했다. 이동 때 준비 파지를 계속 유지하던 R2 대신 팔을 흔드는 원본 달리기를 사용한다. 세 종류의 전후좌우 이동12개만 교체하며 대기·시전·공격·회피와 다른 궁극기는 보존한다.

원본은 읽기 전용 `/Users/qf/Downloads/Destiny-Super-Idle-Movement-2026-11-07-R3-Titan-Running`이다. 전체181개 파일99,386,268바이트의 크기·해시 일치를 확인했다. 실제 `Titan_Running_R3.blend`의32개 액션/72개 본을 읽고 선택한 A/B·방향10개 동작의 시작·중간·끝 행렬을 대조했다. 레스트가 이미 포함된 TRS와 단위/축을 한 번만 합성했다. 원본 속도·주기와2틱 표시 보간을 유지하며 루트XZ 이동은 서버 이동에 중복하지 않는다.

전진은 전달표가 우선 연결하도록 지정한 point4 A(Hammer16/30초, 비무장17/30초), 나머지 방향은 각 CATALOG의 run 역할을 사용한다. Hammer와 비무장의 set 방향 순서는 다르다. 비무장의 활성 Fists 연결은 원본의 후보 수준을 유지한다. Shield에 같은 비무장 달리기를 연결하는 것은 사용자의 명시적 포팅 선택이며, 전용 Shield 상태가 새로 증명된 것은 아니다. 전달 자료의 속도 임계값·전환 예시는 추출 확정값으로 사용하지 않았다. 새 게임플레이 속도나 큰 보행 상태 기계도 추가하지 않았다.

R3는 별도 `titan_running_w338.animation.json` 리소스로 둔다. 로더는 R3 표시·정확한12개 이름·계열·원본 액션·주기를 검사하며, 기존 R2 클래스 이동만 정해진 순서로 덮어쓴다. 다른 clip의 중복과 R1/미표시 데이터, 공격/대기 교체는 거부한다. Spectral의 R2 named 연결표와 ACC 거부도 유지한다. 모델 이름에 R3 해시를 포함해 이전 모델 캐시가 새 이동을 가리지 않게 했다. 클래스의 R2 리소스는 동시에 진행한 Maul 파지5개 수정만 포함하며 R3 담당자가 편집하지 않았다.

실제 Gradle 빌드와5개 관련 클래스18개 단위/모델 검사를 통과했다. master가 세 궁극기의 실제 native 네 방향 달리기·정지 시트와 공격 후 달리기/대기 복귀 시트를 직접 확인했다. 세 복귀 모두 궁극기가 아직 활성 상태에서 끝났다. Hammer/Shield 소품은 동작과 함께 표시됐다. native/의 대표 시트, master-png-review.json, native-summary.json을 참조한다. 전체 원본 캡처·상태는 `/tmp/w337-maul-grip/qa/native`에 있다. 중단이나 수동 입력 우회는 없었다.

단위 검사와 실제 PNG를 구분한다. 이번 배치의 실제 서버 GameTest는 새로 실행하지 않았으며 이전 W336 통과를 새 결과로 세지 않는다. 샘플 PNG는60fps 영상이나 모든 각도·프레임의 무관통 보증이 아니다. FPS 스냅샷 외에 프레임타임 분포를 측정하지 않아 성능 인증도 아니다. 실제 GCB 추가 보간과 별도 사운드 청취 수락은 없다. 최종 빌드/팩/정리는 build-final-validation.json, pack-validation.json, cleanup.json에 있다. 배포 팩은188,236,924바이트로250MB 목표 이내다.
