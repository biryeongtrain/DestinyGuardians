# 실제 연결 재접속과 반복 활동 정리

상태: 최종40연결·두 회차 lifecycle 시험 통과. 원시 결과는 `instances-40-lifecycle.json`, 계산 요약은 `lifecycle-summary.json`이다.

기존 5분 지속 시험은 정상 명시적 퇴장만 다뤘다. 추가 opt-in `--lifecycle`은 기존40연결·18활동 구성에서 첫 측정 후9개의 실제TCP 연결을 끊는다.악마의 소굴3명은 같은 계정으로 새 연결을 열어 기존 공격전 run과 동일 월드로 복귀해야 한다. 복귀를 확인한 뒤 엑소더스3명도 같은 검사를 수행한다. 악마의 소굴과 엑소더스의 각 한 파티는 전원이 접속하지 않은 채 운영 유예2400서버틱을 기다린다. 서버의 유예 값을 축소하거나 시간 필드를 바꾸지 않는다.

유예 동안 최소31개의 실제 연결을 유지한다. 다른 참가자들은 기존 회전·ADS·발사 입력을 계속 보낸다. 이는 실제 이동 경로·그래픽·인터넷 검증은 아니다. 만료된 두 월드가 제거된 후 나머지 활동도 정상 퇴장한다. 같은40개 계정으로18개 활동에 다시 입장하고 측정·정리를 반복해 초기화/정원/월드 소유권 재사용을 확인한다.

```sh
python3 scripts/qa/run_server_scale.py --run-dir /tmp/destiny-scale-lifecycle --scenario instances --players 40 --phase-ticks 300 --lifecycle
```

팩은 해시 검증된 warm cache다. 전체 시뮬레이션 거리는 사용자 운영 설정인6, 전역 시야32 / Destiny 월드 실제 상한8이다. 원시 보고서는 회차별 측정과 정리 결과를 보존한다. 강제GC를 실행하지 않으며 heap-used 값은 live-retention이나 장시간 누수 인증으로 해석하지 않는다. 이 추가 검수는 테스트/도구 변경이며 배포 JAR의 제품 구현은 바꾸지 않는다.

## 초기 실패와 원인

첫 두 실행은 재접속/만료 제한 시간 초과였다. 세 번째는 로스터 진단을 확보한 뒤 소유 JVM만 SIGTERM으로 종료했으며 통과로 세지 않는다. 모두 별도 원시 보고서를 보존한다.

- 악마의 소굴 복귀에서 두 플레이어가 상대의 지정 좌석을 차지해 각각의 단일 이동 검사가 서로를 장애물로 거부했다.3명 모두 팩 준비·입장·전체329청크 수신을 마쳤으나2명은 allows=false로 남았다. 이동할 현재 플레이어들을 함께 계획하고 모든 목적지를 검증한 뒤 이동하는 공용 배치로 수정한다.
- 전원이 끊긴 두 파티는 실제 world.players=[]와 PlayerList 부재에도 로스터 connected=3 / allOfflineAt=-1이었다. Fabric networking6.3.10의 Netty channelInactive 경로가 disconnect CAS를 먼저 소비하고 순차 이벤트를 실행한다. 기존 무기 정리는 서버 스레드를 요구하므로 off-thread에서 예외가 나면 뒤의 공격전 콜백이 누락되고 서버 스레드 fallback도 CAS 때문에 재시도하지 못한다. 어떤 정리 콜백이 가장 먼저 예외를 냈는지는 확정하지 않는다.

공용 보완은 서버 play addon만 대상으로 CAS 이전에 소유 MinecraftServer 스레드로 넘긴다. 실제 이벤트·endSession·중복 방지는 기존 Fabric 구현을 유지한다. 수정 후 시험은 각 의도적 종료 handler별 정확히1회·서버 스레드 이벤트, 동일 run 재접속, 원래2400틱 유예, 두 회차의 월드 정리를 확인해야 한다. 최종 시험에서 아래 조건을 확인했다.

## 수정 후 결과

- 최소31개의 실제 연결을 유지했고 악마의 소굴3명·엑소더스3명이 새 네이티브 플레이어 엔티티로 동일 run/동일 월드에 복귀했다. 전체 추적 청크 수신과 allows=true도 확인했다.
- 의도적인12개 연결 종료 콜백은 각각 정확히1회·Server thread였다. 최종 정상 종료까지 포함한52개 연결의 콜백도 모두 서버 스레드에서 중복 없이 관측됐다.
- 전원 이탈 파티의 로스터 connected=0 / 절대 server-tick allOfflineAt 기록을 확인했다. 유예2400틱을 줄이지 않았고 관측 기준2401틱에 두 월드가 제거됐다.
- 두 회차에서 각각18개 임시 월드를 만들고 정상 정리했다. 각 회차 정리 후 남은 월드는 기본3차원과 영구 탑4개이며, 강제/keep 티켓과 활동 소유권 잔존 검사를 통과했다.
- 회차별15초 steady 측정은 약20.02TPS, p95 16.28/16.38ms였다. 재접속/유예 구간 p95 13.69ms / p99 16.06ms / 최대77.70ms였다. 앞선 별도5분 시험과 이 짧은 회차 측정을 구분한다.

전체JUnit은2873개 중 기존3개 실패(과거 자료/소스 누락2개, CYCLOPS 기준1개)가 유지됐다. 추가 실패는 없으며 전체JUnit green으로 보고하지 않는다. `assemble`은 완료됐다. 기존 native14개 회귀는 별도 최종 실행 결과를 참고한다. 운영13600KF Windows/WAN 검증은 사용자가 진단 도구를 직접 실행해 전달할 결과를 기다린다.

최종 별도 네이티브 회귀14개도 모두 통과했다(`lifecycle-final-native.json`). 실제 배포용 JAR과 SHA256은 `artifact-r2.json`에 기록했다.
