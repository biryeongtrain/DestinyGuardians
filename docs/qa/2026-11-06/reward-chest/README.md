# 개인 보상 상자 — 2026-11-06

이전 대화의 미커밋 상자 구현을 이어서 통합했다. 공용 loot 계층이 연출과 보상 소유권을 관리하고, 활동은 테이블·위치·방향·미광체 범위만 제공한다.

## 구현

- 본체/뚜껑 분리 모델, 등장·개방·소멸, 보상 포물선 분출, 미광체 튀기기·흡수, 접근 안내와 우클릭/근접 개방.
- 개인별 상자와 보상. 착지 후 기존 개인 WorldDrop 수집 경로로 연결하며 짧은 수집 지연을 둔다.
- 상자 생성 시 보상을 한 번 추첨하고, 각 보상이 드롭 또는 우편으로 넘어갔는지 인덱스별로 추적한다. 같은 내용의 보상도 서로 다른 지급 건이다.
- 개방 전/분출 중 이탈에도 아직 이전되지 않은 보상을 우편으로 넘기며 미광체는 한 번 지급한다. 소유자·거리·생존·차원 검증을 적용한다.
- 악마의 소굴 완료 시 세픽스 중앙 바닥에 배치하고 입구 쪽을 향한다. 중복 완료 콜백을 막고 같은 인스턴스의 온라인 다운 상태 참가자도 보상 대상에 포함한다.
- 운영자 전용 `destiny devils qa_complete <player>`는 실제 director 완료 전환을 사용한다. 정상 플레이의 완료 트리거는 기존 보스 처치다.
- `tables.json`의 미광체 `[40, 60]`은 Minecraft 경제용 임시 튜닝이며 원작 DDC 확정 수치가 아니다.

## 원본과 에셋

`assets.json`에 원본 아카이브·Blender 파일·출력 해시를 기록했다. 출처 및 생성 방식은 `scripts/loot/build_chest_models.py`에 있다. 기존 대화에서 생성한 출력을 이번에 검수했으며 이번 작업에서 Blender를 다시 평가하거나 모델을 재생성하지 않았다.

Khvostov Golden Chest와 Glimmer 원본의 직교 렌더를 이용한 저요소 입체 모델이다. 원본 메시 그대로의 변환이 아니다. 본체 1요소, 뚜껑 4요소, 미광체 5요소. 상자 텍스처 1024×752, 미광체 64×64. 실제 QA 서버의 전체 Polymer ZIP은 **177,878,835바이트**였다.

## 실제 클라이언트 QA

격리 서버 25610, Vision 클라이언트 8102/8103의 DevilsQA/DevilsQA2 사용. GCB 클라이언트 모드 없이 실행했다. 서버 heap 4G, 각 클라이언트 heap 2G. 전용 keep_awake master로 재빌드 구간까지 감쌌다.

1. 탑에서 운영자 명령으로 개인 상자를 배치하고 **native 전진 입력**으로 접근하여 개방했다. `chest-open-2.png` 닫힌 상자/안내, `chest-open-8.png` 개방/엔그램·무기·미광체 분출, `chest-open-17.png` 흡수 후 +50 미광체를 확인했다. 제어 시퀀스의 lease 해제 완료도 확인했다.
2. 미광체 3600→3650, 드롭 2개를 확인했다. 추가 미개봉 상자를 만들고 차원을 이동한 뒤 미광체 3700, 우편 4→8, 잔여 드롭/상자 0을 확인했다. 기존 드롭 2개와 미개봉 보상 2개가 회수된 결과다.
3. 2인 공격전의 완료 fixture를 두 번 호출해 각 계정 상자가 1개인 것을 확인했다. 자동 귀환 후 QA1 미광체 3700→3745·우편 8→10, QA2 미광체 4020→4060·우편 0→2, 양쪽 잔여 드롭/상자 0. `first-account-evidence.txt` 참조.
4. 첫 fixture가 지급만 호출하여 전투가 계속되는 문제를 발견해 실제 director 완료 전환으로 수정했다. 재빌드 후 2인으로 다시 실행해 완료 HUD/귀환 카운트다운, 각 상자 1개, 탑 자동 귀환을 확인했다. `final-completion-evidence.txt` 참조. 마지막 아레나 PNG는 두 계정이 같은 위치에 겹쳐 다른 플레이어에게 가려졌다. **아레나 상자 바닥 배치·방향의 최종 시각 수락 증거로 사용하지 않는다.**

## 남은 검증과 제한

- 보스 처치부터 완료까지의 전체 플레이, 다운 상태 참가자의 실제 지급, 실제 연결 종료 직전 분출 중 회수, 서로 다른 계정 상자의 개방 상태를 나란히 비교하는 장면은 미검증이다. 위 완료 검사는 운영자 fixture다.
- 소리 이벤트 연결은 구현했지만 스피커 청취 품질 및 다수 상자 FPS는 검증하지 않았다.
- 우편함 거절 시 상자는 실행 중 재시도한다. **보류 보상의 재시작 영속화는 없다.** 우편함 포화 상태의 종료나 비정상 종료까지 손실 방지를 보장하지 않는다. 이미 착지한 WorldDrop의 우편 거절 처리도 기존 제한이 남는다.
- 완료 전에 접속이 끊긴 참가자까지 소급 지급하지 않는다.
- 상용 출시 품질의 최종 수락으로 기록하지 않는다. 시각 연출과 기본 회수 동작을 검수한 구현 배치다.

## 정리

QA 클라이언트 종료 확인 후 격리 프로필 options.txt를 실행 전 백업으로 복구했다. 이 배치 소유 서버 coordinator와 keep_awake master에 STOP을 전달했다. 사용자 일반 프로필과 월드는 변경하지 않았다. 원시 인증 토큰·제어 응답은 커밋하지 않았다.
