## Rig expansion assessment

Matching the number 72 by itself would not remove retargeting: bind orientation, pivots, proportions, skin weights and attachment conventions must match too. The current player model already separates hip/waist/chest, upper arms/forearms and thighs/calves; it is not the vanilla six-part model. Its 18 groups include non-anatomical shadow, name tag and cape. The runtime animation set addresses 16 groups.

A useful next rig revision would add clavicles, independent wrist/hand skin, ankles/feet and toes, and optionally one additional spine/neck segment, while preserving a single head. Those directly improve revive landing, hand placement, weapon handling and shoulder motion. Add finger chains only if the skin geometry and close camera actually need them. A 72-node logical source rig can be retained for evaluation without creating 72 visible Minecraft item displays; render only groups containing useful geometry. Empty bones are still evaluated, so profile animation cost rather than claiming they are free.

This should be a versioned new limb with legacy aliases and a deliberate migration of skin UVs, armor overlays, cape, held items, first/third-person visibility and existing supers/dodges. Appending empty bones to the current model cannot deform its unsegmented hands/feet. No global rig rewrite was applied in this task.

Add `--verify` for byte-identical output comparison. Manifest records original assets, generator and all consumed helper/model hashes.
