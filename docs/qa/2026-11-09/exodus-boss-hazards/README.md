# Exodus boss visibility, death volumes and traversal distance

2026-11-09 KST 최종 수락. 실제 보스 장면, 충전/피해 단계, 낙사/고스트/체크포인트 복귀를 확인했다. 전체 전투 완주 수락은 아니다.

## 요청과 변경

보스가 있는 상태의 실제 1인칭 화면에서 기존 조명이 전투 구역 주변까지 충분히 닿지 않음을 확인했다. 보스실 다층 바닥 위에 6블록 간격의 level-15 비충돌 보조광을 추가했다. 615개 신규 light 셀과 기존 1개 업그레이드다. 모든 원래 충돌 블록은 유지했다.

원본 패키지의 map layout, mission phases, activity JSON에서 디코딩된 이름 있는 kill/death volume을 찾지 못했다. 원본의 mission_raw 바이너리를 전부 해석해 원래 트리거가 없다고 결론 내린 것은 아니다. 기존 NBT regions/data는 비어 있었다. 이번 위험 구역은 Minecraft용 저작 데이터다.

`hazards.json`의 세 영역을 Nucleoid NBT `regions`, marker `death`로 내보낸다. `TemplateHazards`는 map 소유의 불변 목록을 읽는 공용 코드이며, Exodus 세션은 자기 NBT에서만 이를 적용한다. 다른 활동에 위험 구역을 자동 적용하지 않는다.

- 세계 하부/경계: y < world 28 및 기존 측면 경계. 위쪽 경계는 없어 클래스 점프를 제한하지 않는다.
- 협곡 하부: local x720..1114, z180..660, y0..25 (실제 world y<58).
- 보스실 하부 구조: local x250..390, z1415..1560, y0..31 (실제 world y<64). 인근 저작 경로/마커의 최저 발 높이는 local 41/world 73이다.

기존 무료 복귀를 Guardian Down 사망 기록/부활/전멸 정책에 연결했다. 고스트와 운반 중 전기 구체는 마지막 검증된 안전한 발판에 둔다. 안전 지점이 사라지면 현재 체크포인트 주변 지지 바닥을 찾는다. 임시 피해 무적은 낙사 판정을 무효화하지 않는다.

보스 충전 보충 조건도 수정했다. 기존 `queue.isEmpty() && live.isEmpty()`는 스텔스 장이 켜진 보스가 살아 있어 운반병 부족을 보충하지 못했다. 이제 실제 구체/운반/운반병 수가 요구량보다 적고 대기열이 비었으면 부족한 수만 보충하며 기존 스폰 예산은 유지한다.

## 이동 거리

전체 저작 경로는 2,488 cells / 2,487 horizontal one-block edges, 약 2.5km다. 높이 변화와 전투 우회 이동은 제외한다. 게임 안내선의 425개 샘플 점을 직선으로 이은 길이는 약 2.193km지만, 이는 코너를 생략한 안내선 값이므로 실제 저작 경로와 구분한다.

| 구간 | 저작 경로 수평 거리 |
| --- | ---: |
| 입구 → 첫 전기 충전(B03) | 658m |
| 첫 충전 → 두 번째 충전(B09) | 1,464m |
| 두 번째 충전 → 해킹(B10) | 160m |
| 해킹 → 보스(B11) | 205m |

각 목표 사이 전체 목록은 `route-distance.json`에 있다. 전투 완주 시간을 측정한 결과는 아니다.

## 현재 검사

관련 JUnit 23개 통과, Python 회귀 5개 통과. 전체 JUnit 2,827개 중 3개가 기존 QA와 같은 원인으로 실패했다: CYCLOPS 전투 밸런스 기대값, 누락된 기존 음악 source-inventory.json, 누락된 기존 WeaponFeedbackW112GameTests.java. 이번 작업에서 이 파일/밸런스를 변경하지 않았다. 전체 통과라고 보고하지 않는다.

최종 NBT 전 블록 비교에서 바뀐 셀은 비충돌 light 616개뿐이며 나머지 블록 상태가 동일하다. 안내선 425점과 마커 333개는 세 위험 영역 밖이다. 실제 NBT/GameTest 및 인게임 결과는 최종 갱신한다.

## 후속 구체 위치 보정

첫 실제 보스 진행 검사에서 구체 2개를 충전한 뒤 남은 구체를 정상 발판/스폰 위치에서 회수하지 못했다. 종전 코드는 6칸 아래에 floor를 찾지 못하면 적의 사망 좌표를 그대로 영구 구체 위치로 사용했다. 진단 후 사이클롭스의 실제 구체가 적의 사망 높이 91보다 4블록 낮은 정상 발판 87에 있음을 확인했다. 초기 QA가 픽업 전에 발전기로 텔레포트해 회수를 놓친 것도 원인이며, 이를 모든 정상 발판에서 회수 불가능한 맵 결함으로 결론 내리지 않는다. 실제 발판에서 회수하자 충전/해제가 진행됐다. 낙사 구역과의 상호작용을 위해 구체는 2칸 머리 공간이 있는 지지 바닥에 놓고, 현재 전투의 저작 스폰 발판보다 낮은 장식 바닥 또는 낙사 영역이면 발전기 주변의 안전 바닥으로 보정한다. 유효한 바닥이 전혀 없으면 회수 불가능한 구체를 수량에 포함하지 않아 보충 경로가 재시도할 수 있다. OP 전용 `destiny exodus inspect`는 대기/운반병/구체 위치를 읽기만 하는 진단 명령이다.

이 후속 보정 뒤 관련 JUnit 23개를 다시 실행해 실패 0을 확인했다. 위 전체 2,827개 결과는 이 후속 보정 전의 통합 gate이며, 같은 전체 gate를 반복했다고 주장하지 않는다. 실제 NBT GameTest도 후속 보정 전 실행이며 NBT 데이터/로더/영역 판정은 동일하다. 최종 보스 런타임으로 구체 수집/페이즈 전환을 별도로 수락한다.

## 최종 실제 클라이언트 결과

- 스텔스 장이 켜진 실제 보스, 해제된 실제 보스, 반대편 발판에서 본 보스를 촬영했다. 표준 QA 밝기 gamma 0.5, 외부 셰이더팩 없음. 기본 HUD/손/토스트만 숨겼으며 커스텀 퀘스트 HUD와 실제 전투 이펙트는 남아 있다. PNG 실제 해상도는 `native-review.json`에 있다. 합성/Blender 렌더가 아니다.
- OP fixture로 이전 11개 목표를 건너뛰고 위치/저항 효과/적 피해를 준비했다. 구체 수집/발전기 전달/필드 해제는 제품의 실제 tick 경로를 사용했다. 최종 `inspect`에서 보스가 살아 있는 동안 운반병 3개가 존재하며, 충전 1→2→필드 DOWN 전환을 확인했다.
- 필드 UP에서는 피해 명령이 적용되지 않았고 HP 1800이 유지됐다. 필드 DOWN에서는 보호막(absorption)이 590→580으로 감소했다. HP는 아직 보호막이 남아 1800이며 HP 손실로 잘못 보고하지 않는다.
- 최종 낙사는 서버 fixture로 열린 구멍 위에 위치시킨 뒤 실제 중력으로 y61.9167까지 떨어뜨렸다. NBT `boss_understructure` 판정으로 사망 통계가 1→2, 정확히 1회 증가했다. 고스트는 안전한 체크포인트 주변 (577.5,90,1746.5)에 놓였고 자동 전멸/복귀가 이어졌다. 네이티브 키 입력으로 걸어 떨어진 검사는 아니다.
- 자동 복귀 후 카메라 대기 중 일반 보스 공격으로 추가 사망 1회가 발생했다. `final-fall-checkpoint.png`는 그 뒤 다시 복귀한 상태다. 해당 전투 사망을 낙사 중복 발생으로 계산하거나 숨기지 않는다. 실제 낙사 증가분은 별도 BEFORE/AFTER 로그로 구분했다.
- 초기 클라이언트 재시작 1회는 서버 포트 준비 전 자동 연결해 connection refused가 났다. 같은 실패 클라이언트를 종료한 뒤 포트 준비를 확인하고 다시 연결했다. 이후 시작은 포트 대기를 사용했다.
- 마지막 상태는 실제 플레이어 카메라/지면/생존 상태이고, lease 비활성·heldKeys 빈 목록·모든 nativeInput false다. 이번 단계에서 키 입력 플레이 검증을 주장하지 않는다.

`native-events.txt`, `native-review.json`, 각 PNG 옆 상태 JSON에 근거를 보관했다. 사용자 일반 프로필/월드와 Downloads 원본은 보존했다.
