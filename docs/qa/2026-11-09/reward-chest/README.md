# 공격전 보상 상자 소리·등급 확률

사용자 제공 `0242-00001106.mp3`를 상자의 실제 열기 동작에 연결했다. 원본·변환 결과·도구 해시는 `art/audio/reward-chest/manifest.json`에 남겼다. MP3 컨테이너 길이는 2.573333초이며, 표준 지연/패딩 처리를 반영한 전체 디코더 출력 123,264프레임(2.568초)을 48kHz·스테레오 Vorbis로 보존했다. 원본 파일은 변경하지 않았다.

기존 임시 열림/분출음은 교체했다. 상자가 열릴 때 소유자에게만 `destiny:loot.chest.open`, PLAYERS, volume=1, pitch=1로 한 번 전송한다. 실제 아이템 획득 시 희귀도별 음원은 계속 별도로 재생한다.

사용자는 80%의 적용 범위를 **보상 상자**로 확인했다. 상자는 1회 확정 추첨하며 희귀 무기 20%, 전설 엔그램 48%, 전설 무기 24%, 경이 엔그램 8%다. 전설 이상은 상자당 정확히 80%다. 악마의 소굴/엑소더스의 추락의 완료 확정 장비 1개/2개, 미광체 범위, 적 처치 드랍과 엔그램 해독표는 유지했다. 원작 공식 드랍률이 아닌 사용자 지정 조정이다.

## 확인한 내용

- 관련 JUnit **22/22 통과**. 원본 해시, 전체 OGG 페이지·Vorbis 헤더, 스테레오/48kHz/끝 granule, 이벤트 매핑과 기존 음원 검증 계층을 검사했다. 새 음원도 명시적 해시 목록에 등록했으며 다른 위치 기반 효과음의 모노 검사는 유지한다. `targeted.json`.
- 실제 서버 GameTest **1/1 통과**, 시험 시간 2.527초. 모델/프로필 준비 뒤 시험 시계를 시작한다. `gametest-result.txt`.
- 등장 중·사거리 밖 동작은 무음이며 실제 열기에서 한 번만 전송한다. 재클릭과 분출 시 기존 임시 소리가 겹치지 않고, 관찰자의 연결로 음원이 전송되지 않으며 열린/미개봉 상자 정리도 새 열기 소리를 내지 않는다.
- 확률은 가중치의 유리수 계산으로 4/5임을 대조했다. 기존 HEAD와 비교해 `strike_chest` 이외의 모든 표, 활동 연결·미광체·적 연결·해독 연결이 같은 것도 확인했다. `probabilities.json`.
- 최종 전체 검사 결과는 `full-gate.json`, 실제 Gradle JAR의 음원·클래스·보상 표 일치와 SHA-256은 `artifact.json`, 실제 생성 공용 ZIP은 `pack-audit.json`에 기록한다.
- 최종 전체 JUnit은 **2,846개 중 기존 실패 3건**이다. 기존 음원 QA 자료 누락(`FireVariantsW98Test`), 기존 검사 소스 누락(`GoldenGunHudW122AssetTest`), 기존 피해량 기대값 불일치(`MinorPveBalanceW342Test`)가 동일하게 남았다. 새 실패는 없다.
- 실제 공용 ZIP은 **133,525,858바이트**로 250MB 목표 이내이며 새 음원 해시와 이벤트 정의가 일치했다. 실제 Gradle JAR는 **424,266,541바이트**다.
- 범용 팩 검사기는 실제 ZIP에서 추출한 새 음원의 참조·JSON을 통과했으나, 기존 26.3 생성기의 배열형 `min_format: [97,1]`을 숫자 전용 검사로 거부한다. 메타데이터를 바꾸거나 이 검사를 전체 통과로 표시하지 않는다. `resource-validator.txt`. 별도 OGG/서버/ZIP 대조 결과와 구분한다.

## 검증 범위와 정리

실제 서버 상자/패킷 및 파일/팩 검증이다. Vision 클라이언트·마우스 입력·스피커 청취 검증은 수행하지 않았다. 음원 밸런스나 실제 청취까지 수락한 것으로 표현하지 않는다.

격리 경로는 `/tmp/reward-chest-qa/gametest`, `/tmp/reward-chest-qa/server`다. 이전 소유 QA 폴더를 CoW 복사해 사용하며 일반 Minecraft 프로필·월드는 열지 않았다. GameTest 필터는 `destiny-test:reward_chest_sound_game_tests*`, 준비 상한은 600초다. 각 실행은 `keep_awake.py --seconds 1200`으로 감쌌다. 공용 ZIP을 확인한 후 소유 서버를 정상 종료하며 결과는 `cleanup.json`에 남긴다.
