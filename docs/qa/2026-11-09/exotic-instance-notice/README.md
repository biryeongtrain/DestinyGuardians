# 경이 획득 인스턴스 채팅 알림

획득에 성공한 경이 엔그램 또는 경이 장비를 현재 같은 월드 인스턴스의 모든 접속자에게 알린다. 획득자도 한 번 받는다. 실제 무기/스킨의 등급으로 판별하며 이름은 기존 획득 카드와 같은 한국어 이름을 공용 메서드로 구한다. 조사도 이름의 받침에 맞춘다.

예시:

```text
LootOwner 님이 경이 엔그램을 획득했습니다.
LootOwner 님이 스페이드 에이스를 획득했습니다.
```

현재 공격전 구조는 `StrikeInstances`의 실행 인스턴스마다 별도 `ServerLevel`을 소유한다. 알림은 획득 순간의 실제 월드 객체에 있는 유저를 대상으로 한다. 서버 전체 접속자·화력팀·활동의 이전 참가 명단·같은 차원 유형/맵 템플릿을 기준으로 보내지 않는다. 거리 제한은 없으며, 다른 인스턴스나 이동 전 인스턴스로 큐를 남기지 않는다. 공용 획득 경로에 연결하며 별도 전역 상태나 활동별 하드코딩을 추가하지 않았다.

장비는 `GearAcquisition.store`의 성공 경로, 엔그램은 실제 보관 뒤 알림 경로에서 한 번 알린다. 일반 해독과 엔그램 칸이 가득 찬 경우의 즉시 해독은 실제 받은 무기를 알린다. 드랍 생성이나 단순 보관함 교환은 획득 알림이 아니다. 기존 희귀도별 획득음은 획득자 전용을 유지한다.

## 서버 검증

실제 `StrikeInstances`와 Fantasy 임시 월드 2개(같은 차원 유형)를 사용하는 GameTest **3/3 통과**. 준비 133,843ms 뒤 시험 시계를 시작했고 시험 시간은 2.180초였다. 연결의 실제 `ClientboundSystemChatPacket` 내용을 검사했다.

- 경이 엔그램, 스페이드 에이스, 공용 경로의 직접 지급, 일반 해독과 자동 해독에서 획득자/같은 인스턴스 유저가 정확한 이름의 알림을 한 번씩 받고, 다른 인스턴스는 받지 않는다. 가까운 유저로만 제한하지 않는다.
- 일반·고급·희귀·전설 엔그램과 전설 장비, 이미 소유한 동일 객체의 재지급 거부, 보관 칸 부족, 잘못된 해독, 기존 장비 교환은 경이 알림을 내지 않는다.
- 멤버가 다른 인스턴스로 이동하면 예전 참가 명단에 남아 있어도 이전 인스턴스 알림을 받지 않는다. 이동한 월드에서 획득하면 새 월드의 유저만 받는다.

최종 전체 JUnit은 `full-gate.json`, 실제 Gradle JAR와 변경된 3개 클래스의 일치는 `artifact.json`, 서버 결과는 `gametest-result.txt`에 기록한다. 리소스팩 자산은 추가하지 않았다. 그래픽 클라이언트에서 채팅을 열어 보는 검증은 수행하지 않았으며 서버 패킷 검증과 구분한다.

전체 JUnit **2,846개 중 기존 실패 3건**은 같은 상태다. 기존 음원 QA 자료 누락(`FireVariantsW98Test`), 기존 검사 소스 누락(`GoldenGunHudW122AssetTest`), 기존 피해량 기대값 불일치(`MinorPveBalanceW342Test`)가 남았다. 새 실패는 없다. 실제 Gradle JAR는 **424,269,155바이트**, SHA-256 `dc0f8f702d7726c0f121b2a980ee8f998121518425e31484e56a67c51ddeedd2`다.

격리 실행 경로는 `/tmp/exotic-instance-notice-qa/gametest`, 필터는 `destiny-test:exotic_acquisition_notice_game_tests*`다. 이전 소유 QA 폴더를 CoW 복사했고 `keep_awake.py --seconds 1200`으로 실행을 감쌌다. 테스트는 소유한 임시 인스턴스와 모의 접속자를 정리하며, GameTest 서버가 정상 종료됐음을 확인했다. 일반 Minecraft 프로필/월드나 Vision 클라이언트를 조작하지 않았다.
