# Destiny Guardians

데스티니 가디언즈를 기반으로 만드는 장기 프로젝트입니다.

> 📝 이 문서는 기존 기획 틀을 바탕으로 구체화한 버전입니다. `[결정 필요]` 표시가 있는 항목은 아직 정해지지 않아 확정이 필요합니다.

---

## 1. 개요

데스티니 가디언즈의 시스템(직업, 설정, 콘텐츠)을 가져와 마인크래프트 야생과 어우러지도록 만드는 마인크래프트 모드입니다.

### 1-1. 프로젝트 목표
- 데스티니의 **손맛(총기 사격감, 직업별 이동, 스킬 연계)** 을 마인크래프트에서 재현합니다.
- 야생(채집, 건축, 생존)을 버리지 않고, 데스티니 콘텐츠를 야생 위에 **덧붙이는 구조**로 만듭니다.
- 최종 목표 콘텐츠는 **레이드**이며, 모든 기본 시스템은 레이드를 돌릴 수 있는 수준을 기준으로 완성합니다.

### 1-2. 기술 기준

**마인크래프트 26.3 / Fabric 기반 서버사이드 모드**로 만듭니다.
플레이어는 **바닐라 클라이언트로 접속**하고, 모드는 서버에만 설치합니다. 커스텀 외형은 접속 시 자동 적용되는 **서버 리소스팩**으로 전달합니다.

| 항목 | 방식 | 비고 |
|---|---|---|
| 버전 / 로더 | Minecraft 26.3 + Fabric Loader + Fabric API | 서버에만 설치 |
| 커스텀 아이템·블록·엔티티 | Polymer | 서버에서는 커스텀 객체, 클라이언트에는 바닐라 객체 + 리소스팩 모델로 보임 |
| 리소스팩 배포 | Polymer 자동 리소스팩 생성 + 자동 호스팅(autohost) | 접속 시 리소스팩 강제 적용 |
| 모델 / 애니메이션 | **BetterModel** (Fabric 서버 모드) | Blockbench 모델·애니메이션을 서버에서 재생. 적·보스 모델과 **플레이어 모델 애니메이션**(궁극기, 구르기)에 사용 |
| VFX | 바닐라 파티클 + 디스플레이 엔티티(보간 애니메이션) | 형태가 있는 효과 |
| 화면 효과 | **26.3 포스트 이펙트** (`/posteffect`, `end_of_frame`) | 26.3 정식 기능. 서버가 플레이어별로 켜고 끔 ([docs/07](design/07_포스트이펙트_셰이더.md)) |
| HUD | **DisplayHud** (minigame-lib) | 텍스트·아이템·블록 디스플레이를 화면 좌표에 고정해 HUD로 사용 |
| UI (스킬 트리, 상점) | **DisplayHud** 우선, sgui는 보조 | 단순 목록·보관함 같은 화면만 sgui 사용 |
| 공통 서버 라이브러리 | **minigame-lib** ([minigame-shader](https://github.com/biryeongtrain/minigame-shader)) | DisplayHud, ShaderFX(화면 효과·전환), FOV 조절, 시네마틱, 음악 |
| 데이터 정의 | JSON (데이터 주도) | 무기·능력·적 수치를 코드 수정 없이 조정 |

> ✅ **Polymer**는 `0.18.4+26.3`, **BetterModel**은 3.5.0부터 26.3을 지원합니다. (2026-10-20 확인)
> ⚠️ sgui가 26.3을 지원하는지는 착수 시점에 확인해야 합니다.
> ✅ **minigame-lib는 2.0.0에서 26.3 / Polymer 0.18.4 / Java 25로 포팅되었습니다** (2026-10-22). 아래는 포팅 때 바뀐 셰이더 규칙 기록입니다. 특히 HUD 위치 변환이 들어 있는 **코어 셰이더(`rendertype_text.vsh`, `entity.vsh`, `hud.glsl` 등)는 버전마다 바닐라 셰이더 구조가 바뀌므로** 26.3 셰이더에 맞춰 다시 작성해야 합니다. 26.3에서는 텍스트 셰이더가 `core/text.*`로 바뀌었고, `#moj_import` 대신 `#include`, 입출력 `layout(location)` 필수 등 컴파일 방식이 바뀌었습니다. (세부: [docs/08](design/08_UI_HUD_명세.md) 7장)

#### 서버사이드 제약과 대응

클라이언트 모드가 없으므로 아래 제약을 전제로 설계합니다.

| 제약 | 대응 |
|---|---|
| 새 단축키를 추가할 수 없음 | 바닐라 입력만 사용: 점프, 웅크리기, 달리기, 손 바꾸기(F), 버리기(Q), 핫바 슬롯, 좌·우클릭. 서버는 플레이어 입력 패킷으로 점프·웅크리기·이동 키 상태를 받을 수 있음 |
| 클라이언트 HUD 코드를 추가할 수 없음 | DisplayHud로 HUD와 UI를 구성. 액션바·보스바는 보조 수단 |
| 클라이언트 예측이 없음 | 이동·사격은 서버 처리라 핑에 따라 반응이 늦음. 이동 능력은 속도(velocity) 부여 방식으로 짧고 단순하게 설계 |
| 클라이언트 렌더링 코드를 추가할 수 없음 | 리소스팩 코어 셰이더 + 디스플레이 엔티티 + 바닐라 파티클로 구현 |
| 정조준 줌 | minigame-lib의 **FOV 조절**(`CameraEffects.setFov`)로 줌 구현 + 이동 속도·반동 감소 |

### 1-3. 아트 방향
- **로우폴리 + 포인트 강조**: 디테일보다 실루엣과 특징(색, 형태)이 한눈에 보이게 합니다.
- **실제 Destiny 디자인 우선**: 원작자 ArtStation·Bungie 공개 자료·게임 내 외형을 대조합니다. 일반 SF 참고작으로 임의 대체하지 않습니다.
- AI/Blockbench 제작 시 원작 실루엣·비율·구조를 최대한 보존합니다. 확인하지 못한 외형은 잠정으로 표시합니다.
- 사용 허가·배포 권리가 확인되고 기술적으로 호환되는 공개 원본 모델이 있으면 우선 검토합니다. 이번 H12는 원본 메시를 확보하지 못해 직접 재구성했습니다. 게임 파일을 임의 추출하거나 권리가 불명확한 메시·텍스처·사운드를 재배포하지 않습니다.

## 2. 세계관

데스티니 가디언즈 **붉은 전쟁 이후, EDZ(유럽 사각지대)를 복구하는 수호자들**을 배경으로 합니다.

### 2-1. 설정 요약
- 붉은 전쟁으로 마지막 도시가 큰 피해를 입었고, 수호자들은 빛을 되찾은 뒤 지구 곳곳을 재건하기 시작합니다.
- 플레이어는 EDZ에 파견된 수호자입니다. 폐허가 된 땅을 개척하고(야생), 위협 세력을 몰아내며(전투), 거점을 다시 세웁니다(건축).
- 야생 요소와 설정을 이렇게 연결합니다.
  - **채집·건축** → 수호자 거점(전진기지) 재건
  - **몹 사냥** → EDZ에 남은 적 세력 소탕
  - **보스·레이드** → 붉은 군단 잔당 또는 군세의 핵심 전력 격파

### 2-2. 등장 세력 `[결정 필요]`
EDZ 배경에 맞춰 1차로는 아래 세력을 우선 구현합니다.

| 세력 | 역할 | 대표 유닛 예시 |
|---|---|---|
| 몰락자 (Fallen) | 야생 기본 적, 약탈자 | 졸개, 반달, 캡틴, 서빌 |
| 군세 (Hive) | 지하·동굴형 적 | 시종, 침략자, 기사, 마녀 |
| 카발 (붉은 군단 잔당) | 레이드 적 | 군단병, 투사, 사이온, 백부장 |

### 2-3. 세계 구성
- **EDZ 바이옴 / 구조물**: 무너진 마을, 교회 탑, 몰락자 거점, 군세 둥지 등을 월드 생성 구조물로 배치합니다.
- **수호자 거점**: 상인 NPC(무기 상인, 치장 상인)와 퀘스트 게시판이 있는 거점. 기본 거점 1곳을 생성하고, 이후 플레이어가 확장할 수 있게 합니다.

## 3. 기본 시스템

기본 시스템은 데스티니 가디언즈 시스템을 구현하는 데 반드시 필요한 요소입니다.

| 시스템 | 우선순위 | 설명 |
|---|---|---|
| 직업 및 능력 (3.0 시스템) | 1차 | 타이탄·헌터·워록, 빛 속성 3종 |
| 무기 | 1차 | 총기 사격, 반동, 탄약, 프레임 |
| 적 시스템 | 1차 | 레이드에 필요한 적 AI |
| 스탯 | 2차 | 방어구 스탯과 능력 쿨타임 연동 |
| 미광체 | 2차 | 거래 화폐 |
| 경이 시리즈 | 3차 | 고유 특성을 가진 무기·방어구 |
| 치장 | 3차 | 셰이더, 장식, 방어구 외형 |
| 참새 | 보류 | 탈것. 구현 여부 검토 |

---

### 3-1. 직업 및 능력

1차 구현 요소입니다.

- 타이탄
- 헌터
- 워록

을 구현하고, 각 직업의 특징을 반드시 구현합니다. 직업은 **빛 속성(Arc, Solar, Void)** 만 구현합니다.

#### 3-1-1. 직업별 이동 (필수 특징)

| 직업 | 이동 방식 | 구현 기준 (가안) |
|---|---|---|
| 워록 | **활공** | 공중에서 점프 키 유지 시 낙하 속도 감소 + 전방 추진. 약 2~3초 지속 |
| 타이탄 | **제트팩 상승** | 공중에서 점프 키 유지 시 수직 상승. 약 1.5초 지속 후 하강 |
| 헌터 | **2단(3단) 점프** | 공중에서 점프 키 입력 시 추가 점프. 기본 2단, 특성으로 3단 |

- 공통: 공중 이동 중에는 낙하 피해를 받지 않거나 크게 줄입니다.
- 이동 수치는 밸런스 테스트 후 조정합니다. 야생 이동(엘리트라 등)과 겹치지 않도록 지속 시간을 제한합니다.

#### 3-1-2. 능력 슬롯

각 직업은 아래 슬롯으로 구성됩니다.

GCB-mod 클라이언트가 있는 플레이어는 전용 키(Z·X·C·V·0)로, 없는 플레이어는 아래 **바닐라 입력 조합**으로 능력을 씁니다. 세부 매핑은 [design/12](design/12_스킬_입력_GCB_바닐라_혼용.md)를 따릅니다.

| 슬롯 | 설명 | 입력 (가안) |
|---|---|---|
| 궁극기 (Super) | 게이지를 채워 발동하는 강력한 능력 | 웅크리기 + 손 바꾸기(F) |
| 수류탄 | 투척형 능력 | 손 바꾸기(F) |
| 근접 | 근접 공격 능력 | 무기를 들지 않은 상태 또는 능력 슬롯에서 좌클릭 |
| 직업 능력 | 방벽, 회피, 균열 등 직업 고유 능력 | 웅크리기 두 번 |
| 점프 | 직업별 이동 방식 | 공중에서 점프 키 |
| 측면 (Aspect) | 패시브 특성 (2칸) | - |
| 파편 (Fragment) | 소형 패시브 특성 (속성별 칸 수) | - |

> 대안: 핫바 한 칸을 **능력 슬롯 아이템**으로 고정하고, 그 칸을 들고 좌·우클릭으로 수류탄·근접을 쓰는 방식. 입력이 겹치지 않게 테스트로 확정합니다. `[결정 필요]`
> 능력 쿨타임과 궁극기 게이지는 DisplayHud로 화면에 상시 표시합니다.

#### 3-1-3. 직업별 1차 구현 목록 (가안)

| 직업 | Arc | Solar | Void |
|---|---|---|---|
| 타이탄 | 대혼란의 주먹 / 해머 펀치 / 방벽 | 태양의 망치 / 화염 망치 / 방벽 | 감시자의 수호 방패 / 방패 투척 / 방벽 |
| 헌터 | 아크 지팡이 / 연발 공격 / 회피 | 황금 총 / 칼 투척 / 회피 | 그림자 사격 / 연막탄 / 회피 |
| 워록 | 폭풍 진동 / 연쇄 번개 / 균열 | 새벽의 기도 / 화염 손바닥 / 균열 | 신성 폭발 / 공허 손바닥 / 균열 |

> 1차에서는 직업별 속성당 궁극기 1종, 수류탄 2~3종, 근접 1종, 직업 능력 2종을 목표로 합니다. 이후 확장합니다.

#### 3-1-4. 스킬 트리 (Prism 방식)

[image] image.png

스킬 트리는 Prism과 같은 방식으로 만듭니다. 궁극기, 근접, 직업 능력 등을 각각 선택할 수 있습니다.

- 유저는 **언제든 직업을 바꿀 수 있습니다.** (전투 중 변경 불가, 거점 또는 비전투 상태에서만 변경 `[결정 필요]`)
- 직업은 장비 아이템이 아니라 **플레이어 데이터**로 저장합니다.
- 속성을 섞어 장착할 수 있습니다. 예를 들어 타이탄이 **아크 궁극기 대혼란의 주먹 + 솔라 근접 화염 망치 + 보이드 방벽**을 한 번에 쓸 수 있습니다.
- 속성을 섞을 때의 제한 `[결정 필요]`
  - 안 A: 완전 자유 조합 (Prism처럼)
  - 안 B: 측면·파편은 주 속성 하나만 적용, 능력 슬롯만 자유 조합
- 해당 UI는 **DisplayHud 기반**으로 만들어 인터랙티브하게 조작할 수 있게 합니다. 구조는 3-1-5를 따릅니다.
- sgui는 보관함·목록처럼 상자 화면이 더 편한 경우에만 보조로 사용합니다.

#### 3-1-5. DisplayHud UI

[minigame-shader](https://github.com/biryeongtrain/minigame-shader)의 minigame-lib에 들어 있는 DisplayHud(원본: dorondo0000/DisplayHUD)를 사용합니다.

**동작 방식**
- 텍스트·아이템·블록 디스플레이를 **플레이어에게 탑승(passenger)** 시켜 항상 따라다니게 합니다.
- 디스플레이 엔티티는 **해당 플레이어에게만 보입니다.** 다른 플레이어의 화면에는 나타나지 않습니다.
- 리소스팩 코어 셰이더가 특정 좌표 범위(y < -1000)에 놓인 디스플레이를 **화면 좌표로 옮겨** 그립니다. 그래서 월드 오브젝트가 아니라 화면에 붙은 HUD처럼 보입니다.
- 위치는 **1920×1080 기준 화면 좌표**로 지정합니다. 정렬(LEFT / CENTER / RIGHT)을 정하면 화면 비율이 달라도 왼쪽·가운데·오른쪽 기준으로 자리를 지킵니다.
- 위치·크기·회전은 **보간 시간(틱)** 을 줘서 부드럽게 움직일 수 있습니다. 여러 요소를 묶어 한꺼번에 옮길 수도 있습니다(`HudMover`).
- 사망 시 제거 여부를 HUD마다 정할 수 있고, 리스폰·차원 이동 시 다시 붙습니다.

**요소 종류와 쓰임**

| 요소 | 쓰임 |
|---|---|
| `TextDisplayHud` | 숫자(탄약, 쿨타임 초), 이름, 설명 문구. 리소스팩 폰트 글리프로 아이콘·게이지 이미지도 표시 |
| `ItemDisplayHud` | 무기·능력 아이콘. 리소스팩 아이템 모델로 슬롯 아이콘, 3D 무기 미리보기 |
| `BlockDisplayHud` | 배경 패널, 단색 막대(게이지 채움), 강조 테두리 |

**인터랙티브 조작**

DisplayHud는 화면에 그리기만 하고 입력 처리는 들어 있지 않습니다. 커서와 선택은 직접 만들어야 합니다.

- 참고 구현: minigame-lib의 **시네마틱 편집기**는 월드에 고정한 패널에 상호작용(Interaction) 엔티티 히트박스를 깔고, 화면 중앙 조준점이 닿은 버튼을 밝게 표시한 뒤 클릭으로 실행합니다. 숫자·이름 입력은 바닐라 **Dialog** 창을 씁니다.
- 화면 고정 UI(스킬 트리 등)는 조준점이 화면 중앙에 고정되므로, 아래 중 하나로 커서를 만듭니다. `[결정 필요]`
  - **안 A – 시점 커서**: UI를 여는 동안 플레이어 이동을 막고, 시점(yaw·pitch) 변화량을 커서 위치로 바꿉니다. 커서는 DisplayHud 요소로 그립니다. 마우스로 움직이는 것처럼 느껴집니다.
  - **안 B – 핫바 선택**: 핫바 스크롤(슬롯 변경)로 항목을 이동하고, 우클릭으로 선택, 웅크리기로 뒤로 가기. 구현이 단순하고 안정적입니다.
  - **안 C – 월드 패널**: 편집기처럼 플레이어 앞 월드에 패널을 띄우고 조준해서 클릭. 거점의 스킬 트리 단말기처럼 연출할 때 적합합니다.
- 선택된 항목은 크기·밝기 보간으로 강조하고, 설명 패널을 옆에서 밀어 넣는 식으로 연출합니다.

**화면 구성 (가안)**

| 화면 | 종류 | 내용 |
|---|---|---|
| 전투 HUD | 상시 | 좌하단: 능력 쿨타임(수류탄·근접·직업 능력), 하단 중앙: 궁극기 게이지, 우하단: 무기·탄약, 좌상단: 보호막 |
| 스킬 트리 | 인터랙티브 | 직업 변경, 궁극기·수류탄·근접·직업 능력·측면·파편 선택 |
| 무기 정보 | 인터랙티브 | 무기 수치, 특성 확인·변경 |
| 상점 | 인터랙티브 | 미광체로 구매, 가격·보유량 표시 |
| 레이드 HUD | 상시 | 상단 중앙: 보스 체력, 메카닉 안내, 남은 부활 횟수, 격노 타이머 |

**주의할 점**
- 게이지처럼 자주 바뀌는 값은 매 틱 갱신하지 말고, 값이 바뀔 때만 보간으로 갱신해 패킷 양을 줄입니다.
- 요소마다 엔티티 하나이므로, 화면 하나에 쓰는 요소 수에 상한을 둡니다.
- FOV 조절(정조준)은 GameTime 값을 이용해 셰이더 애니메이션 위상에 영향을 줄 수 있습니다. 정조준 중 HUD 애니메이션이 어긋나는지 테스트가 필요합니다.

#### 3-1-6. 속성 상태 효과 (3.0 키워드)

속성별 공통 키워드를 만들어 능력과 무기 특성이 서로 연계되게 합니다.

| 속성 | 키워드 | 효과 (가안) |
|---|---|---|
| Arc | 증폭 / 실명 / 마비 / 이온 흔적 | 이동 속도 증가, 적 시야 차단, 적 행동 정지, 주우면 능력 에너지 회복 |
| Solar | 연소 / 점화 / 회복 / 광채 / 태양 조각 | 지속 피해, 범위 폭발, 체력 회복, 무기 피해 증가, 주우면 회복 |
| Void | 공허 과부하 / 억제 / 약화 / 투명 / 공허 방벽 / 공허 파편 | 체력 회복 차단, 적 행동 봉인, 받는 피해 증가, 투명화, 보호막, 주우면 능력 에너지 회복 |

#### 3-1-7. VFX
- VFX와 이펙트는 AI로 에셋을 제작합니다.
- 속성 색상을 통일합니다: **Arc = 하늘색 / Solar = 주황색 / Void = 보라색**
- VFX는 **바닐라 파티클(색 지정 가능한 dust 등) + 디스플레이 엔티티**로 만듭니다. 디스플레이 엔티티는 크기·회전 보간을 써서 궁극기, 방벽, 폭발 같은 형태를 연출합니다.
- 화면 전체 효과(궁극기 상태, 속성 키워드, 피격, 조준경)는 **26.3 포스트 이펙트**로 만듭니다. 레이드 진입 같은 화면 전환은 minigame-lib ShaderFX를 쓰되, 포팅 비용이 크면 포스트 이펙트로 옮깁니다. ([docs/07](design/07_포스트이펙트_셰이더.md))
- 궁극기·회피처럼 몸 전체가 움직이는 연출은 BetterModel 플레이어 모델 애니메이션으로 만듭니다. (3-1-8 참고)
- 파티클과 디스플레이 엔티티는 모두 서버가 패킷으로 보내므로, 레이드처럼 인원이 많을 때는 **개수 상한과 거리 제한**을 둬서 네트워크 부하를 관리합니다.

#### 3-1-8. 플레이어 모델 애니메이션 (BetterModel)

궁극기 발동과 구르기(헌터 회피) 같은 동작은 [BetterModel](https://github.com/toxicity188/BetterModel)의 **플레이어 모델(limb)** 로 연출합니다. 바닐라 클라이언트에서는 플레이어 모션을 바꿀 수 없으므로, 동작하는 동안 실제 플레이어를 숨기고 그 자리에 애니메이션 모델을 대신 보여주는 방식입니다.

**BetterModel 개요** (2026-10-20 기준)

| 항목 | 내용 |
|---|---|
| 형태 | 서버 기반 Blockbench 모델 엔진. Paper 플러그인과 **Fabric 서버 모드**를 모두 지원 |
| 버전 | 최신 3.5.1. 3.5.0부터 Minecraft 26.3 지원 |
| 의존성 | Fabric API, Fabric Language Kotlin, **Polymer**(필수), adventure-platform-fabric, cloud. Java 25 이상 |
| 렌더링 | `item_display` 패킷 기반. **코어 셰이더를 쓰지 않음** |
| 리소스팩 | 모델을 리소스팩으로 자동 변환. Polymer 리소스팩에 합쳐짐 |
| 라이선스 | MIT |
| API | `io.github.toxicity188:bettermodel-fabric` (Maven Central) |

**플레이어 모델 구조**
- `BetterModel/players` 폴더의 `steve.bbmodel`을 Blockbench로 열어 애니메이션을 추가합니다.
- 플레이어의 **실제 스킨을 그대로 입혀서** 보여줍니다. 스킨 텍스처를 따로 만들 필요가 없습니다.
- 12부위 리그를 쓰며, 본 이름에 붙이는 태그로 부위를 지정합니다.

| 태그 | 부위 | 태그 | 부위 |
|---|---|---|---|
| `ph` | 머리 | `phip` | 엉덩이 |
| `pc` | 가슴 | `pw` | 허리 |
| `pra` / `prfa` | 오른팔 / 오른쪽 아래팔 | `pla` / `plfa` | 왼팔 / 왼쪽 아래팔 |
| `prl` / `prfl` | 오른다리 / 오른쪽 아랫다리 | `pll` / `plfl` | 왼다리 / 왼쪽 아랫다리 |
| `pri` / `pli` | 오른손 / 왼손 아이템 | `cape` | 망토 |

- 손 아이템 본(`pri`, `pli`)이 있어서 무기를 든 채로 애니메이션할 수 있습니다.
- 갑옷 모델도 지원합니다. 수호자 방어구를 바닐라 갑옷 슬롯으로 표현하지 않는다면 설정에서 `player-armor`를 꺼서 리소스팩 크기와 CPU 사용을 줄입니다.
- Molang 표현식과 IK(역운동학)를 지원합니다.

**재생 방식**
- 테스트 명령: `/bm play <limb> <animation> [loop_type] [hide]`
- 코드에서는 플레이어에게 limb 트래커를 붙이고 애니메이션을 재생한 뒤, 끝나면 트래커를 닫습니다.
- 재생 중에는 **숨김 옵션(`EntityHideOption`)** 으로 실제 플레이어의 몸·장비·불·발광 효과를 숨깁니다.

아래는 저장소 예제를 Java로 옮긴 스케치입니다. 실제 시그니처는 API 버전에 맞춰 확인합니다.

```java
var tracker = BetterModel.limb("guardian").orElseThrow()
    .getOrCreate(ModPlayer.of(player.connection), TrackerModifier.DEFAULT, t -> {
        t.hideOption(EntityHideOption.DEFAULT);          // 실제 플레이어 숨김
        t.rotation(() -> new ModelRotation(player.getXRot(), rollYaw)); // 구르는 방향
    });
if (!tracker.animate("hunter_roll", AnimationModifier.DEFAULT_WITH_PLAY_ONCE, tracker::close)) {
    tracker.close();
}
```

> BetterModel 저장소의 Fabric 테스트 모드(`RollTest`)에 **입력 방향으로 구르기** 예제가 있습니다. 플레이어의 마지막 이동 입력(WASD)으로 방향을 구해 모델을 그쪽으로 돌린 뒤 `roll` 애니메이션을 한 번 재생합니다. 헌터 회피 구현의 출발점으로 쓰기 좋습니다.

**활용 계획**

| 동작 | 애니메이션 | 서버 처리 |
|---|---|---|
| 헌터 회피 (구르기) | 입력 방향으로 구르기 | 같은 방향으로 속도(velocity) 부여, 재장전·근접 충전 특성 발동 |
| 타이탄 방벽 | 방벽을 세우는 동작 | 방벽 엔티티 생성 |
| 워록 균열 | 바닥에 균열을 그리는 동작 | 균열 범위 효과 생성 |
| 궁극기 발동 | 속성·궁극기별 발동 모션 (예: 대혼란의 주먹 도약, 황금 총 뽑기, 새벽의 기도 날개) | 발동 중 무적 시간, ShaderFX 화면 효과 |
| 근접 능력 | 화염 망치 투척, 칼 투척 등 | 투사체 생성 |

- **애니메이션 길이로 서버 타이밍 맞추기**: `BlueprintAnimation.length()`로 애니메이션 길이를 읽어 무적 시간, 이동 시간, 쿨타임 시작 시점을 맞춥니다. 길이를 코드에 따로 적지 않아도 됩니다.
- **본 위치로 이펙트 붙이기**: 본의 월드 위치를 얻어 손끝, 망치 머리 등에 파티클·디스플레이 엔티티 이펙트를 정확히 붙입니다.
- **플레이어별 재생**: 특정 플레이어에게만 보이는 애니메이션을 재생할 수 있습니다. 본인에게만 다른 연출을 보여줄 때 사용합니다.
- 공통 동작(구르기, 기본 발동 모션)은 하나의 limb 파일에 모으고, 궁극기처럼 전용 소품(망치, 총, 날개)이 붙는 동작은 별도 limb로 나눕니다.

**확인이 필요한 부분** `[결정 필요]`
- **1인칭 화면**: 모델은 다른 플레이어에게는 잘 보이지만, 본인이 1인칭일 때 자기 모델이 어떻게 보이는지는 테스트가 필요합니다. 구르기 중에는 카메라가 그대로이므로 화면 흔들림·FOV 변화로 체감을 보완합니다. 궁극기 카메라 방식(고정 시네마틱 / 1인칭 + 궁극기 아이템·포스트 이펙트 / 서버 추적 3인칭)은 [docs/04](design/04_플레이어_모델_3인칭_연출.md) 3장에서 정리했습니다.
- **입력·이동 지연**: 애니메이션은 서버가 재생하므로 핑만큼 늦게 시작합니다. 구르기는 0.3~0.5초 정도로 짧게 만들고, 이동량은 속도 부여로 처리합니다.
- **다른 셰이더와의 충돌**: BetterModel은 코어 셰이더를 쓰지 않지만, minigame-lib의 HUD 셰이더가 아이템 엔티티 셰이더를 덮어씁니다. HUD 판정은 y < -1000 위치에만 적용되므로 충돌 가능성은 낮지만 함께 띄워서 확인해야 합니다.
- **스킨 적용**: 오프라인 모드 서버나 스킨 변경 플러그인을 쓸 때 스킨이 제대로 입혀지는지 확인합니다.

무기는 위 파일과 같은 스타일로, 디테일보다는 포인트와 특징을 살려 구현합니다. 역시 AI로 작업합니다.

#### 3-2-1. 조작

| 입력 | 동작 |
|---|---|
| 좌클릭 | 정조준 전환 (토글). FOV를 줄여 줌 |
| 우클릭 | 발사. 꾹 누르면 자동 발사 |
| 버리기(Q) | 재장전 (무기를 실제로 버리지 않도록 이벤트를 취소) |

- **우클릭 꾹 누르기 감지**: 무기 아이템에 사용 시간이 긴 사용 동작을 부여해, 서버가 "사용 중" 상태를 매 틱 확인하는 방식으로 자동 사격을 처리합니다.
- **좌클릭 감지**: 서버는 좌클릭을 꾹 누른 상태를 알 수 없고 클릭(팔 휘두르기)만 받을 수 있습니다. 그래서 정조준은 **토글**로 만듭니다.
- 무기를 들고 있을 때는 좌클릭 블록 파괴·공격을 막습니다. 야생 작업은 무기를 넣고 합니다.
- **반동**: 서버가 플레이어 시점을 상대 회전으로 살짝 들어 올리는 방식으로 구현합니다. 핑이 높으면 화면이 튀는 느낌이 날 수 있으므로 반동은 작게 시작합니다.
- 총 및 반동은 [GCBAPI weapon behavior](https://github.com/eiqq/GCBAPI/tree/main/src/main/java/org/EIQUI/GCBAPI/core/weapon/behavior)를 레퍼런스로 가져옵니다. (라이선스 허가 받음)

#### 3-2-2. 탄약 체계

| 탄약 | 무기 종류 | 획득 |
|---|---|---|
| 주무기 탄약 (흰색) | 핸드캐논, 자동소총, 기관단총 등 | 무한 또는 대량 지급 |
| 특수 탄약 (초록색) | 산탄총, 저격총, 융합소총 등 | 적 처치 시 드롭 |
| 중화기 탄약 (보라색) | 로켓 발사기, 기관총 등 | 엘리트·보스 처치 시 드롭, 레이드 특정 구간 |

#### 3-2-3. 1차 목표 무기 및 연사 속도

마인크래프트는 1초에 20틱이므로, RPM(분당 발사 수)을 **발사 간격(틱)** 으로 바꿔서 구현합니다.
계산식: `발사 간격(틱) = 1200 / RPM`

| 무기 | 프레임 | RPM | 발사 간격 | 비고 |
|---|---|---|---|---|
| 핸드캐논 | 공격형(적프) | 120 | 10틱 | 높은 피해, 느린 연사 |
| 핸드캐논 | 적응형(공프) | 150 | 8틱 | 기준 프레임 |
| 핸드캐논 | 정밀(정프) | 180 | 약 6.7틱 | 낮은 반동 |
| 자동소총 | 적응형(공프) | 480 | 2.5틱 | 기준 프레임 |
| 자동소총 | 공격형(적프) | 600 | 2틱 | |
| 자동소총 | 고속(속프) | 720 | 약 1.7틱 | 높은 연사, 낮은 피해 |
| 기관단총 | 적응형(공프) | 600 | 2틱 | 기준 프레임 |
| 기관단총 | 경량(경프) | 720 | 약 1.7틱 | 이동 속도 증가 |
| 기관단총 | 공격형(적프) | 900 | 약 1.3틱 | 근거리 특화 |
| 로켓 발사기 | 공격형(적프) | 20 | 60틱 | 투사체, 범위 피해 |
| 로켓 발사기 | 적응형(공프) | 15 | 80틱 | 투사체, 높은 단일 피해 |

> ⚠️ 원래 표는 핸드캐논을 공프 120 / 적프 150으로, 로켓 발사기를 공프 15 / 적프 20으로 적었습니다. 위 표는 "공격형이 더 느리고 세다"는 기준으로 핸드캐논만 순서를 바꿨습니다. 의도가 원래 표와 같다면 되돌려 주세요. `[결정 필요]`
> 단위는 BPM이 아니라 **RPM**으로 통일합니다.

- 발사 간격이 정수가 아닌 경우(1.7틱 등)는 **누적 방식**으로 처리합니다. 매 틱마다 `1/간격`만큼 게이지를 더하고, 1이 넘을 때마다 발사합니다.
- 주무기는 투사체 엔티티 대신 **히트스캔(레이캐스트)** 으로 처리하고, 탄 궤적은 파티클로 보여줍니다. 로켓만 투사체 엔티티로 만듭니다.
- 발사 판정이 서버에서 일어나므로, 움직이는 적을 맞힐 때 핑만큼 어긋날 수 있습니다. 머리 판정 크기를 약간 넉넉하게 잡아 보정합니다. `[결정 필요]`

#### 3-2-4. 무기 수치 항목

모든 무기는 아래 수치를 JSON으로 정의합니다.

| 항목 | 설명 |
|---|---|
| 피해량 | 몸통 피해 / 정밀(머리) 피해 배율 |
| 연사 속도 | RPM |
| 사거리 | 피해가 줄어들기 시작하는 거리(블록) |
| 안정성 | 반동 크기 |
| 조작성 | 꺼내기·정조준 속도 |
| 재장전 속도 | 재장전 시간(틱) |
| 탄창 | 탄창 크기 |
| 반동 방향 | 반동이 튀는 방향 (수직에 가까울수록 다루기 쉬움) |

#### 3-2-5. 무기 특성 (퍽)
- 무기마다 특성 칸(예: 총열, 탄창, 특성 1, 특성 2)을 둡니다.
- 1차 구현 후보 특성: **가속 장전, 살육, 연쇄 처치 보너스, 결속(킬 시 회복)**
- 특성은 3-1-6의 속성 키워드와 연계될 수 있게 만듭니다. (예: 처치 시 이온 흔적 생성)

### 3-3. 미광체

미광체는 수호자들끼리 거래하는 화폐입니다.

#### 3-3-1. 획득처
- 적 처치 시 소량 드롭
- 상자, 구조물 탐색 보상
- 아이템(무기, 재료) 해체
- 퀘스트·레이드 완료 보상

#### 3-3-2. 사용처
- 상인 NPC에게서 무기·재료 구매
- 무기 특성 변경, 강화 비용
- 치장 아이템 구매
- 플레이어 간 거래

#### 3-3-3. 규칙 `[결정 필요]`
- **보유 한도**를 둡니다. (예: 원작처럼 250,000)
- 아이템 형태로 둘지(바닥에 떨어뜨리기·상자 보관 가능), 플레이어 데이터(지갑)로 둘지 결정합니다. 서버사이드 모드라 둘 다 구현할 수 있습니다.
  - 아이템 형태: 야생 감성에 맞지만 복사·분실 문제 관리 필요
  - 지갑 형태: 관리가 쉽고 거래는 명령어·거래 UI로 처리
- 거래 방식: DisplayHud 거래 화면, 명령어(`/미광체 송금`), 또는 거점 거래 게시판
- 보유량은 DisplayHud로 표시합니다.

### 3-4. 스탯

방어구에 스탯을 부여하고, 스탯에 따라 능력 쿨타임과 생존력이 달라지게 합니다. `[결정 필요]` 어떤 스탯 체계를 쓸지 확정해야 합니다.

| 스탯 (가안) | 효과 |
|---|---|
| 기동성 | 이동 속도, 점프 능력 쿨타임 |
| 탄력 | 보호막(추가 체력), 받는 피해 감소 |
| 회복 | 체력 회복 속도 |
| 수양 | 수류탄 쿨타임 |
| 지성 | 궁극기 충전 속도 |
| 힘 | 근접 쿨타임 |

- 스탯 단계는 0~100(10단계)으로 두고, 단계마다 효과가 증가합니다.
- 수호자는 **체력 + 보호막** 구조로 관리합니다. 보호막은 바닐라 흡수(노란 하트) 수치를 활용하면 클라이언트에 그대로 보입니다. 이동 속도·체력 같은 스탯 효과는 바닐라 속성(attribute) 수정으로 적용합니다.

---

### 3-5. 경이 시리즈

경이(Exotic)는 고유 특성을 가진 특별한 무기·방어구입니다.

- **무기 경이는 1개, 방어구 경이는 1개만** 동시에 장착할 수 있습니다.
- 1차 후보: 이자나기의 짐 (첨부된 `izanagi.bbmodel`), 스페이드 에이스 (`Ace.bbmodel`)
  - 이자나기의 짐: 탄창 일부를 소모해 한 발의 강력한 탄을 장전
  - 스페이드 에이스: 정밀 처치 시 추가 효과, 재장전 강화
- 획득처: 레이드, 숨겨진 퀘스트, 구조물 보물상자 등 희귀 경로

### 3-6. 치장

전투 성능과 무관한 외형 요소입니다.

- **방어구 외형**: 직업별 기본 방어구 세트 + 레이드 세트
- **셰이더**: 무기·방어구 색상 변경
- **장식**: 무기·방어구 외형 변경
- **엠블럼 / 감정 표현** `[결정 필요]`

### 3-7. 참새 (보류)

- 소환형 탈것입니다. 아이템 사용으로 소환하고, 빠르게 이동합니다.
- 서버사이드에서는 바닐라 탈것(말 등)에 디스플레이 엔티티 모델을 씌우는 방식이 현실적입니다.
- 야생 이동 수단(말, 엘리트라)과의 밸런스를 검토한 뒤 구현 여부를 정합니다.

### 3-8. 적 시스템

레이드를 위해 반드시 필요한 시스템입니다.

| 등급 | 체력 바 | 특징 |
|---|---|---|
| 일반 | 흰색 | 기본 적, 다수 출현 |
| 정예 | 흰색 (강화) | 고유 공격 패턴 |
| 미니보스 | 노란색 | 많은 체력, 보호막 보유 가능 |
| 보스 | 노란색 (전용 HUD) | 고유 메카닉, 피해 단계(DPS 페이즈) |

- **외형**: BetterModel로 적 엔티티에 Blockbench 모델을 씌웁니다. 공격·피격·사망 애니메이션을 재생하고, 애니메이션 회전을 따라가는 커스텀 히트박스를 씁니다.
- **약점(머리) 판정**: 정밀 피해를 위해 적마다 머리 히트박스를 서버에서 정의합니다. BetterModel 본 위치를 기준으로 머리 판정을 잡아 보이는 모델과 어긋나지 않게 합니다.
- **보스 체력**: DisplayHud 레이드 HUD로 표시합니다. (보스바는 대체 수단)
- **속성 보호막**: Arc·Solar·Void 보호막을 두고, 같은 속성 공격으로 빠르게 깰 수 있게 합니다.
- **챔피언** (선택): 저지불가·과부하·방벽 챔피언과 이를 대응하는 특성. 레이드 이후 확장 콘텐츠로 검토합니다.

## 4. 레이드

가장 먼저 구현할 콘텐츠입니다. 레이드를 구현하려면 직업, 무기, 적 시스템 등 기본 시스템이 모두 필요합니다.

### 4-1. 기본 규칙 (가안)

| 항목 | 내용 |
|---|---|
| 인원 | 화력팀 3~6명 `[결정 필요]` |
| 구성 | 시작 구간 + 조우전 2~3개 + 최종 보스 |
| 소요 시간 | 30분~1시간 목표 |
| 부활 | 조우전 중 부활 횟수 제한, 전멸 시 조우전 재시작 |
| 체크포인트 | 조우전 완료 시 저장 |
| 보상 | 조우전별 레이드 무기·방어구, 최종 보스에서 경이 확률 드롭 |

### 4-2. 연출
- 레이드 진입, 보스 등장, 클리어 장면은 minigame-lib의 **시네마틱**(카메라 경로 + 연출용 엔티티 + 음악·화면 효과 큐)으로 만듭니다. 편집기에서 만든 씬을 `lib.cinematics().play(...)`로 화력팀 전체에게 재생합니다.
- 조우전 BGM은 minigame-lib의 **음악**(OGG 재생, 플레이리스트)으로 처리합니다.

### 4-3. 1차 레이드 구성 예시

배경: EDZ에 숨어든 **붉은 군단 잔당** 거점을 공격합니다.

1. **시작 구간 – 진입**: 외곽 방어선을 돌파하고 문을 엽니다. 기본 전투 확인용 구간.
2. **조우전 1 – 신호 탑**: 팀을 나눠 신호 탑 3개를 동시에 점령합니다. 일정 시간 안에 모두 점령해야 진행됩니다. (역할 분담 학습)
3. **조우전 2 – 표식 전달**: 특정 적을 처치하면 생기는 버프를 팀원끼리 전달해 문을 엽니다. (소통 메카닉)
4. **최종 보스 – 사령관**: 보호막 단계 → 메카닉으로 보호막 해제 → 피해 단계 반복. 일정 시간 안에 처치 못 하면 전멸(격노 타이머).

### 4-4. 레이드 구현에 필요한 시스템 체크리스트
- [ ] 직업 3종 × 속성 3종 기본 능력
- [ ] 주무기·특수·중화기 각 1종 이상
- [ ] 적 AI (일반, 정예, 보스)
- [ ] 레이드 HUD (DisplayHud: 보스 체력, 메카닉 안내, 격노 타이머)
- [ ] 화력팀(파티) 시스템
- [ ] 레이드 인스턴스 (전용 차원 또는 구조물 리셋)
- [ ] 체크포인트·부활 제한
- [ ] 보상 드롭 테이블
