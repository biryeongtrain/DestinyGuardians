# W74 — 활 최적 발사창 정보와 HUD

## 범위

기존 일반활2종에 실제 승인 당김 시계를 기반으로 `IDLE → DRAWING → PERFECT → LATE` 정보를 연결한다. **피로 강제 발사·기한 뒤 피해/정확도 감소까지 구현한 단계는 아니다.** 궁극기 공허활은 별도 능력 경로이므로 이 일반활 계산에 넣지 않는다.

## 타이밍

| 선정 무기 | 기본 완전 당김 | 기본 안정성 | 원문 계산 창 | 20TPS 창 |
|---|---:|---:|---:|---:|
| Biting Winds1621657423 |14틱|43|407.5ms|9틱|
| Whispering Slab211938782 |12틱|53|659ms|14틱|

Whispering Slab의 적법한 Archer’s Tempo 활성화 때 실제 승인 당김은9틱이다. 이 경우 최적 창도 그9틱부터 시작하지만 창 길이는14틱 그대로다. 당김 도중 발동·만료는 W73 snapshot 정책을 유지한다. 버프 만료 뒤 다시 누르는 당김에는 기본12틱을 적용한다.

정밀 `0.3 + 안정성/400초`, 경량 `0.5 + 안정성×3/1000초`는 고정 Oracle 커뮤니티 계산식이다. Bungie6.2.0은 경량0.5/0.8초 양끝과 기한 뒤 위력·정확도 저하 개념을 뒷받침한다. **중간 선형식 전체가 공식 엔진 소스라는 뜻은 아니다.** 정수µs→ceil50ms, `[완전당김, 완전당김+창)`의 half-open 경계는 서버 양자화 정책이다.

## 런타임 계약

`WeaponRuntime.bowDrawState`는 기존 `State.acceptedBowDraw`와 `WeaponCycle.chargeElapsed`를 읽는다. 새로운 두 번째 시계나 saved NBT는 만들지 않는다. 실제 native사용/exactstack/owner/level/사용가능상태/비재장전/accepted profile이 모두 있어야 한다. 읽기로 bind·당김·버프갱신·탄약이동·발사가 일어나지 않는다.

자동 nock 중 다음 누르기는 IDLE이다. 재장전이 실제 완료되어 새 당김이 승인된 순간0부터 진행한다. Q시위풀기·스킬취소·수납·실제offhand교체·copy/거래·차원이동·관전·궁극기·cleanup은 기존 사용 수명경계를 따른다. 임의 제3자 코드가 관찰 사이에서 같은tick 스택을 이동·복귀하는 모든 우회까지 검증했다는 뜻은 아니다.

## 조준선

기존 W44 frame/dot2개를 그대로 쓴다. 외곽만 진행률에 따라 최대35% 좁히고 최적 구간은gold, 구간을 벗어나면 기본 크기/amber로 바꾼다. 중앙4px흰dot·중심좌표·위상별모델은 고정이다. 같은 상태에서는 기존 nativeItem/display를 재사용하며 위상/크기/색이 바뀔 때만 기존cache가 갱신된다. ADS 기본 축소/사격bloom과 합성하고 nock/reload/스코프/super는 기존 숨김규칙을 유지한다.

[오프라인4배 도식](../../art/weapons/w74/offline-reticle-preview.png)은 직접 검토한 합성 이미지다. **Minecraft framebuffer가 아니며, 원작 픽셀정확 UI나 실제 정확도cone를 뜻하지 않는다.** 신규 pack geometry/texture/audio는0이다.

## 남은 차이

LATE 표시는 현재 정보만 제공한다. 기존 완전 당김 profile/피해/속도/중력/탄약/nock/cadence는 그대로이며 무한유지는 아직 원작과 다르다. 미확정 max-hold를 임의4초로 넣거나 창 만료 때 즉시 자동 발사하지 않는다. 정확한 원작 데이터·직접 측정 뒤 피로/정확도/위력 곡선을 별도 연결해야 한다. Oathkeeper와 이국적 활 예외/퍼크 안정성 스탯 modifier는 이번 범위가 아니다.
