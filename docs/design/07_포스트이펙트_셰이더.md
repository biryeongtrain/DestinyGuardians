# 07. 포스트 이펙트 셰이더 (26.3)

26.3에서 **리소스팩이 정의한 포스트 이펙트(후처리 셰이더)를 서버가 플레이어별로 켜고 끌 수 있게** 되었습니다. 클라이언트 모드 없이 화면 전체 효과를 만드는 공식 경로라, 궁극기 상태·속성 키워드·피격·조준경 같은 효과를 모두 이 방식으로 만듭니다.

## 1. 26.3에서 바뀐 것 ✅

근거: [26.3 공식 변경 사항](https://www.minecraft.net/en-us/article/minecraft-java-edition-26-3), 26.3 클라이언트 JAR 파일 직접 확인 (2026-10-21)

| 항목 | 내용 |
|---|---|
| `/posteffect` 명령 | `add <player> <id>`, `remove <player> <id>`, `clear <player>`, `list <player>`. 여러 개를 **겹쳐서** 켤 수 있음 |
| 서버 API | `ServerPlayer.addPostEffect(Identifier)`, `removePostEffect`, `clearPostEffects`, `getPostEffects` |
| 패킷 | `ClientboundPostEffectsPacket(List<Identifier>)` – 켜진 효과 목록 전체를 보냄 |
| 실행 위치 | 효과는 **클라이언트 리소스팩**에 있음. 서버는 실제로 적용됐는지 알 수 없음 |
| 상시 효과 | 리소스팩이 `minecraft:end_of_frame` 포스트 이펙트를 정의하면 **항상 켜짐**. 명령으로 끌 수 없고, 명령으로 켠 효과보다 **먼저** 실행. 여러 팩이 정의하면 마지막 팩 것만 적용 |
| 셰이더 컴파일 | OpenGL도 Vulkan과 똑같이 **ShaderC로 컴파일**. `#moj_import` 대신 `#include`. 입출력에 `layout(location = N)` 필수 |
| 주의 문구 | Mojang: 명령·포스트 이펙트·셰이더는 앞으로 다시 설계될 수 있음. 코어 셰이더 덮어쓰기는 "지원하지 않는 기능" |

**설계 결론**
- 화면 전체 효과는 **포스트 이펙트**로 만듭니다. (공식 기능)
- 코어 셰이더 덮어쓰기(DisplayHud, ShaderFX)는 꼭 필요한 곳에만 씁니다. 버전마다 다시 작성해야 합니다.
- 렌더러가 OpenGL·Vulkan 두 가지이므로 **두 렌더러 모두에서 테스트**합니다.

## 2. 파일 형식 ✅

### 2-1. 위치

```
assets/destiny/post_effect/<분류>/<이름>.json      ← 효과 정의 (ID: destiny:<분류>/<이름>)
assets/destiny/shaders/post/<이름>.fsh             ← 프래그먼트 셰이더
assets/destiny/shaders/post/<이름>.vsh             ← 필요할 때만. 보통 minecraft:core/screenquad 사용
assets/minecraft/post_effect/end_of_frame.json     ← 상시 효과 (팩 전체에 하나)
```

### 2-2. 효과 정의 JSON 필드

26.3 코드(`PostChainConfig`)에서 확인한 필드입니다.

| 위치 | 필드 | 설명 |
|---|---|---|
| 최상위 | `targets` | 이 효과 안에서 쓰는 중간 버퍼 목록 |
| `targets.<이름>` | `width`, `height` | 생략하면 화면 크기. 작게 잡으면 저해상도 버퍼(블러·저장용) |
| | `persistent` | `true`면 **프레임이 지나도 내용 유지**. 효과를 끄면 비워짐 |
| | `clear_color` | 초기화 색 |
| 최상위 | `passes` | 순서대로 실행할 단계 목록 |
| `passes[]` | `vertex_shader` | 보통 `minecraft:core/screenquad` |
| | `fragment_shader` | 예: `destiny:post/super_grade` |
| | `inputs` | 입력 목록 (아래) |
| | `output` | 출력 버퍼. 최종 화면은 `minecraft:main` |
| | `uniforms` | **블록 이름 → 값 목록**. 각 값은 `name`, `type`(`float`, `vec2`~`vec4`, `int`, `matrix4x4` 등), `value` |
| `inputs[]` (버퍼) | `sampler_name`, `target`, `bilinear`, `use_depth_buffer` | `sampler_name: "In"` → 셰이더에서 `InSampler` |
| `inputs[]` (텍스처) | `sampler_name`, `location`, `width`, `height`, `bilinear` | 노이즈·스코프 마스크 같은 이미지 |

### 2-3. 셰이더 작성 규칙 ✅

26.3 바닐라 `shaders/post/blit.fsh`, `color_convolve.fsh` 형식을 따릅니다.

```glsl
#version 330
#extension GL_ARB_separate_shader_objects : require

uniform sampler2D InSampler;                 // inputs[].sampler_name "In"

layout(location = 0) in vec2 texCoord;       // screenquad.vsh 출력

layout(std140) uniform SamplerInfo {         // 자동 제공
    vec2 OutSize;
    vec2 InSize;
};

layout(std140) uniform SuperConfig {         // JSON uniforms의 블록 이름과 같아야 함
    vec3 Tint;
    float Strength;
};

layout(location = 0) out vec4 fragColor;

void main() {
    vec4 c = texture(InSampler, texCoord);
    float lum = dot(c.rgb, vec3(0.299, 0.587, 0.114));
    vec3 graded = mix(c.rgb, Tint * (lum * 1.4 + 0.1), Strength);
    vec2 d = texCoord - 0.5;
    float vignette = smoothstep(0.75, 0.25, length(d));
    fragColor = vec4(graded * mix(0.6, 1.0, vignette), 1.0);
}
```

- uniform은 **블록(std140) 단위**로 묶습니다. JSON의 `uniforms` 키가 블록 이름입니다.
- 정점 출력과 프래그먼트 입력은 **이름이 아니라 location 번호로** 연결됩니다.
- 게임 시간(`GameTime`)은 `Globals` 블록(`#include <minecraft:globals.glsl>`)에 있습니다. 포스트 셰이더에서 이 블록을 쓸 수 있는지는 확인이 필요합니다. 🧪

## 3. 서버 → 셰이더로 값 전달하기

포스트 이펙트는 서버가 **켜고 끄는 것만** 할 수 있고, uniform 값을 실시간으로 바꿀 수는 없습니다. 필요한 표현에 따라 아래 방법을 고릅니다.

| 방법 | 원리 | 쓸 곳 | 상태 |
|---|---|---|---|
| **A. 단계별 효과 ID** | 강도마다 효과를 따로 만듦 (`damage_1`, `damage_2`, `damage_3`) | 강도 3~4단계면 충분한 효과 | ✅ |
| **B. persistent 버퍼로 페이드** | 1×1 persistent 버퍼에 진행도를 저장하고 매 프레임 조금씩 올림. 효과를 켜면 서서히 나타남 | 궁극기 진입, 투명화 진입 | ✅ 필드 확인, 🧪 동작 테스트 |
| **C. DisplayHud 신호 픽셀** | DisplayHud로 화면 구석 1픽셀에 특정 색을 그림 → `end_of_frame`이 그 픽셀을 읽어 값을 해석하고, 그 픽셀은 주변 색으로 덮어 숨김 | 연속 값(피격 강도, 체력 비율, 궁극기 게이지)을 플레이어별로 전달 | 🧪 PoC |
| D. 효과 여러 개 겹쳐 비트 만들기 | 커뮤니티에서 쓰는 방식. 효과 N개의 켜짐/꺼짐으로 숫자를 만듦 | 참고용 | 비권장 (효과 파일 수 폭증) |

### 방법 C 상세 🧪

```
서버: 플레이어 체력 35% → DisplayHud 신호 픽셀 색 R = 0.35×255
클라이언트: 월드 렌더링 → (DisplayHud가 main 버퍼에 신호 픽셀 그림)
         → end_of_frame: 신호 픽셀 읽음 → 저체력 효과 강도 0.35로 적용 → 신호 픽셀 지움
```

- 픽셀 하나에 R·G·B 3개 채널 → 값 3개. 신호 픽셀을 여러 개 두면 값을 더 보낼 수 있습니다.
- DisplayHud는 소유자에게만 보이므로 **플레이어별 값**이 됩니다.
- 확인할 것: 텍스트 렌더링의 안티에일리어싱·밝기 보정 때문에 색이 정확히 유지되는지, 화면 크기가 바뀌어도 신호 픽셀 위치를 셰이더가 찾을 수 있는지.

## 4. 효과 실행 순서와 관리

```
월드 렌더링 (DisplayHud 포함)
 → minecraft:end_of_frame   (상시, 팩에 하나)
 → /posteffect 목록 순서대로 (서버가 켠 효과)
 → 바닐라 GUI (핫바·채팅·인벤토리)  ← 포스트 이펙트 영향 없음
```

- 서버에 **PostEffectManager**를 둡니다. 플레이어마다 "켜야 할 효과 집합"을 상태(궁극기 중, 투명, 조준 등)에서 계산하고, 바뀌었을 때만 `add/remove`합니다.
- 우선순위 규칙: 같은 분류(예: `super/*`)는 하나만 켭니다. 피격(`hit/*`)은 짧게 켰다가 자동으로 끕니다.
- 사망·리스폰·재접속·차원 이동 후 효과가 유지되는지 확인하고, 안 되면 매니저가 다시 보냅니다. 🧪

✅ **minigame-lib 2.0.0(26.3) 확인 사항** (2026-10-22, `port/26.3` 브랜치)
- minigame-lib은 `end_of_frame`을 **쓰지 않습니다**. → 이 프로젝트가 소유합니다.
- 대신 바닐라 **`minecraft:entity_outline`**(발광 테두리) 포스트 효과를 덮어써서, 손 위 HUD 표시(`displayhud_capture` → `displayhud_sobel` → `displayhud_combine`)에 씁니다. 발광 효과를 적 강조 등에 쓰려면 테두리가 정상으로 보이는지 확인해야 합니다.
- HUD 깊이: 일반 HUD는 깊이 약 **0.5**, 손 위 HUD는 **0.85 이상**(역Z 0.90~0.99) 구간에 그려집니다. 포스트 이펙트에서 `use_depth_buffer`로 이 구간을 HUD 마스크로 쓸 수 있습니다. 🧪 (P-03)

⚠️ **DisplayHud도 포스트 이펙트를 받습니다.** DisplayHud는 월드 렌더링 단계에서 그려지므로, 화면을 흐리게 하거나 왜곡하는 효과를 켜면 HUD도 함께 흐려집니다. 바닐라 GUI는 영향이 없습니다.
- 대응 1: 왜곡·블러 효과는 화면 가장자리에만 적용하고 HUD가 있는 영역은 약하게
- 대응 2: 깊이 버퍼(`use_depth_buffer`)로 HUD 픽셀(깊이 ≈ 0.5, 0.85 이상)을 구분해 효과에서 제외 🧪 (P-03)

## 5. `end_of_frame` (상시 효과) 설계

팩 전체에 하나뿐이므로 **"디스패처"** 역할로 가볍게 만듭니다.

| 기능 | 입력 | 처리 |
|---|---|---|
| 피격 비네팅 | 신호 픽셀 R (피격 강도) | 화면 가장자리 붉게 |
| 저체력 | 신호 픽셀 G (체력 비율) | 30% 이하에서 채도 감소 |
| 보호막 상태 | 신호 픽셀 B (보호막 비율) | 보호막 있을 때 가장자리 옅은 하늘색 |
| 신호 픽셀 지우기 | – | 주변 색으로 덮기 |

- 신호 픽셀(방법 C) PoC가 실패하면, 이 기능들은 방법 A(단계별 효과 ID)로 옮기고 `end_of_frame`은 쓰지 않습니다.
- ⚠️ 다른 리소스팩·라이브러리가 `end_of_frame`을 정의하면 하나만 살아남습니다. 서버 리소스팩에서 이 파일의 주인을 이 프로젝트 하나로 정합니다. (09)

## 7. 예시 – 진입 페이드가 있는 궁극기 효과 (방법 B)

```json
{
  "targets": {
    "fade": { "width": 1, "height": 1, "persistent": true },
    "fade_swap": { "width": 1, "height": 1 },
    "swap": {}
  },
  "passes": [
    {
      "vertex_shader": "minecraft:core/screenquad",
      "fragment_shader": "destiny:post/fade_step",
      "inputs": [ { "sampler_name": "Prev", "target": "fade" } ],
      "output": "fade_swap",
      "uniforms": { "FadeConfig": [ { "name": "Step", "type": "float", "value": 0.05 } ] }
    },
    {
      "vertex_shader": "minecraft:core/screenquad",
      "fragment_shader": "minecraft:post/blit",
      "inputs": [ { "sampler_name": "In", "target": "fade_swap" } ],
      "output": "fade",
      "uniforms": { "BlitConfig": [ { "name": "ColorModulate", "type": "vec4", "value": [1.0, 1.0, 1.0, 1.0] } ] }
    },
    {
      "vertex_shader": "minecraft:core/screenquad",
      "fragment_shader": "destiny:post/super_grade",
      "inputs": [
        { "sampler_name": "In", "target": "minecraft:main" },
        { "sampler_name": "Fade", "target": "fade" }
      ],
      "output": "swap",
      "uniforms": { "SuperConfig": [
        { "name": "Tint", "type": "vec3", "value": [0.373, 0.784, 1.0] },
        { "name": "Strength", "type": "float", "value": 0.45 }
      ] }
    },
    {
      "vertex_shader": "minecraft:core/screenquad",
      "fragment_shader": "minecraft:post/blit",
      "inputs": [ { "sampler_name": "In", "target": "swap" } ],
      "output": "minecraft:main",
      "uniforms": { "BlitConfig": [ { "name": "ColorModulate", "type": "vec4", "value": [1.0, 1.0, 1.0, 1.0] } ] }
    }
  ]
}
```

- `fade_step.fsh`: `PrevSampler`의 값에 `Step`을 더해 1까지 올림. 프레임마다 실행되므로 FPS에 따라 속도가 달라집니다. 일정한 속도가 필요하면 `GameTime` 사용을 검토합니다. 🧪
- `super_grade.fsh`: 2-3의 예시 셰이더에 `FadeSampler` 값을 곱해 강도를 조절.
- 같은 버퍼를 한 패스에서 읽고 쓰지 않도록 `fade` → `fade_swap` → `fade`로 돌립니다.
- 이 JSON은 형식 확인을 거친 **작성 예시**입니다. 실제 동작은 테스트 서버에서 확인합니다.

## 8. ShaderFX(minigame-lib)와의 역할 분담

| 기능 | 현재 (minigame-lib) | 26.3 이후 권장 |
|---|---|---|
| 화면 전환 (레이드 진입, 시네마틱) | ShaderFX transition (텍스트 코어 셰이더 덮어쓰기) | 포팅 비용이 크면 포스트 이펙트 + persistent 버퍼로 다시 구현 |
| 단색 페이드 | ShaderFX `fade` | 포스트 이펙트 |
| HUD 화면 고정 | DisplayHud (엔티티·아이템·블록·텍스트 코어 셰이더) | 그대로 유지. ✅ 2.0.0에서 26.3 포팅 완료 |
| FOV 조절 | `CameraEffects.setFov` | 그대로 유지 |

## 9. AI 작업 요청 시 포함할 것

- 이 문서의 2-3 셰이더 규칙 (버전, extension, location, std140, `<이름>Sampler`)
- 효과 ID, 켜는 조건, 길이, 01의 속성 색 값
- 패스 수 상한(2), 화면 해상도 무관하게 동작할 것(`OutSize`, `InSize` 사용)
