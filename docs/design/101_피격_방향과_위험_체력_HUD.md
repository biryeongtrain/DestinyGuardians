# W86 — 피격 방향·위험 체력 HUD

## 목적

원작처럼 피격을 화면에서 읽을 수 있게 한다. 기존65무기/162소리/6540client asset·W85플린치/NoDistractions와 원래HP·탄약을 보존한다. 일반client에 필수mod를 추가하지 않고 DisplayHud의 pack-backed ItemDisplay quad를 사용한다. 최신Destiny 전체HUD의 완전 동일 재현으로 완료 표시하지 않는다.

[원작 연구](../../art/hud/w86/reference-notes.md) · [구조화 자료](../../art/hud/w86/data/research.json) · [W86 QA](../qa/2026-10-25/w86/README.md).

## 데이터 흐름

`PlayerDamageMixin`의 native `Player.actuallyHurt` 완료 뒤 exclusive HP+absorption 실제감소 → `IncomingDamageHud.damaged` → owner-only HUD. W85의 중첩 child-delta 제외와 armor/magic/shield 이후측정을 재사용한다. 요청amount·주변적 검색·damage event 시도만으로 표시하지 않는다.

방향은 같은 level의 알려진 responsible attacker 위치를 우선한다. Projectile이 피해자에 닿은 contact position을 공격자 방향으로 오인하지 않기 위함이다. 공격자가 자신이면 explicit/direct origin을 fallback한다. 좌표는 피격시 한 번 복사하며 그 뒤 움직이는 적을 추적하지 않는다. 알 수 없는위치·다른level·비유한좌표·동일XZ의 수직/중첩위치는 임의 방향을 만들지 않는다. 환경/자해라도 실제HP가위험이면 위험상태표시는현재HP로독립판정한다.

## 명시적 로컬 상태 정책

원작의 정확한수치가확인되지않은 값이며 D2 측정값으로 표현하지 않는다.

- 최대4origin slot, 출처가2block 이내면 같은slot을갱신한다. 나머지는빈자리/가장오래된것을교체한다. 원본entity/UUID/대상은보관하지않는다.
- cue는6tick유지+14tick페이드, 총20tick(20TPS에서1초). 새 실제hit만 갱신하며 iframe거절·zero·면역·완전shieldblock은 새cue를만들지않는다.
- 피격시좌표와 **현재**player 위치/yaw로방향을다시계산한다. front0/right90/back180/left-90, 화면clockwise 기준이다. quad Z회전은음의bearing이며2도단위cache로metadata빈도를제한한다. DisplayHud의vecToQuat는rotateZYX순서라첫번째argument가Z회전이다. 원작의각도정밀도주장이아니다.
- 실제nativeHP/maxHP가0초과30%이하면주변부warning. 이미사용중인체력bar의위험threshold와일치시킨다. 새로운Destinyshieldpool/회복·damage·ammo값은만들지않는다. absorption-only hit는방향cue가되지만 fullHP를임의critical로바꾸지않는다.
- 위험frame은현재HP와24tick의부드러운pulse에따라8단계선택한다. spawn/restore로이미lowHP여도정직하게표시하고heal이threshold를넘으면즉시지운다. timeout후에도lowHP면위험warning만남는다.

## 프레젠테이션 계약 — 정성적 영상 참고

- `incoming_w86_arc_0..7`: 상단기준의compacttaperedwedge, 강→약fade. 중심reticle을가리지않는squarequad를회전한다. 배치는1920×1080기준960,540/320square다. 실제영상의compactred/orangewedge를참고한로컬silhouette이며정확원작mask/크기/방향각도를측정한것은아니다. 초기smootharc는원작근거가약해다듬었다.
- `incoming_w86_critical_0..7`: 16:9주변부저농도warning, centertransparent. 화면전체red rectangle이나극단적flash를만들지않는다.
- 총4arc+1warning=최대5cachednode. existingHUD/reticle/scope/health/textures는수정하지않고새prefix `destiny:hud_incoming_w86_`만소유한다.
- nonGuardian도공유healthHUD를쓰므로같이지원한다. `CombatHud.removeAbilities`가이prefix를지우지않게한다. 무기교체는이전실제피격을지우는사유가아니다.
- 기존source·ammo·FOV/camera·velocity/pose/attribute를변경하지않는다. 방향HUD는정보만표시하며공격자/머리로조준을보정하지않는다.

## 소유권과 정리

session은exactServerPlayer/level을소유한다. 죽음·제거·disconnect·spectator·level교체·서버stop/CombatHud.remove에서노드와data를해제한다. 외부CameraViews/nativegetCamera!=self에서는중단한다. 우리SuperCamera의실제전투3인칭은HUD를유지한다. 다른사람의hud나posteffect소유권은건드리지않는다.

## 검증 경계

출처는형태/배치를정성적으로뒷받침하며정확수치parity의근거가아니다. pure상태/방향수학·nativehurtServer/packet/HUDcache·source/JAR/팩과실제Visionframebuffer는각각별개증거다. 실제완료결과는W86QA에남긴다. 최신화면상태질문이답변되기전동일SDL기동반복을하지않는다. 전체goal은active다.
