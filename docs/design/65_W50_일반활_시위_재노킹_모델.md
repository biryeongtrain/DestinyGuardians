# W50 — 일반 활 시위·화살·재노킹 모델

## 범위

W49의 실제 탄약/당김/자동 재노킹 상태에 일반 활 모델을 연결한다. 대상은
**Biting Winds / Whispering Slab** 두 자루이며 Shadowshot 궁극기 활은 변경하지 않는다.
기존 황금총 방향·탄약 HUD(W39~W49)와 나머지 무기 모델/사운드도 보존한다.

- 원본 리핑에서 재구성한 W30/W31 큐브·기본 안료·UV를 그대로 재사용.
- 활 본체·팔다리·캠은 고정. 실제로 변하는 부분은 **시위 두 구간과 화살**이다.
- 발사하면 화살이 사라지고, 실제 재노킹 시간에 맞춰 다음 화살이 아래에서 장전된다.
- 완전히 당긴 상태를 계속 유지할 수 있으며 자동 발사는 없다. Q는 W49대로 시위를 푼다.
- 1·3인칭 손 컨텍스트에만 적용. GUI/땅/액자/머리는 기존 모델을 그대로 사용한다.

## 지오메트리와 보존

| 무기 | 기존 큐브 | 고정 본체 | 최대 동시 큐브 | 당김 거리(모델 단위) |
|---|---:|---:|---:|---:|
| Biting Winds | 250 | 229 | **252** | 4.8 |
| Whispering Slab | 200 | 190 | **203** | 3.4 |

기존 긴 시위 1개를 양 끝이 고정된 2개 세그먼트로 교체한다. 화살 높이에서 만나고,
중앙 접점만 로컬 +Z(사수 방향)로 이동한다. 화살도 동일 거리만큼 후퇴한다.
원본 화살은 라이저에 가려진 부분의 축이 끊겨 있어, 움직일 때 구멍이 드러나지 않도록
원래 축 텍스처로 짧은 연결 큐브를 Biting1개/Slab2개 추가한다. 본체는 축소하거나 합치지 않는다.

`art/weapons/w50/manifest.json`은 원본 인덱스·SHA·272개 런타임 에셋·큐브 예산을 고정한다.
원본 `models/weapon`, `items/weapon`, W30 bbmodel, PNG는 수정하지 않는다.
각 포즈는 공통 본체 + 움직이는 부품의 composite이므로 전체 250개를 매 프레임 중복 저장하지 않는다.
HIP/ADS/INSPECT 및 좌우손 디스플레이 변환은 기존 파일에서 그대로 상속한다.

## 서버 상태와 패킷

`WeaponBowPresentation`은 서버 메인 스레드의 실제 `WeaponRuntime` 세션만 쓴다.
실제 `ITEM_MODEL`은 무기 식별자로 계속 유지하고, Polymer 전송 시에만
`destiny:weapon_bow_w50/<id>`를 선택한다. 패킷 getter/HUD는 상태를 생성하거나 탄약을 옮기지 않는다.

CMD **float index2의 정수 부분**:

| 값 | 의미 |
|---:|---|
| -1 | 소유 세션 해제, 기본 모델 복귀 |
| 0 | 빈 활, 화살 없음 |
| 1 | 장전된 대기 |
| 2~22 | 실제 chargeElapsed/chargeTicks의 21단계 당김 |
| 32~52 | 실제 reloadRemaining/reloadPhaseTicks의 21단계 재노킹 |

재노킹 첫30%는 화살이 없고, 30~80%에 화살이 올라온다. 이 곡선·거리·세부 움직임은
**Minecraft용 제작값**이지 원작 애니메이션 추출/프레임 실측값이 아니다.
W49의 참고 영상/HUD 및 원본 정적 형상을 참고했지만 손·팔 IK나 팔다리/캠 애니메이션은 구현하지 않았다.

저장된 숫자만으로 live 모델을 승인하지 않도록 ItemStack identity 소유 맵을 둔다.
새 소유권의 첫 샘플과 저장 숫자가 같으면 세션 동안 **.5 fractional offset**을 사용한다.
정수 threshold는 동일 포즈를 고르면서도 실제 컴포넌트가 변경되어 인벤토리/장비 diff가 소유권 전환을 감지한다.
float0/1/추가 float, flags, 문자열(포즈/추가 슬롯), 색상은 보존한다.
취소는 즉시 -1로 바꿔 같은 틱의 캐시 키도 무효화한다.

발사/재장전/교체/능력 취소/사망/접속 종료/차원 변경은 기존 실제 라이프사이클에 연결된다.
재노킹 중 다음 입력은 W49대로 **새 당김만 버퍼**하고, 모델도 nock이 끝나기 전 draw로 바뀌지 않는다.
입력이 이미 풀렸다면 장전 대기로 남는다. 저장/복사/OP 미리보기에는 live 소유권을 복제하지 않는다.

## 편집·검토

- 생성: `rtk proxy python3 scripts/generate_bow_models_w50.py`
- 재현 검증: 위 명령에 `--verify`.
- 편집용 완전 당김: `art/blockbench/weapons/w50/*_draw_20.bbmodel`.
- Blockbench flatten 재현: `rtk proxy python3 scripts/qa/preview_bows_w50.py --verify`.
- [Blockbench 8상태 비교](../qa/2026-10-24/w50/bow-contact-blockbench.jpg)

Blockbench 전용 W50 탭·offscreen 카메라로 loaded/full/empty/nock중간을 각각 캡처했다.
이는 **Minecraft framebuffer나 인게임 입력 통과 증거가 아니다**. 기존 사용자 W30 미저장 탭/뷰/Blender는 보존한다.

## 음원 및 잔여

[음원 조사](../qa/2026-10-24/w50/audio-research.md): 제공 Drive의 Legendary/Bow 하위10폴더,
공개 HTML에 보이는106파일을 확인했다. 이름이 명확한 nock 후보5개를 고정했으나
청취 검수하지 않았으므로 charge/reload는 기존 **unmapped/no-op**을 유지한다.
단순 Draw/Handle을 시위/재장전으로 임의 재명명하지 않는다. 전체 Drive에 음원이 없다는 뜻은 아니다.

현재 QA 초기 SDL 렌더 정지에는 외부 상태 변화 확인이 없어 클라이언트 재실행을 반복하지 않는다.
자동 테스트·26.3 모델 파서·생성팩 바이트 검증은 별도 QA 문서에서 결과를 기록한다.
실제 1·3인칭 화면/키 입력/수신팩/오디오 출력, 원작과의 정확한 화면 구도, 다인·거리·성능은 남은 검증이다.
추가 reload 애니메이션, 완벽 당김/과다 유지 동작, sprint/ADS 연계, 특성·경이·검 시스템과
픽셀 단위 HUD도 전체 무기 목표의 잔여 작업이며 W50으로 전체 목표를 완료 처리하지 않는다.
