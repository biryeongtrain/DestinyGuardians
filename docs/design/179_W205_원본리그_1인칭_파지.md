# W205 — 원본 리그로 맞추는 1인칭 파지

사용자 요청: 플레이어 스킨의 손가락 없는 손을 사용하되, 무기와 손 위치가 실제 Destiny 1인칭과 어울리게 한다. 화면에서 추정한 손목 Euler를 주근거로 삼는 첫 후보를 넘어, 전달받은 원본 Destiny 리그를 먼저 평가한다.

## 실제 소스

SSD의 DestinyGuardians-Animation-Return-2026-10-27/destiny-animation-return/clips/*/blender/source.blend를 읽기만 한다. Blender MCP로 별도 W205_SourceRig_Hands 장면에 append하며 기존 사용자 장면/선택/원본 파일을 보존한다. 32 그룹,60무기 대응 source-map과 idle/ADS/reload action tag를 사용했다. armature-object 누적4×4행렬을 추출한다. FBX import object0.01스케일을 행렬에 또 곱하지 않는다.

본 이름은 FNV-1과 원본 부모연결로 확인했다. 왼 전완897A1504→손8C83CB67, 오른 전완A3781DCD→손DE9D6BEA다. sourceBoneMapIndex와 Blender 샘플 index가 다르므로 이름으로 찾는다. body/utility도 보존하지만 utility를 실제 카메라라고 가정하지 않는다. 이 FBX에는 camera가 없다.

## 적용

- 손가락/원본 플레이어 메시를 복사하지 않는다. W204 플레이어 스킨의 단순 블록 팔을 사용한다.
- 원본 손목−팔꿈치 벡터로 팔 방향을 계산하고, 손목 행렬에서 twist축을 취해 직교화한다. 실제 전완 길이를6.5local-unit 접촉~cuff 구간에 맞춘다. 그러므로 임의의 +27도 손목 roll은 source가 있는 무기의 주근거가 아니다.
- idle/ADS에서 일반 총기의 양손 간격도 원본 양손 본의 상대위치로 맞춘다. 오른손은 현재 무기의 실제 모델 손잡이 접점에 고정한다. 바닐라 양손 carrier는 canonical native/twohand display 회전차로 보정한다.
- Ace80A8A567 / Duke80A8A53D는 현재 무기 본체가 같은 원본 reload clip을 사용하므로 해당21개 샘플의 동적 양손 간격까지 추적한다. 다른 무기의 기존 authored 장전 부품 접촉은 보존하고 source idle 접근방향을 적용한다. 아직 모든 무기 장전이 완전한 source손IK라는 뜻이 아니다.
- 활의 오른손은 기존 시위 draw 변위를 따른다. 지지 손은 리모델링한 활 손잡이 접점에 고정한다. 원본 양손 간격을 그대로 적용한 첫 후보에서 손이 떠 보였으므로 활의 왼손 위치에는 이 간격을 덮어쓰지 않는다. 손가락 없는 블록 손의 두께 때문에 접점은 왼 localY1.5/오른1.0 아래로 보정한다. 사용자 요청으로 hip에서 왼 접점을 추가0.6 내리고 ADS진행에 따라 이 추가분을 줄인다. 손목·팔꿈치 방향/길이는 source FK를 사용한다. 활은 source→view X30도 보정을 명시적으로 사용한다. 사용자 추가지시로 후보의 팔 연장면은 전부 제거했다. 원본 전완 길이를 유지하고 활·움직이는 부품·손 접점 전체를 camera-space Z+11model-unit(.6875m) 옮긴다. hip X/Y는 함께 보정하고 ADS에서는 깊이만 옮긴다. 중심 sight의X/Y는 그대로 두므로 시야 중앙 정렬을 유지할 수 있다. 최종 원작 카메라/메시 일치까지 의미하지 않는다.
- 무기/부품/손의 화면 배치는 공통 first-person adapter를 사용한다. hip 보정은 ADS진행에 따라 줄이며 총기의 완전ADS 무기 display는 byte-exact 유지한다. 활은 카메라 거리 요청으로 ADS 깊이를 변경하되 가늠쇠X/Y정렬을 유지한다.3P/GUI fallback도 유지한다.

권총의 지지 손은 장전 처리 중에만 나타나도록 FK 적용 뒤 visibility를 보정한다. 원본 손목 본의 존재만으로 idle 손 메시가 보인다고 가정하지 않는다.

## 카메라와 한계

X-forward/Z-up→viewXYZ는 축 보정이다. 실제 Bungie카메라를 복원한 것이 아니다. 팔 길이·양손 본 관계는 소스에서 얻지만, 리모델링된 mesh의 접점과 Minecraft의 item projection/FOV는 최종 화면 보정이 필요하다. 원본 플레이 영상으로 총구·rear sight·손잡이의 정규화 화면 위치를 비교한다. 모든60무기에 source데이터가 있다는 사실을 모든무기의 원작화면일치나 native검증으로 보고하지 않는다.

검사/실화면/출처는 [W205 QA](../qa/2026-10-27/w205/README.md)에 기록한다. 현재 빌드는 generated pose entries가65,535를 넘어 JAR ZIP64를 사용한다. 최초 일반ZIP entry-limit실패도 QA로그로 보존한다. 새 게임로직·탄약/퍽 수치는 변경하지 않는다.
