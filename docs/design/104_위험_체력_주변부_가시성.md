# W89 — 위험 체력 주변부 가시성

## 문제와 변경

[W88 실화면](103_Vision_실화면_재개와_피격_방향_보정.md)에서 HP5의 상단 체력 막대는 붉지만 주변부 wash가 보이지 않았다. 정확한26.3 item shader cutoff는0.1이다. 이전 pulse frame1/2는 모든 texel이 cutoff 아래라 사라진다. 두 캡처만으로 모든 phase가 사라진 원인을 확정하지는 않았다.

`incoming_w89_critical_0..7`만 새로 추가했다. 활성 frame0부터 유효한 주변부를 가지며 최대 alpha77..160, alpha≥26 면적43.50..52.81%다. 중앙 타원 반경0.60은 완전히 투명하고 네 변 중앙에도 wash가 있다. 평균 mipmap을 명시했지만 cutoff 자체를 바꾸지 않는다. unsupported `render_type`이나 전역 shader/library override는 없다.

원작의 붉은 주변부를 정성적으로 참고한 **로컬 그래픽**이다. opacity·구름 형상·30% HP threshold·24tick pulse가 원작과 정확히 같다는 주장은 하지 않는다. 이전6588 asset,162 sound event, 방향 arc와 상태 계산식/clock/threshold는 그대로다. runtime은 기존 critical node가 새 모델 bank를 선택하도록만 바꿨다.

## 진단과 회귀

OP 전용 `destiny debug critical-hud-status <player>`는 실제 cached HUD의 serverTick·HP·maxHP·model·entity ID를 읽는다. 조회가 HUD를 생성/갱신/삭제하지 않도록 별도 GameTest로 검사한다.

새6JUnit은 모든 bank의 RGBA/흰색 tint·cutoff 생존·중앙 투명·단조 alpha·양면 UV/CMD tint·mean metadata를 확인한다. 새4GameTest는 HP6/5/1 각각24 server tick의 정확한 기존 수식→새 모델 선택과 cached entity 재사용·회복 제거·기존 방향 arc layer·죽음/관전/차원/owner 수명·권한/읽기 전용 진단을 확인한다. HP6/5/1의 수식은 합집합0..6을 방문하고 frame7은 asset 및 기존 near-zero unit 검사로 구분한다.

## 검증 상태

최종 gate2/3 각각759GT/668JUnit 통과, source7889pin/asset6620/JAR/팩/다운로드 cache 감사와 실제 Vision48PNG 판정은 [W89 QA](../qa/2026-10-25/w89/README.md)에 기록한다. offline preview는 실제 framebuffer 증거가 아니다. native 캡처 전후의 상태는 bracket일 뿐 정확한 frame/server tick 동기화가 아니다.

HP6/5/1 각각16장과 회복 전후를 실제 PNG로 확인했다. 모든 샘플에서 양쪽 주변부가 보이고 회복 후 제거된다. 단, cutoff 때문에 타원 내부 경계가 선명해 부드러운 원작 표현은 추가 개선이 필요하다.

첫 gate는759GT중 기존 Ace far-corridor1건에서 더 가까운 다른 hostile을 선택해 실패했다. 원래 피해량·정확 victim·탄약 검사를 바꾸지 않고 selected entity type/위치/AABB와 전체 corridor 후보 진단만 추가했다. 실패 로그를 보존하며 원인이 확정되지 않으면 재현 원인을 안다고 보고하지 않는다.

전체 무기 재현 목표는 미완료다. 원작 활 피로 수치·무기/궁극기 모션 전수 검증·다인 거리/성능 검증은 별도다.

독립 분석에서 자연 스폰 오염 가능성과 `runBeforeTestEnd`가 timeout-1 예약이라는 별도 teardown 결함을 발견했다. 기존/신규 fixture의 실제 완료/실패 cleanup 보강은 다음 단계다. gate 재통과가 이를 고쳤다는 뜻은 아니다.
