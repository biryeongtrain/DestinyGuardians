# W30 — 일반 무기군·프레임별 모델

## 요청과 범위

- 2026-10-23: 초안 4개 군/11개 조합을 넘어 저격총 등 다른 무기군까지 확대.
- 기준 원본을 실제로 확인: `~/Downloads/Ace.bbmodel` **87큐브**, `izanagi.bbmodel` **79큐브**. 원본 수정 금지.
- 18개 분류(특수/중화기 유탄발사기는 별도)에서 대표 63개를 먼저 선정한다. 시즌 1~20 공유 아카이브의 실제 확보 가능한 전통 프레임 묶음이다. 최신 모든 프레임·경이 고유 프레임의 완전 목록이라는 의미는 아니다.
- 최신 추가 프레임과 이 아카이브에 없는 글레이브의 공격적/속사 프레임은 미제작으로 명시하고, 임의의 다른 총을 같은 이름으로 대체하지 않는다.
- 발사·피해·재장전 엔진은 이번 모델 카탈로그와 별도. 모델 지급/시점/상태 프리뷰를 먼저 만든다. 프리뷰를 실전 사격 구현으로 보고하지 않는다.

## Step 1 — 기준·출처 조사

1. 공유 Drive의 Player Gear 시즌별 Weapons 목록을 읽어 1,279개 파일/폴더 항목을 조사했다. 전체 아카이브 일괄 다운로드 대신 선정 무기 63개만 가져온다.
2. Bungie 공식 공개 Manifest의 `DestinyInventoryItemDefinition`을 내려받아 무기 이름·intrinsic socket을 대조한다. 초안 RPM을 그대로 실제 원작 프레임에 붙이지 않는다. 초안 밸런스 표는 건드리지 않는다.
3. 유사 이름의 재발행/장식과 기본 모델을 구분한다. 장식만 확보된 경우 파일명과 장식명을 기록한다.
4. 기본 파이프라인은 **원본 실루엣 참조 → 큐브 재구성 → 원본 색/표면 세부 베이크 → 네이티브 held item**. HUD viewmodel로 대체하지 않는다.
5. 모델별 `.bbmodel`, 텍스처, Minecraft item definition/model, 파일 해시와 출처를 남긴다. 26.3 triangle 기술은 사용할 수 있지만, 이번 요청은 큐브 중심이므로 불필요한 원본 고밀도 삼각형 복제는 피한다.

### 권리·보존

공유 리핑 데이터는 공개 라이선스가 아니다. 사용자 승인에 따른 로컬 비상업적 개발/검토용이며 공개/상업 배포는 별도 권리 검토가 필요하다. 원본 FBX/BLEND/압축 파일과 스크립트는 레포에 넣지 않고 실행하지 않는다. Blender에서는 별도 background 프로세스에 geometry만 가져오며 autoexec을 끈다. 사용자가 열어 둔 씬과 원본 Blockbench 프로젝트를 덮어쓰지 않는다.

## Step 2 — 원본 기반 큐브 재구성

- 63개 개별 원본을 확보했다. 동일한 총을 리컬러해서 다른 프레임이라고 등록하지 않았다.
- 원본의 side-volume을 3D cuboid로 재구성하고 실제 삼각형 UV의 가장 가까운 표면에서 색상을 베이크했다. 큐브 간 머지로 128개 상한을 지키며, 검/활 등 단순 형태는 의미 없는 큐브를 채워 넣지 않는다. 손으로 원본의 각 파트를 1:1 복각한 작업은 아니다.
- 512² atlas에 원본 표면 문양을 보존한다. 원래 artist scene의 자동실행 코드는 끄고, 바닥/광학 플레어/reticle/VFX mesh는 물리 무기에 포함하지 않는다. 글레이브는 artist pose 대신 FBX bind-space를 사용해 직립 방향으로 재배치했다.
- Blender 5.4 alpha에서 legacy `.blend` library append가 크래시하는 것을 발견했다. 사용자 GUI 프로세스에는 호출하지 않고, 별도 background 프로세스의 `open_mainfile(use_scripts=False)`로 읽도록 바꿨다. 원본 파일은 저장하지 않았다.

## Step 3 — 서버 연결·1차 검증

- `/destiny weapon list [family]`, `equip <id> [player]`, `pose <hip|ads|inspect> [player]`: OP 전용 시각 QA 명령. 기존 일반 아이템을 손에서 덮어쓰지 않는다.
- vanilla STICK + ITEM_MODEL + string CMD를 사용한다. 슬롯·좌우 손·다른 플레이어에게 네이티브 아이템으로 보이며, 추가 owner HUD/카메라는 만들지 않는다.
- 1차 JUnit 141/141, GameTest 174/174. 63종 모든 stack과 3개 포즈의 registry codec 왕복을 검사했다.
- 실제 Vision 렌더에서 `textures/weapon` 경로는 기본 item atlas에 들어가지 않아 자홍색 오류를 발견했다. `textures/item/weapon`으로 이동 후 재빌드·재접속해 실제 색상 로딩을 확인했다. 따라서 정적 codec 통과만으로 렌더 성공이라고 보고하지 않는다.
- 1인칭은 모델의 -Z 총구를 기준으로 hip yaw ±12°, ADS yaw 0°로 맞추고 공식 hand offset에 맞춰 ADS sight 높이를 모델 bounds로 계산한다. 네이티브 framebuffer에서 Austringer의 기계식 조준점이 화면 중앙에 오는 것을 확인했다.
- 후속 렌더 보정: 긴 무기 1인칭 화면 잘림 완화, GUI bounds 중심 맞춤, 네이티브 3인칭 hand layer의 X -90°/Y180°를 고려한 모델 X +90° 보정.

## Step 4 — 전체 시트 검수에서 발견한 형상 결함 수정

- 1차 전체 framebuffer 시트에서 Biting Winds의 얇은 림·시위가 다수의 공중 큐브로 끊기는 결함을 발견했다. 중심 ray만 샘플링하면 셀보다 가는 삼각형을 통째로 놓치는 것이 원인이었다. 이 모델에는 원본 triangle을 각 YZ 셀로 보수적으로 clip하는 surface-volume 재구성을 적용했다. 원본과 무관한 임의 연결 큐브를 추가한 것이 아니다. 가는 부분은 여전히 큐브 격자의 두께·계단 근사가 남는다.
- Apostate는 `.blend`와 `.fbx` 모두 artist 공통 이동 `(-0.532, +0.800, 0)`이 포함되어 있었다. FBX로 바꾸는 것만으로 해결되지 않았다. 공통 stage transform을 역변환해 손잡이 원점을 복원하고 -Y 총구를 -Z로 정규화했다. 부품별 origin을 따로 초기화하지 않았다.
- 회귀 검증 추가: 활 전체 큐브 연결성, Apostate 손 중심·전방 총열과 원본 좌표 보정 메타데이터. 단순 codec·cube count 통과만으로 형상 검수를 대체하지 않는다.
- 최종 렌더 재검증 범위는 모든 63종의 hip/GUI/3인칭 + 대표 20종의 ADS/inspect. 여기서 GUI는 실제 GUI `ItemDisplayContext`를 사용하는 world `item_display`이며, 인벤토리 화면 자동 조작 검증은 아니다.
