# 헌터 수류탄·투척 근접 모델 — H11

## 1. 구현 범위

26.3 Fabric 서버사이드 모드 + 필수 Polymer 리소스팩. 별도 클라이언트 모드 없이 Java item_display로 보입니다.
BetterModel 플레이어 구르기/궁극기 리그는 변경하지 않습니다. 단순 투사체 소품은 bone 애니메이션이 필요 없어
Blockbench Java Block/Item → vanilla 모델 JSON → Polymer 가상 item_display로 연결했습니다.

| 능력 | 아이템 모델 ID | 큐브 | 디자인 |
|---|---|---:|---|
| Arc 섬광 | `destiny:hunter/arc_flashbang` | 27 | 은색 장방형 몸체, 3열 통풍구, 안전고리, 청색 도관 |
| Solar 소이 | `destiny:hunter/solar_incendiary` | 18 | 구리색 열원 캡슐, 방열 리브, 주황 띠, 점화부 |
| Void 소용돌이 | `destiny:hunter/void_vortex` | 24 | 자기 코일 상하단, 보라색 도관, 다이아몬드 코어 |
| Solar 칼 투척 | `destiny:hunter/solar_knife` | 16 | 단차 칼날·등, 태양색 인레이, 감긴 손잡이, 가드 |
| Void 연막 | `destiny:hunter/void_smoke_bomb` | 24 | 짧은 녹회색 캔, 배출구, 보라 식별 띠·표찰 |
| Arc 연속 타격 | 없음 | — | 맨손 돌진·전격 타격 유지; 투사체나 단검을 임의 추가하지 않음 |

모든 외형은 흰색/색상 변경만 한 동일 모델이 아니라, 큐브 구조와 장비 세부가 다릅니다.
각 64×32 RGBA 아틀라스 1장. 큐브는 Java 호환 단일 축 22.5° 배수 회전, 좌표 -16~32 내부.
그룹은 `root/shell`, `root/hardware`, `root/energy`. 텍스처가 임베디드되어 .bbmodel 단독으로 편집 가능합니다.

## 2. 실제로 확인한 시각 레퍼런스와 출처

2026-10-22 Sketchfab 공개 API에서 작가/작품/라이선스 메타데이터를 읽고 대표 렌더 이미지를 육안 확인했습니다.
ArtStation도 조사했으나, 이번 제작의 검증 가능한 시각 근거는 아래 Sketchfab 작품 4개로 한정합니다.
원본 PNG/메시/UV/PBR 맵은 배포물에 포함하지 않습니다. 작품의 로고·문구·정확한 형상/비율을 복제하지 않고,
통풍구·발광 레일·안전장치·칼날/손잡이 비례 같은 조형 언어만 참고하여 신규 큐브와 픽셀 아틀라스를 제작했습니다.

| 작품 / 작가 | 확인한 요소 → 재해석 | 페이지의 라이선스 표시 |
|---|---|---|
| [Flashbang grenade — Nikolay Kudrin](https://sketchfab.com/3d-models/flashbang-grenade-2799b0b859c74db6ae8752fdc6bb4c04) | 구멍 난 외피·안전 레버 → Arc의 3열 검정 통풍구·각진 고리 | CC BY 4.0 |
| [ORBIT Magnetic grenade — kawuru](https://sketchfab.com/3d-models/orbit-magnetic-grenade-d382304852a04339aed6aa325fafd195) | 상하 자기 코일·세로 보라 레일 → Void의 코일과 신규 다이아몬드 코어 | API 라이선스 필드 비어 있음; 이용 허가로 간주하지 않음 |
| [Throwing Knife — Eric Wallbank](https://sketchfab.com/3d-models/throwing-knife-8e47c2ff42894aa1bac12af46d08aced) | 긴 단검 비례·날의 경계 → 단차형 칼날·손잡이. 원본 천공 손잡이는 사용하지 않음 | CC BY 4.0 |
| [Sci-fi Smoke grenade — Novojilov7](https://sketchfab.com/3d-models/sci-fi-smoke-grenade-7917e3fcddc7493582af80491698d609) | 캡·세로 리브·경고 띠 → Solar 방열 핀, Void 연막의 배출구·식별 띠 | CC BY 4.0 |

CC BY 표시 작품도 원본 파일을 내려받아 개작/재배포한 것은 아닙니다. 크레딧은 참고작의 출처 추적을 위해 보존합니다.
ORBIT의 다운로드 권리는 확인되지 않았으므로 원본 파일을 사용할 때에는 별도 허가/라이선스 확인이 필요합니다.
원작 Destiny 에셋 추출이나 Bungie 공식 아트의 1:1 복제를 수행하지 않았습니다.

## 3. 제작·편집 경로

- 원본: `art/blockbench/hunter/<name>.bbmodel` (5개, 텍스처 임베디드)
- 매니페스트: `art/blockbench/hunter/manifest.json`
- 모델: `src/main/resources/assets/destiny/models/hunter/<name>.json`
- 아이템 정의: `src/main/resources/assets/destiny/items/hunter/<name>.json`
- 아틀라스: `src/main/resources/assets/destiny/textures/item/hunter/<name>.png`
- 생성 코드: `scripts/build_hunter_props.js`
- MCP 실행/내보내기: `scripts/export_hunter_props.py`

Blockbench 5.1.4, Blockbench MCP 1.10.1에서 제작했습니다. MCP `get_capabilities`, `tools/list`,
`create_project`, `risky_eval`, `create_offscreen_view`, `set_camera_angle`를 사용했습니다.
프로젝트 선택 뒤에만 모델링/카메라 도구가 도구 목록에 나타나는 호스트 동작을 확인했습니다.
코드 평가 전에 MCP의 native API/code eval 안전 가이드를 읽었고, 신규 모델의 편집은 Undo로 묶었습니다.
`requireNativeModule(fs)`는 사용하지 않습니다. codec 결과와 PNG를 RPC 응답으로 받아 외부 Python에서 저장합니다.

```sh
rtk proxy python3 scripts/export_hunter_props.py
```

실행 시 **새 프로젝트 탭 5개**를 만들며, 기존 사용자 프로젝트를 지우거나 편집하지 않습니다.
내보낸 repo 파일은 같은 이름으로 갱신합니다. Blockbench JSON UUID는 재실행 시 달라질 수 있습니다.
현재 호스트는 Java 형식 버전을 `1.21.11`로 내보내지만, 이 소품은 표준 큐브 모델만 사용하며 26.3에서 실검증합니다.
26.3 전용 셰이더·posteffect 코드는 이 작업에서 변경하지 않았습니다.
호스트 preview cleanup의 `onContextMenu` 오류는 내보내기 실패와 구별해 경고로 기록합니다.

## 4. 게임 연결과 수명

`HunterAbilityVisuals`가 매번 새 PAPER 스택을 만들고 `DataComponents.ITEM_MODEL`로 5개 모델을 선택합니다.
기존 `HunterGrenade`, `HunterMelee`의 바닐라 아이템 외형만 교체합니다.
투척 속도·중력·수명·스케일(수류탄/연막 0.5, 단검 0.6)·피해·쿨타임·상태효과는 유지합니다.

`SimProjectile`은 사용자 모델이 있으면 FIXED billboard, NONE 아이템 컨텍스트로 렌더링합니다.
로컬 -Z를 현재 속도 벡터로 회전시키므로 단검 끝이 날아가는 방향을 따릅니다.
실제 렌더러의 내장 Y=180° 회전을 확인하고 역보정을 포함했습니다.
구형 바닐라 그림자 사격 화살은 기존 CENTER billboard를 유지합니다.
충돌·시간 만료·사망·차원 변경·직업 전환 시 기존 holder 정리 경로를 그대로 사용합니다.
발광은 기존 item_display 밝기 15를 사용한 표현이며 실제 동적 광원/새 셰이더를 뜻하지 않습니다.
