# 헌터 수류탄·투척 근접 모델 — H12 현재 명세

## 1. 구현 범위와 현재 상태

26.3 Fabric 서버사이드 모드 + 필수 Polymer 리소스팩의 투사체 소품 모델입니다.
별도 클라이언트 모드 없이 Java `item_display`로 표시하며, Blockbench Java Block/Item 형식의
편집 가능한 큐브 모델과 vanilla 모델 JSON을 사용합니다.

H12에서는 **실제 Destiny 시각 자료를 확인한 Hunter knife와 Flashbang 두 모델을 재제작**입니다.

### 2.1 Hunter knife — H12 재제작 기준

- 출처 페이지: [Hunter Knife — Destinypedia](https://www.destinypedia.com/Hunter_Knife)

차트에는 Destiny 표기와 ©2014 Bungie가 있으며, 개별 작가명은 확인되지 않았습니다.
Destinypedia가 제공하는 위 이미지들을 직접 육안 확인했습니다. Bungie 명의 차트와
스크린샷의 특징이 일치하므로 실제 Destiny Hunter knife 디자인이라는 근거로 사용합니다.
특정 Destiny 2 버전의 모든 투척 칼 변형을 동일한 모델로 확인한 것은 아닙니다.

재구성에 반영한 특징은 다음과 같습니다.

- 비대칭의 넓고 평평한 칼날, 볼록한 절삭 곡선, 각진 끝부분.
- 끝부분 가까운 칼등의 길고 열린 갈고리형 홈.
- **실제로 뚫린 원형 구멍 3개**: 칼날 중앙부 구멍, 손잡이 앞쪽의 작은 손가락 고리, 뒤쪽의 큰 고리.
  색칠한 원이나 막힌 원판으로 대체하지 않습니다.
- 짧고 휜 손잡이와 겹쳐 감긴 어두운 감개, 얇게 좁아지는 칼날 두께.
- 회색 강철로 보이는 칼날 표면, 밝은 절삭 베벨, 마모·긁힘, Hunter 꺾쇠 문양.
  정확한 합금과 감개 재질은 이미지로 확정하지 않습니다.
- 허구의 금색 장식·태양색 인레이를 추가하지 않습니다.

차트의 전체 길이 표기는 0.433m / 17.047in입니다. 게임 안 표시 크기는 기존 동작을 유지하며,
이 수치를 근거로 투사체 스케일을 변경하지 않습니다. 초기 concept의 끈·술 장식이나
`WORK IN PROGRESS` 렌더의 세부를 최종 게임 외형으로 단정하지 않습니다.

표면의 금속 돌기(studs), 흰색의 가늘어지는 테이퍼 캡, 옆면 검정 레버**입니다.

정확한 치수·후면 구조·재질 조성 등 이미지에서 확인되지 않는 부분은 확정 사실로 기록하지 않습니다.

### 2.3 소이·소용돌이·연막 — 원작 형상 미확인

`solar_incendiary`, `void_vortex`, `void_smoke_bomb`는 H11 일반 SF 모델을 잠정 유지합니다.
현재 외형이 실제 Destiny 원작 디자인이라는 근거는 확보되지 않았습니다.

Incendiary와 Vortex의 위키 이미지에서 확인한 것은 폭발·능력 효과이며,
투척 전 소품의 껍질 형상이나 재질을 확인할 수 있는 자료가 아닙니다.
따라서 폭발 이미지의 색·효과를 껍질의 코일·리브·장치 구조에 대한 증거로 사용하지 않습니다.
연막탄도 물리적 껍질을 확인한 이미지가 없어 형상을 추정하지 않습니다.

## 4. 제작·편집 경로

기존 파일 경로와 연결 구조를 유지합니다.

- 편집 파일: `art/blockbench/hunter/<name>.bbmodel` (5개)
- 매니페스트: `art/blockbench/hunter/manifest.json`
- 모델: `src/main/resources/assets/destiny/models/hunter/<name>.json`
- 아이템 정의: `src/main/resources/assets/destiny/items/hunter/<name>.json`
- 아틀라스: `src/main/resources/assets/destiny/textures/item/hunter/<name>.png`
- 생성 코드: `scripts/build_hunter_props.js`
- MCP 실행/내보내기: `scripts/export_hunter_props.py`

H12도 임베디드 텍스처가 있는 `.bbmodel`, 모델별 64×32 RGBA 아틀라스,
`root/shell`, `root/hardware`, `root/energy` 구조를 사용합니다. Java 단일 축 22.5° 배수 회전,
좌표 -16~32, 6면 UV와 임베디드 PNG 일치를 JUnit으로 확인했습니다.

```sh
rtk proxy python3 scripts/export_hunter_props.py --models arc_flashbang solar_knife
```

Blockbench5.1.4/MCP1.10.1에서 새 프로젝트 탭 2개를 만들고 해당 저장소 파일만 갱신합니다.
선택 인자를 생략하면 5종 모두 재생성하되 나머지 3종의 잠정 상태는 유지합니다.
기존 사용자 탭은 지우거나 수정하지 않습니다. 네이티브 fs 평가 없이 codec/PNG를 RPC로 받아 외부 Python에서 저장합니다.
편집은 Undo 트랜잭션으로 묶었습니다. UUID는 재생성 시 달라질 수 있습니다.
호스트의 offscreen cleanup `onContextMenu is not defined` 오류는 내보내기 성공과 구분해 경고로 기록합니다.

## 5. 게임 연결과 수명 — 기존 동작 유지

H12 변경 범위는 소품 외형입니다. 능력·아이템 모델 ID와 기존 게임플레이는 유지합니다.
BetterModel 플레이어 구르기/궁극기 리그는 변경하지 않습니다.

`HunterAbilityVisuals`가 매번 새 PAPER 스택을 만들고 `DataComponents.ITEM_MODEL`로 5개 모델을 선택하는
기존 연결을 유지합니다. `HunterGrenade`, `HunterMelee`의 투사체 속도·중력·수명·스케일
(수류탄/연막 0.5, 단검 0.6)·피해·쿨타임·상태효과는 변경하지 않습니다.

`SimProjectile`의 사용자 모델에 대한 FIXED billboard, NONE 아이템 컨텍스트와
로컬 -Z를 속도 벡터로 정렬하는 기존 회전 처리도 유지합니다.
내장 Y=180°에 대한 역보정, 바닐라 그림자 사격 화살의 CENTER billboard,
충돌·시간 만료·사망·차원 변경·직업 전환 시 holder 정리 경로를 그대로 사용합니다.
기존 `item_display` 밝기 15 표현은 실제 동적 광원이나 새 셰이더를 뜻하지 않습니다.
26.3 전용 셰이더·posteffect 코드는 이 외형 작업의 변경 범위에 포함하지 않습니다.
