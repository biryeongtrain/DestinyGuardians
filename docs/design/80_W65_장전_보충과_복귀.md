# W65 — 재장전 탄약 보충과 복귀 구간 분리

## 바뀐 플레이 흐름

**장전 시작 → 실제 탄약 보충 → 복귀 모션·소리 계속 → 기존 완료 시점에 발사 가능.**
이전 W64까지는 보충과 모션 해제가 같은 deadline이었다. W65는 명시적인 자료가 있는 6종만 보충을 앞당긴다.

| Duke Mk.44 |42|59|
| Austringer |38|53|

| Fixed Odds |69|106|

| Duke + 실제 획득한 Outlaw |24|33|

20Hz 서버 기준이며 원작 영상 실측 수치가 아니다. 마지막 행은 기존 유효 장전 시간을 한 번 캡처한 뒤 비율을 적용한 통합 정책이다.
실제 HUD 탄창·예비탄은 보충 즉시 갱신하고, 장전 바는 전체 phase의 진행도를 계속 표시한다.
Duke의 21단계 모션과 W63 소리도 전체 구간을 유지한다. 새 모델·텍스처·음원은 추가하지 않았다.
개별 모션 지원은 여전히 **Duke / Beloved 2종**뿐이다. 기관총 모션까지 구현한 것은 아니다.

고정된 Oracle 원본의 `ammo_time=reload_time*ammo_percent`에서 명시 비율만 추출했다.
핸드캐논3종은0.71, 기관총3종은0.65. **선형 융합 소총에 이 비율을 적용하지 않는다.**
나머지57종의 비율은 미상이며 원래 전체 deadline에 지급한다. Rust의 누락 필드 기본값0.0은 실제 게임의 즉시 보충 증거가 아니다.

서버는 `ceil(capturedFullTicks * fraction)`을 사용한다. 원래 초 단위 곱을 먼저 반올림하는 것과 다를 수 있다.
Oracle modifier는 `reload_time`만 변경하고 `ammo_time`을 다시 계산하지 않는 불일치가 있다.
그 불일치를 복제하지 않고 캡처된 유효 시간에 비율을 적용하는 것은 **이 구현의 의도적인 정책**이다.
비율·tick을 공식 최신 샌드박스 수치라고 주장하지 않는다.

Duke 영상의27.10초7/107 →27.20초9/105 뒤에도 손·총 복귀가 이어진다는 관찰과 방향은 일치한다.
하지만 그 영상으로0.71, 최초 허용 발사 시점, 취소 판정, Outlaw 가속을 측정하지 않았다.
이번 변경은 기존 발사 gate를 유지하며 새로운 조기 발사/장전 취소 테크닉 재현을 주장하지 않는다.

## 상태·탄약·특성 계약

- `WeaponRuntime`이 기존 `WeaponOutlaw.plan`을 캡처하고 별도 보충 tick을 `WeaponCycle`에 전달한다.
- 보충 deadline에는 실제 `WeaponMagazine.reload()`와 저장을 **최대 한 번** 수행한다.
- 유한 예비탄은 실제 지급량만 차감한다. 보충 실패/0발도 지급 기회를 소비하므로 뒤늦은 획득으로 재지급되지 않는다.
- 보충 이후에도 `reloading()`은 true. 기존 전체 deadline 전에는 발사·두 번째 장전이 금지된다.
- 전체 종료에는 phase만 해제한다. 추가 지급이나 Kill Clip 재활성화가 없다.
- Kill Clip은 실제 지급 시 활성화하고 복귀 동안에도 시간이 감소한다. Duke의42tick 활성화는59tick에83tick 잔여다.
- 보충 전 취소는 무지급. 보충 뒤 취소/수납/사망/cleanup은 이미 지급한 탄약을 유지하되 중복·환불하지 않는다.
- 교체한 ItemStack과 다른 소유자의 상태는 독립이다. 같은 tick의 away/back도 기존 packet route로 관찰한다.
- 점진 장전은 기존 한 삽입 단위를 유지한다. 기존 cycle overload는 전체 시점 지급으로 호환된다.

## 음향 provenance와 검증

동일 JAR 전체 강제 빌드2회에서 각각 **512 required GameTest /465 JUnit, 실패·오류·skip0**.
기존503GT/455JUnit을 유지하고9GT/10JUnit을 추가했다.
792개 client resource,15개 server-only resource,240개 main class와 생성팩을 확인했다.
사전1538개 asset bytes와542개 원본 무기·황금총 리소스를 보존했다. 추가 native 기동은0회다.

W63 원본 음향 manifest는 역사적 메서드 SHA를 고정한다. W65에서 overload가 바뀌므로 원래 `--verify`는 source drift로 거절한다.
원본 manifest나 검사기를 바꾸지 않았다. [W65 호환 검사기](../../scripts/qa/verify_reload_audio_w65.py)는
리뷰한 현재 전체 소스 SHA를 별도로 고정하고, 변경된 단일 메서드 pin 이외의 원본 입력이 모두 정확한지 검사한다.
그 후 **메모리 안에서만** 역사적 provenance를 복원해 기존 Ogg/PCM/시간 매핑을 재검증한다.
이는 원래 검사기가 현재 소스를 그대로 승인했다는 주장이 아니다.

[QA 결과·초기 실패 로그·회귀 보존](../qa/2026-10-24/w65/README.md).
서버 GameTest·HUD node·패킷·PCM 검사는 실제 Minecraft 화면/키보드 입력/청취를 대신하지 않는다.
사용자가 승인한 격리 Vision 진단1회는 W62에서 소비했다. W65 추가 Minecraft 기동·일반 QA 배포·앱 조작은 없다.

## 남은 작업

- 비율 없는57종의 개별 보충/복귀 자료 조사, 다른 무기 장전 모션과 손/IK.
- 원작 정확한 조기 발사·취소 입력 타이밍, 빈 탄창/부분 장전 차이.
- 황금총·월도·HUD의 최종 실게임 구도, 현재 팩 캐시·모션·청취 검증.
- 추가 특성·경이 무기, 다인·거리·성능 검증. 전체 무기 시스템 목표는 계속 진행 중이다.
