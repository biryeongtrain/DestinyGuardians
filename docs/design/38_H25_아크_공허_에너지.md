# H25 — 무기에 붙어 움직이는 아크·공허 에너지

## 1. 요구 / 보존 범위

사용자: “전기 이펙트도 … 보이드도 … 너무 심심해보여”. H24 아크 지팡이와
H22 당겨진 공허 활에 애니메이션을 따라가는 에너지를 보강한다. H23 발동18틱,
공격/피해/이동/체공/후방 카메라/솔라 모델은 변경하지 않는다.
공식 모델·텍스처 추출이 아닌 자체 제작 형상·atlas. 원작과 동일한 블룸을 주장하지 않는다.

## 2. 단계 기록

1. **에셋**: 원본 64×64 RGB atlas와 겹친 유색 외곽/밝은 코어. 아크32,
   공허 가닥28, 공허 화살촉26 cuboids. 편집 원본 `art/blockbench/vfx_h25/`.
   `scripts/build_super_energy_h25.py --verify`로 12산출물 바이트 재현.
   결정론적 `.bbmodel` 작성이며 native Blockbench codec export/preview를 수행한 것은 아니다.
2. **무기 소켓**: BetterModel3.5.1의 실제 전송 display transform을 기존 서버 pose sampling
   범위 안에서 복사한다. native ItemDisplay는 off-world sentinel/갱신되지 않는 metadata를
   가지므로 위치 근거로 쓰지 않는다. raw model → 손 display 변환 → 전송 scale/quaternion/
   translation → pipeline yaw → 바닐라 플레이어 passenger anchor. 약한 참조 + tracker 종료 시 제거.
3. **표현**: 아크는 봉/양끝6가닥의 요동·회전, 실제 타격 시6틱 증폭.
   공허는 활 양끝2가닥/당겨진 시위2가닥/화살촉 맥동/유입 가닥.
   실제 화살 생성 시점에 발사축 옆6조각 파동으로 전환,8틱 확장 후 제거.
   조준축을 덮는 불투명 원판은 만들지 않는다.
4. **수명·상한**: 소유자당6 item displays 재사용, 전역8묶음/48개 상한,
   420틱 watchdog. 실제 pose가 없으면 임의 얼굴 앞 위치에 생성하지 않는다.
   EntityAttachment로 추적, 본인 명시 watch. 별도 task/clock 없이 PlayerAnimations.tick 직후
   한 서버틱 한 번만 갱신. 정상 종료는 발사 파동만 보존; 취소/사망/차원 변경/연결 종료는 정리.
5. **자동 테스트**: geometry3 + asset4 JUnit, 소켓 packet parity/재사용/분리/발사 수명/
   전역 상한/차원 이동 GameTest4 추가. 전체 **116 JUnit /168 GameTest** 일반 gate 통과.
6. **실화면 검증**: 최종 아크·공허 각각20/5TPS, 본인/관찰자 촬영과 native 입력 검증 완료. [QA 기록](../qa/2026-10-23/h25/README.md)에
   실제 촬영·입력·복구 결과와 최종 강제 재실행 결과를 남겼다.

## 3. 테스트 중 발견·수정

- 최초2회: native backing display 좌표/metadata가 실제 packet 값이라고 가정한 테스트 오류,
  동시 fixture 전체를 tick해 다른 테스트에 간섭,1틱 조기 검사. 각각 실제 packet buffer,
  fixture 자체 clock만 전진,2틱 뒤 수명 검사/quiet window로 수정.
- 3회: BetterModel `TransformationData.Item.getValue()`는 dirty-only이며 clean이면 null.
  reflection 테스트가 NPE로 서버를 중단했다. `getForceValue()`의 바이트코드를 확인하고
  읽기 전용 검사로 교체(실제 buffer dirty flag를 소비하지 않음).
- `runGameTestServer`는 이 프로젝트 task가 아님. 실제 task `runGameTest`로 재실행.
  위 실패는 성공 수에 포함하지 않는다. 원본 로그는 QA `rejected/`에 보존.

## 4. 한계

fullbright geometry이며 광원 투사/후처리 bloom이 아니다. 기존 H20 dust·화살 trail·tether와
합성하며 기존 beam counter와 신규 energy counter를 구분한다. 전역 상한을 넘으면 가장 오래된
에너지 묶음부터 제거(게임플레이에는 영향 없음). 다인 실제 GPU/네트워크 부하는 별도 인수 항목이다.

### 실제 픽셀 피드백 후 보정

첫 Arc20TPS 촬영에서 전류가 봉 아래에 분리되어 보였다. BetterModel은 limb displays를
실제 플레이어에 SetPassengers로 붙인다. tracker.location은 그 바닐라 탑승 높이가 아니다.
소켓 기준을 passenger anchor로 수정하고 native display의 VEHICLE attachment까지 포함한
GameTest 기대값으로 교체했다. BM backing display는 서버 startRiding을 거절하므로
실제 패킷 탑승과 혼동하지 않고 바닐라 seat API로 검사한다.
해당 테스트 작성 중 startRiding 시그니처 compile 실패/서버 탑승 거절1건도 원본 보존.
Polymer의 주기적 tracking 갱신이 본인 watch를 제거하는 경로도 확인해 전용 attachment로
본인 watch를 보존, fake fixture에서도 periodic refresh 후 owner 포함을 검사했다.
보정 후116/168 일반 gate 재통과. 픽셀 재확인 진행.

픽셀 보정2: 아크 긴 가닥이 불투명 봉 내부에 파묻히지 않게 시작 반경을1.6 raw unit
(약0.10m) 밖으로 띄우고 시간에 따라 최대2unit 요동하게 했다. idle 폭1.4배/타격2.2배,
타격6틱 제한은 유지. 바깥 시작 반경과 destroy 후 attachment/watch 제거도 회귀 검사한다.
일반 gate116/168 재통과. 이 후보를 최종 실화면 검증 대상으로 기동한다.
