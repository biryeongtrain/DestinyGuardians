# W95 — 일반 활 발사자 근접 궤적 보정

상태: W95 한정 범위 수락. 815GT/689JUnit 강제2회·Vision8sequence/161PNG·원본16개 검사와 실제 cache 검증 완료. 작은 dust는 남으며 특정 W93 상단 직사각형/전체 무기 목표는 미해결이다. 원작과 동일하다는 주장은 아니다.

## 증거와 범위

[W94 기본/차단/복원 진단](../qa/2026-10-25/w94/README.md)은 실제발사18회에서 큰중앙sprite의 ordinary bow trail 기여를분리했다. 특정W93 top-clipped solid rectangle은재현되지않아여전히별개미해결이다.

W95는 일반활 `WeaponRuntime.tickShot`의 trail 호출만 `BowTrailFx`로분리한다. 원래trace/hitLocation/원점/속도/중력/범위/탄약/nock/damage/모델/사운드/공통Fx는유지한다. 프로파일/원작값을추측해바꾸지않는다.

## 수신자와 샘플 계약

- 원래 `Fx.line`: from+unit(delta)*d, d=0,+step≤length. 짧은길이<1e-4는0개. radius경계에서재샘플하거나추가endpoint를만들지않는다.
- 발사자만 exact object identity로선별한다. 현재level일치·nativecamera=self·등록CameraView없음일때만 현재눈의반경**1.25m미만**인원래샘플을보내지않는다. 정확경계는유지한다. 이수치는원작측정이아닌 provisional Minecraft시각후보이며W95정지self-camera대표에서근접방해감소만수락했다.
- 다른관전자(발사자와같은위치포함)는원래모든샘플/순서/색/size/count/false,false/zero spread·speed/DEFAULT randomization을받는다. 기존native32m거리/level판정과minigameCameraView private recipient hook을그대로통과한다.
- native외부camera또는CameraView는owner제외도하지않아기존시점/전달을보존한다. 원래simple Fx broadcast도우회하던cross-level extra-forwarding overload를새로추가하지않는다.
- vanilla F5는서버가판별하지못하므로1인칭전용감지라고하지않는다. 미래에이미생성된파티클로카메라가움직이면근접obstruction이생길수있다. 현재수신자목록을매호출읽으며owner/샘플/context상태를저장하지않는다.
