# W31 — 무기 기본 안료 복원

63종의 기본 안료 복원과 최대 256큐브 재구성을 완료하고 최종 에셋을 적용했다.
최종 staged 결과는 `/tmp/destiny-weapons-w31/final256-detail`이다.
생성기 검증과 자동 gate를 통과했고, 새 리소스팩의 **native 229장 촬영·검수**를 완료했다.
이는 시각 프리뷰의 이번 수정 검증이며 수작업 최종 아트·총기전투 인수는 아니다.

## 요청과 최종 기준

- light.gg Item Screenshot을 시각적 목표로 W30의 회색/무채색 외형을 기본 안료로 복원한다.
- 사용자 추가 요청에 따라 63종 모두 원본 리핑 표면을 다시 샘플링하고, 무기당 큐브 상한을 256으로 정했다.
- 원본 리핑 파일과 사용자 Blender/Blockbench GUI 장면은 저장·변경하지 않는다. 장착 위치와 hip/ads/inspect 포즈의 display 변환은 유지한다.
- 파생 모델의 geometry와 UV는 의도적으로 변경한다. 초기의 geometry/UV 불변·기존 512 atlas 유지안은 최종 W31 기준이 아니다.

## W31-S1 — 원인 확인과 레퍼런스 고정

- 기존 W30의 단일 Diffuse 추출은 저장된 재질의 dye slot, GStack/wear mask, detail diffuse 합성을 생략했다. Blender 이미지 float의 선형 RGB를 출력용 sRGB로 변환하는 과정도 필요하다.
- Austringer의 저장된 BLEND에는 금색·보라색 안료가 있다. 동봉 Unity shader/Python 프리셋은 다른 빨간 안료이므로 실행·적용하지 않는다.
- 63종의 공식 item screenshot과 SHA256, light.gg URL, Bungie manifest의 `defaultDyes` 식별자를 `art/weapons/w31/references.json`에 고정했다.
- 실제 light.gg 페이지 DOM에서 확인한 것은 **22종**이다. 나머지는 공식 screenshot과 동일한 item hash 기반 URL 패턴을 사용했다. 63개 페이지를 모두 브라우저로 확인한 것은 아니다.
- 리핑 자료의 안료·장식과 공식 기본 외형이 다를 수 있다. Duke Mk.44처럼 gear JSON의 안료도 screenshot과 다르면 screenshot을 시각적 목표로 삼고 보정 근거를 기록한다.

## W31-S2 — 격리된 순수 안료 베이크

- `scripts/art/retexture_weapons_w31.py`는 별도 Blender 프로세스의 `--background --disable-autoexec` 환경에서 실행한다. 원본은 `open_mainfile(..., use_scripts=False)`로 읽고, 사용자 GUI 세션과 분리한 bake scene에서 평가한다. 원본 파일을 저장하거나 동봉 스크립트를 실행하지 않는다.
- 금속용 흰 specular lobe가 이미 섞인 BSDF 합산값은 안료를 회색으로 씻어낸다. 저장된 shader의 순수 안료 `Bake_Color` 출력을 우선하고, 없으면 명시적 dye frame에서 나오는 유일한 비-iridescence RGBA 출력을 emission에 연결해 베이크한다.
- 원본 UV에서 재질별 1024² emission bake를 얻고 선형 RGB를 sRGB로 변환한다. 원본 삼각형의 UV를 새 큐브 face UV에 투영하여 안료·마모·세부 문양을 합성한다.
- `art/weapons/w31/palette-overrides.json`에 Duke의 청색 래커/스틸, Gambit 계열(Bygones·Distant Relation·Bad Omens)의 청록 금속, Cold Denial의 녹색 외장 보정을 명시했다. 해당 dye 채널만 조정하고 wear/detail mask와 목재·구리·흰색·문양 등 다른 채널은 유지한다.
- Bad Omens의 첫 후보는 shader group 이름 불일치로 실패했다. 실제 이름 `Bad Omens_Shader Preset`으로 수정해 재생성했으며, 실패 후보와 최종 결과를 구분한다.
- 누락된 공통 `Iridescence Lookup`은 캐시의 후보 **34개 SHA256이 모두 동일함을 확인한 경우에만** 복원했다. 무기별 Diffuse를 관계없는 다른 무기에서 가져오지 않는다.

## W31-S3 — 256큐브 재구성·최종 적용

`scripts/art/reconstruct_weapons_w30.py`의 `--max-cubes 256 --atlas-size 1024`로
원본 표면에서 cuboid를 다시 구성했다. 두께 샘플은 6→8, 세로/길이 후보 해상도는 최대 320으로
늘렸다. 기존 큐브를 단순 분할한 결과가 아니다. 이후 `--pixels-per-unit 14`로 UV를 다시 배치하고 안료를 투영했다.

| 항목 | W30 기준 | W31 생성 결과 |
|---|---|---|
| 대상 | 63종 | 동일 63종, 전 모델 큐브 증가 |
| 큐브 수 | 51~128 | 148~256, 평균 228.22 |
| 큐브 상한 | 128 | 256 |
| 최종 atlas | 512² | 1024² |
| 모델 단위당 픽셀 | 5 | 14 |
| 장착·포즈 변환 | hip/ads/inspect | 63종×3포즈 모두 정확히 유지 |
| 파생 geometry/UV | W30 재구성 | 원본 재샘플링/UV 재배치 |

생성기 CLI의 기본값 128/512는 과거 실행 재현용으로 남아 있다. W31은 위의 명시적 옵션을
사용한 256/1024/14 결과이며, 기본값을 W31의 최종 사양으로 해석하지 않는다.

Coriolis Force는 조밀한 샘플링에서 accessory의 바깥 범위가 0.348 모델 단위 줄어
새 geometry bounds로 display를 계산하면 포즈가 달라지는 문제가 있었다. 이를 포함한 63종 모두
`art/weapons/w31/baseline.json`의 승인된 `model_bounds`를 `destiny_w31.display_bounds`로 보존하고,
생성기는 이 bounds로 포즈를 계산한다. 실제 geometry의 bounds는 새 재구성 값을 유지한다.
테스트는 hip/ads/inspect 세 상태의 display를 각각 baseline과 정확히 비교한다.

호환성을 위해 출력은 기존 `art/blockbench/weapons/w30/`, `art/weapons/w30/` 및
런타임 `models/weapon/`, `textures/item/weapon/w30/` 등의 안정된 경로와 모델 ID를 사용한다.
W31 레퍼런스·보정표·baseline은 `art/weapons/w31/`에 둔다.
과거 `docs/qa/2026-10-23/w30/` 기록은 그대로 보존하고, 새 검증 근거는
`docs/qa/2026-10-23/w31/`에 별도로 기록한다. W30 통과 수치를 W31 결과로 재사용하지 않는다.

### 확인된 자동 검증과 재현성

- 최종 에셋을 적용하고 생성기 출력 **318파일 verify**를 완료했다.
- `WeaponRetextureW31Test`에 JUnit 4개를 추가했다. 전 모델 큐브 증가/256 상한·원본 식별자/3포즈 유지, embedded/runtime texture 일치와 bake 출처·1024 atlas/밀도 14, 63종 screenshot/default dye 참조, 대표 안료와 누락 이미지 magenta 회귀를 검사한다. 기존 `WeaponCatalogTest`의 예산·texture 크기 검사도 256/1024에 맞췄다.
- 전체 gate `rtk proxy ./gradlew runGameTest test build --rerun-tasks`가 **20 tasks 성공, GameTest175/175 · JUnit146/146, 실패·오류·스킵0**으로 완료됐다. 실제 task명은 `runGameTest`이다. 잘못된 `runGameTestServer` 요청의 실패 로그도 별도로 남겼다.
- 대표 4종의 독립 재베이크에서 파싱한 JSON 값과 PNG bytes가 각각 동일했다. metadata migration에 따른 raw bbmodel member 순서 차이가 있으므로 전체 bbmodel 파일의 byte 일치를 주장하지 않는다.

### 남은 인수와 한계

총기 사격·탄약·재장전 등 전투 구현, PBR 반사, 실시간 dye 교체는 범위 밖이다.
원본 장식/리핑 형상의 차이와 cuboid·UV 근사 한계가 남으므로 원작의 조명·광택·형상까지 완전히 같다고 주장하지 않는다.
