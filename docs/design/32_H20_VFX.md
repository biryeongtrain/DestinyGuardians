# H20 — 궁극기 외곽 디테일·서버틱 수명 계약

2026-10-22. H19B 장비·아티스트 BetterModel 모델을 교체하지 않는 **추가 연출**이다.
피해, 탄수, 공격 예약, 카메라, HUD, limb 애니메이션의 시간축은 변경하지 않는다.

## 연결 API (부모 통합용)

모든 호출은 기존 능력과 같이 서버 스레드에서 실행한다. `HunterSuper` 수정은 부모가 담당한다.

```java
// 성공한 활성화 및 limb/prop 설정 뒤, 한 번
SuperVfx.materialize(player, element);

// Void의 실제 draw 진행 중 매 서버틱. 버튼 입력만으로 release 효과를 실행하지 않는다.
SuperVfx.charge(player, actualDrawProgress01);

// 실제 화살 생성/접촉 틱에 연결. 이 VFX가 발사 시점을 결정하지 않는다.
SuperVfx.voidRelease(player, projectileOrigin, projectileDirection);
SimProjectile arrow = SimProjectile.launch(/* 기존 게임플레이 인자 */);
SuperVfx.followArrow(player, arrow);

// 정상 세션 종료. Void 화살·닻은 여기에 묶어 취소하지 않는다.
SuperVfx.dematerialize(player, element);
```

- `materialize`, `voidRelease`, `followArrow`는 수락 여부를 `boolean`으로 반환한다.
- `charge`는 Void 장비 cue가 있어야 동작한다. 유한값은 0..1로 제한하고 NaN/무한대는 무시한다.
  2틱 넘게 갱신되지 않으면 충전 외곽만 idle로 돌아간다. 화살을 발사하거나 draw를 취소하지 않는다.
- `voidRelease`는 유한·비영 방향과 눈에서 4블록 이내 origin만 허용한다. 입력 방향을 정규화한다.
  고정 origin/방향으로 7틱 동안 release snap을 마무리한다. 정상 `dematerialize`가 잘라내지 않는다.
- `followArrow`에는 반드시 그 소유자가 방금 생성한 실제 `SimProjectile`을 전달한다.
  위치와 `isDone`만 관찰한다. 별도의 화살·충돌·피해·예약 작업을 만들지 않는다.
- **강제 취소/사망/로그아웃/차원 변경:** 기존 `AbilityService.cleanup`의 `SuperVfx.cancelOwned`를 사용한다.
  `dematerialize`는 정상 종료 전용이다. 전역 종료의 기존 `clearAll`도 새 상태를 함께 비운다.
- 기존 `arcSweep`, `solarShot`, `anchor`, `tether`, `cancelLinks` 시그니처는 그대로다.
  Arc/Gun의 발사·타격 accent는 부모가 기존 훅을 실제 접촉 틱으로 옮기면 함께 동기화된다.
  기본 소환/회수 cue는 Arc/Solar에도 같은 `materialize`/`dematerialize` 훅을 사용한다.

## 보이는 내용과 가림 제한

| 단계 | 추가 디테일 | 갱신/종료 |
|---|---|---|
| Void 생성 | 위·아래로 펼쳐지는 끊어진 보랏빛 limb 외곽, 옅은 끝점 | 10틱 생성 후 작은 idle 윤곽 |
| 충전 | 시위 방향으로 모이는 쌍 모트, 뒤로 물러나는 nock 불빛 | 실제 progress, 2틱 간격 |
| release | 중앙이 빈 좌우 충격 조각, 고정 방향의 작은 팽창 | 2틱 간격, 7틱 상한 |
| 비행 | 실제 위치 사이 최대 4개 가는 wake 점 + 옅은 양갈래 2점 | 틱당 최대 6점, 실체 완료/42틱 상한 |
| 닻 | 세 갈래 바닥 rune, 회전하는 끝점·궤도 구슬, 생성/회수 envelope | 3틱 간격, 기존 TTL과 200틱 상한 |
| Arc | 지팡이 양끝 분기·축의 작은 전기 점, 타격 시 전방 외곽 12점 | 작은 idle/생성, 기존 arcSweep 접촉 훅 |
| Solar | 총신 상단/실린더 주변 gold edge 점, 총구의 갈라진 flash | 작은 idle/생성, 기존 solarShot 훅 |
| 정상 회수 | 작은 분리 조각/잔광 | 5틱 상한, 게임플레이 연장 없음 |

장비 cue는 눈에서 전방 .9블록·오른쪽 .48블록·아래 .45블록을 기준으로 한다.
look의 right/up/forward 직교 기저를 사용하고 수직 조준에는 유한 fallback 기저가 있다.
이는 **실제 뼈/socket 부착이 아닌 근사 외곽 프레이밍**이다. 새 효과는 작은 dust 점이며
얼굴을 감싸는 큰 cloud, 면을 채우는 disc, 화면 전체 덮개를 만들지 않는다.
release도 로컬 중앙 통로를 비운다. 실제 카메라/장비와의 가림 여부는 다각도 실화면 확인이 필요하다.
Arc 회수·Solar 반동 자체의 관절 모션은 부모/애니메이션 작업 범위다.

## 자산·아티스트 설정·출처

- H15 BetterModel burst/anchor와 `destiny:fx/{solar_trail,void_link}_h15` 빔 경로를 유지한다.
  H19B 활·drawn 장비와 arrow, 설치된 아티스트 모델·설정·텍스처를 쓰거나 덮어쓰지 않는다.
- 닻 accent는 기존 `HunterVfx.play(VOID_ANCHOR)`가 성공한 경우만 생성한다.
  기존 tracker가 TTL/상한/실패/소유자 정리로 사라지면 다음 accent tick에서 rune도 제거한다.
  원래 닻의 위치는 유지하고 보조 rune만 표면 근처에 놓는다.
- H20에 새 mesh/texture/모델 배포/설정 파일은 없다. `Element`의 기존 색·glow 팔레트와
  자체 작성한 희소 기하 패턴이다. Destiny 원본 mesh 추출이나 정확한 원작 효과 재현이 아니다.
  H20에서 새 외부 참고 이미지를 가져왔다고 주장하지 않는다. 기존 자산의 출처·권리/재구성 한계는
  [H15 VFX 계약](22_궁극기_VFX_구현.md), [장비 문서](20_헌터_궁극기_장비.md)를 따른다.
- 독립 disable/config 항목은 추가하지 않았다. 기존 BetterModel 경로/운영자 설치 정책은 그대로이며,
  새 입자는 일반 바닐라 dust 전송이다. 클라이언트 입자 설정·거리·벽에 따라 보이지 않을 수 있다.

## 예산·정리·관측

- **새 display/holder/BetterModel tracker: 0개.** 기존 실제 beam/모델 예산은 변경하지 않는다.
  기존 `SuperVfx.activeCount`는 계속 Polymer beam 수다.
- 입자 cue 상태는 소유자 최대 4개·전체 24개. 오래된 상태부터 제거하며 같은 소유자의 장비/화살 cue는
  각 1개만 보유한다. 닻은 위치별로 보유한다. 장비 cue watchdog은 420틱이다.
- 추가 입자 요청은 **소유자 24점/서버틱·전체 192점/서버틱** 이하.
  같은 cue를 같은 서버틱에 여러 번 tick해도 한 프레임만 생성한다. 20TPS 최대 3,840점/초다.
  이는 새 H20 전용 상한으로, 기존 `Fx`/`SimProjectile`/능력 코드의 입자 수를 포함하지 않는다.
  네트워크 fanout·전체 생존 입자 수·FPS·GPU 비용의 실측값은 아니다.
- 패턴 단일 프레임: bow 최대 14점(생성+charge 조합의 기하 상한), 일반 charge 10점,
  staff 8점, gun 6점, release 8점, anchor 12점. global/owner budget으로 더 줄어들 수 있다.
- `SimProjectile.tickAll` 뒤 기존 `SuperVfx.tick`에서 비행을 관찰한다. 완료된 화살의 마지막 sub-tick
  충돌 구간을 재시뮬레이션하지 않는다. 최대 8블록을 넘는 점프는 trail을 잇지 않는다.
- 사망/관전/로그아웃/차원 변경, watchdog, 명시적 owner/global cleanup으로 cue를 제거한다.
  렌더 전송 예외는 해당 cue만 버리고 경고하며 gameplay에 예외를 전파하지 않는다.
- 이미 클라이언트에 전송된 dust는 취소 패킷으로 지울 수 없다. 바닐라 입자 자체 수명 후 소멸한다.
  취소 후 새 점 생성·서버 측 참조가 남지 않는다는 계약이지 즉시 화면 입자 0개라는 주장은 아니다.
- QA용 읽기 API: `lifecycleCount(player)`, `lifecycleSnapshots()`(owner/kind/phase/age/expiresAt),
  `lifecycleParticleCount(player)`(현재 서버틱의 요청점 수). 실제 viewer/렌더 성공 증거는 아니다.
