## 구현

`WeaponAiming`의 실제 owner/exactstack/level/session을 따르는 `WeaponAimMovement`가 accepted ADS에서 transient attribute pair를 설치한다. Shift input0.3 중립화와 최종 MOVEMENT_SPEED 배율을 분리해 square-input 정규화 후에도 지상 대각선 배율이 유지되도록 했다. base값/속도벡터/위치/클라이언트 입력을 직접 쓰지 않는다.

`destiny:weapon_ads_sneak_w75`와 `destiny:weapon_ads_movement_w75`는 실제 설치한 object identity로 소유한다. 둘 중 하나라도 선점/교체되면 pair 전체를 양보하되 남의 object는 제거하지 않는다. 안정 상태에서는 같은 object를 재사용해 계속 dirty로 만들지 않는다. 일반 attribute 동기화 경로를 사용하며 전송 지연/같은 프레임 적용은 보장하지 않는다.

조준 해제·reload/skill suspend·무기교체·죽음·관전·차원·궁극기·후방카메라·disconnect에서 즉시/다음 tick 정리한다. `WeaponRuntime.clearAll`에 ADS-only 세션도 포함해 아직 사격하지 않은 플레이어의 속도도 복구한다.

## 경계와 후속

**지상 상대 가속/최종 정상 속도 적응이며 원작 모터 전체가 아니다.** 공중0.02 고정 가속은 배율을 우회하므로 공중ADS 속도는 미구현이다. 기존 관성/질주 impulse를 덮어쓰지 않는다. 탑승/비행/활강/수영/물·용암/사다리/기어가기에는 적용하지 않는다.

MOVEMENT_SPEED의 바닐라 FOV-effect 합성과 외부 sneak 감속의 잔존은 알려진 차이다. 실제 client FOV 설정별 검증과 공중 입력은 남는다. [26.3 소비/동기화 정적 감사](../qa/2026-10-24/w75/native-consumer-audit.json).

새 리소스팩 자산·소리는 없다. 사용자의 새 Vision 사용 요청에 따라 별도 실행 폴더/포트로 실제 월드에 접속하고 대표 이동/수납7시나리오를 검증했다. 과거 SDL 정지의 원인을 규명하거나 모든 환경에서 영구 해결했다고 단정하지는 않는다. headless GameTest/attribute packet과 실제 native logical input·픽셀을 구분하며, OS 키 입력·실청취·FPS percentile은 검증하지 않았다. 전체 무기/HUD 목표 active.
