# 117. 무기별 원음과 장전 연결 — W102

## 적용 범위

무기군 공통음 대신 사용자가 제공한 Drive의 **동일 무기 이름 폴더**에서 `Fire_1.mp3` / `Reload_1.mp3`를 선택했습니다. 폴더 이름·파일 라벨·실제 payload hash는 고정했지만, 공식 원본·독립 청취 식별·배포 라이선스를 확인했다는 의미는 아닙니다.

| 무기 ID | 발사 | 전체 장전 | 기존 장전 tick |
|---|---|---|---|
| `blast_furnace` | 전용 | 전용 | 43 / Outlaw 24 |
| `chattering_bone` | 전용 | 전용 | 34 / Outlaw 24 |
| `aishas_embrace` | 전용 | 전용 | 46 |
| `long_arm` | 전용 | 기존 유지 | 개별 삽입 정책 유지 |
| `whispering_slab` | 전용 | 기존 유지 | 활 정책 유지 |
| `retrofit_escapade` | 전용 | 전용 | 90 |

Long Arm의 `Reload_1`은 전체 동작이라 한 발 삽입마다 재생하지 않습니다. 활의 `Draw`도 장전음으로 이름을 바꾸지 않습니다. Dragonfly/Firefly의 식별되지 않은 음원은 이번 무기 원음으로 대체하지 않습니다.

## 연결 구조

- `DestinySounds.weaponKey`의 기존 정확 ID 우선 정책을 그대로 사용합니다. 10 base event +6 timed event·16 Ogg만 추가하며 과거 event/음원은 모두 유지합니다.
- `NamedReloadAudioW102`는 기존 W63의 정확한 여섯 `(id,ticks)`를 교체합니다. 기존 duration key·event/source/asset 형태가 다르면 거절하며 새 profile의 event·asset·source SHA도 확인합니다.
- 기존 `ReloadAudio`의 개인 emitter·수신 거리·취소 시 emitter 제거와 `WeaponRuntime`의 장전 승인/완료 authority는 바꾸지 않습니다. 장전 기본시간·Outlaw 시간·장탄수·발사 속도·HUD는 불변입니다.
- mono 32 kHz Vorbis·기존 headroom 정책을 적용했습니다. timed clip은 pitch-preserving `atempo`로 기존 tick에 맞추므로 원본 transient가 완전히 동일하다는 주장은 하지 않습니다.
- Pulse `Fire_1`에는 uploader의 한 burst가 들어 있을 수 있습니다. 기존 코드는 승인된 burst trigger에서만 소리를 내고 후속 탄환은 `emit(...,false)`로 처리합니다. 이 정책과 개별 탄환 비용은 유지하며, 실제 원음 burst 길이·영상 동기화는 별도 청취 검토 사항입니다.

## 재현과 검토 파일

`rtk proxy python3 scripts/audio/build_named_sounds_w102.py --verify`는 오프라인에서 두 번 재변환해 모든 output byte와 기존196개 audio/tool/profile 보존을 검사합니다. 원본은 ignored private cache에만 보관하고 hash-pinned source metadata를 별도로 남겼습니다.

[무기별 확인용 WAV와 검증 기록](../qa/2026-10-25/w102/README.md)에서 FIRE →1초 무음→RELOAD 순서로 확인할 수 있습니다. fire-only 무기는 FIRE만 포함합니다. WAV는 review용이며 런타임 참조가 아닙니다.
