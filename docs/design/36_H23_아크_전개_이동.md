# H23 — 아크 지팡이 단발 전개 후 이동

## H23-S1 요청과 범위

사용자 첨부 Arcstrider 이미지를 전개 실루엣 기준으로 삼는다. 넓게 벌린 굽힌 무릎,
머리 옆 오른손에 가로 지팡이, 전방으로 내민 자유 왼손. 이 자세를 궁극기 내내
반복하지 않고 단발 전개→짧은 유지→기존 준비 자세→이동/공격으로 나눈다.
H22 공허의 당겨진 시위·웅크림·도약과 솔라는 보존한다. 원작 메시/모션 추출 아님.

## H23-S2 구현

- 새 H23_r2 모델/리소스, CREATE_NEW 설치. 기존 H15~H22 파일 덮어쓰기 없음.
- `h15_super_arc_start`: .00 중립, .10 준비, .20~.45 첨부 실루엣 유지,
  .60 회수, .75~.85 기존 준비 자세. 1 transition 포함18서버틱(.9초).
  이 시간은 마인크래프트용 설계값이며 원작 프레임 측정값을 주장하지 않는다.
- `h15_super_arc_move`: 실제 수평 이동이 있을 때만 별도 .6초 보행주기.
  시작/공격 one-shot 우선, 멈추거나 공중이면 준비 자세. 지팡이/기존 공격 접점 유지.
- SuperCamera 세션 소유 deadline까지 방향키·점프·스프린트 가속 입력만 억제.
  회전/시야는 유지. 속도 강제0, 위치고정, teleport, 비행/noGravity 사용 안 함.
  기존 관성/외부충격·중력/충돌은 계속 적용. 해제 후 현재 입력 즉시 복귀.
  이동 잠금 중 별도 AIR_JUMP 능력도 BUSY. 조기 PRIMARY는 기존1회 큐로 처리.
- 취소/죽음/차원변경/접속종료는 기존 카메라 세션 제거와 함께 입력 gate 제거.

## 검증

진행 중. 최종 자동 테스트·실제 Vision 입력/픽셀 결과는 후속 단계에 기록한다.

## H23-S3 — 원작 참고 / 첫 인수에서 발견한 문제

  실제 브라우저 재생/일시정지 화면 관찰: 후방 카메라, 준비/공격/이동의 분리와 지팡이 휴대 자세.
  영상 설명의 basic .09 / light combo .43 / infinite dodge2:21 구간도 확인했다.
  정확한 발동 시간이나 모션 프레임을 추출한 것은 아니다. 발동 실루엣은 사용자 첨부가 우선.
- [Bungie 포럼 영상 링크](https://www.bungie.net/en/Forums/Post/228087513)는 탐색 보조 자료.
  오래된 GIF 링크는404, PC Gamer의 Gfycat 임베드는 현재 참고 영상으로 사용하지 않았다.
- 첫 자동 gate에서 기존 H20 테스트가 발동 즉시 AIR_JUMP 가능을 가정하여1개 실패.
  H23 의도에 맞춰 전개중 BUSY/전개경계 OK와 사용횟수를 둘 다 검사하도록 갱신했다.
- 최초 H23 실제 픽셀에서 무릎이 벌어지지 않고 교차하는 결함을 발견.
  두 허벅지 Z방향을 수정하고 발목 FK의 좌우 위치를 검증에 추가했다.
  최초 설치본을 덮어쓰지 않고 새 `guardian_hunter_h23_r2`로 설치한다.
- 첫5TPS 스크립트는175client ticks로30초 runner 제한을 초과했다.
  neutral 정리는 성공했으나 완료로 세지 않는다.48tick의 짧은 시나리오로 수정.
