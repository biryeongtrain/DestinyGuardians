# H20 일반 스킬 — 모션·접촉·판정 동기화

## S1. 범위와 확인한 기존 동작 (2026-10-22)

이 문서는 H20 목표 5의 수류탄·근접·회피 부분만 다룬다. 궁극기/카메라/BetterModel clock 구현은 부모 작업 소유다.

- 기존 `Tasks`는 첫 호출에 age=0을 전달하며, 입력이 발생한 **같은** END_SERVER_TICK에도 실행될 수 있다. 따라서 `age == 4`를 입력 후 4틱으로 간주하지 않는다.
- 기존 순서는 `SimProjectile.tickAll → Tasks.tickAll → PlayerAnimations.tick`이다.
- H15 네 방향 구르기는 .70초 clip이며 방향마다 root 회전축/부호가 다르다. 기존 resolver와 입력 상대 물리는 유지한다. H15 key만 읽었으며 새로운 지면 접촉의 실제 화면 일치는 아직 증명하지 않았다.
- 기존 Solar 칼/공허 연막의 충돌 콜백은 충돌 시점 `player.level()`을 다시 가져왔다. 이제 발사 cast가 캡처한 level을 사용하고 콜백 전에 생명주기를 검사한다.

## S2. 서버 tick 계약

T는 `activate`가 승인된 `server.getTickCount()`이다. wall clock, Tasks 호출 횟수, BetterModel bone 완료 콜백으로 판정을 진행하지 않는다.

| 스킬 | T | T+2 | T+4 |
|---|---|---|---|
| 세 속성 수류탄 | 준비 모션/시각적 수류탄 | 준비 | 실제 projectile 생성 + 투척음 + 손 장비 복원 |
| Arc 근접 | 준비 모션 | 기존 크기의 수평 돌진/lift 적용 | 피해·처치 보상·타격 VFX·타격음 동시 실행 |
| Solar 칼 | 준비 모션/시각적 칼 | 준비 | 실제 칼 생성 + 투척음 + 손 장비 복원 |
| Void 연막 | 준비 모션/시각적 연막탄 | 준비 | 실제 연막탄 생성 + 손 장비 복원; 충돌에서 연막/음향 시작 |
| 방향 회피 | **즉시** 기존 velocity, fall reset, 무적 6틱, 도박꾼 재충전 | 현재 발 위치의 지면 cue dust/음향 | 진행 중인 구르기 회복 |

던지는 위치와 조준은 T+4에 샘플링한다. 준비 중 조준을 바꿀 수 있으며 aim을 강제로 회전하지 않는다. 투사체는 T+4에 표시되고, 현 중앙 tick 순서상 첫 물리 전진은 다음 T+5이다. 충돌 VFX/피해는 실제 충돌 콜백에서만 발생한다.

기존 damage/radius/speed/gravity/lifetime/status 수치 및 지속장판 pulse 주기는 변경하지 않는다. Arc 돌진 시점만 T에서 T+2로 옮겼다. 승인 시 쿨다운을 소비하며 중도 취소는 환불하지 않는다.

## S3. 모션 에이전트와의 계약

`HunterAbilityVisuals`는 logical 이름을 요청한다. `PlayerAnimations`가 versioned H20 limb의 기존 `h15_` 이름 공간으로 해석한다. `h20_` prefix clip을 요구하지 않는다.

| 요청 | 실제 clip | 접촉 |
|---|---|---|
| `grenade` | `h15_grenade` | local .15초 + start transition 1틱 = 총 T+4 |
| `melee` | `h15_melee` | local .15초 + start transition 1틱 = 총 T+4 |
| `melee_solar` | `h15_melee_solar` | 위와 동일; 없는 경우 `grenade` fallback |
| `melee_void` | `h15_melee_void` | 위와 동일; 없는 경우 `grenade` fallback |
| 기존 `rollAnimation(input)` | 네 방향 `h15_roll_*` | 지면 cue T+2; 물리는 T |

초기 H20 source를 확인했을 때 일반 clip은 `h15_grenade` / `h15_melee` 두 개뿐이었다. Solar/Void 전용 clip 추가를 부모를 통해 Hilbert에 요청했다. 전용 clip이 없으면 두 투척의 모션은 같지만 장비/비행체/충돌 효과는 각각 다르다. clip 또는 BetterModel이 없어도 gameplay contact timer는 동작한다. 실제 20/5TPS의 local key 대 서버 접촉 일치는 부모 runtime QA 대상이다.

## S4. 취소·장비 안전성 / 부모 통합 API

```java
// 서버 스레드 전용. startSuper가 다른 모션을 시작하기 전, 그리고 cleanup에서 호출한다.
HunterSkillCast.cancelPending(player);
```

- 새 일반 cast는 owner별 새 opaque visual token으로 이전 일반 cast의 **미발사 windup**만 무효화한다. 이전 lunge/contact는 다음 Tasks 검사에서 제거된다.
- `cancelPending`은 token만 무효화한다. `Tasks.cancelOwned`/projectile 전체 삭제를 호출하지 않으므로 기존 수류탄, 연막, 다른 작업을 지우지 않는다. cleanup 자체의 기존 broad cleanup 정책은 유지한다.
- 캡처한 player 생존/제거/연결/관전자 상태, level **identity**, GuardianRuntime **identity**, 직업, 해당 슬롯의 장착 ID를 검사한다. 공식 death/logout/class/dimension cleanup과, 그 경로를 우회한 일부 직접 상태 변경에도 미발사 판정이 발생하지 않는다.
- 발사 이후 충돌/연막·소용돌이 pulse는 생명주기만 검사한다. 새 일반 cast의 visual token 교체나 super 진입만으로 기존 비행체/장판의 피해를 중단하지 않는다. 슬롯 교체/직업 변경/runtime 교체는 중단한다.
- 손 장비는 `PlayerAnimations.superItem`의 시각 override뿐이다. 실제 인벤토리/GameProfile/aim은 수정하지 않는다. 접촉 시 현재 소유 token일 때만 EMPTY override로 **현재 실제 장비 mapping**을 복원한다. 저장한 옛 ItemStack을 인벤토리에 다시 쓰지 않는다.
- BetterModel 비동기 완료 콜백을 gameplay/장비 쓰기에 사용하지 않는다. one-shot 회복과 vanilla 복귀는 기존 `PlayerAnimations.tick` 소유다.
- token 저장소는 weak player key + player를 참조하지 않는 값이다. 별도 전역 반복 task나 cleanup 누락 시 player를 유지하는 강한 registry는 없다.

**부모 필요 조건:** super 중 일반 스킬은 BUSY(JUMP 제외), `startSuper`/`cleanup`에서 위 hook을 호출한다. 다른 시스템이 직접 ordinary 모션을 중단할 경우에도 hook을 먼저 호출해야 한다. 임의의 외부 `PlayerAnimations.stop` 호출 자체를 이 helper가 감지하지는 않는다. class/장비를 직접 바꾸고 공식 cleanup을 생략하면 gameplay는 취소되지만 기존 limb의 즉시 시각 정리까지 보장하지 않는다.

## S5. 추가 검사 코드와 실제 검증 상태

- `HunterSkillTimingTest`: 8개 순수 JUnit. 같은 tick 중복 호출, 정확한 T+4/한 번 실행, 접촉/준비 중 무효화, 명시 취소, 관측 tick 건너뜀, signed tick wrap, 돌진/회피 T+2, 음수 delay.
- 새 GameTest entrypoint: **`kim.biryeong.destiny.test.HunterOrdinaryTimingGameTests`**. 등록은 부모가 `src/gametest/resources/fabric.mod.json`에서 수행한다.
- 12개 GameTest: 세 투척 최초 생성 T+4, Arc 최초 피해 T+4, cleanup/직업/runtime/죽음/차원 취소, 새 일반 cast의 이전 windup 취소, 기존 비행체·무관 작업 보존, 회피 즉시 방향 물리/무적6/aim 보존 및 task 종료.
- 최초 생성/피해 시점은 실제 END_SERVER_TICK에서 contact task 다음 observer가 기록하고, GameTest assertion은 나중에 수행한다. 전역 Tasks 수동 tick이나 sleep은 없다.
- 연결 종료는 `hasDisconnected` 및 공식 cleanup으로 방어하지만 새 테스트에 실제 소켓 logout 재현은 없다. 장비가 회복 중 바뀌는 화면, 20/5TPS contact 프레임, observer/actor 다각도 및 최종 vanilla 복귀는 runtime QA로 남는다.

**이 하위 작업에서 실행한 것:** 소스/clip 읽기, 소유 diff 정적 리뷰, `git diff --check`(오류 없음). **실행하지 않은 것:** Gradle, JUnit, GameTest, 서버/클라이언트, live capture. 다른 작업자의 과거 green 결과를 이 추가 테스트의 통과로 표기하지 않는다. commit하지 않는다.
