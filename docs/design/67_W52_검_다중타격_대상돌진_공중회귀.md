# W52 — 검 약공격 다중 타격·대상 돌진·공중 회귀

## 범위

W51의 검 5프레임·단일 탄약·에너지·가드·HUD 위에 약공격의 다중 타격과 짧은 대상 유도 이동을 추가한다.
황금총의 W39 1인칭 조준, 장탄·예비탄·재장전 HUD, 일반 무기의 발사/재장전/활 프레젠테이션은 유지한다.
기존 모델·안료·UV·원본 542 에셋·음원 매핑은 수정하지 않는다.

## 확인된 원작 근거와 구현 선택

- Bungie 2020 업데이트: 모든 검 하위 유형의 약공격 cleave와 반복 콤보. 사전 안내는 반복을 **지상**으로 명시한다.
- Bungie 2019: 공격적 프레임의 공중 약공격 대상 돌진, 경량 프레임의 지상/공중 공격 존재.
- Bungie 2023-10-17: 공격적 프레임 공중 강공격의 잘못된 full-energy 요구 및 회복 지연 누락 수정.
- W51의 이후 규칙 유지: 양의 에너지는 강공격 full power, 소용돌이 강공격 4탄.

근거: [조사 보고서](../qa/2026-10-24/w52/reference-report.md), [공식 인용/캐시](../../art/weapons/w52/references/sources.json),
[영상 출처](../../art/weapons/w52/references/videos.json).
9개 공식 기사와 15개 실제 기사 인용을 확인했다. 영상은 총 30초의 제한된 발췌에서 16개 정지 프레임을 검토했다.
공중 시트의 124.8초 Warframe 장면은 Destiny 근거에서 제외한다.
영상은 자세/화면상 이동 참고이며 입력, 정확한 아이템 hash, 현재 빌드, 피해 범위나 세계 좌표 측정이 아니다.

**아래 거리·각도·대상 수·이동 방법은 모두 Minecraft용 authored 튜닝이며 원작 실측값이 아니다.**
Eager Edge/Valiant Charge 같은 별도 특전의 범위를 기본 검에 적용하지 않는다.

## 약공격 거래 순서

1. 기존 소유 아이템·생존·게임 모드·가드·공통 공격 주기 검사.
2. 정상 검은 탄약 1개를 한 번만 소모. 빈 검은 기존 약한 약공격만 허용하며 탄약을 만들지 않는다.
3. 이동 전 유효한 cleave 대상 목록 수집.
4. 탄약이 있었던 정상 약공격에만 현재 보이는 전방 적을 향해 제한된 수평 이동.
5. 이동 후 cleave 대상을 추가하고 entity identity로 중복 제거.
6. 전체 합집합에서 최대 16명에게 각각 한 번의 실제 HP 피해. 대상마다 추가 탄약을 소모하지 않는다.

시작/종료 자세를 합치는 **근사 sweep**이다. 연속 애니메이션의 칼날 충돌이나 모든 중간 자세를 시뮬레이션하지 않는다.
가까운 측면 적을 지나쳤더라도 시작 자세의 유효 접촉을 유지한다. 합집합 cap은 두 자세에 각각 16명이 아니라 **총 16명**이다.
시작 자세 접촉이 우선이며 각 자세의 후보는 몸 중심 거리, UUID 순으로 정렬된다.

## 공간 정책

| 항목 | authored 값/정책 |
|---|---|
| 전방 | 플레이어 yaw, pitch와 분리 |
| 플레이어 기준점 | 발 위치 + Y 0.9 |
| 적 기준점 | 몸통 높이의 중간 |
| cleave | 수평 3.5블록, 좌우 각 65도, 기준점 높이 차 ±1.5 |
| 돌진 대상 획득 | 수평 5.3블록, 좌우 각 35도, 높이 차 ±1.25 |
| 이동 | 최대 1.8블록, 대상까지 1.1블록은 남기고 정지 |
| 이동 안전 검사 | 0.1블록 간격의 전체 플레이어 AABB, loaded chunk, world border, noCollision |
| 상한 | 자세당 정밀 후보 64명, 전체 실제 타격 16명 |

적 없는 헛치기, 후방·좁은 획득 원뿔 밖의 적, 너무 높은/먼 적, 아군·길들인 동물·플레이어는 돌진을 유발하지 않는다.
넓은 cleave 원뿔의 측면 적은 돌진 대상이 아니어도 피해를 받을 수 있다.
눈→적 몸통 collider LOS가 막히면 타격/획득을 거부한다. 끝점 벽 동률도 벽 우선이다.
ray 경로의 loaded chunk를 먼저 검사하고 이동 AABB의 네 모서리와 border를 검사한다. 유체는 LOS 장애물로 취급하지 않는다.
step-up, 엔티티 밀기, 수직 이동, 저장된 target lock, 카메라 강제 전환은 추가하지 않는다.

## 공중 이동과 실제 발견한 결함

첫 공중 회귀 테스트는 기존 속도 (0.2, -0.35, 0.1)가 위치 보정 뒤 (0, 0, 0)이 되는 문제를 발견했다.
26.3의 ServerPlayer.teleportTo는 상대 delta=0/상대 회전을 보내지만,
서버의 PositionMoveRotation 기준은 getDeltaMovement가 아닌 **getKnownMovement/lastKnownClientMovement**다.
새 move helper는 호출 전 서버 delta를 보관하고 보정 직후 복원한다.
클라이언트 패킷은 기존 상대 delta=0을 유지하므로 클라이언트의 실제 낙하/점프 속도를 절대 서버 추정치로 덮어쓰지 않는다.

테스트는 실제 서버 위치·Y·시야·공중 플래그·속도를 검사하고, EmbeddedChannel에 실제 큐된 위치 패킷도 검사한다.
이는 **서버 패킷 생성 증거**이며 실제 클라이언트 수신/소비/렌더 증거는 아니다.
[바이트코드 발췌](../qa/2026-10-24/w52/native-teleport-bytecode.txt)와 실패 gate/diagnostic 로그를 보존한다.

## ground/air 경계

공격적 프레임의 공중 약공격 돌진과 양의 에너지 공중 강공격·회복 지연을 회귀 검증한다.
현재 5프레임 공중 약공격은 같은 authored 수평 기하를 사용한다.
지상/공중의 정확한 콤보 제한·초기화, 프레임별 공중 강공격 형태·에너지 예외는 미확인이다.
특히 caster/vortex가 지상 전용이라는 근거를 찾지 못했으므로 **임의의 공중 금지 규칙은 넣지 않는다**.
기존 일반화된 공중 강공격 형태를 원작과 완전히 같다고 인증하지 않는다.
