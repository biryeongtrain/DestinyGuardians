# W195 — 검 공격·사격 퍽 집중 배치

애니메이션은 Windows 파일 전달 전까지 보류한다. W194 완료 뒤 W195의 6개 퍽을 3 worktree로 분리한다. master가 공유 경로·이동 modifier·중앙 QA를 소유한다.

| Worktree | 기능 | 수락 조건 |
|---|---|---|
| sword-offense | Whirlwind Blade / En Garde | 실제 유료 검 명중 누적, block/stow 해제, 실제 준비 완료 후 시간 창 |
| precision-openers | Opening Shot / Box Breathing | 실제 유료 첫 탄의 거리·정확도 스냅샷, 실제 ADS 충전 후 다음 정밀탄 |
| sway-assassin | Dynamic Sway Reduction / Assassin’s Blade | 실제 유료 연사 누적·해제, 실제 검 처치 피해·이동 버프와 stow 유지 |

## 단계 1 — 격리

67,360파일의 dirty/untracked 기준선 SHA256 `a6234de1c0200c28a53fa230e702c0f2f485281753b4ec664a88035d055b5d0f`로 3 worktree와 의존성을 독립 복제했다. 원본의 commit/stash/reset/clean/push는 수행하지 않는다. 각 worker에 16개 배타 경로를 할당했다. W194 봉인 QA는 보존한다.

## 단계 2 — 전투 연결

48개 worker 소유 파일을 기준 해시 대조 후 통합했다. 등록 퍽은 60종에서 66종으로 늘었다. 기본 특성의 정확한 무기·소켓·plug-set 튜플만 허용하며 강화 특성이나 임의 기본 선택은 추가하지 않았다.

| 퍽 | 적용 동작 | DDC Weapon Perks 행 / 합법 튜플 |
|---|---|---|
| Whirlwind Blade | 실제 유료 검 명중마다 다음 공격 피해 누적, 방어·수납 시 해제 | 248 / 5 |
| En Garde | 실제 무기 준비 완료 후 짧은 검 피해 강화 창 | 82 / 3 (원본 중복 4개) |
| Opening Shot | 유료 첫 탄 사거리·정확도·정확도 확산 증가량 조정, 연속 사격 시 재준비 지연 | 157 / 14 |
| Box Breathing | 실제 ADS 30틱 유지 후 다음 정밀탄 강화, 발사·조준 해제로 충전 해제 | 35 / 2 |
| Dynamic Sway Reduction | 실제 유료 연사 누적에 따른 안정성·확산 조정, 입력 해제·수납·재장전 시 초기화 | 77 / 2 |
| Assassin’s Blade | 실제 검 처치 후 피해·보행 강화, 추가 처치 갱신, 수납 중 유지 | 21 / 3 |

`WeaponShotTraits`는 실제 탄약 지불 후 한 번 생성하며 trace·정밀 피해·반동이 같은 발사 스냅샷을 사용한다. Opening Shot 사거리는 다른 원시 Range 보너스와 합친 뒤 한 번만 clamp한다. Box Breathing은 지불 직전 장탄수를 사용하므로 마지막 1발에도 준비 효과가 적용되며 추가 burst·퍽 폭발에는 전달하지 않는다.

검 피해 특성은 실제 비용 지불 직후 확보하여 windup 이후 자신의 타격·cleave·caster에 전달한다. Whirlwind Blade는 실제 양수 피해에만 누적한다. Assassin’s Blade는 실제 최종타에만 발동하며 수납 이후에도 이미 지불한 자신의 caster 발사 스냅샷은 유지한다. 다른 무기의 후속 공격에 피해 보너스를 전달하지 않는다.

`WeaponPerkMovement`는 Assassin’s Blade의 수납 중 버프도 관찰한다. 자기 modifier 객체만 제거하고 같은 ID를 외부 소유자가 교체하면 물러난다. 달리기·탑승·비행·수중·사다리·기어가기에는 보행 보너스를 적용하지 않는다.

### 출처와 포트 한계

- 사용자 지정 [DDC](https://docs.google.com/spreadsheets/d/1WaxvbLx7UoSZaBqdFr1u32F2uWVLo-CJunJB4nlGUE4), 공식 manifest `245114.26.10.13.2000-1-bnet.66137`, 65개 정규 무기의 실제 무작위 소켓 풀을 대조했다. 각 `art/weapons/w195/*/source.json`에 원문·입력 해시·튜플 근거를 보존했다.
- En Garde의 재사용 대기시간은 출처에도 `2?초`다. 현재 40틱은 임시 포트 정책이며 확정 수치로 취급하지 않는다.
- Opening Shot 및 Box Breathing의 Aim Assist 관련 값은 출처 메타데이터다. 서버 조준 보정·자력은 구현하지 않았다.
- Dynamic Sway Reduction의 중간 단계 cone 수치는 출처에 `?`로 남아 있다. 중간 단계는 기존 cone을 유지하고 확인된 최대 누적에서만 0을 적용한다. 정확한 전체 곡선 구현을 주장하지 않는다.
- Assassin’s Blade의 원작 이동 알고리즘은 확인되지 않았다. Minecraft 보행·좌우 이동 x1.4는 로컬 환산이며 원작의 정확한 이동 비율이 아니다.
- 새 HUD 버프 아이콘·라벨이나 모델·애니메이션은 이 배치에 추가하지 않았다.

## 단계 3 — 범위 검증

순수 상태·이벤트 회귀 30개와 컴파일을 통과했다. 서버 targeted 1차는 5/6 통과했다. Opening Shot의 원거리 표적이 작은 기본 구조 밖에 있어 명중하지 않았으며, 해당 시나리오를 기존 48블록 사격장 안으로 옮기고 실제 시야 충돌 preflight를 추가했다. 제품 trace를 완화하거나 강제 청크 로드를 추가하지 않았다. 수정 후 targeted 2차는 6/6 통과했다.

검증한 동작은 첫 탄 실제 사거리, 마지막 장탄의 준비된 정밀탄 소비, 실제 검 명중과 방어 해제, 준비 창 만료, 유료 연사와 실제 입력 해제, 검 처치·수납 중 보행·달리기 제외·외부 modifier 보존이다. 단순 수치 미러 테스트는 추가하지 않았다.

## 검증

중앙 전체 gate 1회를 마쳤다. 전체 JUnit **1,955/1,955**, 새 상태 회귀 **30/30**, targeted 서버 **6/6** 통과. 전체 서버는 **1,294개 중 1,270 통과·24 실패**다. W195 새 시나리오는 모두 통과했고, 실패 ID는 W193/W194에서 확인된 범위다. W194 대비 이자나기 카메라 항목은 통과하고 Threat Detector ADS 항목이 다시 실패했다. 후자를 분리 실행해도 `progress=0.5 expected=0.75 exit=4 stacks=2 pugilist=0 on tick 21`로 실패하며 W193 기록과 메시지가 같다. 해당 기존 결함은 미해결이며 전체 build는 실패 상태로 기록한다. 이유 없이 전체 gate를 반복하지 않았다.

`assemble`은 통과했다. JAR 49,040,680bytes, SHA256 `8ec9fb0d4836ab85264209c86c9efebde7a504f076778d1a896a81c4988bc39b`. 6개 출처 generator의 `--verify`를 통과했고 W194 봉인 QA 306파일의 불변성을 다시 확인했다. 3개 worker는 종료했으며 worktree는 보존했다.

[W195 QA](../qa/2026-10-27/w195/)에 시도별 원본 로그·출처 검토·최종 소스 해시와 통합 후 master 수정 내역을 보존한다. Vision/native 입력·렌더링·청취는 수행하지 않았으며 headless 결과로 대체 주장하지 않는다. 전체 무기 목표는 계속 active이며 애니메이션 handoff는 보존한다.
