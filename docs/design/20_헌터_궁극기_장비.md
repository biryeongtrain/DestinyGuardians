# H15 헌터 궁극기 장비

## 최종 통합 결과

전체 GameTest71/71·JUnit28/28에 이 문서의 장비 테스트7개가 포함된다.
JVM2 실제 클라이언트에서 지팡이·황금 총·활의 장비/공격/복원을 확인했다.
화살은 전용 item ID로 투사체에 연결했고 크기·축 계약은 자동 검사했다.
정상 속도 캡처만으로 화살의 근접 비행 방향까지 확인했다고 주장하지 않는다.
[실제 화면/움직임 안내](../qa/2026-10-22/README.md) · [검증 조건](../qa/2026-10-22/super-h15-validation.json).
아래의 에셋 담당자 범위와 미실행 표기는 제작 당시의 기록이다.
HTTP 응답과 해시는 출처·파일 동일성의 근거이며 이용 허락의 증거는 아니다.
참조 이미지의 재배포 라이선스는 별도로 확인하지 않았다.

2026-10-22. 공유 체크아웃에서 Blockbench 5.1.4 + MCP 1.10.1로 제작한 Java 아이템 모델이다. 네 모델 모두 새 탭에서 제작했고, 생성 응답의 프로젝트 UUID로 탭을 다시 선택한 뒤 제작과 내보내기를 하나의 짧은 동기 호출 안에서 수행했다. 다른 에이전트의 탭을 지우거나 모델을 수정하지 않았다.

큐브당 6면·12삼각형 기준의 상한이다. 겹친 내부 면을 제거한 최적화 메시의 수치가 아니다. 텍스처는 각각 `textures/item/supers/<name>.png`, 256×128 RGBA다. Bow와 arrow는 같은 공허 팔레트를 사용한다. 아틀라스는 불투명하며 밝은 인레이 면에 `light_emission`과 `shade:false`를 사용한다. 블룸·연기·잔상·궁극기 활성화 연출은 별도 런타임 VFX가 담당한다.

원래 세 아이템 정의와 `models/item/` 경로를 유지했다. 루트 `models/arc_staff.json` 등의 우회 모델은 만들지 않았다. 새 화살만 `items/shadow_arrow.json`과 `models/item/shadow_arrow.json`을 추가했다. 기존 GUI 회전·크기와 3인칭 오른손의 `[0,2,0]` 이동을 보존했다. 코덱은 기본 회전 `[0,0,0]`과 크기 `[1,1,1]`을 생략하므로 텍스트 비교 대신 기본값을 복원해 검사한다.

## 형상

- **Arc Staff:** 긴 분절 축, 팔각에 가까운 단면, 금속 페룰과 잠금 스터드, 감긴 중앙 그립, 네 방향 청색 인레이, 양끝의 열린 이중 포크와 흰 전기 연결선. 극단적으로 적은 큐브로 만든 기존 막대 대신 장비로 식별되는 구조를 사용했다.
- **Golden Gun:** Last Word의 긴 상부 배럴, 측면 통풍구, 하부 총열 덮개, 프레임 밖으로 돌출된 20단 원형 실린더, 세로로 휜 그립, 열린 곡선 방아쇠 울, 해머·가늠자·가늠쇠, 실제로 열린 총구, 태양빛 테두리와 측면 장식. Last Word의 검정·목재 재질을 그대로 복사하지 않고 Golden Gun의 주황·금색 발광 상태로 재해석했다. 측면 문양은 새로 만든 기하 장식이며 TEX MECHANICA 문자·원본 장식을 그대로 전사한 것이 아니다.
- **Shadowshot bow:** 그립에서 바깥으로 휘어지는 양쪽 림, 앞뒤 보라색 인레이, 깊이가 갈라진 끝 포크, 정적 현과 화살 받침. 스크린샷의 불규칙한 스펙트럴 외곽선을 Minecraft용 연속 큐브 곡선으로 해석했다.
- **Shadowshot arrow:** 가는 에너지 축, 십자 단면의 다이아몬드 촉, 네 방향 공허 깃과 분할 노크. 레퍼런스에서 독립 화살의 정밀한 제작 도면을 얻은 것은 아니며, 활의 공허 시각 언어에 맞춘 독자적인 소형 발사체다.

### 화살 런타임 계약

`destiny:shadow_arrow` 아이템 / `destiny:item/shadow_arrow` 모델. **전방은 로컬 -Z**이며 별도 회전을 메시 안에 굽지 않았다. 중심은 `[8,8,8]`, 경계는 `[6.81,6.81,1]`부터 `[9.19,9.19,15]`다. X×Y×Z 치수는 **2.38×2.38×14 모델 단위**, 즉 **0.14875×0.14875×0.875 블록**이다. 앞촉은 `z=1`, 뒤 노크는 `z=15`다. 이 치수는 기본 크기 1의 모델 기준이며 item_display/Polymer에서 추가하는 배율과 회전은 부모 런타임 통합의 책임이다. 정적 아이템 모델만 추가했으며 SimProjectile·BM·빔 Java 코드는 수정하지 않았다.

**원본 게임 메시나 게임 텍스처를 추출한 결과가 아니다.** 큐브 형상과 재질 아틀라스는 이번 작업에서 새로 제작했다. Destiny 디자인과 참조 스크린샷의 권리는 Bungie 및 각 권리자에게 있으며, 다운받은 참조 이미지는 편집 검토용 `art/`에만 두고 런타임 리소스에는 넣지 않았다. ArtStation·Sketchfab 메시를 확보했다거나 검증했다는 주장은 하지 않는다. Staff 포크의 정밀 구조, 총의 미세 장식, 활의 스펙트럴 단면과 화살은 스크린샷을 바탕으로 한 재구성이며 원작의 정확한 토폴로지·치수를 보증하지 않는다.

## 편집 원본과 재생성

- `art/blockbench/supers/{arc_staff,golden_gun,shadow_bow,shadow_arrow}.bbmodel`: 그룹 구조와 임베디드 PNG가 있는 편집 원본.
- `art/blockbench/supers/manifest.json`: 모델별 UUID, 예산, 텍스처 해시, 경계, 변환과 스크린샷 경로.
- `scripts/build_hunter_supers.js`: MCP에서 실행하는 Blockbench 네이티브 Cube·Texture·Group 제작 코드. 자체 Undo 트랜잭션을 열고 닫는다.
- `scripts/export_hunter_supers.py`: 새 Java Block/Item 탭을 만들고 UUID를 선택하여 네이티브 `Codecs.java_block`과 `Codecs.project`로 내보낸다. 파일 저장은 외부 Python이 수행하며 eval에서 OS·파일시스템 API를 사용하지 않는다.

재생성 명령은 `rtk proxy python3 -B scripts/export_hunter_supers.py`다. 일부만 만들 때는 `--models shadow_arrow`처럼 지정한다. 이 명령은 실제 런타임 에셋을 덮어쓰므로 부모의 라이브 검증 중에는 실행하지 않는다. 기존 세 아이템 정의가 이미 올바르면 다시 쓰지 않는다. Blockbench 네이티브 프리뷰 폐기에서 알려진 오류가 발생할 수 있으나, 성공한 내보내기 파일은 보존된다.

## 검증 및 한계

`HunterSuperPropAssetTest`의 **7개 테스트를 javac + JUnit Platform Launcher로 직접 실행해 모두 통과**했다. Gradle은 실행하지 않았다. 검증 항목은 아이템 경로, 유한·비영 큐브와 허용 범위·회전·UV, 상세도 예산, PNG 크기와 알파·색상, 원본과 내보내기의 큐브 수·임베디드 텍스처 일치, 기존 GUI·3인칭 변환, 총구·방아쇠 울의 빈 공간, 실린더의 원형 단면, Staff/Bow의 실제 포크·곡선 기하, 화살 중심·크기·-Z 방향, 다운로드 참조 파일의 해시다.

[`supers_h15_overview.png`](../qa/2026-10-22/supers_h15_overview.png)는 네 모델의 비교 이미지다. 각 장비의 `supers_h15_<name>_hero.png`와 `_profile.png`도 같은 QA 폴더에 있다. 원본 프레임은 프로젝트 UUID를 지정한 Blockbench의 독립 뷰로 캡처했고, 비교 이미지는 그 프레임을 배치했다.

에셋 담당자의 검증은 **Blockbench 외형 및 파일 계약까지**다. 실제 Minecraft GUI 프레이밍·손 그립 정렬, 클라이언트 조명·블룸, SimProjectile의 이동 방향·회전·충돌, 궁극기 수명주기, BM/Polymer의 동적 배율은 이 작업에서 플레이 검증하지 않았다. 기존 display 변환을 유지한 것이 실제 손 정렬이나 GUI에서 잘리지 않음을 보증하지는 않는다. 불꽃·아크 잔상·공허 안개 및 활의 당김 애니메이션은 이 정적 모델에 포함되지 않는다. 부모 통합 테스트 결과와 라이브 서버·클라이언트 검증은 별도 보고한다.

부모의 라이브 검증 시작 요청 이후 런타임 모델·아이템·텍스처를 고정했다. 추가 Gradle 실행, 런타임 Java 수정, 커밋은 하지 않았다.
