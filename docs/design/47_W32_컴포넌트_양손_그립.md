# W32 — 서버사이드 컴포넌트 양손 그립

## S1 조사 / 범위

요청: 기존 무기 모델을 양손으로 잡는다. MC 26.3 로컬 client bytecode에서
`AvatarRenderer.getArmPose`는 **CROSSBOW 아이템 + 비어 있지 않은 CHARGED_PROJECTILES**일 때
idle `CROSSBOW_HOLD`를 사용한다. STICK에 컴포넌트만 붙여서는 작동하지 않는다.
`consumable.animation`은 사용 중 자세이며 안정적인 idle 그립 대체가 아니다.

안전 설계: 실제 서버 아이템은 CrossbowItem이 아닌 **Polymer Item**으로 등록한다.
클라이언트 복제본에만 CROSSBOW와 장전 컴포넌트를 부여한다. 서버에는 탄약·발사·사용 지속 상태가 없다.
실제 석궁/일반 아이템에 전역 mixin이나 overlay를 걸지 않는다.

기본 양손: 장총류 46종. 핸드캐논·보조무기는 기존 자세 기본, 명령으로 양손 선택 가능.
활·검·글레이브는 석궁 자세를 억지로 적용하지 않는다. 실제 오프핸드·카메라·궁극기 모델은 유지.
1인칭은 기존 hip/ads/inspect 정적 구도를 보정한다. **1인칭 실제 양팔은 이 컴포넌트로 생성되지 않는다.**

## 작업 단계

- S1: 정확한 26.3 렌더러·Polymer API 확인 완료.
- S2: 비발사 Polymer 아이템, 그립 명령, 전용 변환·회귀 검사 구현 완료.
- S3: 최종 179/179 GameTest, 149/149 JUnit, 강제 전체 build20tasks·생성507파일 verify 완료.
  Vision static246PNG·native use/move/attack3시나리오와 source/JAR/pack/cache 일치 확인.

W30/W31 geometry/texture/기존 display와 증거는 보존하고, W32 그립 display는 별도 parent 모델에 둔다.
장전 자세는 바닐라 우선순위(휘두름/다른 손 사용 등)의 영향을 받으며 개별 총별 IK는 아니다.

## 구현과 사용

- `WeaponPreviewItem` 등록은 mod init 시점. 실제 타입은 일반 Item이며 `use`는 비소모 CONSUME로 끝난다.
- `WeaponModels.create`는 장총46종을 TWO_HAND 기본으로 만든다. 권총9종 NATIVE, 활/검/글레이브8종 NATIVE.
- `grip two_hand` / `grip native`는 OP 전용, 주 손 프리뷰만 복사 교체하고 일반 아이템은 보호한다.
- 예: `/destiny weapon equip beloved` → 기본 양손. `/destiny weapon grip native` → 기존 자세.
- 기존 STICK 프리뷰는 pose/인식 호환을 유지하며, grip 명령 또는 재장착으로 Polymer 타입에 전환한다.
- 서버 metadata의 grip과 CUSTOM_MODEL_DATA 문자열 hip/ads/inspect는 독립이다.
  Polymer 복제본 flags[0]만 그립 parent 모델을 선택한다. 서버 원본은 장전 컴포넌트가 없다.
- W31 기본 모델/texture/geometry/display를 보존하고, 상태별 `_twohand` parent189개만 추가한다.
- 3인칭 기본 회전은 `[5.729578,-17.188734,0]`, 이동은 `[0,-2,2]`, 크기는0.7이다.
  초기 [0,2,0]에서 높게 뜨는 것을 측면 실화면으로 확인하고 수정했다.
- 1인칭 idle 보정은 renderer의 `T(-0.641864*handSign,0,0) Ry(10*handSign)` 역변환이다.
  좌/우 hip·ads·inspect 모든63종×3×2행렬을 JUnit에서 비교한다.

## 한계 / 후속

- 지원 범위는 **주 손 idle/일반 이동의 바닐라 3인칭 양손 자세**다. 1인칭 실제 양팔 생성 아님.
- 바닐라 휘두르기 중에는 CROSSBOW_HOLD가 잠시 풀리고, 석궁 1인칭 idle 이동 보정도 적용되지 않는다.
  따라서 휘두름 중 1인칭 구도까지 고정한 구현은 아니다. 총기 공격/반동 시스템과 함께 후속 조정한다.
- 양손 자체는 고정된 바닐라 팔 자세다. 무기별 IK, 손가락, 어깨 거치 로켓 자세는 아니다.
  일부 grip/탄창이 팔과 겹치는 지점이 있어 개별 art tuning이 남는다.
- 실제 오프핸드 아이템을 숨기거나 삭제하지 않는다. 다른 물건을 쥐고 있으면 3인칭에서 함께 보일 수 있다.
  프리뷰를 오프핸드로 옮겨 사용할 때는 `grip native`를 권장한다. 오프핸드용 보정/dual wield 미지원.
- 왼손잡이 실제 화면·실제 다인 접속·성능·인벤토리 GUI·궁극기 조합의 새로운 실시간 인수는 하지 않았다.
  기존 전체 회귀 gate는 통과했으나 이것으로 위 항목을 실검증했다고 주장하지 않는다.
- 기존 HUD particle/end_of_frame 경고는 W31에서도 있던 문제로 별도 유지했다.
