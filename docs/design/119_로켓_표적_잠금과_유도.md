## 원작 확인과 서버 조정의 구분

**확인된 사실:** 정밀 프레임 고유 설명은 조준 중 목표 잠금 및 자동 추적 로켓을, Tracking Module 설명은 조준 중 표적 잠금을 명시한다.

**이 구현의 조정값:** ADS 진행률 0.95 이상에서 살아 있는 적의 몸통 중심이 64블록·8도 원뿔 안에 보이면 연속 20회 유효 서버 틱 표본으로 잠근다. 첫 유효 표본이 1이고 20번째에 잠긴다. 시야·완전 조준 전환 시간은 별도다. 후보는 조준축 근접도, 거리, UUID 순으로 결정하고 새 후보 검색은 틱마다 최대 32후보에 LOS를 검사한다(기존 표적 유효성 검사는 별도). 가려진 후보만 있는 검색 창은 다음 틱에 순환 이동해 뒤쪽의 보이는 표적을 영구 누락하지 않는다. 기존 표적이 계속 유효하면 유지한다. 이 수치들은 원작 측정값이 아니다.

발사체는 매 실제 틱 최대 3도 회전하며 기존 속도 2.2, 사거리 80, 수명·벽/엔티티 충돌·폭발 피해·탄창/예비탄/연사 간격을 유지한다. 정밀 고유 기능과 선택 모듈은 같은 **로컬** 조정값을 사용한다. 최신 D2의 유도 방정식이나 PvP 보정이라고 주장하지 않는다.

공식 원문으로 확인하지 못한 획득 시간·유예·회전률·발사 후 연속 ADS 필요·가림 시 추적 취소·수납 이후 동작은 source JSON에 null로 보존한다. 커뮤니티의 1초 조준 해제 지속 설명은 참고만 하며 정확한 runtime 규칙으로 채택하지 않았다.

## 실제 수명과 권한

- `WeaponAiming.trackingInput`은 현재 실제 crouch/ADS·카메라 소유·재장전·취급 대기·플레이어 수명을 읽기 전용으로 검증한다. HUD를 조회해 조준 시간을 얻을 수 없다.
- `WeaponTracking.update`는 실제 서버 틱마다 최대 한 표본만 추가한다. ADS만 하는 플레이어도 전역 틱에서 갱신하므로 테스트용 사전 발사가 필요 없다. 틱 누락·다른 원본 stack/level/표적은 연속성을 끊는다.
- 실제 조준 해제, 승인된 수납 패킷, 재장전/스킬 suspend, 원본 stack의 성공한 특성 편집은 발사 전 잠금을 즉시 무효화한다. 같은 틱에 되돌려도 20표본을 다시 얻어야 한다. 편집하지 않은 중복 선택은 무효화하지 않는다.
- **실제 탄약 결제에 성공한 Shot 생성 시점**에만 표적을 캡처한다. 잠그지 않은 발사·힙파이어·지원하지 않는 무기는 직진한다. 조회/잠금 자체는 탄약·쿨다운을 바꾸지 않는다.
- 발사 후 수납/특성 변경은 이미 결제한 원래 표적을 바꾸지 않는다(로컬 정책). 적 사망/제거·아군화·차원 이동·표적 청크 미로드 시 유도가 영구 해제되고 남은 경로는 직진한다. 다른 적에게 재획득하지 않는다.
- 가림 자체로 공중 유도를 취소하지 않는다. 기존 세그먼트 충돌이 벽 통과를 금지한다. 획득 LOS도 기존 보수적 loaded-segment 검사를 통과한 뒤에만 `clip`한다. 청크 강제 로드는 추가하지 않는다. 청크 미로드 경계의 실증과 소스 감사 범위는 구분한다.
- `WeaponRuntime.flights`는 실제 승인된 발사체의 불변 관측 목록만 제공하며 주입/강제 표적/시간 변경 API가 아니다.

## HUD

기존 로켓 레티클의 frame 하나를 획득 중 황색 `F6D66B`, 잠금 후 적색 `E85C50`으로 투영한다. 중심점은 고정 흰색이며 기존 두 노드·모델·텍스처를 재사용한다. 상태 조회는 시간을 진행하지 않는다. 이는 읽기 쉬운 초기 표시이며 원작 레티클의 픽셀 단위 복제가 아니다. 새로운 잠금 음원을 임의의 원작 사운드로 표시하지 않는다.

## 검증 및 남은 작업

실행 결과는 [W104 QA](../qa/2026-10-25/w104/README.md)에 기록한다. 순수 회전 알고리즘, 정확 소켓, 실제 ADS·결제 발사·이동 표적·벽·수명·유한 탄약과 HUD 그래프를 자동 검증한다. 시각/청취 수락은 Vision 실제 framebuffer/재생 증거와 별개다. 현재 Mac 잠금 아래에서 클라이언트를 반복 기동하거나 잠금을 우회하지 않는다. 모델·음원·기존 봉인 증거는 보존하며 전체 목표는 진행 중이다.
