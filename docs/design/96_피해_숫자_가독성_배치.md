# W81 — 피해 숫자 가독성 배치

## 목적과 근거

W80 실제화면에서 폭발탄약의 몸통직격2.5HP/폭발3.25HP가 각각white3으로 반올림되어 같은곳에 겹쳤다. 일반자동연사도 같은표적에 여러 숫자를 만든다. 실제확인된피해만 보여주는 기존 계약은 유지하면서 각 숫자를 읽을 수 있게 배치한다.

- [원작 gameplay와 원본 프레임·clip·provenance](../../art/hud/w81-damage-feedback/reference-notes.md): Ammit연사와 EP장비/발사를 실제확인. white/yellow·여러label공존·공간분산은 관찰했다. 원작에서도 일부중첩이 있어 **엄밀nonoverlap은 원작 알고리즘이 아니라 이프로젝트의 local가독성정책**이다.
- [native26.3 text renderer bytecode](../qa/2026-10-24/w81/native-text-renderer.javap.txt):1/40scale·텍스트원점·9px행높이 근거. 보수적10px/shadow폭·.035gap은 authored envelope이지 실제glyph bitmap 측정치가 아니다.
- 숫자는 Minecraft HP의 Math.round(최소1),원작피해단위 아님. 기존whitebody/yellowprecision,임팩트/폭발 개별표시를 보존. precision만으로보이는모든원작노란숫자를설명하지 않는다.

## 구현

[DamageNumberLayout](../../src/main/java/kim/biryeong/destiny/fx/DamageNumberLayout.java)은 pureJava값/투영/interval packing만 담당한다. [WeaponDamageNumbers](../../src/main/java/kim/biryeong/destiny/fx/WeaponDamageNumbers.java)의 기존boundedholderqueue가 유일한reservation저장소다. 추가UUIDmap/비동기시계/클라이언트패킷은 없다.

1. owner의 현재eye/yaw/pitch에서 impactanchor를 7block논리평면에 투영한다. forwarddepth<=.05/invalid/behind는 보이는reservation을 만들지 않는다. 수직pitch에서도yaw정의right/up기저를 쓴다.
2. `a=clamp(distance,4,96)/forwardDepth`. 기존billboard의scale=.65, x=body-.18/crit+.18, y=.12+age*.025+lift를 보존한다. nativeorigin/shadow를 포함해논리중심은 x추가1pixel/y추가4pixel,반폭=(digits*6+2)/40*.65*a/2,반높이=10/40*.65*a/2로잡는다.
3. 같은정확owner/connection/level의liveholder만 충돌후보다. 실제서버age와저장lift를 투영하므로다른worldanchor/거리의같은화면위치도 감지한다.
4. 가까운clamp와먼거리의각상승속도차이는 `delta=(oldA-newA)*.025*(15-oldAge)`로계산한다. 새숫자와같이상승하는frame에서oldbox의centerY+=delta/2,halfHeight+=abs(delta)/2로공존시간전체sweep를예약한다. 기존숫자는건드리지않는다.
5. 수평으로겹치는interval들을bottom/top순정렬,원래Y보다아래로내리지않고가장낮은빈자리를선택한다. lift=(packedY-desiredY)/newA. 단일고정lift,실제ENDtick상승,expiry시자연reservation반환.
6. 16tick수명/owner24/global256/FIFOeviction,사망·이탈·level/connection교체정리,owner-onlyprivatewatcher,기존textshadow/occlusion정책유지. damage/ammo/perk/precisioncallback에는손대지않는다.

## 보장과 한계

- 정적owner시선/anchor에서는새배치후남은공존시간의상대상승까지고려한다. 기존label을새hit때재배치하지않아jump를피한다.
- 서버eye기반근사다. 실제clientFOV/후방camera/프레임interpolation/빠른카메라·플레이어이동후의재중첩을완전히보장하지않는다. 수평확장/새font리소스/fade/원작정확폰트·size비율은이번범위아님.
- cap내denseconfirm은화면위로긴stack을만들수있다. value를합치거나hit를누락시켜가독성을속이지않는다. 일반연사반복/slot재사용은테스트한다. 다인최대부하·percentile측정아님.
- 수치/VFX/음향·모델/클라이언트asset을변경하지않았다. 패킷기하통과는framebufferproof가아니다.
