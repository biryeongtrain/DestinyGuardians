# W196 — Windows 추출 애니메이션 검증 재개

사용자가 Windows 추출 결과를 전달하여 애니메이션 보류를 해제했다. 아래 두 묶음을 읽기 전용으로 받았다. 사용자가 Animation-Export라고 부른 무기 묶음의 실제 폴더명은 Animation-Return이다. 원본과 기존 handoff는 수정하지 않는다.

- 궁극기: `/Volumes/qf-ssd/DestinyGuardians-Super-Animation-VFX-2026-10-27/destiny-animation-return`
- 무기: `/Volumes/qf-ssd/DestinyGuardians-Animation-Return-2026-10-27/destiny-animation-return`

## 단계 1 — 자료 확인

전달 REPORT는 build 25932352의 플레이어 원본 2,171클립, Blender 고유 2,160클립, raw-only 11개를 보고한다. 이것은 전달자의 결과이며 Mac에서 독립 확인 전 성공으로 확정하지 않는다. 헌터 아크 지팡이 18개와 Shadowshot 2개를 우선 확인한다. 3P 전신 리그를 1P 무기 장전으로 바꾸어 부르지 않는다.

## 병렬 작업과 수락 조건

- master: 원본 골격·시간축·좌표계의 독립 Blender 평가, 현재 BetterModel 본 구조와 대응 조사, 대표 모션 프리뷰, 결과 취합. live Blender의 미저장 작업은 건드리지 않는다.
- source-intake worktree: 반환 묶음 해시·경로·클립/rig 대응과 1P/장전 존재 여부를 검사하는 재실행 가능한 도구. 입력 원본은 읽기 전용, 문서의 성공 주장을 그대로 반복하지 않는다.
- effect-links worktree: 원본 이벤트→시퀀스→파티클 직접 연결과 자산 존재를 검사하는 도구. 후보와 직접 연결을 구분하며 정적 PNG/FBX를 완성 GPU 이펙트 재생으로 세지 않는다.

이번 배치는 추출 자료 검증이다. 실제 변환·Minecraft 적용·Vision 재생은 각각 별도 증거가 필요하며, 자료 검사만으로 제품 기능이 완성됐다고 보고하지 않는다.

## 단계 2 — 무기 자료 추가 수령

무기 묶음은 65개 대상 중 60개를 32개 공유 그룹에 연결한다. 나머지 5개는 검이며 이 1P 장전 추출 경로의 대상이 아니다. 210개 고유 클립, 332개 클립+리그 조합, 509개 그룹 액션 인스턴스를 구분한다. 무기 전용/FirstPerson FBX 64개는 **골격·애니메이션 곡선**이며 메시·텍스처는 없다. 기존 큐브/삼각 무기 모델을 대체하는 메시 묶음으로 취급하지 않는다.

무기 연결은 전역 manifest의 이름 합집합 대신 그룹별 `source-map.json`과 inventory selector를 따른다. 같은 그룹의 공유 클립이므로 이름만으로 무기 독점 모션임을 확정하지 않는다.

| 무기 | 그룹 | 원본 장전 태그 | 독립 평가 |
|---|---|---|---|
| Duke Mk.44 | `hand_cannon_cedb29ae` | `80A8A53D` | 80본, 127샘플, 4.2초 |
| 스페이드 에이스 | `hand_cannon_f163a4c8` | `80A8A567` | 80본, 127샘플, 4.2초 |
| 이자나기의 짐 | `sniper_rifle_ececad46` | `80A8A140`, `80A8A150`, `80A8A14D` | 76본, 각 102샘플, 3.366667초 |

에이스는 API `347366834` / item `812C4BEA` / selector `5267F9DF`, 이자나기는 API `3211806999` / selector `A9639716`으로 연결된다. 에이스와 Duke의 장전 태그는 서로 다르다. 이자나기 `80A8A14D`에는 그룹 이름으로 `reload_special`과 full/empty가 함께 연결되어 있으며, 이것만으로 Honed Edge 전용 동작·발동 시점을 확정하지 않는다.

`reload_continue_empty` 등 정적 placeholder는 실제로 존재한다. 정지 클립을 임의 동작으로 만들지 않는다. 활·산탄총 등 나머지 그룹의 동작 의미와 손 접촉은 아직 독립 평가하지 않았다.

해시 인덱스의 궁극기 5,011개·무기 796개 파일은 모두 일치하며 누락·미등재 파일은 없다. 인덱스 자체는 자기 해시 대상에서 제외되므로 별도 `source-pins.json`에 관측 해시를 기록했다. 이는 전달 인덱스와 로컬 파일의 일치 검증이며 서명된 외부 출처 인증은 아니다. 검사 도구에서 처음 감지한 무기 44개 manifest 측정 비교 차이는 원본 frame count와 Blender keyed range를 혼동한 데서 왔다. 두 수치를 분리한 결과 나머지 측정값은 일치했다. 전체 그룹에는 정적 액션의 source count/keyed range 차이가 궁극기 163건·무기 71건 있으며 모두 `changingCurves=0`이다. 차이를 없애거나 동적 재생 성공으로 바꾸어 보고하지 않았다.

## 단계 3 — 격리 Blender에서 실제 FBX 평가

live Blender MCP 대신 별도 `--background --factory-startup --disable-autoexec` 프로세스를 사용했다. Mac Blender는 5.4.0 Alpha / build `7a8f04b3bb5a`다. 원본을 저장하거나 수정하지 않았다.

`scripts/animation/sample_destiny_rig.py`로 헌터 20개와 무기 5개, 총 **25개 클립의 모든 원본 프레임**을 평가했다. 본 집합·해시 이름별 부모 대응, 유한한 변환, 실제 위치 변화와 단일 액션 슬롯을 확인했다. 이 결과는 원본 파서를 다시 구현한 바이너리 독립 디코딩이 아니라, 전달 FBX를 별도 Blender에서 평가한 결과다.

| 궁극기 | 클립 | 원본 시간축 |
|---|---|---|
| 아크 지팡이 지상 전개 | `80A8A922` | 30fps, 44샘플, 1.433333초 |
| 아크 지팡이 공중 전개 | `80A8A95C` | 30fps, 40샘플, 1.3초 |
| 아크 지팡이 약공격 1 | `80A8A937` | 30fps, 40샘플, 1.3초 |
| Shadowshot 지상 | `80A8AD97` | 30fps, 40샘플, 1.3초 |
| Shadowshot 공중 | `80A8AD8A` | 30fps, 40샘플, 1.3초 |

Shadowshot 지상 프리뷰에서 몸을 낮춘 준비 자세, 상승·다리 접기, 양팔 전개, 회복으로 이어지는 변화를 볼 수 있다. 아크 전개에서도 위로 뻗었다가 몸을 낮추며 회복하는 동작을 확인했다. 이것은 메시 없는 골격 관찰이며 활 시위·지팡이 파지 접촉까지 확인한 것은 아니다. 황금총으로 확정된 클립은 아직 없다.

### 좌표계에서 발견한 핵심 차이

FBX import 후 armature 바깥 행렬은 다음과 같다. Z축 높이가 월드 -Y로 가며 0.01 배율이 걸린다.

```text
[ .01, 0,    0,    0 ]
[ 0,   0,   -.01,  0 ]
[ 0,   .01,  0,    0 ]
[ 0,   0,    0,    1 ]
```

armature 내부 rest head/foot 좌표는 Z가 높이 축이다. 샘플은 **armature object 공간의 누적 4×4 pose 행렬**을 보존하고 바깥 행렬을 metadata로만 기록한다. 본 순서는 bone-map Index 순서와 다르므로 해시 이름으로 대응했다. source forward 부호와 Minecraft 축 대응은 미확정이다. world 좌표를 그대로 복사하거나 이 행렬들을 local Euler로 해석하지 않는다.

현재 BetterModel 모델 `guardian_hunter_h26_r2`는 18개 그룹이며 source 전신 리그는 72본이다. pelvis·spine·head·오른손 등 알려진 semantic 본부터 연결하고, 아직 hash 이름뿐인 본은 rest topology와 실제 움직임을 대조한다. 손가락·여러 척추·neck 체인을 축약할 때 target rest basis를 기준으로 회전 차이를 변환해야 한다. source의 root 이동량과 카메라/서버 이동을 이중 적용하지 않는다.

이자나기 weapon 본은 root `4A0810C4`, bolt `69768858` (`b_bolt`), magazine `52EDE88C` (`b_magazine`), 미확정 `72997168`을 포함한다. 기존 분리 탄창/볼트의 첫 연결 대상으로 쓸 수 있다. 에이스의 무기 본 8개는 실린더 등의 semantic이 충분하지 않아 현 단계에서 임의 이름을 부여하지 않았다.

## 단계 4 — VFX 연결 조사

`effect-links.json`은 458개 particle 정의 중 전달자가 직접 연결로 보고한 34개와 graph 후보 424개를 구분한다. 1,313개 참조 자산은 존재하고 비어 있지 않다. 그러나 보고된 120행의 전체 clip→event→entity→component→particle 경로를 독립 뒷받침할 component-node JSON 등이 부족하다.

특히 **아크 지팡이·Shadowshot의 직접 particle 연결은 현재 자료에서 확인되지 않았다.** Spectral Blades·Silkstrike 등의 근거를 두 궁극기로 옮기지 않는다. `S80808C1A`의 알려지지 않은 필드, sequence 시간 단위, emitter/attachment 연결은 미해결이다. 메시·PNG가 있다는 사실을 완성 GPU 이펙트 재생으로 세지 않는다. 이 정보 부족은 이미 받은 애니메이션 리타게팅의 착수를 막지는 않는다.

프리뷰는 X/Z·Y/Z 직교 투영 골격이며 실제 Destiny/Minecraft 카메라가 아니다. 주황색은 weapon 본, RGB는 손·무기 본 축이다. GIF는 30fps를 누적 10ms 단위로 반올림하며 마지막 샘플을 한 프레임 유지한다. 원본 길이는 `(N-1)/fps`, 반복 GIF 길이는 약 `N/fps`로 구분한다.

다음 제품 배치는 (1) 원본 rest basis→현재 rig 변환과 Shadowshot/아크 대표 전개 리타게팅, (2) 이자나기 탄창·볼트와 에이스 장전 연결을 별도 worktree에서 병렬 진행하고, master가 Vision 1P/3P·카메라·탄약 전환·중단/교체 복구를 한 세션에 모아 확인한다. 기존 아크 0.50초 전개/0.35초 공격과 원본 전체 길이는 다르므로 조작 반응을 잃도록 원본 길이를 무조건 덮어쓰지 않는다. Shadowshot 자동 준비→발사와 연속 사운드도 유지해야 한다.

이번 배치는 자료 수령·오프라인 평가 도구와 문서만 변경했다. Minecraft 적용·Vision·실제 손/메시 접촉·게임플레이 타이밍 검증은 아직 하지 않았다. 전체 Gradle gate는 이 배치에서 실행하지 않았고, W195 전체 서버 회귀의 24개 실패가 해결됐다는 뜻도 아니다. 이전 봉인 QA와 일반 게임 프로필은 보존한다.

## 단계 5 — 통합 확인

두 worktree의 배타 소유 파일 8개를 baseline/main 해시 비교 후 통합했다. source-intake 테스트 18개(실제 두 묶음 포함), effect-links 테스트 13개가 main에서 통과했다. 평가·렌더 도구도 실제 출력 생성에 사용했고 4개 대표 contact sheet를 눈으로 확인했다. main의 sampler에 원본 폴더 내부 출력을 막는 경로 검사를 추가했으며 이는 변환 결과를 바꾸지 않는다. 검증 재현법은 [REPRODUCE](../qa/2026-10-27/w196/REPRODUCE.md), 최종 범위·산출물 지문은 [verification.json](../qa/2026-10-27/w196/verification.json)에 남긴다. 이번 수령 검증 완료와 전체 무기 시스템 goal 완료는 구분한다.
