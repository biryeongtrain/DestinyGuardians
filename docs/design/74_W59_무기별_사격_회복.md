# W59 — 무기별 사격 회복

## 수정한 격차

기존 W58은 무기를 바꿔 들 준비 시간은 계산했지만, 하나의 owner `State.cycle.readyAt`을 공유했다.
따라서 로켓의48틱 발사 간격이 준비가 끝난 핸드캐논에도 전이됐다.
W59는 **같은 실제 무기의 발사 회복**과 **다음 무기를 들 준비(Handling)**를 분리한다.

[수치 출처·정책 경계](../../art/weapons/w59/README.md). 새 현재 원작 patch/animation cancel 실측을 주장하지 않는다.
W46 공식RPM+historical커뮤니티timing과W58Handling을 그대로 사용하며 수치/geometry/소리/HUDlayout은 변경하지 않는다.

## 소유권과 처리

- State별 `WeaponCadenceBank`가 실제 ItemStack 참조별 fractional firing deadline만 보관한다.
- 다른 실제 총기·월도는 원래 무기의RPM을 물려받지 않는다. 동일모델/동일id/같은컴포넌트도 다른 실제 아이템이면 독립이다.
- 원래 무기로 돌아오면 남은 자기 deadline을 복구한다. 실제 예비탄으로 명사수 즉시 재장전해도 이 deadline은 유지한다.
- `WeaponCycle.restoreFiringDeadline`은 pending reload/charge/burst가 없는 상태에서만 사용할 수 있다.
  bind는 먼저 기존 pending 상태를 취소한 뒤 deadline을 복구한다. 탄약·pendingshot·장전task는 복원하지 않는다.
- W58Handling도 동시에 만족해야 발사한다. 입력/시간 만료가 저절로 발사를 만들어내지는 않는다.
- 이미 발사한 투사체는 기존처럼 비행하며, source weapon의 탄약을 환불하지 않는다.
- 검은 actor의 실제 스윙/돌진 동작이므로 기존 공유 recovery를 보존한다. 검교체로 연속공격을 우회하지 못한다.
  이 actor 정책은 원작 정확 인터럽트 실측이 아니라 기존 동작 보호다.
- owner별128개 live clock을 상한으로 한다. 만료분은 write에서 정리하며 초과시 live clock을 지우지 않고
  overflow deadline까지 보수적으로 지연한다. 일반 원작규칙이 아닌 pathological server-safety 정책이다.
- death/disconnect/dimension/server-stop은 기존 State cleanup으로 transient bank도 해제한다.
