# W115 — 원본 형상을 보존하는 고밀도 무기 모델

## 사용자 결정

에이스/이자나기처럼 표면을 정돈하되 원본을 보존해야 한다. 첫 R1 시안은 큰 패널로 지나치게 단순화되어 불수락했다. 큐브를 줄이는 것이 목표가 아니며 예전256개 제한을 기계적으로 적용하지 않는다. 26.3의 자유회전과 삼각형 표현을 함께 사용한다.

## 작업 이력

1. 기존249/223cube 용광로·망치머리와 에이스87cube를 확인했다.
2. 독립Git worktree 두개에서71/86cube 시안을 만들고 master가 비교렌더·Blockbench를 검토했다.
3. 사용자가 원본 디테일 손실을 지적했다. R1은 `docs/qa/2026-10-25/w115/rejected-r1`에 보존하고 pack converter 등록을 제거했다. R1을 현재 수락 모델이라고 취급하지 않는다.
4. 설치된26.3 client JAR의 parser·rotation 코드를 실제 확인했다. 임의x/y/z 및 단일축67.4도, zero-depth plane,768요소 parser수용을 JUnit3개로 검증했다. 이는 성능 측정이 아니다.
5. 원본 ripped geometry·기본안료 bake를 다시 확인하며 R2 원본보존형 재구성을 두worktree에서 진행한다. master는 변환도구·중앙회귀·실화면을 담당한다.
6. R2 수락 전까지 원본canonical model·기존W114part·animation/display/audio/stat을 변경하지 않는다. 확인된 geometry만 exact7path output교체로 적용한다.

## 26.3 표현

- nativecuboid `rotation`에 origin과x/y/z를 지정할 수 있다. 내부행렬은 `Rz*Ry*Rx`이며 itemdisplay 변환순서와 혼동하지 않는다.
- 원본meshJSON을 직접 로드한다고 가정하지 않는다. 기존H28의변환된triangularalpha plane방식과, 새 `scripts/mesh/native_triangle_elements_w115.py`의회전zero-depth요소 방식이 있다.
- 새adapter는 임의삼각형을 최장변의높이로 나누어 최대2개직각삼각형면으로 표현한다. 각각일반요소2면과UV삼각alpha를 사용하므로 cube마다Display엔티티를 만들 필요가 없다.
- 원본면을 보존하는회전cuboid/PCAfit와 필요한부위triangle를 혼합한다. UV안료·부품분리·중복내부면을 개별검토한다. 큐브수만늘리는단순분할은 불수락한다.
