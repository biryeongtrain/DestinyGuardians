# W49 — 빈 탄창 자동 재장전·활 재노킹

## 구현한 동작

1. **성공한 마지막 원거리 발사**가 현재 아이템 소유 세션에 자동 재장전 후보를 남긴다.
   별도 클릭 없이 같은/다음 서버 처리에서 재장전을 시작한다. 처음부터 비어 있던 아이템을
   조회하거나 HUD를 갱신하는 것만으로는 자동 충전하지 않는다.
2. 융합/선형융합의 공유 탄약 버스트는 탄수가0이어도 이미 지불한 남은 볼트를 모두 처리한
   후 재장전한다. 무기 교체·스킬·사망 정리는 후보와 미실행 볼트를 취소하며 탄을 환불하지 않는다.
3. **발사로 시작한 자동 무기 재장전**만 실제 native hold 또는 갱신되는 양손 heartbeat를
   유지하면 완료 뒤 연사한다. 입력 해제/lease 만료 시 추가 발사하지 않는다. 세미오토는
   기존 native fired 세션을 release까지 유지하고, heartbeat는 새로운 gap 이후 입력을 요구해
   장전 완료가 새 trigger로 잘못 처리되지 않게 한다.
4. 활2종은 `놓아 발사 → 자동 재노킹 → 1발 준비/idle`로 이어진다. 재노킹 중 실제 다음
   press는 **다음 당김만** buffer한다. 당김 시간은 재노킹 완료부터 새로 계산하고, 완료만으로
   화살을 쏘지 않는다. Q는 당긴 시위를 화살 없이 풀며 이미 진행 중인 재노킹 자체는 유지한다.
5. 일찍 놓아도 화살은 발사된다. 약한 피해·낮은 속도·큰 낙차를 적용하고 다시 자동 재노킹한다.
   완전히 당겼을 때는 기존 원본 프로필을 정확히 사용한다.
6. 기존 탄약 HUD가 실제0→1, 재노킹 기한 및 완료를 표시한다. 새 활의 아이템 도움말에
   Q 시위 풀기·자동 재노킹을 추가했다. HUD 조회는 저장 탄약을 변경하지 않는다.

## 원작 근거와 Minecraft용 결정 구분

[조사 문서](../../art/weapons/w49/README-empty-reload-references.md),
[공식 정의/영상 출처·SHA](../../art/weapons/w49/empty-reload-references.json),
[현재 코드/정책 SHA](../../art/weapons/w49/implementation.json).

- 실제 공식 bow intrinsic은 Reload로 당긴 화살 취소를 명시한다. Minecraft 입력은 Q에 매핑.
- 실제 참고 영상에서 발사 후0발, 회복/재노킹 후1발·당기지 않은 idle을 관찰했다.
  입력 overlay가 없으므로 두 번째 클릭/Reload가 없었다는 물리 입력 증명으로 쓰지 않는다.
- Bungie Hotfix6.3.0.7은 재장전 뒤 충전 지연 우회 문제를 별도로 다룬다.
  모든 충전 무기가 계속 누른 입력으로 자동 재발사한다는 규칙으로 일반화하지 않는다.
- 부분 당김 방향은 역사적 개발자 인터뷰와 커뮤니티 기술을 참고했다. 아래 곡선은
  **원작에서 추출한 수치가 아닌 Minecraft용 authored 튜닝**이다.

```text
progress = 실제 당긴 tick / 해당 활의 기존 drawTicks
damage   = base * (0.35 + 0.65 * progress)
speed    = base * (0.25 + 0.75 * progress)
gravity  = base * (3 - 2 * progress)
full draw 이상이면 원본 profile 그대로
```

시작 지연의 same/next-server-callback 정책도 원작 실측값이 아니다. 기존 W46의 역사적
nock/reload 근사값은 유지했다. 현재 영상으로 정확한 기본 장전 속도/퍽/버프를 인증하지 않는다.

## 여전히 남은 범위

- 활 시위/팔/재노킹 모델 애니메이션은 추가하지 않았다. 완전 당김 유지·perfect draw·강제 overdraw
  해제·프레임/경이별 보정은 아직 없다.
- `weapon.bow.charge`와 `weapon.bow.reload`는 W33에서 미매핑된 상태 그대로다. 호출은 있으나
  custom lookup은 no-op. **전용 음원을 새로 연결했다고 주장하지 않는다.**
- 수동·빈 탄창 trigger로 시작한 재장전은 기존 no-queued-shot 정책이다. global Full Auto 옵션,
  모든 퍽/경이, sprint 취소·자동 restart, 재노킹 중 ADS 유지의 원작 일치는 후속.
- 예비탄이 없어 실패한 자동 재장전은 무한 재시도하지 않는다. 나중에 예비탄만 얻으면 실제 입력으로
  재장전을 요청해야 한다. 이 정책도 원작 일반 규칙으로 인증하지 않는다.
- 실제 Vision 입력·화면·오디오·수신 cache·일반 서버 배포 및 다인 검증은 미완료.
  기존 클라이언트 초기 렌더 정지 확인 응답 없이 재시작을 반복하지 않았다.

전체 무기/HUD/모델/사운드 구현 목표는 active이며 이 단계만으로 완료로 표시하지 않는다.
