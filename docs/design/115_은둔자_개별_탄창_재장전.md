# 115. 은둔자 개별 탄창 재장전 — W100

## 목표와 구현 경계

SMG 개별 재장전 표현을 추가하되 서버사이드 Polymer·바닐라 클라이언트·기존 양손 carrier를 유지합니다. 대상은 `the_recluse` 하나입니다. 현재 카탈로그의41발/43tick, 재장전 accepted identity·clock·탄약·HUD·사운드 권한을 변경하지 않습니다.

`WeaponReloadPresentation`의 지원 predicate와 namespace routing에만 Recluse를 추가했습니다. 진행 float1·grip flag0를 사용하며 실제 active reload에서만 새 item graph로 전환합니다. 비활성·다른 context는 기존 graph, 시작/끝은 정확한 원래 HIP transform입니다.

## 모델과 레퍼런스

- 원본217큐브를193 body +24 lower-cartridge proxy로 분할하고 모든 faces/UV/textures를 보존합니다.
- 21 진행 샘플 ×2부품 ×2grip=84 pose, part2개와 wrapper1개로87 asset. 양쪽 first-person display와 native/twohand 보정을 검사합니다. 왼손 native gameplay는 아직 아닙니다.
- generic FBX component를 실제 탄창으로 단정하지 않습니다. 혼합 seam과 하부 proxy 한계는 [모델 노트](../../art/weapons/w100/model-notes.md)에 명시했습니다.
- [원작 영상 참고](../../art/weapons/w100/reference-notes.md)의 몸체 raise/roll·하부 교환·복귀를 근사했습니다. 손가림 때문에 정확 궤적은 복원하지 못했으며 원작 animation/hand IK는 없습니다. 역사 영상의36발/강화 장전속도를 현행 정책으로 넣지 않았습니다.

## 검증과 한정 판정

새7GT/11JUnit은 accepted reload·실제 tick·PLAY wire·양grip·owner/recipient·copy/NBT·취소/Q중복·HUD/탄약,87개 native parser·큐브 보존·signed native matrix·fallback/endpoint를 검사합니다. W98/W64의 과거 닫힌 지원목록 두 곳은 정확한 추가 경로/ID만 허용하는 명시적 oracle migration이며 실패 시도는 보존합니다.

강제829GT/715JUnit 전체2회, 생성팩/실제 다운로드 cache 일치,8609source pin/7106asset 감사가 통과했습니다. probe-free Vision 실제82PNG/4native sequence에서 양grip0→41, 몸체 lift/roll·HIP 복귀·장전 HUD·ADS/look복귀·최종41→40을 확인했습니다. dev source/classes 실행으로 패키지 JAR 직접로드 수락과는 구분합니다.

## W100-N1 — 탄창 교체 가시성 미해결

기본 화면에서 탄창 proxy가 하단 밖/몸체 뒤로 가립니다. 몸체가 움직이고41발이 된다는 이유로 분리·교환·삽입의 시각 완성도를 수락하지 않습니다.

후속 단계는 **active reload 중에만 framing/부품 경로를 조정**하고 다음을 같은 Vision batch에서 확인해야 합니다:

1. 기본 해상도에서 분리→배출→삽입→안착을 눈으로 구분.
2. native/twohand 모두 검사, HIP 시작/끝·다른 context 불변.
3. 재장전/취소/탄약/clock/audio 권한과 기존 asset 보존.
4. 최종 생성팩/독립 cache·실제 PNG·입력중립·격리 cleanup을 함께 보존.

원작 손 IK, 왼손 native, 3인칭 장전, 음향 실청취, 다인·거리·성능과 전체 목표는 미완료입니다.
