# W91 — 이자나기 장전·강화 표시와 무기 교체 모션

> 현재 상태: 중앙791GT/681JUnit강제2회는 통과했으나, 실제Vision에서 새장전/교체모델이 반영되지 않아 **시각 수락 실패**. 이 문서는 구현 계약이며 완료 선언이 아니다. 후속은 실제 wire snapshot 경로 수정이다.

## 범위와 원본 보존

서버사이드 Polymer의 실제 전투 아이템을 사용한다. 새 클라이언트 모드/손 IK/새 탄약 권한은 추가하지 않는다. W84 이자나기 원본79큐브·474면 UV·3atlas 및 기존 무기 자산은 그대로 보존하고, 새 `weapon_izanagi_w91` / `weapon_swap_w91` 네임스페이스만 추가한다. 원작 프레임 실측 애니메이션이 아니라 기존 참고 영상과 원본 기하를 바탕으로 만든 **로컬 연출**이다.

## N1 — 일반 장전 / 연마된 칼날

- `WeaponRuntime`의 수락된 일반 재장전과 실제 Honed Pending을 구분한다. `WeaponIzanagi.honing`은 동일 owner/level/held-stack과 eligibility를 관측하는 순수 getter다. 완료 tick 전에 표시만으로 강화탄을 지급하지 않는다.
- 일반·연마 각각21샘플. 본체78큐브와 원본의 독립 탄창1큐브를 composite로 분리해 본체 기울기와 탄창 인출/재삽입을 표현한다. 확실한 bolt rig가 없어 별도 볼트 왕복/손 애니메이션은 주장하지 않는다.
- 기존61tick Honed 완료가 실제 탄약을 지불해 charge≥2가 된 뒤에만 총신 가장자리16큐브 cue가 붙는다(합계95큐브). 원본 각인/렌즈를 가리지 않는 청백색 경계이며 실제 bloom/전기 arc/fullbright shader가 아니다.
- float6: 일반0..1, 연마2..3, 실제 완료4. 새 binding의0/.00025/.0005 offset은 기존 selector와 donor live sample을 피해 Polymer cache를 무효화한다. 저장된 cosmetic 값만으로 모델을 활성화하지 않는다.
- 실제 유료 발사에서 강화 charge 소진 직후 cue를 제거한다. 완료 charge의 기존 stow/save/load 정책은 그대로이며 pending만 기존 취소 정책을 따른다.
- float3 ADS, flag0 carrier, string0 pose를 보존한다. 강화 상태에서도 원본 3D scope lens/ADS/inspect를 유지한다. 새로운 불투명 fullscreen scope를 발명하지 않는다.
- owner cleanup은 현재 손뿐 아니라 OWNERS에 기록된 이전 stack을 정리한다. 다른 필드는 현재 component에서 읽고 자신이 소유한 float6만 복원한다. 늦은 donor cleanup은 recipient binding을 건드리지 않는다.

## N2 — Austringer ↔ Beloved

- 기존 Handling 트랜잭션의 outgoing/phase/progress를 읽는다. 새로운 fire-ready 시계는 없다. 기존 STOW/READY deadline·탄약·HUD의 실제 선택 무기는 변하지 않는다.
- 바닐라는 incoming stack을 먼저 선택하므로, 1인칭 STOW는 incoming carrier 위에 outgoing 기하를 렌더하고 READY는 incoming 기하를 렌더한다. 이 두 무기의 서로 다른 조합에만 적용한다.
- 방향2 × phase2 × sample21 × carrier2 =168 display-only child. 원본 기하/UV/텍스처를 parent로 상속한다. HIP 양끝 정확한 기존 transform, 양손 carrier의 보정, 왼손/오른손 display를 따로 유지한다.
- GUI/3인칭은 실제 선택된 incoming 원본 graph를 쓴다. 1인칭의 아래로 수납/아래에서 꺼내기·작은 overshoot는 로컬 연출이다. 바닐라 손 IK·render frame 보간은 없다.
- float5는 STOW0..1, READY2..3+양의<.001 binding offset. 저장된 selector·기존 donor sample과 겹치지 않으며 recipient 복원 snapshot에는 원래 slot5만 유지한다.
- 미완료 STOW 재선택은 원래 outgoing/stowAt을 보존한다. READY 중 재선택은 실제 incoming을 새 outgoing으로 삼는다. skill cancel은 독립 Handling deadline을 초기화하지 않는다.

## 통합·검증

라우터 우선순위는 **Swap > Insert > Izanagi > 기존 Reload > 기존 ADS/Bow/Scope/base**다. 신규 helper는 원래 기능이 수락한 상태만 표시한다. OP `weapon-presentation-status`는 tick/무기/model/CMD/Handling/실제 reload/Honed/charge/ammo만 읽는다. `weapon-honed-reload`는 실제 reloadHoned를 호출하는 fixture로, 완료 charge를 직접 주지 않는다.

중앙 결과는 [W91 QA](../qa/2026-10-25/w91/README.md), [실제 작업 트리](../qa/2026-10-25/w91/parallel-work-queue.json), [소스 수락](../qa/2026-10-25/w91/integration.json)에 기록한다. generator 검사는 native framebuffer를 대체하지 않는다. Vision v1에서 Q/Ctrl+Q/숫자 slot key는 지원하지 않으므로 재장전·선택 명령을 native 키 입력으로 보고하지 않는다. 실제 use/ADS와 lease release, 서버 탄약/charge, PNG를 분리해 검증한다. 정확 tick/frame 동기화·청취·다인 성능·전 무기 재현 완료는 이 묶음의 수락 범위가 아니다.

## 계층형 실행

총괄→N1/N2 L1→각 asset L2. 두 L1에 child API가 노출되지 않아 총괄이 native spawn을 중계했다. `logicalParent=L1`, `spawnedBy=topmaster`를 별도로 기록했다. L1은 helper/시험과 자식1차리뷰를 담당했고, 총괄은 공유 소스·등록·2차리뷰·직렬 build·단일 Vision batch를 담당한다. 자식과 lead는 리뷰 후 모두 종료했다. 작업량 없이 깊이만 늘리는 중계 agent는 생성하지 않았다.
