# 04. 플레이어 모델·3인칭 연출

궁극기, 구르기, 방벽처럼 **몸 전체가 움직이는 동작**을 BetterModel 플레이어 모델로 만드는 명세입니다. 동작별 시점은 구분하며, 헌터 궁극기의 최신 요구는 아래 H18 정정을 따릅니다.

> **H18 정정 (2026-10-22):** 황금총은 기존 시점 유지, 전기 지팡이·공허 활은 발동부터 마지막 회복까지 강제 후방 3인칭이 목표입니다.
> 아래 지속형 전체 1인칭 권장은 초기안이며 헌터 Arc/Void에는 적용하지 않습니다.
> 26.3 코드를 확인한 결과 별도 카메라 엔티티만 지정하면 일반 이동/회전 전송이 제한됩니다.
> 사용자는 바닐라 서버 이동/조준 방식을 선택했습니다. 본인 전용 가상 좌석·후방 카메라와 서버 native physics를 구현했으며, 자동/화면/실제 입력 검증은 별도로 기록합니다. F5 자체 잠금은 지원하지 않습니다.
> 최신 요구·근거·수명은 [25. 궁극기 3인칭 카메라](25_궁극기_3인칭_카메라.md)를 따릅니다.

## 1. 원리

바닐라 클라이언트는 플레이어 자세를 서버가 바꿀 수 없습니다. 그래서 동작하는 동안:

1. 실제 플레이어를 숨기고 (`EntityHideOption`: 몸·장비·불·발광)
2. 같은 자리에 **플레이어 스킨을 입힌 BetterModel 모델(limb)** 을 띄워 애니메이션을 재생하고
3. 끝나면 모델을 닫고 실제 플레이어를 다시 보여줍니다.

✅ BetterModel 3.5.1, Fabric 서버 모드, 26.3 지원. 저장소의 `RollTest`(Fabric 테스트 모드)가 이 흐름 그대로 구르기를 구현합니다.

## 2. 누가 무엇을 보나 – 시점 매트릭스

이 표가 이 문서에서 가장 중요합니다. **본인 화면**과 **다른 플레이어 화면**을 따로 설계합니다.

| 동작 | 다른 플레이어가 보는 것 | 본인이 보는 것 | 카메라 방식 |
|---|---|---|---|
| 헌터 구르기 | limb 구르기 애니메이션 | 1인칭 유지 + 화면 기울기·잔상 포스트 이펙트 | 1인칭 |
| 타이탄 방벽 / 워록 균열 | limb 동작 | 1인칭 유지 + 손 아이템 모델 교체 | 1인칭 |
| 근접 능력 (화염 망치 투척 등) | limb 투척 동작 | 1인칭: 손에 망치 아이템 모델 → 투척 | 1인칭 |
| 순간형 궁극기 (천둥 강타, 신성 폭발, 새벽의 기도 발동) | limb 발동 동작 | **짧은 3인칭 시네마틱** (1~2초) | 고정 카메라 (방식 A) |
| 지속형 궁극기 (황금 총, 아크 지팡이, 대혼란의 주먹, 태양의 망치) | limb 지속 자세 + 소품 | **1인칭 + 궁극기 무기 아이템 모델 + 궁극기 포스트 이펙트** | 1인칭 (방식 C), 3인칭 추적은 🧪 (방식 B) |

- ✅ 2026-10-22 확인: 1인칭에서 본인 limb 모델이 카메라 앞을 가립니다 ([검증 기록](11_작업_계획.md#검증-기록)). 그래서 **1인칭일 때는 본인에게 limb를 숨깁니다**.
- 시점 판단: GCB-mod 플레이어는 시점 이벤트로 1인칭/3인칭을 알 수 있어 3인칭이면 본인에게도 보여줍니다. 바닐라 플레이어는 1인칭으로 가정합니다. ([12](12_스킬_입력_GCB_바닐라_혼용.md) 6장)

## 3. 카메라 방식

| 방식 | 설명 | 장점 | 한계 | 상태 |
|---|---|---|---|---|
| **A. 고정 시네마틱 카메라** | minigame-lib 시네마틱. 클라이언트를 잠시 관전 모드로 바꾸고 카메라를 연출용 엔티티에 붙임. 플레이어 입력 차단 | 3인칭으로 몸 전체가 보임. 이미 구현된 기능 | 그동안 조작 불가. 1~2초 연출에만 적합 | ✅ minigame-lib에 구현됨 (`CameraViewSession`) |
| **B. 서버 추적 3인칭 카메라** | 플레이어 뒤에 카메라 엔티티를 두고 매 틱 따라가게 함. 이동은 입력 패킷(WASD)으로 서버가 처리 | 데스티니처럼 3인칭으로 돌아다님 | 카메라가 다른 엔티티일 때 마우스 시점·조준을 서버가 받을 수 있는지 불확실. 핑만큼 카메라가 늦음 | 🧪 PoC 필요 |
| **C. 1인칭 + 궁극기 아이템·포스트 이펙트** | 1인칭 유지. 손에 궁극기 무기(황금 총, 아크 지팡이) 아이템 모델을 쥐어 주고 화면 효과로 "궁극기 상태"를 표현 | 조작감이 그대로. 지연 없음 | 본인은 자기 몸을 못 봄 | ✅ 바닐라 기능만으로 가능 |

**권장**: 순간형 궁극기는 A, 지속형 궁극기는 C로 시작합니다. B는 PoC로 마우스 시점을 받을 수 있는지 확인한 뒤 결정합니다.

> 방식 B 대안 – **탑승형 3인칭 PoC**: 탑승 중 별도 회전 전송 경로를 활용할 여지는 있습니다.
> 그러나 외부 카메라와 함께 이동·조준·하차·충돌이 정상이라는 실제 검증은 아직 없습니다.
> GCB 탈것 입력을 강제 카메라 완성품으로 간주하지 않습니다. ([12](12_스킬_입력_GCB_바닐라_혼용.md) 8장, P-06; 최신 제약은 문서25)

### 방식 B PoC 확인 항목 🧪
- [ ] 카메라를 다른 엔티티로 바꾼 상태에서 클라이언트가 이동 입력 패킷(앞뒤좌우·점프·웅크리기)을 계속 보내는가
- [ ] 마우스 회전이 서버로 전달되는가 (전달 안 되면 조준 불가 → 방식 B 폐기)
- [ ] 카메라 엔티티 이동 보간(텔레포트 보간 1~2틱)으로 화면이 떨리지 않는가
- [ ] 핑 100ms에서 체감

## 4. limb 파일 구성

| limb 파일 | 내용 | 비고 |
|---|---|---|
| `guardian_common` | 공통 동작: 구르기, 슬라이드, 피격 경직, 부활 | 모든 직업 공용 |
| `guardian_titan` | 방벽, 근접 3종, 궁극기 발동 자세 | 망치·방패 소품 본 포함 |
| `guardian_hunter` | 근접 3종, 궁극기 발동·지속 자세 | 칼·황금 총·아크 지팡이 소품 |
| `guardian_warlock` | 균열, 근접 3종, 궁극기 발동·지속 | 날개(새벽의 기도) 소품 |

- 모두 BetterModel 기본 `steve.bbmodel` 리그에서 시작합니다.
- 소품 본은 기본적으로 숨김(크기 0) 상태로 두고, 애니메이션 안에서 크기를 키워 등장시킵니다.

### 4-1. 본 태그 (BetterModel 규칙) ✅

| 태그 | 부위 | 태그 | 부위 |
|---|---|---|---|
| `ph` | 머리 | `phip` | 엉덩이 |
| `pc` | 가슴 | `pw` | 허리 |
| `pra` / `prfa` | 오른팔 / 오른쪽 아래팔 | `pla` / `plfa` | 왼팔 / 왼쪽 아래팔 |
| `prl` / `prfl` | 오른다리 / 오른쪽 아랫다리 | `pll` / `plfl` | 왼다리 / 왼쪽 아랫다리 |

- 손 아이템 본(`pri`)에 실제로 들고 있는 무기 아이템이 붙으므로, 총을 든 채로 구르기가 됩니다.
- 헌터 망토는 `cape` 태그 본으로 만듭니다.

## 6. 방어구 외형

| 방식 | 설명 | 장점 | 한계 |
|---|---|---|---|
| **바닐라 장비 에셋(equipment)** | `assets/<ns>/equipment/*.json` + 갑옷 텍스처. 바닐라 체형 위에 텍스처만 바뀜 | 항상 보임. 추가 비용 없음 | 형태는 바닐라 갑옷 그대로 |
| **BetterModel 플레이어 갑옷** | limb 재생 중에 갑옷도 같이 표시 | 동작 중에도 갑옷 유지 | 동작 중에만 |
| **장식 부착 모델** | 어깨 장식·망토·표식을 플레이어에 상시 부착 | 실루엣이 확실히 바뀜 | 플레이어마다 엔티티가 늘어남 → 레이드 부하 |

- 1차: **바닐라 장비 에셋**으로 직업별 기본 세트 + 레이드 세트를 만듭니다. 직업 상징(헌터 망토, 타이탄 표식, 워록 결속)은 텍스처로 표현합니다.
- 장식 부착 모델은 거점 같은 저부하 구역에서만 켜는 선택 기능으로 검토합니다. `[결정 필요]`
- limb 재생 중 갑옷이 바닐라 갑옷과 같은 모습으로 보이는지 확인합니다. 🧪

## 7. 제작 요청 체크리스트 (애니메이터·AI용)

- [ ] `steve.bbmodel` 리그를 그대로 사용 (본 이름·태그 변경 금지)
- [ ] 길이가 틱 단위로 나누어떨어짐
- [ ] 첫 프레임과 마지막 프레임이 바닐라 서 있는 자세와 같음 (전환 시 튀지 않게)
- [ ] 이벤트 틱을 5장 표에 기록
- [ ] 소품 본은 시작·끝에서 크기 0
- [ ] 회전 루트 이동(몸 전체 이동)은 애니메이션에 넣지 않음. 이동은 서버가 실제 플레이어를 움직여서 처리 (모델과 판정 위치가 어긋나지 않게)

## 8. 리스크

| 리스크 | 대응 |
|---|---|
| 핑만큼 동작이 늦게 시작 | 동작을 짧게. 이동은 서버 속도 부여로 즉시 처리 |
| 본 수 × 플레이어 수 = 엔티티 폭증 (레이드 6인 동시 궁극기) | limb 본 수를 기본 리그 + 소품 3개 이하로 제한 |
| 스킨이 안 입혀짐 (오프라인 모드, 스킨 플러그인) | 테스트 서버에서 확인, 실패 시 기본 스킨 대체 |
| 본인 화면에서 모델이 카메라를 가림 | 소유자에게 limb 숨김 (2장) |
