# H20 — 헌터 전투 모션·판정·VFX 동기화

## 범위와 기준 (2026-10-22)

H19B(`bfd4b45`)에서 활 handed transform, V자 시위와 장전 화살 export를 수정했다.
이 단계는 그 결과를 대체하지 않고 아래 다섯 요구를 모두 구현·검증한다.
직전 목표 턴은 상태 확인과 작업 제안만 있었고 구현 진전은 없었다. 여기서 실제 변경을 시작한다.

**최종 상태:** 아래 S1~S6은 실패/수정 과정을 기록한 시간순 이력이다. 현재 인수는 S7 및

## S1. 구현 전략

- BetterModel 3.5.1 실제 API/스케줄러를 감사해 wall-clock과 server-tick 혼용을 제거한다. cleanup timeout만 늘리는 것으로 동기화를 주장하지 않는다.
- 새 H20 limb와 clip을 versioned 리소스로 제공한다. 설치된 H15/H19와 아티스트 모델은 `CREATE_NEW` 원칙으로 보존한다.
- 모션 authoring, VFX, 일반 스킬은 분리된 파일 소유권으로 병렬 작업한다. 중앙 세션/판정/통합은 주 작업에서 담당한다.
- GameTest/단위 검사 후 새 서버/actor/observer를 실행한다. native 논리 입력은 vanilla packet 경로를 사용하며 fixture 명령과 구별한다.
- 원본 Vision options, 보존 JAR, 기존 배포 ZIP, 설치 모델의 해시를 확인한다. 테스트 종료 시 lease/키/카메라/VFX/포트를 정리한다.

## S1 시작 시 알려진 결함 (S7에서 수정·검증)

- H19의 draw 판정은 7 server ticks인데 BetterModel 재생은 별도 시간축이어서 5TPS에서 release보다 모션 복귀가 빠르다.
- `.15s` 중간 당김에서 full drawn 아이템으로 바로 바뀌어 약 2.24 모델 단위의 접점 차이가 있다.
- Arc/GoldenGun 판정은 입력 시 즉시이며 준비 동작/회복 구간과 연결되지 않았다.

검증 결과와 실패는 단계별로 이 문서 및 QA 디렉터리에 추가한다.

## S2. 실제 스케줄러 전환과 첫 회귀 검사

BetterModel 3.5.1 `Tracker` 바이트코드에서 25ms 고정 scheduler와 별도 per-player 상태를 확인했다.
`BetterModelClockMixin`은 **우리가 claim한 player tracker만** server tick당 두 frame으로 옮긴다.
scheduled lambda의 frame 증가와 직접 `start()`의 tick도 같은 monitor에서 차단해 이중 진행을 막는다.
타 모델/VFX tracker에는 변경이 없다. 콜백 timeout만 조절하는 방식은 사용하지 않았다.

- 기존 GameTest104 + JUnit60 통과 (`s1-existing-suite.txt`).
- 새 실제 BetterModel fixture는 첫 시도에 `bone(String)` 이름 해석 차이로 NPE를 냈다. 실패 로그를 `s1-failed-fixture.txt`에 보존했다. raw bone predicate로 fixture를 바로잡았다.
- 새 검사 포함 GameTest105 통과 (`s1-clock-gametest.txt`): 225ms 서버 정지 중 실제 손 위치/owned frame 불변, 수동 tick마다 정확히 두 frame, close 이후 진행 없음.
- 이는 서버 상태 증거다. **client display의 미래 keyframe 보간과 실제 저TPS 화면 검증은 아직 인수하지 않았다.** 별도 보완·촬영이 필요하다.

## S3. 판정과 수명 통합 (구현 중)

- Arc/Solar에 전개 대기·단일 입력 예약·wind-up contact를 추가했다. 기본 contact는 각각5/3 ticks, 재입력은 회복 구간 동안 중복 판정을 만들지 않는다.
- Golden Gun HUD에 같은 prop의 등장/반동/복귀/소멸을 넣었다. 플레이어 aim/camera를 변경하지 않는다.
- 정상 종료만 accepted recovery를 허용한다. 명시적 `endSuper`, 사망/관전자 cleanup은 pending 세션·limb·카메라를 즉시 폐기한다.
- 궁극기 중 grenade/melee/dodge가 pending contact 모션을 교체하지 않도록 BUSY 처리한다. JUMP는 기존대로 허용한다.
- 위 S3는 아직 통합 테스트/화면 검증 전이며 완료가 아니다.

## S4. 전송 포즈 샘플링과 native item 변환 감사

- 소유 player tracker의 local animation channel을 서버가 도달한 fraction에서 먼저 샘플링한 뒤
  BetterModel hierarchy를 합성한다. 미래 keyframe 전송을 막고 smoothing은1틱으로 제한한다.
  다른 BetterModel 모델/VFX의 scheduler는 바꾸지 않는다.
- H2019클립, staged bow4개, bounded VFX lifecycle, 일반스킬T+4 contact를 통합했다.
- 초기127 GameTest green은 완전한 렌더 recipe를 입증하지 못했다. native display-inner Ry180을
  빠뜨린 fixture와 반대 handed JSON이 서로 상쇄된 오류였다. H19B handed 방향으로 복원하고
  unit/GameTest 모두 이 회전을 포함하도록 수정했다. 역사 H19/H19B 자산은 수정하지 않았다.
- 수정 후 release tick7의 실제 전송 hand/nock gap은0.0023블록,127 GameTest 통과.
  뒤이어 JUnit 컴파일은26.3 PoseStack API rename(`mulPose`→`rotateDegrees`) 때문에 실패하여
  API를 바로잡았다. 이 build를 전체 성공으로 기록하지 않는다.
- 강화한 ±30°·전단계 접점 검사는 첫 -30° tick1에서0.03185블록으로 .025 허용치를 넘겼다.
  최대값/전체 단계 진단을 수집 중이며 허용치만 올려 해결했다고 표시하지 않는다.

## S5. 첫 실제 화면과 aim/clock 결함 수정

- 새 서버와 Vision actor8102/observer8103에서 native sneak+swap/attack를 실행했다.
  `/tmp/destiny-h20-frames/void-right20`, `void-owner20`, `void-right5-before-aimfix`에 실제 프레임을
  수집했다.20TPS는 단계별 당김·릴리스가 보이며5TPS 화면은 **pitch30 아래 조준에도 활이 위를
  향하는 결함**을 드러냈다. 전단계 손 접점만 검사한 이전 fixture로는 방향 오류를 잡을 수 없었다.
- complete display recipe에서 전방+Z이므로 공유 upper-body modifier의 pitch 부호를 +로 수정.
  조준 궁극기(Void/Solar)에만 BetterModel 시각 tracker yaw를 authoritative view yaw로 지정하여
  독립 body smoother와 head yaw 제거로 생기는 사선 조준 불일치도 방지한다. 실제 몸/시점/입력은 불변.
- 강화 GameTest는±30pitch,70/−150yaw, 일부러 다른bodyyaw를 쓰고 전송 bone quaternion과
  emitted pipeline yaw를 합성한 화살 축이 실제 gameplay look와 dot>.9999인지 검사한다.
- 전단계 진단으로 첫1tick은 ready→draw reaching blend의0.03185블록, 이후 held/draw/release는
  최대0.002283블록임을 분리했다. 전환은<.04, 모든 실당김/릴리스는 더 엄격한<.005로 검사한다.
  단순히 전단계 허용치를 늘린 것이 아니다. 화면상 reaching이 자연스러운지도 최종 촬영에서 확인한다.
- clock audit의 queued/callback implicit animationTick 추가 진행 경로를 막았다. 정상 scheduled
  animation handler와 explicit prime만 일회용 permit을 소비하며 재진입 전에 permit을 해제한다.
- 위 aim/clock 수정과 추가 궁극기 timing16개 포함 **143 GameTest +88 JUnit, build 성공**.
  후속 clock guard fixture와 최종 새 JVM 화면 검증은 아직 진행 중이다. 최초 화면을 최종으로 쓰지 않는다.

## S6. 아크 중간 접점과 본인 화면 (진행 중)

- 정적 감사뿐 아니라40Hz 실제 전송 snapshot으로 Arc 양손 support gap을 측정했다.
  keyed pose는 맞지만 inter-key에서 최대0.1641블록 이격을 검출하여 GameTest가 실패했다.
  generator의 중간 IK 재계산으로 수정 중이며 허용치를 완화하는 대응은 하지 않는다.
- 사용자 추가 요구: 본인 화면에서 모델/활이 더 정면·중앙을 향해 사격 동작을 보여야 한다.
  사용자가 **기존 Void 강제 후방3인칭 유지, 중앙 구도 보강**으로 확인했다.
  gameplay aim과 visual barrel 방향을 따로 비틀어 중앙처럼 보이게 만들지는 않는다.
