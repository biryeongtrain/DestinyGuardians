# W82 — 경량 유탄의 도탄·원격 폭발

## 범위와 출처

- 정확한 `salvager_s_salvo` / Bungie **2060863616**, Lightweight intrinsic **474269988**만 적용한다. Wave/Compressed Wave/Heavy GL/로켓은 기존 동작을 유지한다.
- [보관한 조사와 원문](../../art/weapons/w82/reference-notes.md): 공식 intrinsic은 **발사 시 발사, 버튼 해제 시 폭발**을 명시한다. Bungie 2021-01-28 발표는 버튼을 유지해도 **캐릭터 접촉 시 폭발**을 명시한다. 지형 도탄과 최소 arming 존재는 커뮤니티 정성 자료다.
- 정확한 arming 수치, 조기 해제 무시/예약 여부, 원작 물리·최대 수명은 이번 자료로 확정하지 못했다. 아래 값은 Minecraft 설계이며 원작 수치라고 주장하지 않는다.

## 사용자가 선택한 입력 방식

**기존 양손 자세 유지, 해제 인식 지연 허용**을 명시 선택했다.

26.3 실제 `CrossbowItem.use`는 charged stack에서 native use/release를 시작하지 않는다. 기존 Polymer charged-crossbow 양손 자세는 유지하고 4tick 간격 반복 use로 6tick lease를 갱신한다. 반복이 끊겨 lease가 만료될 때 해제로 해석하므로 최대 약 **0.3초(정상 20TPS)** 지연이 있다. 지연 중 직접 접촉은 먼저 폭발할 수 있다. 빠른 누르기/떼기의 정확한 물리 해제 시각과 arming 경계는 복원할 수 없다. 서버 지연이 있으면 실시간 0.3초 보장은 아니다.

기존 명시적 `NATIVE` grip은 STICK+Consumable로 실제 release 패킷을 사용한다. 기본 Salvo를 한손으로 바꾸거나 클라이언트 모드를 요구하지 않는다. STICK+CHARGED_PROJECTILES만으로 HOLD pose를 얻을 수 없고, SPEAR pose도 twoHanded가 아니다. CONSUMABLE을 charged CROSSBOW에 붙여도 CrossbowItem override 때문에 해결되지 않는다.

## 로컬 시뮬레이션 정책

| 항목 | 정책 | 증거 경계 |
|---|---|---|
| 원격 arming | 발사 수락 이후 서버 10tick | **저작한 0.5초 기준**, 원작 수치 미확인 |
| 조기 해제 | 해당 입력 소유권을 소모하고 나중으로 예약하지 않음 | 원작 조기 해제 동작 미확인 |
| 지형 접촉 | native collider face 반사, 속도 .65배, .04block 표면 밖 이동 | restitution/offset은 로컬 |
| 적 직접 접촉 | 유지·arming 여부와 무관하게 기존 radial impact | 공식 발표와 부합, HP는 기존 로컬 PvE 값 |
| 안전 종료 | 기존 100tick/경로 거리 예산 유지, 16회 반사 상한; 먼저 도달하면 폭발 | 수명·거리·cap 폭발은 로컬 safety policy |
| 피해/탄약 | 기존 반경3/HP15×경량.95, 거리 감쇄/차폐/적 필터, 발사 시 한 발 지불 | 원작 피해 숫자/Spike impact split 미복제 |
| 표현 | 기존 arc 색상 trail/ring, 기존 GL fire/impact 음원 재사용 | 전용 ricochet 음원/실청취/원작 VFX 완전 복제 아님 |

지형 반사는 실제 폭발이 아니므로 impact 음원을 재생하지 않는다. 반사 후 해당 tick의 잔여 이동은 버리는 단순 유한 스텝 물리다. cap/거리 만료도 blast를 만드는 만큼 그 경계를 테스트와 문서에서 숨기지 않는다.

## 상태·소유권

1. 실제 `WeaponCycle.fire`가 한 발 지불한 뒤 한 Shot을 만든다. remote fuse는 그 Shot에만 존재한다.
2. State는 현재 유지 중인 단 한 remote Shot을 참조한다. 유지 중에는 마지막 발의 자동 재장전만 보류한다. 직접 적중/수명 종료/해제로 참조가 끝나면 원래 자동 reload를 진행한다.
3. 유효 원본 stack·owner 객체·level·catalog entry가 같은 release만 요청을 넣는다. 다른 stack release는 원격 폭발 권한을 얻지 않는다.
4. 수동 재장전/스킬/무기 교체는 **해제가 아닌 detach**다. 이미 지불한 탄환은 기존 탄도대로 계속 가지만 취소 동작 자체가 즉시 원격 폭발을 만들지 않는다.
5. 이미 수락한 release 이후 무기 교체가 그 폭발을 취소하지 않는다. 반대로 취소된 이전 입력이 새 Shot을 폭발시키지 않는다.
6. 죽음/로그아웃/관전/차원 이동/서버 종료는 기존 cleanup과 projectile budget으로 정리한다. 새로운 타이머 스레드/클라이언트 직접 데미지/재지불은 없다.

## 회귀·검증

기존 W78 `ordinarySalvagersSalvoStillExplodesRadially`는 이제 의도적으로 폐기된 **지면 즉시 폭발** 가정을 갖고 있었다. 첫 693GT에서 그 한 시험만 실패한 원본을 보관한다. 해당 시험은 **첫 segment 실제 적 접촉**으로 전환해 같은 후방/측면 radial 피해, 전방 wave 없음, 소멸 검사를 보존하고 실제 충돌·한 발 지불 preflight를 추가했다. 다른 시험을 빼거나 assertion을 약화해 통과시키지 않는다.

새 unit/GameTest와 실제 Vision 검증 결과는 [QA](../qa/2026-10-25/w82/README.md)에 분리 기록한다. 실제 framebuffer를 보지 않은 시점에는 시각 성공을 주장하지 않는다. 전체 무기/HUD 목표는 아직 진행 중이다.
