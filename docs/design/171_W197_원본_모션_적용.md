# W197 — 추출한 장전·아크 모션의 제품 적용

W196에서 평가한 원본 FBX pose를 기존 모델에 연결한다. 이번 배치는 원본 자료 검사에서 실제 모델/리소스 변경으로 넘어간다. 원본 SSD·W196 봉인 QA는 읽기 전용이며 일반 Minecraft 프로필과 live Blender/Blockbench 작업은 보존한다.

## 작업 분할

| 담당 | 제품 변경 | 배타 소유 범위 | 수락 조건 |
|---|---|---|---|
| 이자나기 worktree | 일반/특수 후보 장전, 탄창·볼트 | W91 generator/기존 출력, W197 motion dataset, 관련 asset tests | 원본 pose 유래, 기존 79큐브·UV·양손/좌우 손·충전/조준 유지, 중립 복구 |
| 에이스 worktree | 실제 `80A8A567` 본체 및 확인 가능한 실린더 모션 | W157 generator/기존 출력, W197 motion dataset, 관련 asset tests | Duke 대체 금지, 원본 근거/미확정 부품 구분, 기존 메시·Memento·ADS 유지 |
| 헌터 worktree | 아크 지상 전개·약공격 리타게팅 | 새 W197 bbmodel/animation resource/generator/dataset/test | source rest/topology에서 target limb 변환, 18개 다른 클립·rig·staff 연결 유지 |
| master | 새 헌터 모델 설치 경로, 통합·회귀·Vision/CU | 공유 Java/통합 테스트/QA | 새 모델 버전 설치, 기존 타이밍·탄약·자동 Shadowshot 보존, 실제 화면 검증 취합 |

세 worktree는 현재 미커밋·untracked 기준선 67,743개 파일(SHA `1e1950547af54694cb48952159032fdee905e5c00d14c9aefa5850aea6d67b04`)을 CoW로 복제했다. 작업 manifest는 QA의 `batch.json`으로 보존한다. master는 반환 소유 경로와 main의 baseline hash를 비교한 뒤 통합한다.

## 유지할 동작과 변환 원칙

- 장전 progress 21단계와 실제 탄약·완료 시점은 기존 서버 runtime이 관리한다. source 4.2초/3.366667초를 기계적으로 게임 장전 시간에 덮어쓰지 않는다.
- 아크는 기존 전개 0.50초, 약공격 0.35초, 접촉 0.10초를 유지하고 원본 포즈를 이 시간축으로 변환한다. 새 body motion이 더 느린 손작업 모션으로 퇴행하지 않게 한다.
- source는 armature object 공간의 누적 행렬이다. 바깥 FBX 0.01/축 회전은 이중 적용하지 않는다. 원본 본 순서와 target 순서를 zip하지 않는다.
- 메시·큐브·UV를 유지하고 변환/부품 분할만 필요한 범위에서 바꾼다. 확정되지 않은 hash 본에 실린더 같은 이름을 임의로 부여하지 않는다.
- 이자나기의 `80A8A14D`는 source `reload_special` 후보이며 Honed Edge 독점 타이밍의 증명은 아니다. 실제 적용한 source 범위와 authoring 보정은 별도 기록한다.
- Shadowshot 자동 준비→발사·연속 사운드와 기존 공허 리그는 이 배치에서 보존한다. VFX JSON의 미해결 링크는 애니메이션 적용 성공과 구분한다.

## 단계별 기록

1. 기존 장전/rig·실제 패킷 입력·native QA 경로를 읽고 소유 파일과 테스트 범위를 지정했다.
2. 세 worktree 복제와 격리 GCB 의존성 기준선 검증을 완료했다. worker는 원본 입력·공유 Java·native 창을 변경하지 않는다.
3. master가 Finder의 데스크톱 상태와 비어 있는 Vision 8102 포트를 확인했다. 배치 전체를 최대 3,600초 awake coordinator로 감싸 준비·빌드·기동 사이의 idle 구간도 포함한다.
4. 세 worker의 소유 delta 351개(에이스83·이자나기262·헌터6)를 main baseline과 비교한 뒤 통합했다. 새 헌터 모델 id/resource를 선택했으며 이전 설치 모델은 덮어쓰지 않는다.
5. 통합 Python source/재현 검사39개(에이스22·이자나기8·헌터9)와 scope 검사6개가 통과했다. 생성물은 각각88·323·2개 byte-exact로 재현됐다.
6. 첫 targeted JUnit27개 중 scope 입력 pin1개가 변경된 W91 wrapper를 가리켜 실패했다. scope generator의 pin과 manifest를 갱신했고 scope 제품7개는 이전과 byte-identical임을 확인했다. targeted 재실행27개와 전체 JUnit1,958개·assemble가 통과했다.
7. 격리 Vision에서 양 grip 장전4회·ADS5회, 이자나기 특수 장전 관측, 아크 전개·공격·이동을 기록했다. 아크 서버 이동은 약4.23블록이며 cleanup 뒤 본인 카메라와 입력 중립을 확인했다. 특수 장전 발동은 명시적 서버 fixture이므로 native Ctrl+Q 증명이 아니다. 상세 결과는 봉인 QA의 `verification.json`에 있다.
8. 사용자가 장전·궁극기의 끊김과 느린 보간을 지적했다. W197 기능 검증을 최종 모션 품질 수락으로 취급하지 않으며, 후속 [W198](172_W198_애니메이션_갱신과_보간.md)에서 표시 갱신과 보간 재시작을 수정한다. W197의21샘플 설명은 당시 구현 기록이다.

## 검증 범위

각 worker의 의미 있는 source/part/endpoint 검사 후 master가 관련 JUnit과 최종 전체 gate를 한 번 취합한다. 새 전투·탄약 코드를 추가하지 않는 cosmetic 경로지만 기존 lifecycle·양손·scope 경로가 유지되는지는 확인한다. native 테스트는 격리 서버와 client에서 장전 양손/한손, 이자나기 충전/복귀, 아크 3P 전개·공격을 모아 실행한다. 모델/입력/서버 결과/PNG를 구분하고 실패·미검증·cleanup을 남긴다.
