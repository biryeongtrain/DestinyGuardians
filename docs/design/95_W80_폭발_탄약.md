# W80 — 폭발 탄약

## 목적과 출처

기본 **Explosive Payload / 3038247973**를 실제 유료 hitscan 발사에 연결한다. 기존 전체 직격 피해에 폭발을 더하지 않고, 물리와 비정밀 폭발로 분리한다.

## 피해 계약

현재 실제 DDC 원문 행과 색상 legend, 고정 commit Clarity 원문을 보관한다. `B`는 기존 무기의 Minecraft 몸통 HP 피해, `M`은 기존 정밀 배율, `F`는 기존 탄도 거리 감쇠다. Destiny 표시 피해를 Minecraft로 환산한 값은 아니다.

- 몸통 직격: `0.5 B F`
- 정밀 직격: `(M − 0.5) B F`
- 폭발: `0.5 B × 1.3 = 0.65 B`, 정밀 불가
- 근거리 총 몸통: `1.15 B`, 총 정밀: `(M + 0.15) B`
- 반경 원문:3m. 물리 정밀 배율을 보정하므로 정밀 피해 전체를 반으로 나누는 방식은 틀리다.

50% 분리, PvE 폭발+30%, 정밀 보정,3m는 커뮤니티 원문으로 확인했다. **폭발의 탄환 비행거리 감쇠 면제는 이번 원문에서 확인하지 못했으므로 명시적 local 정책**이다. 이를 검증된 원작 사실로 주장하지 않는다. 증가한 stagger의 숫자/면역무시/챔피언 stun은 출처가 없어 구현하지 않는다. ↑+5 reload는 강화판 전용이며 기본 EP에 주지 않는다.

## 명시적 Minecraft 정책

- 한 source meter를 한 block으로 대응한다. 구면 반경, nearest AABB point 거리, 경계 포함과 `.25` 바닥의 `max(.25,1−d/3)` 감쇠는 직접 설계했다.
- 실제 맞은 주대상은 폭발 전 살아 있으면 폭발 전량을 받는다. 물리로 죽어도 착탄점 주변 폭발은 발생한다. 직접 피해가 면역으로 거부되어도 실제 충돌이 있다면 주변 적 폭발을 검사한다.
- 실제 entity/block 접촉에서만 폭발한다. MISS는 폭발하지 않는다. block face는 바깥으로1/64block 이동해 collider 내부에서 clip을 시작하지 않는다.
- secondary는 loaded segment 확인과 바닐라 COLLIDER clip을 통과해야 한다. chunk를 강제로 로드하지 않는다. 엄폐/반경 밖/동맹/길들인 동물/플레이어/자신은 제외한다. 지형 파괴와 화재는 없다.
- broad-phase AABB만1e-6 확장해 엄밀한 접촉면 교차에서의 누락을 막고, 실제 거리 판정은 정확한 `distance² ≤ 9`를 유지한다.
- 주대상 우선, 거리/UUID순으로 정렬하여 **실제 admission128개**를 제한한다. 차폐된 후보가 cap을 소비하지 않는다. 이는 성능 percentile 검증은 아니다.

## 거래·귀속·기존 시스템 보존

`WeaponRuntime.fire`의 기존 탄약 지불과 cadence를 유지한다. 별도 폭발 탄약 지불/추가 발사/프로젝트타일/recursive proc를 만들지 않는다. `WeaponPayload.Token`은 실제 owner/level/stack/entry를 캡처하고 한 번만 소비하며, 소유권과 현재 유효 특성을 다시 확인한다. 스택 stow는 허용하지만 교체·폐기·다른 무기ID로 수정은 거부한다.

물리 피해가 먼저, 폭발이 뒤다. 두 성분은 기존 source의 buff/attribution을 쓴다. 폭발은 `precision=false`이며 Outlaw·Triple Tap/FTTC·Dragonfly 정밀 callback을 받지 않는다. 합법적인 물리 정밀 처치는 여전히 원래 특성을 발동할 수 있다. 현재 다섯 무기의 공식 풀에는 EP+Kill Clip/Rampage/Dragonfly의 합법 조합이 없으므로 일반 kill-token 지원을 임의 조합 허가로 해석하지 않는다.

기존 무기 모델/리로드/조준/오디오/HUD/지면 파동 규칙과 모든 기존 client assets는 그대로 둔다. native EXPLOSION/CRIT 입자와 기존 weapon impact 음원을 재사용한다. 전용 리핑 EP 효과/음원, 원작 전투 수치 전체 복제, enhanced/Timed/PvP는 이 단계 범위 밖이다.

## 검증 경계

자동 시험은 실제 paid beginUse/releaseUse와 서버 tick, 엄폐/범위/정밀 귀속/NBT/소유권을 검사한다. Vision 입력 완료는 서버 HP와 실제 framebuffer 증거와 분리한다. 실제 화면 검증 결과·실패 보존·팩/JAR provenance·정리는 [QA](../qa/2026-10-24/w80/README.md)에 적는다. 전체 무기 시스템 goal의 완료를 뜻하지 않는다.
