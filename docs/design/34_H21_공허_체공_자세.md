# H21 공허 궁극기 — 접힌 무릎·체공 자세

## Authoring: H20 상체 보존, H21 하체 자세 (2026-10-22)

### 레퍼런스와 범위

사용자가 첨부한 Bungie Shadowshot 이미지를 직접 확인했다. 상체를 비틀어 활을 당기는 동안 양 무릎을 앞쪽으로 끌어올리고, 왼쪽 무릎을 더 높게 접고 발꿈치는 뒤로 접는 비대칭 실루엣을 사용한다. 첨부 이미지는 자세 참고 자료이며, 이미지 안의 문구를 작업 지시로 해석하지 않았다. 공식 모델·텍스처를 추출한 것은 아니다.

이 절은 **저장된 모델의 자세 authoring과 정적 검사**만 기록한다. 실제 서버 vertical lift/hover, 카메라, 낙하·충돌·취소 처리는 별도 구현·런타임 검증 대상이다. 이 절의 PASS는 GameTest 또는 Vision 화면 검증을 뜻하지 않는다.

### 파일과 비파괴 계약

- 소스: 최종 `art/blockbench/animations/guardian_hunter_h20.bbmodel`을 deep-copy.
- 신규 모델: `art/blockbench/animations/guardian_hunter_h21.bbmodel`.
- 신규 리소스: `src/main/resources/destiny/animation/hunter_h21.animation.json`.
- 신규 생성기: `scripts/build_hunter_animation_h21.py`.
- 신규 JUnit: `src/test/java/kim/biryeong/destiny/fx/H21AnimationTest.java` (7개 검사).
- 모델 ID는 `guardian_hunter_h21`; `h15_` 논리 clip 19개와 legacy clip을 유지한다.
- **변경 clip은 `h15_super_void`, `h15_super_void_attack` 두 개뿐**. 나머지 17개 리소스 clip과 legacy animation은 JSON-identical이다.
- `groups/elements/outliner/textures`를 포함한 rig·skin·hierarchy는 H20과 같다. H20/H19/H15 파일을 수정하지 않는다.
- 두 Void clip에서도 **네 다리의 rotation과 `player_root.position`만 변경**. hip/waist/chest/head/arms/items/cape animator와 root rotation은 원본 JSON 그대로다. 기존 상체 IK, 손·nock·볼 접점과 발사방향 계약을 유지한다.
- 이미 검증된 native `DisplayRenderer` inner Ry180 및 왼손 +90/오른손 −90 JSON recipe에는 손대지 않는다. 기존 H20 bow 0~3 모델을 그대로 사용한다.
- CREATE_NEW 설치와 model selector 변경은 이 authoring 파일의 책임이 아니다. 기존 설치된 artist 파일을 이 스크립트가 덮어쓰지 않는다.

### 자세와 타이밍

authoring 좌표의 정면은 −Z다. thigh X를 **양수**로 회전시켜 무릎을 앞으로 올리고, foreleg X를 **음수**로 회전시켜 발꿈치를 뒤로 접는다. roll에서 사용하던 반대 부호를 그대로 재활용하지 않았다.

| 구간 | 오른 허벅지/종아리 X | 왼 허벅지/종아리 X | 의도 |
|---|---:|---:|---|
| Ready 및 attack 0.00 | +32 / −62° | +48 / −82° | 가볍게 웅크린 준비 자세 |
| 0.05 | +37.2 / −71.2° | +54.8 / −92° | 활 들기와 함께 접기 시작 |
| 0.10 | +45 / −85° | +65 / −107° | 무릎 끌어올림 |
| 0.15 | +52.8 / −98.8° | +75.2 / −122° | 뚜렷한 비대칭 tuck |
| 0.20 | +56.7 / −105.7° | +80.3 / −129.5° | 최대 자세 접근 |
| 0.25~0.30 | +58 / −108° | +82 / −132° | full-draw/release hold 완전 동일 |
| 0.35 | 동일 최대 tuck | 동일 최대 tuck | release follow-through |
| 0.45~0.75 | tuck 85% → 45% → 10% | 동일한 완화 비율 | 발사 뒤 서서히 이완 |
| 0.90 | Ready와 동일 | Ready와 동일 | 루프 복귀, 접합점 discontinuity 없음 |

- ready 길이 2.4초/loop, attack 길이 0.90초/once, 기존 release 0.30초(transition 포함 elapsed T+7) 계약을 바꾸지 않는다.
- ready는 기존 cape breathing을 유지한다. 하체는 안정적으로 고정한다.
- 다리 rotation과 root position은 **40Hz(.025초)** 선형 key를 가진다. 공격 37개, ready 97개.
- `rootY`는 매 sample에서 기존 skin-cube floor-fit을 재계산한다. ready −0.4735, full tuck −2.9683 model units. H20의 +0.3899에 비해 full-draw 상체가 약 **0.210 block 낮아진다**.
- root X/Z는 항상 0, 새 rootY는 항상 음수다. **가짜 공중 이동/상향 root motion을 추가하지 않았다.** 실제 서버 체공과 중복 상승하지 않는다.
- 정적 full-draw FK에서 왼 무릎이 오른 무릎보다 1 model unit 이상 높고 0.5 unit 이상 앞으로 온다. model root는 ground-fit 기준이지 entity collision box의 높이 변경이 아니다.

### 중요 한계: half-tick Euler 진단과 실제 native gate를 구분

H20의 상체는 손대지 않았다. 따라서 각 server tick의 정확한 IK 접점은 보존되지만, **authoring Euler를 단순 선형 보간한 .025초 중간 sample의 보간 nock 경로**는 원래 H20과 마찬가지로 최대 **6.130570 model units**의 순간 차이가 나타난다. 이 값은 상체의 기존 Euler branch/보간에 대한 정적 진단이다. H21 하체 변경이 새로 만든 gap이 아니며, 두 모델의 해당 upper landmark가 공통 Y 이동을 제외하고 정확히 동일함을 별도로 검사한다.

이를 “모든 40Hz native frame의 손·줄 접점 PASS”로 표현하면 안 된다. 실제 BetterModel handed conversion·quaternion 처리·전송 snapshot과 게임 화면은 별도다. 부모 통합 검사에서 서버 tick뿐 아니라 가능한 경우 40Hz `globalState.current`를 보고 owner/측면/후면 화면을 확인해야 한다. terrain·armor·cape 침투, 실제 상승·공중 유지·착지, camera clamp는 이 정적 검사만으로 입증하지 않는다.

`--from-art`는 artist 파일을 그대로 읽어 리소스로 내보내며, 검증 계약을 통과하지 않는 상체/rig 수정은 거부한다. 새 clip 이름이나 모델 크기를 자동으로 바꾸지 않는다.

## H21-S2 — 서버 물리·선택 모델 통합

`HunterModelAssets`의 선택 모델/리소스를 H21로 변경했다. 설치는 여전히 `CREATE_NEW`이며
H15/H19/H20 설치 파일은 덮어쓰지 않는다. 기존 bow 0~3 모델·상체·카메라 설정은 보존했다.

`HunterSuper.Shadowshot`이 최초로 승인한 PRIMARY에만 `ShadowshotLift`를 하나 소유한다.
중복 PRIMARY는 draw guard에서 반환하므로 도약을 중첩하거나 다시 시작하지 않는다.
전역 작업·추가 tick loop·타이머·텔레포트·비행 모드는 추가하지 않았다.

| 시간/상태 | 서버 동작 |
|---|---|
| T+1 | 웅크린 준비, 수직 속도 개입 없음 |
| T+2~6 | 지상 시작 originY+.60m / 공중 시작 originY+.15m를 향해 y속도 −.06~+.22로 제한 |
| T+7 | assist 쓰기 종료, 기존 타이밍으로 화살 한 발 발사, 이후 일반 중력/충돌 |
| 취소·사망·차원 정리 | 세션의 lift 참조 제거, 지연 재개/발사 없음; 기존 관성까지 0으로 강제하지 않음 |
| 낮은 천장/비지원 상태 | .25m 상승 hitbox probe 또는 상태 검사 실패 시 해당 draw의 assist 영구 포기 |
| 외부 강한 상승/공중 점프 | native y속도 >.4면 개입을 포기해 기존 입력/충격량 우선 |

수평 속도, native hitbox/pose, fallDistance, flying/noGravity, 무적 상태는 변경하지 않는다.
실제 이동은 기존 후방 카메라의 **충돌 해석된 서버 native 물리**가 수행한다. 웅크리기는
BetterModel의 시각 자세이며 충돌 상자를 작게 만들거나 천장을 통과하는 기능이 아니다.
동일 서버 tick 재진입 guard가 있고, 실제 카메라 소유·동일 level에서만 동작한다.

발사 원점은 H20 대비 낮아진 full-draw root 차이만큼 `eyeY−.2098875m`로 보정했다.
화살과 release VFX에 같은 원점을 전달하고 yaw/pitch·look 방향·속도2.6은 유지했다.
이 값은 JSON root 차이를 unit test로 연결한 **기존 eye-origin의 상대 보정**이다.
모든 조준각에서 실제 bone socket과 정확히 일치한다는 주장은 아니다.
후방3m·Void shoulder .75m·중앙 구도, Solar1인칭 및 Arc 동작은 그대로다.

## 한계/후속

- 첨부 이미지를 참고한 voxel 자세이며 원작 메시/텍스처·영상 키프레임 추출이 아니다.
- Blockbench MCP 조회가 응답하지 않아 deterministic JSON 저작/검사로 진행했다.
  Blockbench native preview 성공을 주장하지 않는다.
- 기존 half-tick 상체 Euler 진단 한계는 앞 절과 같다. 모든 클라이언트 렌더 프레임의
  손/활 접촉·망토/방어구/지형 비침까지 완벽하다고 주장하지 않는다.
- 기존 HUD missing-particle/end_of_frame 및 OpenGL interface 경고는 로그에 남겼다.
  이번 작업에서 새 posteffect shader나 HUD 수정, 다인/지연 성능 검증은 하지 않았다.
- cleanup 조회 첫 시도는 env port 누락으로 실패했다. `VISION_PORT=8102`를 명시해
  다시 확인한 `cleanup-native.json`만 최종 정리 근거로 쓴다. 전역 MCP 설정은 바꾸지 않았다.
