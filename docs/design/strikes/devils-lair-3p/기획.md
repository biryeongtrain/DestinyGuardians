## 3. 맵 제작 원칙

### 좌표와 크기

원본 XYZ는 Z-up. 마커 변환은 `world = origin + s × (x, z, -y)`이며 s=1을 1차 대조값으로 둔다. GLB는 이미 Y-up으로 회전되므로 재회전하지 않는다. actor local은 부모 회전/이동과 합성해야 한다. CSV의 parentXYZ만으로 정확한 최종 spawn을 선언하지 않는다.

원본 전체 bounds는 배경/공유 지오메트리 영향으로 야적장 폭 약8748, 소굴 약29070 source unit까지 나온다. 이 bounds를 플레이 가능 맵 크기로 삼거나 전부 블록화하지 않는다. **주동선과 전장 crop → 충돌/길찾기 → 배경 실루엣** 순서로 나눈다. 바닥·벽·엄폐는 실제 블록 충돌, 먼 우주선/스카이라인은 접근 불가능한 시각층으로 만든다.

아래 좌표는 전술 graybox용이다. 각 구역 입구 방향을 로컬 남쪽(z=0), 진행 방향을 북쪽(+z), x는 좌우, y는 해당 바닥 대비 높이로 정한다. **원본 GLB 실측 평면도가 아니다.** 원본 지오메트리 overlay 이후 구역별 rigid transform과 crop을 확정하며, 통로·사선 규격을 맞추기 위한 수정은 기록한다. 본문의 계획 좌표를 추출 좌표에 직접 섞지 않는다.

### 공통 전투 공간

- 완전 엄폐 높이2–3블록, 낮은 시야 조절물1블록. 1블록 장애물을 자동으로 앉은 사격 엄폐라고 간주하지 않는다. 기존 이동/사격 높이에 맞춰 시험한다.
- 엄폐 사이 노출 이동은 실내6–10, 실외10–16블록. 핵심 목표에서 한 방향만 보는 무적 사격 자리는 만들지 않는다.
- 핵심 통로 경사/계단은 AI가 지나갈 수 있게1블록 단차로 정리한다. 장식 배관을 바닥 충돌로 방치하지 않는다. 보스 눈/워커 다리로의 사선을 최소2개 확보한다.
- 개인 점프·대시로 접근할 수 있는 외곽은 연속 난간/벽 또는 명확한 낙하 경계로 처리한다. 투명 장벽만으로 실제 갈 수 있을 듯한 길을 막지 않는다.
- 전장 전환은 12–20블록 길이의 굽은 연결 통로로 시야를 끊는다. 다음 전장 준비 전 입장 금지, 현재 교전 중인 플레이어 앞에서 맵 배치 금지.
- 도착 발판은3명이 겹치지 않는 최소8×6블록. 체크포인트는 적 스폰/보스 포격/장벽 충돌과 겹치지 않는다.

## 4. 적 팩, 웨이브, 최대 동시 수

### 용어와 전역 규칙

- **몹 팩:** 같은 진입로·활성화 이벤트를 공유하는 최대8기의 전술 단위. 아래 모든 일반 팩은8기다.
- **웨이브:** 여러 팩을 포함하는 진행 단위. 방어2/3의32기는 동시에32기가 아니라 24기 상한 안에서 순차 도착한다.
- **동시 수:** 살아 있는 전투 actor 수. 무적 세픽스, 보호막 서비터, 브리그, 워커도 포함. 워커 다리 판정체는 한 actor의 부위이며 몹으로 중복 집계하지 않는다.
- 화면용 무공격 스키프는 동시 actor 상한 밖이지만 구역당1대, 고스트 대표1개다. 스키프 포탑 공격은 첫 버전에서 사용하지 않는다. Display/히트박스/파티클 entity 예산은 별도다.
- 현재 구역만 적을 활성화한다. 뒤 구역 잔존 적을 다음 구역으로 끌고 가지 못하며 필수 전투 완료 후 경계에서 정리한다.

### 예약과 안전한 스폰

팩8기의 전체 자리를 먼저 예약하고2기/틱 이하로 생성한다. 생성 중 예약도 하드캡에 포함한다. 기존 팩의 생존자가 있으면 활성 팩으로 세며 최대 팩 수와 actor 수 중 하나라도 초과하면 큐에서 기다린다. spawn을 실패했다고 처치로 간주하지 않는다.

SP는 피해 구간에도 **서비터3자리를 미리 확보**한다. 따라서 피해 구간 일반 몹 상한20(세픽스1 포함 총21), 보호막 전환 후 최대24다. 강제 무적 상태를 먼저 만들고 필수 서비터가 영원히 대기하는 교착을 방지한다. 서비터 그룹은3자리 원자 예약, 실제3기 생성 확인 후 실드 링크가 켜진다.

- 스폰 후보는 진입로별 최소3개 발판. 플레이어 최소12블록, 되도록 LoS 밖. 부족하면 먼 후보→문 뒤 대기 순서, 플레이어 발밑/등 바로 뒤 pop-in 금지.
- 하차/문 개방 예고2초, 생크/서비터 전이 예고1.2초. 예고 중 피해 없음. 블록 지형·몸통 여유·도달 가능한 경로 확인 후 활성화.
- 연속 증원은 최소6초 간격이며 여러 HP 임계치를 동시에 넘겨도 한 팩씩 FIFO 처리. 현재 이벤트/actor cap은 인원수와 무관하다.
- 필수 적이 전장 밖/unload로 lost되면 같은 slot ID/남은 체력으로 안전 발판에 재배치한다. kill/reward 증가 없음. 10초간 경로 불능이면 재배치, 같은 slot3회 실패면 해당 encounter를 checkpoint로 복구하고 로그 기록. 성공으로 넘기지 않는다.
- 보스 처치 시 해당 전투의 선택 증원 큐 취소, 이미 살아 있는 잡몹은 짧은 퇴각 후 제거. 제거는 처치·드롭·궁극기 에너지 지급 아님.

워커 다리 HP는 코어와 분리된 제압 자원이며 코어1600에 다리600을 합쳐 HUD에 표시하지 않는다. 다리 파괴→0.8초 stagger→12초 코어 노출, 다른 다리 피해는 단계마다 유지. 코어 외피는0.1배, 노출 코어1배, 다리는1배; 여섯 다리를 모두 쓴 뒤 코어가 남으면 회복 종료 후 가장 오래 파괴된 한 다리를100으로 복원해 전투가 막히지 않게 한다. 코어 사망이 유일한 워커 완료 조건이다. 기존 WalkerBoss와 다르면 활동 전용 tuning/상태로 구현하며 튜토리얼 보스를 전역 변경하지 않는다.

세픽스 눈은 기존 무기의 정밀 계수만 적용하고 별도2배를 중복 곱하지 않는다. 체력67/33%에서 해당 경계에 피해를 clamp하고 다음 실드 단계로 한 번 진입한다. 초과 피해는 다음 단계로 저장하지 않는다. 보호막 해제 후2초 복귀 여유, 무한 DPS 시간 제한 없음. 실드 중 서비터3기를 잡으면 즉시 해제하며 호위 팩 전멸까지 요구하지 않는다. 이동은 유효한4anchor 중 현재와 다른 곳, 최소10초 간격, 0.8초 예고/0.4초 전이; 벽·천장·플레이어와 충돌하면 이동을 취소한다. 전이 중 무적 총1.2초, 수신 피해는 버리지 않고 무적 피드백을 표시한다.

최근 변경한 PRIMARY1.5/SPECIAL2.5/SUPER3.0은 `PveDamageBalance`에서 이미 적용된다. 이 활동에서 추가 배율을 곱하지 않는다. **특탄 정상 유효거리 중심 명중으로 일반 드렉1기, 직접 타격형 궁극기의 정상 명중으로 일반 드렉1기 이상을 확실히 처치**하는지 수락 검사한다. 산탄 일부 펠릿/사거리 밖, 지속형 궁극기의 단일 tick, 지원 궁극기를 같은 단발 기준으로 취급하지 않는다. 미달이면 hit/저항/실피해 경로부터 확인하고 드렉 HP만 낮춰 판정 문제를 숨기지 않는다.

## 6. 진행·전멸·재접속·보급

- 입장:3개의 참가 슬롯을 확정하고3명 world/pack ready 후 시작. 공개 매칭은 이번 기획 범위 밖. 중도 신규 참가 금지, 기존 참가 UUID 재접속은 허용한다.
- 이탈: 남은 팀의 수치/팩/타이머는 유지. 재접속 슬롯120초 보존, 돌아온 플레이어는 현재 단계 안전발판으로 합류하고 저장 로드아웃·탄약을 이어간다. 재접속 보급/보상 반복 없음.
- 전원 오프라인: 입력 없는 활동 일시정지,120초 내 복귀 없으면 안전 종료. 살아 있는 접속자0명이며 down 상태만 남으면8초 전멸 카운트; 누군가 부활하면 취소. 정상 게임 중 disconnect를 살아 있는 팀원으로 무한 보존하지 않는다.
- 부활: RY 개인 자동 부활5초. RF/BL/SP 전투는 자가부활30초, 아군 revive3초 상호작용. 부활 토큰 제한 없음. 부활 후3초 보호, 공격 시 보호 종료.
- CP1은 RF 입장 전: 초기 확보와3회 방어 전체 초기화. CP2는 BL 입장 전: 워커/브리그/증원 reset. CP3는 SP 입장 전: 경비/보스/실드 모두 reset. 완료한 이전 구역으로 되돌리지 않는다.
- 체크포인트 reset 시 encounter generation을 바꾸고 이전 actor/큐/콜백/잠금/소리 모두 폐기한다. 재스폰을 처치로 세지 않는다. 보스 HP/기믹을 재접속만으로 초기화하지 않는다.
- HP는 checkpoint restart 시20. 특탄/중탄은 그 체크포인트 최초 보급 수락 직후 저장한 탄약(보급 미사용이면 최초 진입 잔량) 이상으로 재시도마다 복원하지 않고, `max(사망시 잔량, 진입 저장량)`으로 복구한다. 이후 전멸로 탄약이 증식하지 않도록 checkpoint별 baseline은 불변. 궁극기는 사망 시 잔량 유지, 전멸 충전 보너스 없음.
- 구역 첫 진입 시 개인 보급 상호작용1회: 특탄 reserve를 해당 무기 최대의50%, 중탄25%까지 보충(이미 많으면 유지). mags/무기 정체성 변경 없음. 재접속·전멸로 사용권 재발급하지 않는다. 일반 ammo economy drop을 유지하고 인원별 드롭 배율을 붙이지 않는다.
- 배고픔 고정·자연 회복 차단·비전투 fractional 회복은 기존 서버 시스템 사용. 별도의 활동 회복 루프를 만들지 않는다.
- 완료: 실제 Sepiks death 이벤트에서 activity UUID+player UUID 보상키 저장 후 개인1회 지급. 첫 버전은 기존 활동 보상 컨테이너 연결까지, 원작 고유 무기를 새로 복제 지급하지 않는다. 상자 클릭 실패와 disconnect는 미수령으로 보관한다. 보상 종류/양은 기존 경제 정책 연결 전 결정 항목이다.

시네마틱은 시작 브리핑의 입력 잠금과 보스 각성 최대4초만 사용한다. 정제소는 이동 가능한 고스트 동작, 워커/브리그는 gameplay 안에서 시선 유도한다. 원본 등장 동작이4초보다 길면 강제 잠금을 늘리지 않고 뒤 구간은 gameplay로 이어지도록 연출을 조정한다. 화면을 검게 가린 동안 공격/낙사 없음. 한 명 재접속 때문에 팀 연출을 다시 재생하지 않는다.

BGM은 RECORDS(주크박스), 장전은 PLAYERS. 음악은 접근/정제소/기계전/보스/완료의5개 큐를 목표로 하되 원본41 WEM 중 실제 clip을 청취·루프 분석해서 매핑한다. `80D63BFA`는 제외. 파일 순서로 이어 붙이거나 원작 전투 레이어를 복원했다고 주장하지 않는다. 기본판에 황혼전 Sepiks Redux를 자동 적용하지 않는다. 현재 기획은 큐 기능과 원본 후보를 지정한 것이며 최종 음악 편집본은 아니다.

`RisingServices.FallenKind`는 현재 DREG/VANDAL/CAPTAIN/SHANK/WALKER뿐이다. 전달 모델이 있다는 이유로 군체·브리그·서비터의 AI가 이미 있다고 판단하지 않는다. `GuardianRisesInstances`의 owner 기반 lifecycle은 팀 소유권으로 확장하거나 새 adapter를 만들고, 기존 튜토리얼 progress enum/저장값을 변경하지 않는다. `RisingEncounters`의 기존 MAX_ACTIVE=24는 새 전장의32상한과 분리한 활동 설정으로 구현한다.

사용할 경계: `Combat.damage/PveDamageBalance`, 무기 `AmmoGeneration` attribution, 현재 ammo economy, DisplayHud/ObjectiveTracker, presentation의 멱등 cleanup. 기존 `guardian_rises/` dimension 한정 코드는 새 공격전 scope에 명시적으로 연결한다. 실드 연결과 보스 판정은 월드 모델 표시에 의존하지 않으며 server authority로 계산한다.

## 9. 수락 기준과 남은 확정 작업

### 플레이/성능 수락

- 실제3명 기준 완료, 인원 이탈/복귀에도 HP/팩/타이머 불변. 입장3인 규칙과 재접속120초 정책 확인.
- 모든 일반 팩≤8, 구역 actor 상한24/24/32/24를 예약 중까지 준수. actor cap 때문에 필수 서비터/보스 전이가 교착되지 않음.
- 적을 빨리 죽여도 중복 증원/단계 스킵 없음. 느리게 잡아도 유한 증원 이외 추가 없음. 세픽스 실드 두 번만 발생.
- 3인 상이한 클래스/흰탄·특탄·궁극기로 실제 hit/kill 검증. 정상 특탄/직접 궁극기 명중 드렉 처치 기준 충족.
- 정제소 전멸, 워커 전멸, 실드 중 전멸, 보스 사망 직전 disconnect를 각각 재현. 보상·상자·고스트 중복 없음.
- 정적 HUD 재접속 복구, fractional 체력 회복, 장전 PLAYERS/BGM RECORDS, 카메라/입력/포스트 효과 복원.
- 목표 서버20TPS, 3인/최대32기 구간10분에서 tick p95≤45ms 목표. p99와 spike도 기록하고 무조건 통과라고 단정하지 않는다. 클라이언트 목표60FPS는 해상도·장비·팩 설정과 함께 측정하며 현재 달성하지 않았다.
- 성능이 부족하면 모델 LOD/보이지 않는 애니메이션·파티클·AI 경로 재계산부터 최적화한다. 동시 수 조정이 필요하면3인 고정 설정 자체를 변경하고 문서/팩 계획을 함께 개정한다. 플레이어 수 기반 자동 축소로 대체하지 않는다.

### 구현 전에 확정할 항목

1. 원본 GLB의 실제 플레이 동선 crop/scale 및 위 graybox와 겹쳐본 좌표 승인. 현재 문서는 GLB를 렌더해 실측한 맵이 아니다.
2. Brig 중복 parent, 원점 Sepiks, 워프 마커의 최종 world transform과 히트박스 크기.
3. 음악 cue의 실제 OGG 선택/길이/루프, SFX variant인지 layer인지 청취 대조.
4. 소유권 태그·군체 및 신규 보스 AI의 실제 구현 범위와 모델 예산.
5. 기존 경제 정책에 맞는 클리어 보상 종류/수량. 본 문서에서 임의 신규 고유 무기를 지급하지 않는다.

이 다섯 항목은 구현 단계의 검증·결정 목록이다. 현재 요청한 기획의 팩 수, 단계, 지도 역할, 전투 수치와3인 고정 규칙은 위와 같이 구체적으로 제안한다. 게임 코드·원본 에셋·운영 서버는 이번 기획 작성에서 변경하지 않았다.
