## 정확한 선택 자격과 자동 선택 금지

선정 63개 중 아래 **13개 tuple만** 허용한다. 모든 행의 base perk hash는 `2779035018`이고 socket 번호는 원본 JSON index 그대로다. 표의 자격은 `(id, item hash, socket, perk hash, plug-set hash)` 전체에 묶인다. 같은 이름의 재발매판·강화판·다른 무기로 넓히지 않는다.

| 선택 ID | Item hash | Socket | Plug-set hash | 자격 근거 |
|---|---:|---:|---:|---|
| `seventh_seraph_officer_revolver` | 3037520408 | 4 | 3527094473 | randomized |
| `steelfeather_repeater` | 1251729046 | 3 | 473189353 | randomized |
| `cold_denial` | 1216130969 | 3 | 330841869 | randomized |
| `blast_furnace` | 3843477312 | 3 | 1976101165 | randomized |
| `the_recluse` | 3354242550 | 3 | 242 | fixed curated initial trait |
| `brass_attacks` | 2121785039 | 3 | 100135553 | randomized |
| `hollow_words` | 607191995 | 3 | 637298592 | randomized |
| `null_composure` | 1644680957 | 3 | 272 | fixed curated initial trait |
| `coriolis_force` | 3512349612 | 3 | 2568674372 | randomized |
| `retraced_path` | 548958835 | 3 | 2945646047 | randomized |
| `fixed_odds` | 2194955522 | 3 | 4227334000 | randomized |

randomized 11개는 실제 randomized pool의 `currentlyCanRoll=true`를 요구한다. weight 0만으로 제외하지 않는다. curated 2개는 해당 item 자신의 base initial trait와 정확한 fake reusable pool을 근거로 하며 random roll로 부르지 않는다. 은둔자의 242는 singleton이고 Null Composure의 272는 Feeding Frenzy/Heating Up 선택지가 있다.

**원본 initial/curated 옵션이 있어도 새 stack에 자동 선택·자동 장착하지 않는다.** [WeaponPerks](../../src/main/java/kim/biryeong/destiny/weapon/WeaponPerks.java)의 명시적 소켓 선택이 있어야 활성 자격이 생긴다. 선택 자체·HUD 조회·무기 지급만으로 중첩을 지급하지 않는다. 미선택 13개와 나머지 50개는 기본 동작을 따른다.

Outlaw와 겹치는 것은 정확한 Blast Furnace `3843477312` 한 개이며 양쪽 모두 socket **3**, pool **1976101165**다. 같은 소켓에서 서로 교체되므로 동시 활성·두 장전 배율 곱셈을 만들지 않는다. Brass Attacks는 Feeding Frenzy socket **3**과 Dragonfly socket **4**(`2848615171`, pool `3403850295`)를 각각 선택할 수 있다. 선택 집합에 Payload 동시 조합은 없다.

## 단계별 장전

[제품 JSON](../../src/main/resources/destiny/weapons/w108-feeding-frenzy.json)과 [FeedingFrenzyProfile](../../src/main/java/kim/biryeong/destiny/weapon/FeedingFrenzyProfile.java)은 정확한 13개 자격·5단계·65개 장전 계획을 검증한다.

| 중첩 | Reload stat 가산 | 장전 시간 배율 | 은둔자 effective stat | 은둔자 first/interval tick |
|---:|---:|---:|---:|---:|
| 0 | 0 | 1 | 28 | 43 |
| 1 | 8 | 0.975 | 36 | 40 |
| 2 | 50 | 0.90 | 78 | 28 |
| 3 | 60 | 0.87 | 88 | 25 |
| 4 | 75 | 0.84 | 100 | 23 |
| 5 | 100 | 0.80 | 100 | 22 |

계산 순서는 `r = min(100, baseReloadStat + tier.reloadBonus)`, `seconds = (evpp*r*r + vpp*r + offset) * tier.durationMultiplier`, `ticks = ceil(seconds*20)`다. stat 가산·cap·시간 배율을 모두 적용한 뒤 **마지막에 한 번만 올림**한다. 이미 반올림한 기본 tick에 배율만 곱하지 않는다. 은둔자는 기본 **43 → x1~x5 40/28/25/23/22tick**, 탄창 41발이다.

장전 시작 시 실제 보유 중첩을 한 번 snapshot한다. 진행 중 만료나 추가 처치로 이미 시작한 장전의 완료 시점을 다시 계산하지 않는다. 만료 뒤 새로 시작한 장전은 기본값이다. 13개 모두 whole-magazine이고 projectile mode인 대상은 없다. shell 최초 삽입·projectile 양성 사례를 이번 자격에 꾸며 넣지 않는다. 탄약 공급·소비·전달은 기존 경로를 사용하며 이 특성은 탄약을 생성하거나 피해 배율을 주지 않는다.

## 유료 실제 처치와 원본 토큰

[WeaponRuntime](../../src/main/java/kim/biryeong/destiny/weapon/WeaponRuntime.java)의 실제 탄약 결제/발사 경로에서 선택된 원본 stack의 토큰을 보존하고, production damage가 양의 실제 HP/absorption 감소와 final blow를 확인한 경우에만 중첩을 준다. body/head 처치 모두 가능하다. 살아 있는 표적의 비치명 피해, 단순 명중·정밀 명중, 빈 탄약 입력, 충전 수락만 된 상태, 미선택 무기, 능력 귀속 처치는 자격을 얻지 않는다. 실제 charged fusion의 결제된 emission은 처치가 일어난 뒤에만 귀속한다.

[WeaponFeedingFrenzy](../../src/main/java/kim/biryeong/destiny/weapon/WeaponFeedingFrenzy.java)의 세션은 owner 객체·level·인벤토리에 남은 **동일 ItemStack 객체**와 현재 선택을 확인한다. 같은 직렬화 내용의 교체품이나 다른 선택 무기는 이전 세션/토큰을 상속하지 않는다. trait의 실제 편집·clear/reselect와 owner cleanup은 세션을 폐기한다. 이미 선택된 같은 옵션을 다시 선택하는 no-op은 deadline을 갱신하지 않는다. HUD/장전 조회는 상태를 새로 만들거나 처치를 주입하지 않는다.

## LOCAL 수명 정책

참조 JSON과 profile의 `stowPersistence`, `reloadConsumption`, `killRefreshAllStacks`, `expirationAllOrOneStack`는 출처 상태를 뜻하는 **UNKNOWN**을 유지한다. 아래는 현재 [cycle](../../src/main/java/kim/biryeong/destiny/weapon/FeedingFrenzyCycle.java)과 runtime에서 선택한 LOCAL 동작이다.

| 정책 | 현재 구현 |
|---|---|
| 수납 유지 | 여전히 소유한 동일 원본 stack의 deadline을 보존한다. 보관 중에도 서버 시간은 흐르고, 다시 들었을 때 남은 시간만 보인다. 수납이 시간을 멈추거나 갱신하지 않는다. |
| 장전 비소비 | 장전 시작/완료로 중첩을 소비하거나 70tick을 새로 주지 않는다. |
| 전체 window 갱신 | qualifying kill마다 `min(5, old+1)`, deadline은 그 처치 tick +70. x5에서도 실제 추가 처치가 전체 window를 갱신한다. |
| 전체 만료 | deadline 직전 1tick까지 유지하고 deadline에서 전체 x0/0. 만료 시점/이후 새 처치는 x1부터 시작한다. 광란식 한 단계씩 감소하지 않는다. |
| 장전 snapshot | 시작 당시 계획을 완료까지 유지한다. 다음 장전에만 새로운 상태를 쓴다. |
| Dragonfly 2차 처치 | [WeaponDragonfly](../../src/main/java/kim/biryeong/destiny/weapon/WeaponDragonfly.java)의 양의 실제 피해·치명 결과를 최초 유료 원본 토큰에 귀속한다. 원작의 2차 proc 동작을 입증한 것은 아니다. |

Brass Attacks의 정밀 1차 처치와 실제 치명 폭발 witness 한 개는 LOCAL 기대 x2다. body 1차 처치는 x1이며 Dragonfly를 발생시키지 않는다. 2차 처치는 재귀 폭발·Outlaw 정밀 처치·Feeding Frenzy 피해 배율을 만들지 않는다. 원본 교체 후 낡은 토큰으로 다른 무기에 보상을 넘기지 않는다.

## HUD와 증거 경계

[WeaponPerkHud](../../src/main/java/kim/biryeong/destiny/hud/WeaponPerkHud.java)는 실제 held-source 중첩·잔여 tick의 읽기 전용 조회로 marker, `FEEDING FRENZY`, x, count, minutes/colon/tens/ones의 **8개 node**를 구성한다. x1~x5와 남은 시간을 표시하고 비활성/만료 시 제거한다. 초 표시는 `ceil(remainingTicks/20)`이므로 70tick에서 `0:04`, 이후 `0:03`…`0:01`이다. 이것을 4초 수명으로 해석하지 않는다.

[HUD manifest](../../art/weapons/w108/hud/manifest.json): 자체 생성 118×24px 라벨, item/model/PNG **정확히3파일·12,354bytes**. 기존 marker·x·숫자·colon을 재사용한다. [offline preview](../../art/weapons/w108/hud/offline-preview.png)는 오프라인 그림이고, 실제 화면은 [Vision x5 PNG](../qa/2026-10-25/w108/native/frames/fixed-five-hud.png)로 따로 확인했다.

native attempt1에서 item atlas 밖 `textures/gui/hud` PNG가 magenta로 렌더됐다. 자기 runtime 중지 후 `textures/item/hud/perk_feeding_frenzy_w108.png`로 이동·모델/신규 test/generator를 수정했고, 수정 후 실제 PNG에서 라벨·x5·타이머를 확인했다. 실패는 덮어쓰지 않았다.
