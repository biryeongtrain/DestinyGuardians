# 25. 궁극기 후방 3인칭 카메라 — H18

2026-10-22. **바닐라 서버사이드 구현 / 자동·화면 확인 / 실제 입력 인수 미완료.**
H17 빌드에는 이 기능이 없다. 아래 초기 조사와 후속 구현 기록을 구분한다.

## 1. 요구사항

| 헌터 궁극기 | 목표 시점 | 유지 구간 |
|---|---|---|
| Solar / 황금총 | 기존 시점 유지, 강제 전환 없음 | 발동·3발·회복 모두 기존 정책 |
| Arc / 전기 지팡이 | 강제 후방 3인칭 + BetterModel 동작 | 발동 → 준비/이동/공격 → 마지막 회복 |
| Void / 공허 활 | 강제 후방 3인칭 + BetterModel 동작 | 발동 → 조준/발사 → 마지막 회복 |

사용자는 뒤쪽 **카메라 엔티티**를 제안했다. 조작 불가능한 관전 연출이 아니라 이동·점프·마우스 조준·공격이 가능한 전투 카메라가 목표다.
회피 시점 변경은 이번 요구에 포함하지 않는다. 피해·에너지·쿨타임·피격 위치는 유지한다.

## 2. 실제 26.3 코드에서 확인한 제약

로컬 Fabric Loom 캐시 `26.3/minecraft-client.jar`를 Java25 `javap -c -p`로 확인하고 현재 의존성 소스와 대조했다.
아래는 **정적 코드 확인**이며 실제 조작/화면 검증은 아니다.

| 위치 | 확인 결과 | 영향 |
|---|---|---|
| `LocalPlayer.isControlledCamera()` | camera entity가 LocalPlayer 자신일 때만 true | 외부 카메라는 F5 후방 시점과 다름 |
| `LocalPlayer.applyInput()` | 위 조건에서 일반 이동 입력 적용 | 카메라 패킷만 보내서는 일반 이동을 유지하지 못함 |
| `LocalPlayer.sendPosition()` | 위 조건에서 일반 위치·회전 전송 | 키 상태 수신만으로 마우스 조준 전송까지 확보할 수 없음 |
| `LocalPlayer.tick()` | 키 상태 패킷은 별도 전송 | 서버 이동 PoC 재료이지 완성된 전투 조작이 아님 |
| `MouseHandler.turnPlayer()` | LocalPlayer를 회전시킴 | 원격 카메라 엔티티가 자동으로 같은 방향을 보는 것은 아님 |
| `ServerPlayer.setCamera(entity)` / `tick()` | 최초 순간이동 및 이후 플레이어가 카메라 위치·방향을 따라가는 경로 | 실제 몸과 판정 위치 보존을 위해 직접 호출 금지 |

`ClientboundSetCameraPacket` 직접 전송은 서버 `setCamera`의 몸 이동 부작용을 피하지만 **클라이언트 입력/회전 gate는 해결하지 못한다.**
탑승 중 별도 회전 전송을 활용하려면 이동·충돌·하차·낙하까지 검증해야 한다.

### 기존 의존성 경계

- `libs/minigame-lib/.../cinematic/CameraViewSession.java`: 클라이언트 spectator respawn, 비행/무적 설정을 사용한다.
- `.../cinematic/CameraViews.java`, `.../mixin/ViewInputMixin.java`: 피해/입력 제한과 별도 스트리밍을 사용한다. 전투 궁극기에 그대로 연결하지 않는다.
- `.../camera/api/CameraEffects.java`: 현재 FOV 효과이지 강제 후방 시점 API가 아니다.
- 로컬 `GCB-server`의 `GCBCameraTypeC2SPacket`은 시점 **보고**다. 서버 camera type 필드 변경은 클라이언트 시점 변경이 아니다. 현재 강제 시점 S2C 지원은 확인되지 않았다.

## 3. 결정할 구현 경로

### A. 선택적 클라이언트 지원 확장 — 조작 보존 우선

- GCB 등 클라이언트 구현과 서버 협상을 함께 추가한다. 서버/C2S 필드만으로 구현하지 않는다.
- 네이티브 후방 perspective를 강제하면 camera entity는 LocalPlayer인 채 일반 조작 경로를 유지할 수 있다. **별도 카메라 엔티티와는 다른 대안**이다.
- 별도 엔티티가 필수라면 해당 세션 중 클라이언트 이동·회전 전송 유지와 로컬 시선/카메라 방향 동기화가 필요하다. 단순 F5 setter보다 범위가 크다.
- 지원 버전/기능 handshake, 세션 token, 적용 ACK/타임아웃을 둔다. 원래 first/rear/front 시점 저장과 로컬 통신 단절 시 해제를 포함한다.
- 미지원 바닐라 접속은 유지하되 기존 안전한 시점으로 폴백한다. 이를 바닐라 강제 3인칭 완료라고 표기하지 않는다.

### B. 바닐라 전용 후방 엔티티 — 실험적 서버 이동/조준 PoC

- 별도 카메라와 키 상태로 서버 이동을 처리하고 마우스 회전 전달 경로를 별도 입증한다.
- 탑승 경로는 검토 대상이지 해결 완료가 아니다. 하차·재탑승·충돌·낙하·차원 변경 부작용을 포함한다.
- 회전 전달이 입증되기 전 실제 궁극기에 연결하지 않는다. 로컬 저지연 화면만으로 조작감 통과를 선언하지 않는다.
- 바닐라에서 서버가 네이티브 F5를 직접 설정하는 기능으로 설명하지 않는다.

**사용자 결정:** B — 바닐라 서버사이드 유지. 후방 카메라와 서버 이동 제어까지 구현한다. GCB 클라이언트 확장은 하지 않는다.

## 4. 공통 수명 계약

제안 상태: `REQUESTED → ACTIVE → RECOVERING → CLOSED`.

1. Solar는 카메라 세션을 만들거나 원래 시점을 덮어쓰지 않는다.
2. Arc/Void는 지원 여부와 외부 카메라 점유를 확인하고 적용 확인 후 본인 limb를 표시한다. 중복 1인칭 궁극기 손 HUD는 숨긴다.
3. 피해·투사체 원점은 실제 몸/시선 기준이다. 카메라 위치를 판정 원점으로 쓰지 않는다.
4. Arc는 gameplay 종료 뒤 진행 중인 마지막 one-shot 회복까지 유지한다.
5. Void는 발사 다음 틱에 gameplay가 끝날 수 있다. `superSession != null`만 보지 않고 `PlayerAnimations.finishSuper`의 시각적 회복 종료까지 추적한다.
6. 콜백은 run/token의 플래그만 변경하고 주 서버틱에서 복원한다. 이전 콜백이 새 세션을 닫지 못하게 한다.
7. 사망/차원/접속 종료/서버 종료/직업·속성 변경은 강제 정리한다. 정리는 멱등이며 자기 엔티티만 제거한다.
8. 외부 카메라가 선점하면 이전 세션이 시점을 덮어쓰지 않는다. 자신의 소유권이 유지된 경우만 저장한 시점을 복원한다.
9. 복원 후 본인 limb/손 HUD를 재평가한다. `gcbClient/gcbThirdPerson`을 가짜로 설정하지 않고 확인된 카메라 세션 소유 상태를 별도로 사용한다.

### 후방 프레이밍 초안 — 수치 미검증

- 어깨/시선 높이 기준 후방 약 3블록, 작은 위/오른쪽 오프셋부터 비교한다.
- 몸↔목표 카메라 구간 차폐 검사로 벽 앞에 당기고 보간한다. 벽 너머 관측을 허용하지 않는다.
- 몸에 가까워졌을 때 limb 화면 가림을 위한 근접 숨김/투명 정책이 필요하다.
- 공허 활의 화면 중앙↔몸 발사 궤적 시차와 장애물을 검사한다.
- 소유자만 전환하고 관찰자는 기존 몸/limb를 본다. 새 카메라에서도 DisplayHud 배치가 유지되는지 실측한다.

## 7. H18-S2/S3 구현 기록 — 검증 진행 중

- `SuperCamera`: 본인에게만 빈 item_display 2개(가상 좌석/카메라)를 보낸다. 서버 월드에는 엔티티를 추가하지 않는다.
- 클라이언트만 가상 승객이다. 실제 ServerPlayer는 탑승하지 않고 `getCamera()==player` 및 원래 몸/판정을 유지한다.
- 외부 camera entity에서도 vanilla `sendChanges()`의 승객 분기는 `Rot`를 매틱 전송한다. 실제 Vision 클라이언트에서 수신을 확인했다.
  `/look`로 LocalPlayer 시선을 바꾼 뒤 서버 yaw/pitch 일치를 확인했다. 이는 실제 네트워크 경로 증거이지 하드웨어 마우스 시험은 아니다.
- 이동은 `ServerPlayer.doTick` 직전 키 상태를 native xxa/zza/jumping/sprint/shift로 공급한다. 별도 travel을 호출해 이중 이동시키지 않는다.
- 활성 중 move packet의 위치/ground 주장은 적용하지 않는다. 유한 회전만 받고 native 충돌·중력 결과를 유지한다.
- 독립 검토에서 move packet 취소가 vanilla 낙하 정산까지 건너뛰는 문제를 발견했다. native tick 전후 실제 이동량으로 `doCheckFallDamage`를 한 번 호출하도록 보완했다. 낙하 GameTest로 후속 확인한다.
- 카메라는 시선 기준 후방3/오른쪽0.45/위0.25, 빈 display의1틱 위치/회전 보간을 쓴다. 벽 검사는9개 ray와0.22블록 여유를 사용한다.
- 최초 ArmorStand PoC에서 ‘내리기’ 안내와 좌석 높이 차이를 확인했다. 빈 item_display, 좌석+0.6보정, 자체 탑승 안내 공백 처리로 바꾸고 새 JVM 화면에서 재확인했다.
- `finishSuper` 이후 최종 playback이 끝날 때까지 유지한다. 회전 패킷40틱 이상 누락, 외부 cinematic, 실제 탑승, 비행/수면, 죽음/차원 변경/큰 순간이동은 안전 해제한다.
- `-Ddestiny.superCamera=false`는 카메라만 기존 방식으로 되돌리는 임시 운영 스위치다. 끈 상태를 강제3인칭 완료라고 설명하지 않는다.
- 바닐라 F5 설정을 서버에서 잠그거나 저장/변경하지 않는다. 사용자가 이미 rear/front이거나 도중 F5를 누르면 원격 카메라 위에 native perspective가 중첩될 수 있다. **F5 잠금은 구현 범위 밖의 바닐라 제약**이다.
- 외부 카메라는 서버 `getCamera`/`CameraViews`로 선점을 감지한다. 타 모드의 패킷만 사용하는 독립 카메라까지 완전한 소유권 협상이 된 것은 아니다.
- 실제 키/마우스·지연·다인/청크 경계·근접 벽 camera 보간의 전체 검증 결과는 QA 문서에서 별도 기록한다.
