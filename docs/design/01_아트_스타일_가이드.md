# 01. 아트 스타일 가이드

모든 AI 에셋 요청에 이 문서를 같이 붙입니다.

## 1. 핵심 원칙

1. **로우폴리 + 실루엣 우선**: 3~5m 거리에서 무기 종류, 적 종류, 직업이 실루엣만으로 구분돼야 합니다.
2. **포인트 1~2개**: 디테일을 많이 넣지 말고, 그 대상을 상징하는 특징 1~2개를 크게 키웁니다. (예: 이자나기의 짐 = 긴 총열 + 붉은 장식 끈)
3. **마인크래프트 픽셀 밀도에 맞추기**: 텍스처는 바닐라 블록·아이템과 나란히 놓여도 튀지 않게, 블록 1개당 16px 밀도를 기준으로 합니다.
4. **배포 에셋은 자체 제작 원칙**: 기본 공개 배포물은 레퍼런스를 보고 재디자인합니다. 이후 사용자 지시로 승인된 H28/H29/W30의 공유 리핑 자료 참조·원본 색상 베이크는 **로컬 비상업적 검토 예외**입니다. 이는 공개/상업 배포 권한을 부여하지 않으며 원본 압축·FBX·BLEND·스크립트는 레포에 포함하지 않습니다. 파생물도 배포 전 권리 검토가 필요합니다. 세부 출처·예외 범위는 각 단계 문서를 따릅니다.
5. **속성 색은 고정**: Arc / Solar / Void 색은 아래 팔레트만 씁니다. 다른 문서·셰이더도 같은 값을 씁니다.

## 2. 색 팔레트

### 2-1. 속성 색 `[결정 필요: 최종 값 확정]`

| 속성 | 주색 | 밝은색(발광) | 어두운색(그림자) | 쓰임 |
|---|---|---|---|---|
| Arc | `#5FC8FF` | `#C8F4FF` | `#1E5A8C` | 번개, 전류 줄기 |
| Solar | `#FF7A1A` | `#FFD38A` | `#9C2E0A` | 불꽃, 태양 광채 |
| Void | `#A86BFF` | `#E2C8FF` | `#3B1A6E` | 공허 구체, 연기 |
| Kinetic(무속성) | `#E8E8E8` | `#FFFFFF` | `#6E6E6E` | 일반 탄, 탄피 |

- 셰이더(07), VFX(06), UI(08)는 이 표의 hex 값을 그대로 씁니다.
- 셰이더에서 쓸 때는 0~1 값으로 바꿉니다. 예: Arc `#5FC8FF` → `vec3(0.373, 0.784, 1.0)`

## 3. 모델 예산

2026-10-25 최신 사용자 지시가 아래 일반/경이 무기 상한을 대체한다. full과 body+magazine은 동일 조립체이므로 중복 합산하지 않으며 삼각 adapter의 각 출력 요소는 개별 집계한다. 기존 과거 후보가 모두 이 상한에 맞춰졌다는 뜻은 아니다. [W124 구성 원칙](131_무기_정돈된_면과_1000요소_상한.md).

| 대상 | 형식 | 큐브/요소 상한 | 텍스처 | 본(뼈대) 상한 | 비고 |
|---|---|---|---|---|---|
| 일반 무기 | Java 아이템 모델 | **큐브+삼각/윤곽 출력 요소 합계 1,000** | 무기별 기존 atlas/저작 UV | – | 본체+탄창 조립체 전체; 1,000개를 채우는 목표가 아님 |
| 경이 무기 | Java 아이템 모델 | **합계 1,000** | 무기별 기존 atlas/저작 UV | – | Ace87/Izanagi79 같은 정돈된 큰 면과 텍스처 디테일을 기준으로 함 |
| 상태별 무기 모델(조준·사격 등) | Java 아이템 모델 | 기본 모델과 동일 | 기본 텍스처 공유 | – | 03 참고 |
| 플레이어 애니메이션 소품(망치·황금 총) | BetterModel 본 | 60 | 64×64 | 소품당 3 | limb 파일에 포함 |
| 일반 적 | BetterModel 모델 | 150 | 128×128 | **20** | 본 1개 = 디스플레이 엔티티 1개 |
| 정예·미니보스 | BetterModel 모델 | 250 | 128×128 | **30** | |
| 레이드 보스 | BetterModel 모델 | 500 | 256×256 | **60** | 화면당 1~2마리 |
| UI 아이콘 | 폰트 글리프 / 아이템 모델 | – | 32×32 (아이콘), 256×256 (패널) | – | 08 참고 |

> ⚠️ BetterModel은 **본마다 `item_display` 엔티티 하나**를 씁니다. 본 수가 곧 네트워크 비용입니다. 레이드에서 적 15마리 × 20본 = 300 엔티티가 한 화면에 생길 수 있으니 본 상한을 지켜야 합니다.

## 4. 형태 언어

| 세력·대상 | 형태 키워드 | 피해야 할 것 |
|---|---|---|
| 타이탄 | 넓은 어깨, 두꺼운 판갑, 사각형 | 가는 선 |
| 헌터 | 망토, 날렵한 V자 실루엣, 후드 | 무거운 판갑 |
| 워록 | 긴 로브, 비대칭 장식, 곡선 | 각진 판갑 |
| 몰락자 | 네 팔, 가는 다리, 망토 조각, 청록색 눈 | 인간형 비율 |
| 군세 | 뼈·키틴질, 초록 발광, 뾰족한 돌기 | 깔끔한 금속 |
| 카발 | 둔중한 장갑, 붉은 군단 문양, 호흡기 | 날렵한 형태 |
| 무기 | 총열·탄창·조준경을 큰 덩어리로 | 나사·볼트 같은 미세 디테일 |

## 5. 이름 규칙

- 모든 ID는 영어 소문자 + 숫자 + `_` 만 씁니다.
- 네임스페이스: `destiny` (09 참고)

| 대상 | 규칙 | 예 |
|---|---|---|
| 무기 아이템 모델 | `weapon/<종류>/<이름>` | `weapon/hand_cannon/ace_of_spades` |
| 무기 상태 모델 | `weapon/<종류>/<이름>_<상태>` | `..._ads`, `..._fire`, `..._reload_1` |
| 플레이어 limb | `guardian_<그룹>` | `guardian_common`, `guardian_super_arc` |
| 플레이어 애니메이션 | `<직업>_<동작>` / `common_<동작>` | `hunter_roll`, `titan_thundercrash` |
| 적 모델 | `enemy_<세력>_<유닛>` | `enemy_fallen_dreg` |
| 보스 모델 | `boss_<레이드>_<이름>` | `boss_redlegion_commander` |
| 포스트 이펙트 | `destiny:<분류>/<이름>` | `destiny:state/super_active` |
| HUD 글리프 | `destiny:hud/<이름>` | `destiny:hud/grenade_arc` |
| 본 이름 | 소문자 영어 + BetterModel 태그 | `ph_head`, `h_weakpoint` |

## 6. Blockbench 작업 규칙

- 형식: 무기는 **Java Block/Item**, 플레이어·적은 **BetterModel이 읽는 Generic/Bedrock `.bbmodel`**
- 원점: 무기는 손잡이 위치를 (8, 8, 8) 근처에 맞추고 디스플레이 설정에서 손 위치를 조정합니다.
- 텍스처는 `.bbmodel` 안에 포함하지 말고 PNG로 따로 저장해 버전 관리합니다. (AI 수정 이력 추적용)
- 애니메이션 길이는 **틱 단위로 나누어떨어지게** 만듭니다. (1틱 = 0.05초. 예: 0.4초 = 8틱)
