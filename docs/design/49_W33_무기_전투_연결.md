# W33 무기 전투 연결 — 구현 단계 기록

작성: 2026-10-23. 범위: W30/W31 63개 모델의 **18개 무기군**에 대한 서버 PvE 전투 기본 동작.
기존 대규모 미커밋 변경은 유지했다. 이 작업은 커밋·푸시·Gradle 실행을 하지 않았으며, 아래 게이트 결과는 부모 작업자가 실행해 전달한 결과다.

## 1. 프리뷰와 전투 아이템 분리

- `/destiny weapon equip <id> [player]`: 기존 W32 시각 프리뷰. `WeaponPreviewItem.use()`는 그대로 비활성이다.
- `/destiny weapon load <id> [player]`: 별도 `destiny:weapon_combat`을 생성한다. 이름에 `[전투]`, lore에 PvE·탄창·예비탄·입력을 명시한다.
- `/destiny weapon status`: 현재 동작 방식과 탄약·재장전 상태를 확인한다.
- `/destiny weapon reload`: 명령 재장전. 실제 아이템 입력은 OP 권한 없이 사용할 수 있다.
- 명령은 기존 `/destiny weapon` OP 범위에 있다. `load`와 프리뷰 `equip`은 일반 아이템과 이미 들고 있는 전투 아이템을 덮어쓰지 않는다. 같은 모델을 지정하더라도 live 탄약·재장전 상태를 보존하기 위해 거부한다. 새 전투 아이템 생성은 관리자의 명시적 지급이며, 일반 플레이 중 탄약 공급 시스템은 아니다.
- 프리뷰 태그만으로 피해를 얻을 수 없다. 실제 전투 등록 아이템, live 태그, 카탈로그 ID, 모델 ID가 함께 맞아야 한다.
- 기존 `WeaponModels`에서 live 아이템도 모델·포즈를 읽을 수 있게 확장했다. 그립 변환은 live 아이템 종류와 현재 탄약을 보존한다.

## 2. 입력 프로토콜과 W32 양손 그립 보존

| 입력 | 서버 의미 |
| --- | --- |
| 주 손 우클릭 | 즉발 무기는 1회 발사, 자동 무기는 유지 중 연사 |
| 활 우클릭 유지 후 놓기 | 서버 충전 시간이 충족된 경우에만 화살 발사 |
| 융합·선형 융합 우클릭 유지 | 서버 충전 완료 시 1회 발사/버스트; 다시 발사하려면 입력을 해제하고 재입력 |
| 웅크리기 + 우클릭 | 유한 예비탄을 사용하는 지연 재장전 |
| 검 좌클릭 또는 우클릭 | 짧은 서버 레이 판정의 근접 공격 |
| 글레이브 좌클릭 | 근접 공격; 우클릭은 직선 투사체 |
| 궁극기 좌클릭 / 수호자 웅크리기+좌클릭 | 기존 궁극기/근접 능력 입력이 우선 |

**양손 그립(기본 46종)**: 클라이언트 전송본에만 충전된 바닐라 석궁과 그립 모델 선택자를 넣는다. 26.3 `CrossbowItem.use`는 이 상태에서 native 사용 상태를 시작하지 않고 로컬 발사를 예측하며, 우클릭 유지 시 4틱마다 재시도한다. 따라서 서버도 `startUsingItem`을 호출하지 않는다. 수신된 우클릭 패킷마다 6틱 사용 유효 기간을 갱신하고, 그 기간 안에서만 서버 연사·충전을 허용한다. 재입력은 발사 쿨다운 중에도 유효 기간을 갱신한다. 단, 재장전은 별도 완료 시점을 가지므로 재장전 중 heartbeat는 발사 유효 기간을 만들거나 재장전 시간을 취소·연장하지 않는다. 빈 탄창 입력으로 자동 재장전이 시작된 경우에도 발사 유효 기간을 해제하며, 재장전 중 입력을 완료 후 발사로 예약하지 않는다. 재장전 완료 후 새 입력은 정상 처리한다. 만료 검사를 발사보다 먼저 수행하고 유지·충전·미발사 버스트를 취소하되 발사 쿨다운은 보존한다. 손을 놓았을 때 최대 6틱의 만료 지연이 있으며 단발 재입력도 이 해제 구간을 구분해야 한다.

**native 그립(권총·활·검·글레이브 및 명시적 native 변환)**: 전송본은 `STICK`에 3600초 무음 `CONSUMABLE`, `NONE` 애니메이션, 파티클 없음으로 실제 사용/해제 패킷을 받는다. 서버 원본에는 소비·충전 석궁 컴포넌트를 넣지 않는다. 최대 사용 시간 종료도 서버 아이템을 소비하지 않는다. 전송본 `UseEffects(true,false,1f)`로 소비 동작의 기본 감속·달리기 금지를 제거한다. 웅크리기 진입 시 live 사용을 취소하여 기존 능력 입력을 우선하며, 취소된 활은 발사하지 않는다.

W32 프리뷰의 석궁 포즈·비활성 사용은 유지한다. 부모는 후보 JAR `5fa113…`에서 18개 무기군 모두의 실제 클라이언트 입력·탄약 소비·피해 수락을 확인했다고 전달했다. 세부 시각·청감 품질과 63종 각 모델의 개별 live 검증까지 통과했다고 확대 해석하지 않는다. 아래 후속 재장전/보호/사운드 호출 수정은 이 live 검증 이후의 변경이며, 추가 live 실행 없이 부모의 전체 빌드·테스트 게이트를 기다린다.

| auto_rifle | 연사 히트스캔 |
| pulse_rifle | 3발/공격적 프레임 4발의 시간차 버스트 |
| scout_rifle | 긴 사거리 단발 히트스캔 |
| submachine_gun | 짧은 사거리 고속 연사 |

| bow | 충전 후 해제하는 중력 투사체 |
| sniper_rifle | 저속 고피해 장거리 히트스캔 |

## 4. 서버 상태·안전·생명주기

- `WeaponMagazine`: 탄창·예비탄은 실제 ItemStack custom data에 저장되어 저장/불러오기와 그립 변경을 통과한다. 누락된 탄약은 0으로 읽고, 음수·상한 초과를 제한한다. 재장전은 완료 시점에만 예비탄에서 탄창으로 옮기며 무한 탄약을 만들지 않는다. 인벤토리 화살과 보조 손은 사용하지 않는다.
- `WeaponCycle`: 서버 틱 기준 발사 간격, 충전, 지연 재장전, 2틱 간격 버스트를 제어한다. 중복 패킷이나 무기 교체로 플레이어 발사 쿨다운을 초기화할 수 없다. 교체·취소는 미완료 재장전·충전·버스트를 취소한다. 버스트는 탄마다 탄창을 소비한다.
- 히트스캔은 블록 충돌 위치까지 줄인 레이에서 가장 가까운 적을 선택한다. 산탄 피해는 대상별로 합산한다. 바닐라 기본 타격과 블록 파괴를 차단하여 별도 공격 속도/탄약 우회를 막는다.
- 기존 `Combat.isEnemy`의 PvE Mob 판정을 사용하되 플레이어·갑옷 거치대·길들인 동물·동맹은 제외한다. 기존 Mob 범위에는 일부 중립 생물도 포함된다. 피해는 `Combat.damage(..., KINETIC)`를 통해 기존 처치 크레딧과 연결한다.
- 투사체는 실제 위치·속도·중력·충돌을 서버에서 계산하고 파티클로 표시한다. 최대 사거리 96, 수명 100틱, 소유자별 활성 투사체 최대 16개로 제한한다. 미로딩 청크 경계를 넘기 전에 폐기한다.
- 폭발은 거리 감쇠·블록 가림을 적용한 PvE 피해만 만든다. 지형 폭발, 블록 파괴, 화재, 플레이어 폭발 피해를 발생시키지 않는다.
- 종료·사망·차원 이동·서버 중지 이벤트는 런타임 자체에서 등록한다. 소유자의 상태·투사체만 정리하며 다른 플레이어의 발사체를 제거하지 않는다. 사망·관전자·궁극기 사용 중 새 무기 입력은 거부한다.

## 5. 사운드 연결

- 승인된 발사: `DestinySounds.weapon(player, entry, "fire")`.
- 승인된 충전/재장전 시작: 같은 API의 `charge` / `reload`.
- 충돌: `DestinySounds.at(level, hitPosition, DestinySounds.weaponKey(entry, "impact"), .8f)`로 실제 충돌 위치에 재생한다.
- charge/reload/fire는 Entry 오버로드로, impact는 Entry 기반 `weaponKey`로 이벤트를 선택한다. 모델별 exact alias가 있으면 우선하며 없으면 무기군 매핑으로 돌아간다. alias가 같은 OGG 바이트를 공유하는 경우에도 이벤트 선택 경로는 모델별 override를 보존한다. 사운드 API·alias 회귀 테스트는 부모 작업자가 소유한다.
- 원본 pulse 음원에는 버스트가 포함될 수 있어 지연 버스트의 첫 탄에만 fire 음원을 재생하고 나머지 탄은 피해·시각 판정만 한다. 부모 오디오 작업에서 fusion은 **1.05초**, linear fusion은 **0.65초** 경계로 충전/발사 원본을 분할했다. 두 경계는 **청취하지 않은 시간 추정치**이며 실제 들으면서 확인한 타이밍·청감 품질을 뜻하지 않는다. charge/fire 정렬·길이·잔향의 청감 조정은 별도 검증 대상이다.
- API의 boolean 반환값은 매핑·디스패치를 뜻하며 실제 스피커에서 들렸다는 증거로 사용하지 않는다. 사운드·에셋·헌터 능력 파일은 부모 작업자 소유다.

## 6. 초기화 및 수정 경계

`DestinyGuardians.onInitialize()`에 `WeaponRuntime.init()`을 `WeaponPreviewItem.init()` 직후 추가했다. 부모 요청에 따라 `SoundCommands.register()`도 `WeaponCommands.register()` 직후 추가했다. 그 외 기존 초기화 변경은 보존했다.

`InputRouter`의 live 항목만 추가했다: 웅크리기 진입 사용 취소, live 항목의 START_DESTROY_BLOCK 거부, 기존 스킬 분기 전 `WeaponRuntime.onPunch` 호출. 런타임이 궁극기/웅크리기 수호자 근접 입력을 넘겨주므로 기존 능력 라우팅이 이어진다. 헌터 능력·오디오·에셋·빌드 스크립트는 수정하지 않았다.

신규 무기 소스: `WeaponProfile`, `WeaponMagazine`, `WeaponCycle`, `WeaponCombatItem`, `WeaponItems`, `WeaponRuntime`.
기존 무기 소스 확장: `WeaponCommands`, `WeaponModels`.

- `src/gametest/resources/fabric.mod.json`에 `WeaponCombatGameTests`, 부모의 `SoundW33GameTests` 두 entrypoint만 추가했다. `TestPlayers`는 수정하지 않았다.
- 후속 수정 전 후보에 대한 부모 전달 결과: 전체 **193 required GameTests 통과**, JUnit·build **SUCCESS**. 전달된 JAR SHA-256: `5fa113047ec3a851762eece3642c9f90b3d5d72dd8da6a1d2626fbe014ac2e2c`.
- 부모는 위 후보의 18개 무기군 live 입력·탄약·피해 수락 검증을 완료하고 소유 서버/클라이언트를 종료했다고 전달했다. 그 후 무기 파일·무기 테스트·이 문서만 다시 수정하도록 허용했다. 현재 후속 변경은 **새 전체 게이트 대기**다. 이 작업자는 Gradle·live 실행을 하지 않았고 부모가 전체 게이트를 소유한다. 다른 변경이 없다면 required GameTest 예상 수는 193 + 3 = **196개**이며, 실제 실행 결과는 아직 없다.

### 후속 수정: 재장전 lease와 live 아이템 보호

1. `heartbeatUse`가 재장전 중임을 확인하면 `heldUntil=-1`을 유지하고 반환한다. 반복 heartbeat 또는 긴 입력 공백이 기존 완료 시점을 취소·재시작하거나 완료 후 발사를 예약하지 않는다.
