# 21. 궁극기 발동·적중 화면 펄스 (26.3)

## 최종 통합 검증 (2026-10-22)

전체 GameTest71/71·JUnit28/28에 펄스 GameTest8개·JUnit2개가 포함된다.
정상 서버틱으로 만료·중복 비연장·선점·수동/외부 효과 보존·생명주기 정리를 검사했다.
JVM2 Copper Golem Vision26.3/OpenGL에서 발동/사격과 화면 복원을 촬영했고
신규 체인/GLSL의 누락·uniform 오류를 관찰하지 않았다.
[검증 조건·해시](../qa/2026-10-22/super-h15-validation.json).

화면 촬영은 정확한10/4틱 TTL의 측정 근거가 아니며 해당 수명은 GameTest로 판정한다.
Vulkan·다른 화면비·어두운 배경·다인 부하는 남아 있다.
아래 미실행/부모 통합 대기 표기는 담당자 저작 당시 기록이다.

## 1. 범위와 표현

기존 `super/{arc,solar,void}_active`의 지속 색보정은 그대로 두고, 별도의 짧은 펄스를 추가한다.
중앙 조준점을 비워 둔 속성색 코로나와 가장자리 빛을 원본 화면 위에 약하게 더한다.
발동은 10 서버 틱(20 TPS 기준 0.5초), 적중은 4틱(0.2초)이다. 서버가 느려지거나 일시정지하면 실제 시간은 늘어난다.
발동의 최대 빛 기여는 10%, 적중은 7%이며 셰이더에서도 12% 상한을 둔다.

원본을 같은 UV에서 한 번 읽으며 블러·좌표 왜곡·흑색 비네트·전체 화면 백색 플래시는 없다.
코로나는 정규화한 화면 좌표 기준이므로 와이드 화면에서는 타원형이다.
밝은 픽셀이나 발광 물체를 추출하지 않으며, **선택적 블룸이 아니다**.
바닐라 GUI보다 앞에서 실행된다. 월드 단계의 DisplayHud도 영향을 받으므로 HUD를 마스킹한다고 주장하지 않는다.
낮은 강도와 중앙의 빈 공간으로 가독성을 보조하며 실제 DisplayHud 가독성은 렌더러별 확인이 필요하다.

## 2. 실제 26.3 형식 확인

2026-10-22 로컬 26.3 클라이언트 JAR의 `assets/minecraft/post_effect/creeper.json`,
`assets/minecraft/shaders/include/globals.glsl`과 서버 JAR의 `ServerPlayer` 시그니처·바이트코드를 확인했다.
기존 `super/*_active.json`, `super_grade.fsh`, minigame-lib의 `entity_outline.json`,
`displayhud_combine.fsh`, `camera/api/CameraEffects.java`도 확인했다.

1. `addPostEffect(Identifier)`는 새 ID일 때만 추가하고 `true`를 반환한다. 이미 있으면 `false`다.
2. `removePostEffect(Identifier)`는 그 ID만 제거한다. 변경은 dirty flag를 통해 효과 ID 목록으로 동기화된다.
3. API는 효과 시작 시각이나 사용자 uniform 값을 전달하지 않는다.
4. JSON uniform은 `블록 이름 → [{name, type, value}, ...]`이며 GLSL의 `layout(std140)` 순서와 일치해야 한다.
5. `Globals.GameTime`은 효과별 경과 시간이 아니다. minigame-lib의 동적 FOV는 음수 월드 시간을 사용한다.

따라서 이번 버전은 **고정 강도 + 서버 TTL**이다. 시간에 따른 부드러운 페이드나 재생 시작 기준의 shader envelope는 구현하지 않았다.
`smoothstep`은 공간 경계만 부드럽게 한다. 임의의 `fract(GameTime)`를 시작 시각처럼 쓰지 않는다.
persistent 버퍼 기반 페이드도 FPS·재활성화 초기화가 실제로 검증되지 않아 사용하지 않는다.

## 3. 리소스와 소유권

| ID 접미사 (`destiny:super/`) | 종류 | TTL |
|---|---|---|
| `arc_activation_pulse`, `solar_activation_pulse`, `void_activation_pulse` | 발동 | 10틱 |
| `arc_impact_pulse`, `solar_impact_pulse`, `void_impact_pulse` | 적중 | 4틱 |

각 JSON은 `minecraft:main → swap → minecraft:main`의 두 패스다.
공유 셰이더는 새 `assets/destiny/shaders/post/super_pulse.fsh`이며 `PulseConfig`는 `vec4 Tint`, `vec4 Shape` 순서다.
마지막 blit은 바닐라 `BlitConfig.ColorModulate = vec4(1)`을 사용한다.
새 Minecraft 네임스페이스 오버라이드·persistent 버퍼·깊이/발광/DisplayHud 캡처 변경은 없다.

`PostEffects`의 펄스 슬롯은 UUID당 하나다. 같은 종류의 중복 요청, 다른 속성 요청, 발동 재요청은 진행 중인 펄스의 TTL을 연장하지 않는다.
단, 적중은 진행 중인 발동을 제거하고 4틱 적중 펄스로 한 번 교체한다. 진행 중인 적중은 교체하지 않는다.
한 발동→적중 구간은 최대 14틱 이내이며, 끝난 뒤의 새 요청은 새 펄스로 처리한다.
연속 적중은 만료 후 새 펄스를 만들 수 있으며 별도의 장기 쿨다운은 없다.

`addPostEffect`가 `true`인 경우만 추적하고 정리한다. 이미 수동으로 켜져 있던 같은 ID는 소유하지 않으며 제거하지 않는다.
이 여섯 ID는 정상 게임 흐름에서 이 매니저 전용으로 사용한다. 다른 코드가 진행 중 같은 ID를 제거·재추가하면 소유권 변경을 API로 구분할 수 없다.
기존 활성 궁극기 ID나 타 모드·명령 효과를 순회해서 지우지 않으며 `clearPostEffects()`를 호출하지 않는다.

## 4. 부모 통합 순서와 정확한 API

모든 호출은 **서버 스레드**에서 한다. 아래 이벤트 연결은 부모 작업 범위이며 이 변경에서는 연결하지 않는다.

1. 서버 틱에 한 번 연결한다.

   ```java
   ServerTickEvents.END_SERVER_TICK.register(PostEffects::tick);
   ```

   이미 `AbilityService`의 끝 틱 콜백이 있으면 그 안에서 `PostEffects.tick(server)`를 한 번 호출해도 된다.

2. 궁극기 발동 성공 후 기존 지속 효과를 켜고 펄스를 요청한다.

   ```java
   PostEffects.enter(player, element); // 기존 지속 효과
   PostEffects.pulse(player, element, false); // 새 발동 펄스
   ```

3. 실제 유효 적중이 확인된 위치에서 공격자에게 호출한다. 입력·발사만 했거나 빗나간 경우에는 호출하지 않는다.

   ```java
   PostEffects.pulse(player, element, true);
   ```

   다중 대상 공격에서 여러 번 호출해도 TTL은 연장되지 않는다. 투사체 콜백의 늦은 적중도 살아 있고 연결된 플레이어라면 요청할 수 있다.
   이 API 자체는 궁극기 권한·피해 성공·세션 유효성을 판정하지 않으므로 부모가 콜백의 게임 규칙을 검사한다.

4. 취소·사망·접속 종료 등 즉시 정리 경로에서 호출한다.

   ```java
   PostEffects.cancel(player); // 매니저가 소유한 이 플레이어 인스턴스의 펄스만
   PostEffects.exit(player, element); // 지속 궁극기 종료가 필요한 경로에서 별도 호출
   ```

   `exit`만으로 펄스를 취소하지 않는다. 정상 종료 직전의 적중 플래시를 TTL까지 남길지, 강제 취소할지는 부모가 선택한다.
   사망·차원 이동·세션 무효화는 `cancel`을 사용한다. DISCONNECT에서는 `handler.getPlayer()`를 넘긴다.

5. 서버 정지 시 서버 스레드의 정리 콜백에서 호출한다.

   ```java
   ServerLifecycleEvents.SERVER_STOPPING.register(server -> PostEffects.clearAll());
   ```

   `clearAll()`은 추적한 펄스 ID만 제거하고 플레이어 참조를 모두 해제한다. 기존 지속 효과의 정리를 대신하지 않는다.

공개 계약: `void pulse(ServerPlayer, Element, boolean impact)`, `void tick(MinecraftServer)`,
`void cancel(ServerPlayer)`, `void clearAll()`.
`KINETIC` 펄스는 아무것도 하지 않으며 존재하지 않는 리소스를 요청하지 않는다.
발동/적중 수명 상수는 `ACTIVATION_PULSE_TICKS`, `IMPACT_PULSE_TICKS`다.

## 5. 수명주기 안전장치

각 슬롯에는 원래 `ServerPlayer`, `ServerLevel`, 시작 서버 틱, TTL, 추가한 ID를 저장한다.
틱은 월드 시간이 아닌 서버 tick counter의 차이로 계산하므로 시간 변경과 차원별 시간에 영향받지 않으며 짧은 구간의 int 래핑에도 안전하다.
다음 조건이면 소유한 ID만 제거하고 슬롯을 해제한다.

- 10/4틱 만료
- 사망, 엔티티 제거, 연결 종료
- 원래 ServerLevel과 현재 차원 인스턴스 불일치
- PlayerList에 같은 UUID의 다른 플레이어 인스턴스가 존재함(리스폰/재접속)
- 외부에서 해당 ID를 이미 제거함(재추가하지 않음)

차원/접속/사망은 이벤트의 `cancel`이 즉시 정리하고, 연결 누락 시에도 다음 `tick`이 정리한다.
오래된 플레이어 인스턴스의 늦은 `cancel`이 같은 UUID의 새 인스턴스 슬롯을 지우지 않는다.
PlayerList 조회가 null인 것만으로 연결 종료로 판정하지 않는다. GameTest의 살아 있는 임베디드 플레이어는
목록에 등록되지 않을 수 있으며, 이 경우에도 생존·제거·`hasDisconnected`·차원·TTL 검사는 그대로 적용한다.
틱을 연결하지 않으면 자동 만료하지 않으므로 통합 1단계가 필수다.
서버는 클라이언트 셰이더 컴파일·리소스팩 적용 성공을 알 수 없다.

## 6. 검증과 남은 실제 화면 QA

새 `PostPulseAssetTest`는 여섯 JSON과 GLSL uniform 블록의 이름·타입·순서·벡터 길이,
두 패스의 입출력, framebuffer feedback 부재, 비영구 타깃, blit의 중립 값,
강도 상한과 중앙 코로나 제외 범위를 검사한다. 부모 빌드에서 실행한다.
이 작업에서는 요청대로 Gradle·서버·클라이언트를 실행하지 않는다.
이 테스트는 GPU 컴파일이나 매니저 수명주기 실행을 입증하는 테스트가 아니다.

작성 시 독립 JSON/GLSL 검사로 여섯 체인의 uniform 순서·강도·타깃 흐름을 확인했고,
26.3 JAR의 실제 `screenquad.vsh` 출력 및 `blit.fsh` 블록과 대조했다.
`glslangValidator -S frag .../super_pulse.fsh` 문법 검사와 `git diff --check`도 통과했다.
JUnit 실행과 OpenGL/Vulkan 게임 내 컴파일·화면 검증은 부모 통합 후 남아 있다.

새 `src/gametest/java/kim/biryeong/destiny/test/PostPulseGameTests.java`는 8개 GameTest를 제공한다.
부모가 `kim.biryeong.destiny.test.PostPulseGameTests`를 GameTest 진입점에 등록한다.
발동/적중의 정상 틱 만료, 각각의 중복 요청 시 TTL 비연장, 적중의 발동 선점,
`cancel`/`AbilityService.cleanup`의 소유자 격리와 지속 궁극기·외부 효과 보존,
사망·차원 변경·연결 종료 시 무효 소유자만 정리, 수동 펄스 소유권과 Kinetic no-op을 검사한다.
수명 검사는 매니저 틱을 수동 호출하거나 시간을 조작하지 않고 정상 서버 틱을 기다린다.
만료 직전과 만료 후를 모두 확인해 PlayerList 밖의 가짜 소유자가 조기 제거되는 회귀도 잡는다.
병렬 테스트의 상태를 지우지 않도록 테스트에서 `clearAll()`은 사용하지 않는다.
GameTest는 이번 작업에서 실행하지 않았다.

부모 통합 후 실제 QA 순서:

1. OpenGL/Vulkan에서 팩을 로드하고 shader/uniform 오류 여부를 확인한다.
2. Arc/Solar/Void 발동과 실제 명중을 각각 확인한다. 빗나간 공격은 적중 펄스가 없어야 한다.
3. 활성 궁극기 + 외부 `/posteffect`를 켠 상태로 펄스 만료·cancel·clearAll 후 기존 효과 ID가 그대로인지 확인한다.
4. 다중 대상 연타 중 펄스 ID가 하나 이하인지, 재요청이 기존 만료 시각을 늘리지 않는지 확인한다.
5. 발동→적중 선점과 사망·차원 변경·접속 종료·리스폰·서버 종료에서 슬롯과 ID가 정리되는지 확인한다.
6. 수동으로 같은 펄스 ID를 먼저 켠 뒤 pulse/cancel을 호출해 수동 ID를 지우지 않는지 확인하고 수동 ID는 직접 제거한다.
7. 밝은/어두운 배경, 16:9/21:9, HUD 배율별로 DisplayHud와 조준점 가독성을 확인한다.
