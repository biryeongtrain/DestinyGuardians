# W76 — 바닐라 HUD 정리와 offhand 가독성

## 상태

W75의 실제 화면에 남은 허기·핫바와 기존 Destiny DisplayHud를 조사했다. **초기 조사와 이후 구현을 구분한다.** 처음에는 Mac 잠금으로 CU 접근이 거절됐으나 이후 재확인에서 앱 접근이 가능해져 격리 실게임 검증을 진행했다. 최종 결과는 아래 구현 절과 QA를 따른다. 전원 영구 설정은 바꾸지 않았다. [안전 상태](../qa/2026-10-24/w76/safety.json).

## 정확 26.3 감사

별도 읽기 worker Dewey가 공식 캐시 client JAR (`~/.gradle/caches/fabric-loom/26.3/minecraft-client.jar`, SHA-1 `e877b6a07acd633fb3bb475002175cec036e7b87`)의 bytecode/셰이더를 대조했다. 프로토콜777, 리소스 형식97.1. 워커는 파일/앱을 수정하지 않았다. 정적 감사이지 framebuffer 검증은 아니다.

### 안전하게 분리 가능한 범위

`assets/minecraft/textures/gui/sprites/hud/` 개별 PNG의 투명 대체:

- `food_empty`, `food_half`, `food_full`, 각각의 `_hunger` 변형: 6개.
- `hotbar`, `hotbar_selection`, `hotbar_offhand_left`, `hotbar_offhand_right`: 프레임 4개.
- `hotbar_attack_indicator_background`, `hotbar_attack_indicator_progress`: 2개.
- `experience_bar_background`, `experience_bar_progress`: 바 2개.

원본 크기와 필요한 metadata를 유지하고 GUI atlas 전체는 바꾸지 않는다. **핫바 프레임을 없애도 아이템/숫자는 남는다.** XP 레벨은 `ContextualBar.extractExperienceLevel`이 `gui.experience.level` 번역 키를 쓰므로 빈 번역으로 없앨 여지가 있다. 모든 지원 locale을 커버해야 하며 아직 적용/시각 검증하지 않았다. 정보 대체/게임플레이 범위도 구현 전에 결정한다.

### 공유 렌더 경로 때문에 안전하게 분리되지 않는 범위

- `Hud.extractItemHotbar → extractSlot → GuiGraphicsExtractor.item`과 `AbstractContainerScreen.extractSlot`이 공통 GUI 아이템 렌더러로 들어간다.
- `GuiRenderer.prepareItemElements → GuiItemAtlas.getOrUpdate → submitBlitFromItemAtlas`에는 HUD/menu 플래그가 없고 양쪽 모두 `ItemDisplayContext.GUI`다.
- 공통 `GUI_TEXTURED_PREMULTIPLIED_ALPHA`와 `position_tex_color` 셰이더를 사용한다. BlitRenderState의 2D vertex Z는 양쪽 모두0이다.
- GuiRenderer의 ortho/transform 버퍼도 공유된다. CPU stratum은 셰이더 문맥으로 전달되지 않는다. `IS_GUI`는 월드/GUI 구분일 뿐 HUD/컨테이너 구분이 아니다.
- `Globals.MenuBlurRadius`는 사용자 설정값이지 메뉴 열림 상태가 아니다.
- counts/itemBar/itemCooldown은 공유 text/rectangle 경로라 숫자/색/좌표로 지우면 컨테이너도 손상된다.

따라서 오래된 Z threshold, atlas UV/크기, 화면 하단 clip, GUI 모델 전체공백, 글꼴 숫자 전체공백을 채택하지 않는다. client inventory spoof도 메뉴와 동일 inventory를 바꾸므로 단순 렌더 수정으로 취급하지 않는다.

### minigame-lib / posteffect

ShaderFX glyph marker alpha251/253/252는 해당 glyph만 식별한다. DisplayHud의 `Position.y < -1000` 및 밝기(16,32)는 custom world geometry만 식별한다. 다른 vanilla GUI draw에 상태를 전달하지 않는다. `GameRenderer.render`의 post-effect가 GUI보다 먼저여서 후에 그려질 vanilla 핫바를 지우지 못한다. RPHandler가 text.fsh를 생성하므로 향후 공통 텍스트 수정은 생성기와 합성해야 한다.

## 구현 — 전용 그래픽/locale overlay와 offhand 가림 복구

- [생성기](../../scripts/generate_vanilla_hud_w76.py): 표준 라이브러리만 사용해14개 완전투명 RGBA PNG와143개 locale(공식142개+en_us)의 단일 XP 키 overlay를 만든다. 원본 JAR/index를 `--inspect-source`로 대조하고 `--verify`는 파일을 쓰지 않는다.
- [출처 사실](../../art/hud/w76-vanilla/references/source.json): 원본크기/SHA/locale목록만 보관한다. 원본 이미지나 번역 사전을 복제하지 않는다.
- [서버 리소스 계약](../../src/main/resources/destiny/hud/w76-vanilla.json): 적용범위와 잔존요소를 명시한다.
- 기존heart/crosshair 및 무기·HUD 모델/텍스처/오디오/공유shader는 보존한다. 공유 필수팩의 전역 시각변경이며 허기·XP 시뮬레이션/인벤토리 데이터는 변경하지 않는다. custom locale/다른팩우선순위까지 보장하지 않는다.

초기 실제 English PNG에서 offhand cobblestone이 좌하단 HUD를 덮는 문제를 발견했다. `CombatHud.sprite`가 **left alignment + offhand 비공백**일 때만 기존 DisplayHud above-hand 경로를 선택하도록 고쳤다. cache key에 이 상태를 넣어 empty↔occupied 전환에서 같은 HUD entity를 재사용하며 상태를 갱신한다. center 체력·기본빈손은 원래 경로를 유지한다. 별도 client 모드나 새로운 공통 GUI shader는 요구하지 않는다. 해당 경로의 실제 post-effect 호환성/화면과 packet/cache/복구를 최종 검증한다.

[QA](../qa/2026-10-24/w76/README.md)에는 초기 b2cf JAR의612GT/559JUnit2회와 offhand 보정 후 최종 gate/PNG를 구별해 기록한다. hotbar item icons/counts 및 tutorial toast 등 남은 요소를 삭제했다고 표현하지 않는다.
