# 17. 헌터 VFX 디테일 개정 — H14

작성일: 2026-10-22. H14 최종 에셋으로 GameTest52/52·JUnit10/10, build 통과(13:51:12 KST).
정상20TPS 실제26.3 프레임버퍼에서 능력6종을 확인했다. 연막은 첫 촬영 후 윤곽/명암을 수정해 세 번째 새 JVM에서 재촬영했다. 이후 미출력 메시 제거 후 새 서버 팩의 byte 동일성을 확인했다.
아래는 시각 디테일 개정과 실제 출력 비용의 기록이다. **근거리 카드 면 교차와 평면감은 남는다. 연막도 추가 아트 보정 여지**이며,
완전한 원작 재현·볼류메트릭·프레임레이트 성능 검증 완료로 해석하지 않는다.

## 1. 요청 해석의 교정

요청은 H13보다 정교한 VFX다. 단순한 lowpoly 덩어리·굵은 분절 호·작은 색상표만으로 충분하다고 해석한 범위를 교정한다.
곡선의 흐름, 전격의 가는 분기, 화염의 겹침과 잔불, 소용돌이 중심과 외곽의 대비, 연무의 덩어리 구분을 늘렸다.
색만 바꾼 같은 구체·고리를 네 속성에 반복하는 방향으로 처리하지 않는다.

구현은 **곡선 메시 + 128×128 아틀라스 카드 + 16×16 단색 팔레트 텍스처**의 혼합이다.
BetterModel 3.5.1의 실제 파서와 출력 경로가 지원하는 범위 안에서 형상을 세분화한 개정이며,
원작의 메시·텍스처·셰이더를 추출하거나 재배포한 작업이 아니다.

## 2. 현재 생성기와 정확한 에셋 수

근거 파일은 [H14 매니페스트](../../art/blockbench/vfx/manifest.json),
[형상 생성기](../../scripts/build_hunter_vfx.js), [내보내기 스크립트](../../scripts/export_hunter_vfx.py)다.
Blockbench 5.1.4 / MCP 1.10.1의 Generic(`free`) 프로젝트에서 생성한다.
아래 `Cube`는 생성기의 얇은 카드이며, 본 수는 매니페스트의 `render_bones`다.

| 런타임 모델 ID | 카드(Cube) | Mesh | 메시 삼각형 | 삼각형×3 모델 파트 | 렌더 본 | 클립 / 길이 |
|---|---:|---:|---:|---:|---:|---|
| `destiny_vfx_arc_h14` | 19 | 24 | 720 | 2,160 | 6 | `spawn` / 0.8초 |
| `destiny_vfx_solar_h14` | 45 | 16 | 864 | 2,592 | 8 | `spawn` / 1.1초 |
| `destiny_vfx_vortex_h14` | 23 | 11 | 1,024 | 3,072 | 4 | `loop` / 1초 |
| `destiny_vfx_smoke_h14` | 30 | 0 | 0 | 0 | 6 | `loop` / 2초 |
| 합계 | 117 | 51 | 2,608 | 7,824 | 24 | 서로 다른 모델 4개 |

합계는 에셋 4개를 합산한 값이다. 동시에 활성화된 효과 수나 디스플레이 엔티티 수를 뜻하지 않는다.
리본은 구간마다 정방향 삼각형 2개와 역방향 2개를 명시해 양면을 구성하며, 위 삼각형 수에 이미 포함되어 있다.
생성기는 모델당 삼각형 수가 1,800을 넘으면 실패하도록 검사한다.

`java-mesh` 0.0.1의 `MeshModel.create()`는 **삼각형 하나마다 모델 파트 3개**를 출력한다.
따라서 본이 4~8개라는 수치만으로 렌더 비용을 설명할 수 없다. 위 파트 수는 메시 변환분이며 카드 출력은 별도다.
이 수치를 draw call 수·FPS·TPS·서버 처리시간으로 환산하거나 성능이 충분하다고 판정하지 않는다.
[생성 팩 크기 기록](../qa/2026-10-22/vfx-h14-generated-pack-budget.json)도 정적 출력 관찰이며 부하 측정 결과가 아니다.

## 3. 메시와 카드의 역할

메시는 리본 경로의 양쪽 폭을 계산한 곡선 띠와 삼각형으로 나눈 구체를 만든다.
임의의 삼각형마다 별도 텍스처 색을 선택할 수 있어, 중심과 외곽의 색 차이를 형상과 함께 표현한다.

카드 아틀라스는 모델마다 128×128 PNG 한 장이다. 위쪽 16픽셀 띠에는 32픽셀 폭의 팔레트 4칸을 놓고,
나머지 영역에는 flare `[0,16,64,72]`, flame `[0,72,64,128]`, cloud `[64,16,128,128]` 타일을 만든다.
노이즈·색 변화·빈 픽셀을 가진 카드의 상세 모양은 이 아틀라스로 표현한다.
카드는 앞뒤 두 면에 텍스처를 지정하며 두께는0.024 제작 단위다. 생성기의 `light_emission=15` 대입은 Generic codec에서 직렬화되지 않는다.
생성기의 빈 픽셀은 그리지 않은 투명 영역이고, 그린 픽셀은 불투명 RGB다. 연속적인 알파 페이드를 구현한 것이 아니다.

메시는 아틀라스의 픽셀 디테일을 그대로 표시하지 못하므로 **색상별 16×16 단색 PNG 4장**을 별도로 둔다.
각 모델은 카드 아틀라스1장과 팔레트4장, 합계5장을 임베드한다. 최종 연막은 카드만 써서 팔레트4장은 미참조이며 크기는16×16이다.
메시 UV는 `[7,7]`, `[9,7]`, `[7,9]`로 배치한다. 단색 이미지이므로 Blockbench의 픽셀 UV와
BetterModel의 0~16 정규화 샘플링 차이가 색 선택에 영향을 주지 않는다.

| 모델 | 직접 작성한 팔레트: 밝음 → 어두움 |
|---|---|
| Arc | `#F5FDFF`, `#B4EFFF`, `#43B8F4`, `#2264A5` |
| Solar | `#FFF8D1`, `#FFDA69`, `#FF8B2F`, `#B82C15` |
| Vortex | `#FFE5FF`, `#D49DFF`, `#9053D4`, `#452462` |
| Smoke | `#AB9FBD`, `#887A9A`, `#60536E`, `#382E48` |

이 HEX와 클립 길이는 H14의 제작값이다. Bungie 공식 팔레트나 원작 영상에서 측정한 타이밍으로 표시하지 않는다.

## 4. BetterModel 3.5.1 파서 조사 결과

캐시된 `bettermodel-api/core` 3.5.1 및 `java-mesh` 0.0.1 jar를 `javap -c -p`로 읽었다.
조사한 파서·메시 변환·모델 파이프라인 클래스는 실제 서버의 processed jar와 바이트가 일치했다.

| 항목 | 확인한 계약 |
|---|---|
| 요소 타입 | `ModelElement.PARSER`는 `cube`, `mesh`, `locator`, `camera`, `null_object`를 분기한다. `type` 생략 시 `cube`다. Generic/free를 큐브 전용으로 제한하지 않는다. |
| Mesh 필드 | `uuid`, `origin: Float3`, `rotation: Float3`, `vertices: Map<String,Float3>`, `faces`, `visibility`. 각 면은 `vertices: Set<String>`, `uv: Map<String,Float2>`, `texture: int`를 가진다. 참조한 꼭짓점의 위치와 UV가 모두 필요하다. |
| 실제 출력 | `ModelPipeline` → `Group.buildMeshItemModel()` → `MeshBuilder`. 삼각형은 직접 변환하고 다각형은 ear clipping으로 삼각분할한다. |
| 메시 회전 | XYZ Euler 각도를 `toQuaternionXYZ()`로 변환해 적용한다. 단일 축의 22.5° 배수에만 제한되지 않는다. 위치에는 메시 origin과 그룹 origin의 차이를 반영한다. |
| 큐브 회전 | 단일 축의 `0, ±22.5, ±45°`는 일반 요소 회전 경로를 쓰며, 그 밖의 XYZ 회전은 별도 모델 묶음의 fixed display 회전으로 처리한다. |
| 카드 UV | `ModelUV`의 `uv: Float4`, `rotation: int`, 숫자 `texture` 인덱스를 해상도에 맞춰 출력한다. 카드 아틀라스의 상세 픽셀을 사용할 수 있다. |
| 메시 UV | 각 UV를 16으로 나눈 뒤 `MeshMath.sampleTriangleAverageColor()`가 텍스처 영역의 RGB 평균을 구한다. 출력은 삼각형별 상수 tint다. 픽셀 단위 텍스처 매핑이 유지되는 경로가 아니다. |
| 재질 한계 | Mesh 파서에는 픽셀 알파 재현, 사용자 normals/스무스 노멀, `shade`, `light_emission` 전달 필드가 없다. 큐브에는 `light_emission`이 있다. |

메시 UV `[U,V]`의 샘플 좌표는 `x=(U/16)×(width−1)`, `y=(1−V/16)×(height−1)`이다.
PNG 위쪽이 작은 y이며 V는 반전된다. 샘플러는 삼각형 안의 픽셀 중심 `(x+0.5,y+0.5)`을 검사해 RGB를 정수 평균하고,
샘플이 없으면 UV 무게중심을 픽셀 좌표로 바꿔 반올림·범위 제한한 한 픽셀을 읽는다.
알파에 따른 면의 구멍이나 부드러운 투명도는 메시 출력으로 전달하지 않는다.

**상수 tint 자체는 unlit 설정이 아니다.** 생성되는 메시 기본 삼각형에도 `shade:false`나 `light_emission`은 없다.
현재 런타임은 별도로 `TrackerUpdateAction.brightness(15,15)`를 지정하며, 이 밝기는 블록/하늘광 override이며 방향별 면 음영까지 제거하는 unlit 설정은 아니다.
이를 셰이더 bloom·동적 광원·가산 블렌딩·볼류메트릭 연기 구현으로 설명하지 않는다.

## 5. 속성별 조형과 레퍼런스 상태

- Arc: 작은 이온 중심과 교차 섬광 카드, 끊어진 곡선 충격파 3개, 주 전격 4갈래와 가는 분기·불꽃 입자. 굵기가 일정한 장식 고리에서 벗어나 중심과 가는 선을 구분한다.
- Solar: 백열 중심과 섬광 카드, 열기 호 3개, 화염 그룹 6개의 곡선 리본 2층·불꽃 카드·잔불을 겹친다. 바깥쪽·위쪽 이동과 축소 트랙을 사용한다.
- Vortex: 밝은 중심, 폭이 변하는 궤도 리본 6개와 가는 유입 리본 4개, 궤도 먼지 카드 20개. inner/outer/wisps의 회전과 크기 변화를 분리한다.
- Smoke: plume 그룹6개에 cloud 카드5개씩을 배치한다. 최종 연막은 메시를 쓰지 않는다. 1차 실제 프레임버퍼에서 잎처럼 보인 외곽을 교정해, 낮은 주파수의 둥근 billow 경계와 완만한 내부 명암·난류로 바꿨다. 모든 카드의 로컬 회전을0으로 통일하고 본 애니메이션은 면 안의 Z축 회전만 사용한다. 연막에만 본 단위 CENTER 빌보드를 적용해 보는 방향에 따라 교차 면이 옆면으로 서는 문제를 줄였다. 가장자리는 미세 확률 cutout으로 처리한다. 최종30카드/6본이며 다른3종 에셋은 바꾸지 않았다. 최종 실화면 정면과 측면에서 카메라를 향하는 연무를 확인했다. 블룸/실제 볼륨은 아니며 극근거리 평면감은 후속 보정 대상이다.

레퍼런스의 증거 등급과 미확인 범위는 [15. 헌터 VFX 레퍼런스](15_헌터_VFX_레퍼런스.md)를 그대로 승계한다.
매니페스트에서 Arc·Solar·Vortex는 `reference_based_detailed_adaptation`, Smoke는 `provisional_not_destiny_verified`다.
소이·소용돌이는 능력 이름에 연결된 실제 게임 정지 이미지가 있고, Arc는 작가 Hunter 표지와 Flashbang 카드가 근거다.
이것을 실제 Combination Blow 타격 프레임이나 Flashbang 게임플레이 폭발의 직접 검증으로 격상하지 않는다.
선택한 Solar knife 변형의 정확한 VFX와 Hunter 연막의 발생·확산·소멸 영상도 확보 상태로 바꾸지 않는다.
Smoke의 실제 구현 캡처는 확보했지만, 이는 원작 Hunter 연막 레퍼런스 확보와 별개다.

## 6. 런타임 ID 전환과 유지한 동작

`HunterVfxAssets.MODELS`와 `HunterVfx.Kind`는 `_h14` ID를 사용한다.
Arc 섬광탄/연속 타격은 Arc 모델, Solar 소이탄/투척 칼은 Solar 모델을 공유하며, Void 소용돌이와 연막은 각각 별도 모델이다.
6종 능력을 서로 다른 에셋 6개로 늘린 것은 아니다.

편집본은 `art/blockbench/vfx/`, 번들본은 `src/main/resources/destiny/vfx/`에 있다.
H13 편집본·번들본과 [H13 매니페스트](../../art/blockbench/vfx/manifest-h13.json)는 보존한다.
설치기는 `config/bettermodel/models/`에 없는 파일만 복사하므로 기존 H13 아티스트 파일을 덮어쓰지 않는다.
같은 이름으로 이미 설치한 H14 파일 역시 자동 교체하지 않는 계약이다.

게임플레이와 TTL 계약은 [16. 헌터 VFX 구현](16_헌터_VFX_구현.md)의 기존 동작을 유지한다.
피해·끌림·상태 효과·쿨타임·투사체 동작을 이번 디테일 개정의 변경 대상으로 삼지 않는다.

| 항목 | 유지한 계약 |
|---|---|
| 단발 | Arc 최대 16틱, Solar 최대 22틱. 클립은 `spawn` / `PLAY_ONCE` |
| 지속 | Vortex/Smoke는 요청 수명을 쓰되 최대 200틱. 클립은 `loop` / `LOOP` |
| 실제 수명 | `min(요청 틱, 200, 종류별 상한)`이며 루프 클립 길이와 구분 |
| 규모·관찰자 | 소유자당 4개, 전체 24개 tracker 상한. 같은 월드의 48블록 이내 관찰자, 5틱마다 갱신 |
| 정리 경로 | TTL·소유자 상태 검사, `cancelOwned()`·`clearAll()` 경로 유지. 실제 자연 만료 active0·clear·서버종료와 클라이언트 옵션 복구를 QA에 기록 |

### 연막 방향 보정

설치 API의 `TrackerUpdateAction.billboard(PlatformBillboard.CENTER)`를 연막 tracker에만 적용한다.
기본 본 태그가 아니라 `ModelDisplay.billboard()`로 전달되는 본 단위 업데이트다. `PlatformBillboard`는
`FIXED`, `VERTICAL`, `HORIZONTAL`, `CENTER`를 지원한다. 각 plume의 카드들이 함께 카메라를 향한다.
**카드마다 독립 디스플레이를 만들지 않으며6본을 유지한다.** 본마다 원점이 달라 연무 덩어리 위치가 분리된다.
본 안의 여러 카드도 같은 로컬 방향이어야 한다. 내부 카드가 각기 Y로 회전하면 빌보드만 설정해도 여전히 옆면이 보이므로 형상과 애니메이션을 함께 수정했다.

### 남는 한계

메시는 스무스 노멀/픽셀 텍스처가 아니라 상수 tint이며, 카드도 진짜 볼류메트릭이 아니다.
근접·상면·강한 이동에서 카드 평면감/면 교차가 남을 수 있다. 연막의 정확한 원작 충실도는 미확인이다.
별도 bloom·가산 블렌딩·포스트 이펙트·동적 조명은 이번 디테일 개정에 추가하지 않았다.
원작 영상의 타이밍/광학적 일치, 밤/동굴·여러 관찰자·24개 동시 효과 FPS/TPS는 미검증이다.

### 출력 검사를 통해 제거한 미사용 형상

중간 Smoke 에셋에 직각 카드와 작은 구체 메시를 같은 본에 넣었으나 실제 생성 팩은 큐브5개씩의 일반 block model6개만 참조했고 메시 파트는0이었다. 렌더러 등록 성공만으로 모든 요소의 렌더링을 보장하지 않음을 확인했다. Arc/Solar/Vortex의 곡선 메시는 실제 composite 파트2160/2592/3072개로 확인된다.
최종 연막은 빌보드 카드만으로 의도한 시각을 구성하므로 미출력 구체를 편집본/번들에서 제거하고 테스트를 수정했다.
[렌더 동등성 검사](../qa/2026-10-22/vfx-h14-smoke-render-equivalence.json)는 정리 전 실제 촬영 팩과 정리 후 새 서버 팩의 item6개+참조 block model6개가 바이트 단위로 동일함을 기록한다. 따라서 최종 카드-only 에셋의 화면 근거는 세 번째 JVM 캡처와 동일한 출력이다.
