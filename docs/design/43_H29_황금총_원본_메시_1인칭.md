사용자 요청: 황금총도 Blender로 원본을 가져와 적용하고 잘못된 1인칭 회전을 고친다.
기존 H28 전기/공허 모델·후방 카메라·공격 타이밍은 보존한다. Solar는 1인칭을 유지한다.

- 현재 황금총은 3발 설정이다. Marksman의 기반 실루엣은 Eyasluna이므로 해당 원본을 선택한다.
  Deadshot의 The Last Word와 구분한다.
- 참고: https://www.destinypedia.com/Golden_Gun (2026-10-23 열람, Trivia의 두 변형 설명).
- 제공 Drive의 `.Player Gear/Season 15.5 - 30th Anniversary/Weapons/Eyasluna.7z`:
  https://drive.google.com/file/d/19wzb1iIxcOeqEyr9_rsZ4CitUyenFilO/view
- 이 파일은 **일반 Eyasluna 원본**이며 궁극기 전용 셰이더/애니메이션 원본이라고 주장하지 않는다.
  원작 디자인은 Bungie. 아카이브 내 저자 표기가 있으면 별도로 기록한다.
  공개 라이선스 확인 전 공개 배포/푸시하지 않는다. 원본 binary/texture/script는 저장소에 넣지 않는다.
- 다운로드는 `/tmp/destiny-golden-h29/`, 사용자 Blender의 기존 장면/원본 파일은 변경하지 않는다.
  아카이브의 Python/shader 코드는 실행하지 않고 별도 장면에 FBX/메시만 가져온다.

현재 원인 후보: 개인 화면용 `ItemDisplayHud`가 일반 GUI 문맥을 사용해 기존 모델의
인벤토리용 `[20,135,-10]` 회전을 그대로 적용한다. 실제 경로를 확인한 뒤 개인용 문맥과
3인칭 장착 문맥을 분리하고, 총구가 화면 중앙 위쪽으로 향하는 시점으로 수정한다.

## S2: Blender 변환 / 회전 경로 수정

원본 FBX를 별도 장면에 import하고 native `.blend`는 library append로만 검사했다.
포함 Python/shader 스크립트는 실행하지 않았다. 기존 다섯 장면의 오브젝트 목록은 불변이다.
Frame 15,622tri / cylinder 1,452tri / sight 350tri. Reticle/helper 평면 6tri는 제외했다.
원본 복사본만 weld1e-6 후 각각 1,800 / 450 / 100tri, 합계 **2,350tri**로 변환했다.
원본 꼭짓점→변환 표면의 최대 거리(raw item unit)는 frame .16527 / cylinder .04723 / sight .02865다.
Hausdorff 거리나 모든 실루엣 방향의 무손실 주장은 아니다. 원본/변환 비교 렌더를 직접 확인했다.

원본 -Y 총구를 raw +Z, grip 기준 `(8,8,8)`로 정규화했다. 삼각형당 H28 alpha quad 1개를
재사용하므로 2,350mesh파트다. 원본 diffuse UV 4샘플 평균을 보존하고 밝기 L로
`(195+60L,74+132L,8+50L)`의 별도 Solar gold 팔레트를 입혔다. 원작 에너지 셰이더/PBR는 아니다.

- `golden_gun_h29`를 실제 Solar 장비와 개인 HUD에서 공용으로 선택한다.
- 개인 HUD는 `GUI` 대신 `FIRST_PERSON_RIGHT_HAND` 문맥을 사용한다.
  첫 조준 후보 회전 `[-24,28,0]`, ready `(1280,925)`, 크기420. 실제 화면에서 조정한다.
  인벤토리 GUI 사선 회전과 3인칭 손 translation2는 별도로 유지한다.
- 추가 원인: DisplayHud의 `vecToQuat`는 `rotateZYX(vector.x,vector.y,vector.z)`를 호출한다.
  기존 `setLeftRotation(0,0,roll)`은 화면 Z roll이 아니라 X pitch였다.
  라이브러리 전체를 변경하지 않고 Solar 호출만 `(roll,0,0)`로 어댑트했다.
  소환/반동/소멸이 화면 법선을 보존하는지를 unit + 실제 HUD GameTest로 검사한다.
- 생성기 `scripts/build_golden_gun_h29.py [--verify]`는 저장소의 colored derivative로 재현하며
  Blender/원본 archive/사용자 아트 파일에 쓰지 않는다.

## S3: 첫 gate와 실화면 피드백

첫 전체 gate는171GameTest/136JUnit 통과했다. 실제 새 서버/새 팩으로 native Solar 발동·3발을
확인했으나 첫 후보 `[-24,28,0]`는 총구가 화면 바깥 오른쪽을 향하고 총구 구멍이 보였다.
따라서 이 이미지를 올바른 조준 구도 통과로 세지 않는다. HUD 경로의 실제 투영을 기준으로
총 뒤에서 보는 `[24,-152,0]` 후보로 수정한다. 왼손 asset 문맥도 부호 대칭으로 명시한다.
개인 HUD의 오른손 선택과 인벤토리/실제 손 아이템 불변은 유지한다.
자체 client/server를 종료한 뒤 생성·gate·새 팩 검증을 다시 수행한다.

## S4: 재검증 / 낮은 TPS 입력 시나리오 보정

두 번째 전체 gate도171GameTest/136JUnit 통과. 수정 후 실제 화면에서 총구가 중앙 위쪽으로
향하고 뒤쪽에서 총 상단을 보는 것을 확인했다. 외부 측면도 실제 손에 장착된 원본 실루엣을
확인했다. 20TPS 발동+3회 native attack 완료, 다른 yaw90/pitch-15와 forward 이동도 완료했다.

5TPS 첫 시나리오는189client ticks를 사용해 runner의30초 deadline을 넘었다.
client ticks를 고정20Hz wall time으로 간주한 QA 시나리오 오류이며 게임 통과로 세지 않는다.
실패 후에도 lease=false/heldKeys=[]/pendingSteps=0/native중립/health20/self-camera를 확인했다.
fixture subclass를 다시 설정하여 잔여 session을 정리하고65client ticks로 줄여 다시 검증한다.
이는 실제 native 경로를 쓰는 테스트이며 제어 우회나 임의 ability 호출로 대체하지 않는다.
