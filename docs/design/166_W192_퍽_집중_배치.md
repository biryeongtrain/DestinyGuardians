# W192 퍽 집중 배치

사용자 지시: 애니메이션은 Windows 파일을 받을 때까지 보류한다. 수치 퍽별 테스트 대신 공식 소켓·DDC 수치와 실제 적용 경로를 확인하고 처리량을 늘린다. 새 발동/만료/피해/탄약 동작만 필요한 범위로 검증한다.

## 1. 범위와 분담

| 담당 | 퍽 | 기본 소켓 대상 | 구현 범위 |
|---|---|---:|---|
| 격리 worktree 리더 1 | Rangefinder | 18 | ADS 사거리·줌·투사체 속도 |
| 격리 worktree 리더 2 | Backup Plan | 3 | 실제 stow→ready, 충전 snapshot·피해·LFR 갱신 |
| 격리 worktree 리더 3 | Encore | 1 | 실제 유료 무기 처치·정밀 처치, 중첩·만료 |
| master | Well-Rounded | 5 | 성공한 능력 사용·강화 근접 적중, 공통 합산·통합 |

각 리더는 `/private/tmp/destiny-w192/batch.json`의 소유 파일만 수정한다. main의 dirty snapshot 기준선은 66,093개 파일, SHA256 `022911470c2d652e66631580508e0849c2590f4ed165573d27a67b8cb36345a3`이다. 공통 runtime/registry/ability 경로와 중앙 검증은 master가 소유한다. 애니메이션/모델 변경은 포함하지 않는다.

## 2. 출처와 구현 기록

- Bungie 로컬 pinned manifest 버전 `245114.26.10.13.2000-1-bnet.66137`, 실제 랜덤 소켓 풀의 기본 Trait만 선택. Enhanced는 제외.
- DDC Perks 행 174/24/83/246을 각 provenance에 보관한다. 입력 HTML SHA256 `8b8109ecd80601965edcfc9559a784bd17cfc0e2e84419385ab68788fd376437`.
- Well-Rounded: 5개 기본 소켓, 원시 handling 곡선·동시 소켓 증거 생성. 능력 성공/자원 지불 이후 이벤트와 실제 powered melee positive loss 경로를 연결한다. stow/궁극기 중 타이머는 진행한다.
- 공통 사거리 경로는 기본 Range + 활성 퍽 보너스를 합산한 뒤 100 상한을 한 번 적용한다. Stats for All의 별도 falloff ×1.05와 기존 ADS falloff 보간은 보존한다.

## 3. 통합 기록

- 세 worktree의 소유 delta 22개 파일을 기준 해시와 main drift 확인 후 통합했다. 리더 3개는 종료했으며 worktree는 보존한다.
- 구현 퍽 registry 45→49. `destiny perk select`/목록/해제 및 소켓 변경 invalidate 경로에 4개를 연결했다.
- Rangefinder: 실제 소유 ADS >=.5에 Range +10/투사체 초기 속도 ×1.05, 줌 목표 ×1.1은 기존 FOV 진입 보간으로 표시한다. 줌을 사거리 scalar에 중복 적용하지 않는다.
- Encore: 유료 emission token을 실제 정밀/일반 최종타 확인에 전달한다. splash는 정밀 credit 없이 같은 token을 공유한다.
- Backup Plan: 실제 stow 이력 60tick 뒤 ready. charge acceptance에서 raw milliseconds ×.7과 damage ×.8을 캡처하며 충전 완료·후속 공유 탄약 bolt도 같은 profile을 사용한다. 활/일반 burst의 기존 정책을 보존한다. 실제 paid LFR emission만 아직 유효한 창을 갱신한다.
- Well-Rounded: 능력 성공·자원 지불 후 수류탄/궁극기 이벤트, positive direct powered melee contact에 연결했다. 복사본·소켓 변경·원본 상실은 state를 넘겨받지 못한다.
- Handling/ADS는 정확한 다른 소켓의 동시 선택 보너스를 raw stat에 합산한다. 들어오는 Threat Detector는 실제 selection 경계에서 원본을 샘플링한다.

## 4. 검증 기록

- 중앙 targeted JUnit: 새 상태 테스트 **20/20 통과** (Backup Plan 10, Encore 7, Well-Rounded 3). 이어진 GameTest fixture 컴파일에서 26.3의 `setPermanentlyInvulnerable` API 이름을 수정했다. 게임 로직 수정에 의한 재시도는 아니다.
- 새 headless 서버 GameTest **6/6 통과**: Well-Rounded 성공/거부·stow/원본 상실, 실제 궁극기 자원 지불/유지, 강화 근접 실제 피해/중복, Encore 유료 정밀 처치/stow, Backup Plan 만료를 가로지르는 charge snapshot, 실제 paid LFR 갱신.
- 최종 전체 JUnit **1,882/1,882 통과**, failure/error/skip 0.
- 최종 전체 서버: **1,276개 중 1,252 통과·24 실패**. 실패 ID는 모두 W191에서도 관측된 항목이며 새 W192 실패는 없다. 기존 presentation/reticle/wire/model 기대값과 간헐적인 ThreatDetector ADS 실패를 포함한다. 원인이 전부 과거부터 존재했다고 증명한 것은 아니며, 전체 build를 green이라고 보고하지 않는다. 이번에 관측되지 않은 IzanagiScope 실패도 해결 완료로 간주하지 않는다.
- `assemble` 성공. JAR `build/libs/destiny-guardians-0.1.0+26.3.jar`, **48,746,944 bytes**, SHA256 `030bcb7d378fb1e3b9f5eb028802c308ed9153142a571ca4f6f79e3d82204a70`.
- 단순 수치에는 출처/실제 적용 경로 리뷰를 적용했다. 수치별 mirror test·Vision/native 입력·실화면/청취 검증은 수행하지 않았다. 애니메이션/모델 조사나 구현을 재개하지 않았다.
- `docs/qa/2026-10-27/w192/`에 원본 로그·단위 XML·새 서버 XML·전체 실패 목록·통합 해시·출처/적용 경로 기록을 보관한다. W191 봉인 **301개 파일 모두 불변**을 확인했다.

## 5. 완료 범위와 다음 작업

이번 배치의 4개 퍽 구현·출처 대조·범위별 검증을 완료했다. 구현된 선택 퍽은 **45→49종**이다. 전체 무기 목표는 진행 중이며 완료로 표시하지 않는다. 다음 배치도 정확한 기본 소켓의 미구현 퍽을 묶어 진행한다. Windows 파일 전달 전까지 애니메이션 대기 방침을 유지한다.
