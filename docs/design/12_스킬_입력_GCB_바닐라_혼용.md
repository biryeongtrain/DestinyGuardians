# 12. 스킬 입력 – GCB와 바닐라 혼용

능력 입력을 **GCB-mod 클라이언트가 있는 플레이어는 전용 키(Z·X·C·V 등)로, 없는 플레이어는 바닐라 입력 조합으로** 처리합니다. 서버는 플레이어마다 GCB 사용 여부를 보고 입력 경로를 고릅니다. 바닐라 플레이어도 모든 기능을 쓸 수 있고, GCB는 조작감을 높이는 선택 사항입니다.

근거 (2026-10-22 확인)
- GCB-mod: <https://github.com/eiqq/GCB-mod> (커밋 `fb14bfa`, 2026-10-11, mod_version 4.1.1, Minecraft 26.3, AGPL-3.0) – 클라이언트 소스 직접 확인
- GCB-server: `~/IdeaProjects/GCB-server` (origin `biryeongtrain/GCB-server`, 로컬 작업본 `1.2.0+26.3`, MIT) – 서버 소스 직접 확인

## 1. GCB 구성

| 구성 | 위치 | 역할 |
|---|---|---|
| **GCB-mod** | 플레이어 클라이언트 (선택 설치) | 키 입력 상태·카메라 시점을 서버로 보냄, 서버가 보낸 모양 파티클 그리기, 모델 본 묶음 갱신 수신, 탈것 예측 |
| **GCB-server** | 서버 라이브러리 | `minecraft:gcb` 채널 수신, 플레이어별 키·시점·모드 상태 저장, 이벤트 발행, 파티클·묶음 전송 |

### 1-1. 클라이언트 → 서버 (GCB-mod 소스 확인) ✅

| 데이터 | 보내는 시점 | 형식 (`minecraft:gcb` 문자열 채널) |
|---|---|---|
| 모드 버전 | 접속 직후 | `<버전>` |
| 설치 모드 목록 | 접속 직후 | `MODS:<modId>` (모드마다) |
| **키 상태** | 화면(GUI)이 닫혀 있을 때, 상태가 바뀐 틱 | `KEYINPUT:<키 이름>:<true/false>` |
| **카메라 시점** | F5로 시점이 바뀔 때 | `PERSPECTIVE:FIRST_PERSON / THIRD_PERSON_BACK / THIRD_PERSON_FRONT` |

**보내는 키 (18개)**

| 분류 | 키 | 비고 |
|---|---|---|
| GCB 전용 키 | **Z, X, C, V, 0** | GCB가 키 설정에 "gcb" 분류로 새로 등록. 플레이어가 키를 바꿔도 서버는 같은 이름으로 받음 |
| 핫바 | 1~9 | 바닐라 핫바 키의 눌림 상태. **바닐라 슬롯 변경도 그대로 일어남** |
| 바닐라 동작 | 공격(좌클릭), 사용(우클릭), 블록 선택(휠 클릭), 버리기(Q) | **누르고 있는 상태**를 알 수 있음. 바닐라 동작도 그대로 일어남 |

> README에는 "13개 키"라고 적혀 있지만 실제 코드는 5 + 9 + 4 = 18개를 보냅니다.

### 1-2. 서버 API (GCB-server 소스 확인) ✅

```java
// 키 상태가 바뀔 때
PlayerKeyStateChangedEvent.EVENT.register((player, pushed, key) -> { ... });   // key: Key.KEY_Z, KEY_ATTACK ...
// 카메라 시점이 바뀔 때
PlayerCameraTypeChangedEvent.EVENT.register((player, cameraType) -> { ... });  // FIRST_PERSON, THIRD_PERSON_BACK, THIRD_PERSON_FRONT

GCBPlayer gp = (GCBPlayer) serverPlayer;   // Mixin 으로 ServerPlayer 에 붙음
gp.gcb$hasMod();            // GCB 패킷을 한 번이라도 받았는가
gp.gcb$getModVersion();
gp.gcb$isKeyPressed(Key.KEY_ATTACK);
gp.gcb$getCameraType();
```

- 그 밖에: `GCBParticleS2CPacket`(원·선·궤적·구·나선 모양 파티클), `PlayerVelocityS2CPacket`(26.3에서는 바닐라 속도 패킷으로 보냄), Polymer `ElementHolder` Display 변환 묶음 전송(`gcb:bulk_data`).

## 2. GCB가 해결하는 문제

| 바닐라만으로의 한계 (메인 문서 1-2) | GCB가 있을 때 |
|---|---|
| 새 단축키를 만들 수 없음 | Z·X·C·V·0 다섯 개 전용 키 |
| 좌클릭을 **누르고 있는지** 알 수 없음 → 정조준을 토글로 만듦 | `KEY_ATTACK` 눌림 상태 → **누르고 있는 동안 정조준** |
| 서버가 F5 시점을 모름 → 본인 limb 표시를 정할 수 없음 (04, P-01) | `PERSPECTIVE` → 1인칭이면 숨기고 3인칭이면 보여줌 |
| 파티클을 서버가 점마다 보냄 | 모양 파티클 한 패킷 → 클라이언트가 그림 |
| 3인칭 탈것 조작이 3틱 늦음 | 탈것 예측(1틱) |

## 3. 입력 매핑 – GCB / 바닐라

| 동작 | GCB 플레이어 | 바닐라 플레이어 (대체) | 비고 |
|---|---|---|---|
| 수류탄 | **Z** | 손 바꾸기(F) | |
| 근접 능력 | **V** | 웅크리기 + 좌클릭 | 바닐라 조합 `[결정 필요]` |
| 직업 능력 (방벽·회피·균열) | **C** | 웅크리기 두 번 | ⚠️ C는 바닐라 "핫바 저장" 키와 겹침 (4장) |
| 궁극기 | **X** | 웅크리기 + F | ⚠️ X는 바닐라 "핫바 불러오기" 키와 겹침 |
| 스킬 트리 열기 | **0** | 명령 `/guardian` 또는 거점 단말기 | |
| 정조준 | **좌클릭 누르고 있기** | 좌클릭 토글 | |
| 사격 | 우클릭 누르고 있기 | 우클릭 누르고 있기 | 둘 다 아이템 사용 상태로 처리 |
| 재장전 | Q | Q | 둘 다 버리기 이벤트 취소 |
| 직업 이동 (활공·제트팩·2단 점프) | 공중에서 점프 | 공중에서 점프 | 바닐라 입력 패킷 |
| UI 커서 이동 | 핫바 1~9 / 시점 | 핫바 스크롤 | 08-5 |

- GCB 플레이어도 **바닐라 조합은 그대로 쓸 수 있게** 둡니다. 키를 몰라도 플레이할 수 있게 하기 위함입니다.
- 같은 동작이 같은 틱에 두 경로로 들어오면 한 번만 실행합니다(동작별 틱 디바운스).

## 4. 키 충돌 ✅ (26.3 클라이언트 `Options` 확인)

26.3 기본 키 설정(SDL3 스캔코드)에서:

| 키 | 바닐라 기본 동작 | 영향 |
|---|---|---|
| C | 핫바 저장 (`key.saveToolbarActivator`) | **크리에이티브에서만** 동작. 서바이벌 플레이에는 영향 없음 |
| X | 핫바 불러오기 (`key.loadToolbarActivator`) | 〃 |
| Z, V, 0 | 기본 동작 없음 | 없음 |
| O | 친구 화면 (`key.friends`, 26.3 추가) | GCB 키 아님 |

- 서버 운영자·크리에이티브 테스트 중에는 C·X가 겹치므로 GCB 키 설정에서 바꾸도록 안내합니다.

## 5. 서버 구조 – 입력 라우터 (W2-03)

```
            ┌─ VanillaInputSource ─ 플레이어 입력 패킷(점프·웅크리기·이동), 손 바꾸기, 버리기,
            │                       아이템 사용 시작·끝, 팔 휘두르기
RawInput ───┤
            └─ GcbInputSource ───── PlayerKeyStateChangedEvent, PlayerCameraTypeChangedEvent
                         │
                         ▼
               InputProfile (플레이어별: VANILLA / GCB)
                         │  키 → 동작 매핑표 (data/destiny/input/*.json)
                         ▼
               GuardianAction (GRENADE, MELEE, CLASS_ABILITY, SUPER, ADS_START/END, FIRE, RELOAD, ...)
                         │  디바운스, 쿨타임·상태 검사
                         ▼
               AbilityExecutor / WeaponController
```

- **프로필 결정**: 접속 시 VANILLA로 시작 → GCB 패킷을 처음 받으면(`gcb$hasMod`) GCB로 전환. 버전 패킷이 늦게 와도 그 사이에는 바닐라 입력이 동작합니다.
- **매핑은 데이터로**: 키 → 동작 표를 JSON으로 두어 서버 설정으로 바꿀 수 있게 합니다.
- **신뢰하지 않기**: GCB 키 패킷은 클라이언트가 보내는 값이므로 바닐라 패킷과 똑같이 검증합니다. 쿨타임·상태 검사는 서버에서만 하고, 키 패킷이 틱당 비정상적으로 많으면 무시합니다.
- **GUI 상태**: GCB-mod는 화면(GUI)이 열려 있으면 키를 보내지 않습니다. 화면을 여는 순간 "누름" 상태가 남아 있을 수 있으므로, 서버는 컨테이너·다이얼로그를 열 때 해당 플레이어의 GCB 키 상태를 모두 "뗌"으로 초기화합니다. 🧪

## 6. 카메라 시점 활용 (04-2, P-01)

2026-10-22 테스트([11 검증 기록](11_작업_계획.md#검증-기록))에서 **본인 limb 모델이 1인칭 화면을 가린다**는 것을 확인했습니다. 시점에 따라 본인 표시를 바꿉니다.

| 플레이어 | 시점 | 본인에게 limb 표시 | 다른 플레이어에게 |
|---|---|---|---|
| GCB | 1인칭 | 숨김 | 표시 |
| GCB | 3인칭 (뒤/앞) | **표시** | 표시 |
| 바닐라 | 알 수 없음 → 1인칭으로 가정 | 숨김 | 표시 |

- 바닐라 플레이어가 F5로 볼 때는 동작 중 자기 몸이 안 보입니다(실제 플레이어도 숨김 상태). 허용하는 제약으로 둡니다.
- GCB 플레이어가 동작 중간에 시점을 바꾸면 이벤트를 받아 즉시 표시를 바꿉니다.
- 구현: BetterModel 파이프라인의 보기 필터(`viewFilter`)에서 "본인이고 1인칭이면 제외". 🧪

## 7. VFX·모델 전송

| 기능 | GCB 플레이어 | 바닐라 플레이어 |
|---|---|---|
| 모양 파티클 (탄 궤적, 균열 원, 충격파 링) | `GCBParticleS2CPacket` 한 패킷 (원·선·궤적·구·나선, 엔티티 추적, 시간 애니메이션) | 서버가 점 파티클로 계산해 전송 |
| Display 변환 묶음 | Polymer `ElementHolder` 경로의 변환을 `gcb:bulk_data` 한 패킷으로 | 바닐라 메타데이터 패킷 |

- VFX 코드는 `FxSender` 하나로 감싸고, 보는 사람(viewer)마다 GCB 여부에 따라 전송 방식을 고릅니다.
- ⚠️ 묶음 전송은 **Polymer `ElementHolder`를 거치는 모델만** 대상입니다. BetterModel은 자체 패킷 경로를, DisplayHud 2.x는 자체 `HudPackets`를 쓰므로 대상이 아닐 가능성이 큽니다. 효과가 필요하면 별도 확인이 필요합니다. 🧪

## 8. 3인칭 탑승형 연출 (04-3 방식 B 보완)

GCB 서버(게임캐릭터배틀)는 **플레이어가 모델을 씌운 서버 몹에 탑승**해 3인칭 캐릭터를 조작합니다. GCB-mod의 탈것 예측이 이 구조를 위한 것입니다.

| 항목 | 내용 |
|---|---|
| 구조 | 보이지 않는 서버 몹 + BetterModel 모델, 플레이어가 탑승 |
| 이동 입력 | 탑승 중에도 바닐라 플레이어 입력 패킷(WASD·점프)이 서버로 옴 → 서버가 몹을 움직임 |
| 조준 | 플레이어 자신의 시점 회전이 그대로 서버로 옴 → 04-3 방식 B의 "마우스 회전을 받을 수 있나" 문제를 피함 |
| 시점 | 서버가 F5를 강제할 수 없음. GCB 플레이어는 시점 이벤트로 안내·확인 가능 |
| GCB 이점 | 탈것 위치 보간 3틱 → 1틱 + 1틱 앞 예측 (서버 권한 몹일 때만) |

- 지속형 궁극기(황금 총·아크 지팡이 등)를 3인칭으로 보여주고 싶을 때의 후보로 둡니다. PoC: P-05.
