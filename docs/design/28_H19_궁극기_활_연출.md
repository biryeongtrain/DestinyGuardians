# H19 — Shadowshot 활 사격 연출

> 후속 [H19B 방향/내보내기 보정](29_H19B_활_3인칭_방향_보정.md): H19의 handed 변환 생략과 drawn 모델의 배열 순서·UV 결함을 수정한다. 아래는 H19 당시 설계/검증 기록이며 최신 장착 방향의 인수 근거는 H19B를 따른다.

## S1. 레퍼런스와 현재 문제 (2026-10-22)

- [Bungie Void3.0 소개](https://www.bungie.net/7/en/News/article/51021): Deadfall의 단발 닻과 Moebius의 다중 화살을 구별한다. 이번 구현은 기존 Deadfall 단발을 유지한다. 원작의 최신 밸런스 수치를 복사하는 작업은 아니다.
- [Shadowshot 홍보 이미지](https://destiny.wiki.gallery/images/7/7e/Shadowshot.jpg), [발사 후 이미지](https://destiny.wiki.gallery/images/c/c6/Shadowshot2.jpg): 저장된 `art/blockbench/supers/references/` 두 파일을 이번에 직접 열어 확인했다. Bungie 워터마크가 있는 위키 미러 이미지다. 활 지지팔을 펴고 반대팔로 시위를 당기는 비대칭 자세, 보라·백색 에너지의 갈라진 활 실루엣을 참고한다.
- 공식 소개의 [Hunter 영상](https://youtube.com/embed/KpMu_B7cowY)은 링크를 찾았지만 열기 제한으로 영상을 재생·프레임 분석하지 못했다. 영상에서 정확한 시간/모캡 데이터를 추출했다고 주장하지 않는다.
- 원작 메시·애니메이션·스프라이트를 추출한 것이 아니다. 기존 자체 제작 H15 활에 자체 제작 draw 상태와 새 전신 모션을 더한다. 참고 이미지는 런타임 팩에 넣지 않는다.

H15는 활을 오른손에 고정하고 반대팔을 크게 움직였으며, primary 순간 화살을 바로 발사한 뒤0.21초쯤 시각 릴리스를 재생했다. 준비/당김/화살 타이밍이 분리돼 활 사격으로 읽히기 어려웠다.

## S2. 구현 계약

- 새 `guardian_hunter_h19` 모델·클립 리소스를 설치한다. 기존 설치된 H15/아티스트 파일은 덮어쓰지 않는다. 방향 회피·Arc·Solar 클립은 보존하고 기존 `h15_` 클립 ID는 호환용으로 유지한다.
- 왼손에 활, 오른손은 빈 당김손. 실제 인벤토리는 변경하지 않고 BetterModel item bone의 시각 override만 바꾼다.
- 낮은 준비 → 활 들기 → 당김 → 조준 유지 → 릴리스 → 팔·망토 후속 → 준비 복귀를 저작한다. 전체0.90초, 릴리스 키0.30초. BetterModel 시작 보간1틱을 포함해 서버 화살 contact는7틱이다. 원작의 정확한 프레임 수 복제는 아니다.
-4틱에 V자 당긴 시위와 nocked arrow 모델로 전환하고7틱에 화살을 실제 발사하면서 nocked arrow를 제거한다. 원샷 중 재입력은 발사를 복제하거나 draw를 재시작하지 않는다.
- 조준 제한시간이 끝나도 같은 bounded draw를 거쳐 단발을 발사한다. 사망·직업/차원 변경·접속 종료 등의 cleanup은 pending release를 취소한다. session 종료 뒤 마지막 회복 애니메이션과 카메라는 기존 종료 계약을 따른다.
- H18의 원격 카메라 실제 연결 이동 문제도 함께 검증한다. 별도 원인·최소 수정은 [27번 문서](27_H19_카메라_이동_작업.md)에 분리했다.

## S3. 저작 도구와 검증 경계

Blockbench가 실행 중이고3000포트가 열려 있었으나 MCP tool과 직접 MCP initialize가 응답하지 않았다(5초 직접 요청2회 timeout). 사용자 탭/프로세스를 강제 종료하거나 재시작하지 않았다.
이번 단계는 기존 JSON 저작 파이프라인으로 편집 가능한 `.bbmodel`과 런타임 에셋을 함께 생성한다. Blockbench 네이티브 UI 프리뷰 통과를 주장하지 않으며 실제 Minecraft framebuffer를 별도 검사한다.

최종 테스트·실제 입력·PNG·남은 한계는 후속 S4와 QA에 기록한다. 구현 중 문서이므로 코드 작성만으로 전체 궁극기/스킬 인수 완료로 표시하지 않는다.

## S4. 통합 검증과 반복 수정

- 최초 컴파일에서26.3의 `CROSSBOW_LOADING_START`가 Holder인 점을 수정했다. 최초 GameTest는 기존 즉시 발사를 기대하던3개가 실패했고, 새 계약의 draw1~6틱 유지/7틱 contact와 .90초 clip의 completion grace 이후26틱 복원으로 갱신했다. 실패 기록도 QA에 보존했다.
- 최종 `runGameTest test build`: **GameTest104/104, JUnit59/59**, 실패·오류·스킵0. Python full-chain FK와2상태 아이템 리소스 검사도 통과했다. FK는 정확한 엔진 handed transform/픽셀의 대체가 아니다.
- 최초 실제 PNG에서 머리 뒤로 활이 가려졌다. 원본 모델을 무작정 두껍게 만들지 않고 **Void 전용 shoulder .45→1.15m**, rear3m/충돌 제한은 유지했다. Arc는 기존 .45m, Solar는 카메라 no-op다. 변경 뒤 새 JVM/팩으로 normal20TPS 촬영을 반복했다.
- 실제 native sneak+swap→attack에서 준비/당김/회복→self camera 복원 PNG를 확인했다. 실제 클라이언트 입력이지만 OS/Computer Use가 아니다. 논리 release7틱은 GameTest 증거이며, 약8~11Hz PNG를 정확한 contact 프레임 계측이라고 해석하지 않는다.
- 최종 native forward+sprint100틱: Arc Z100.5→139.7826204683161, Void Z100.5→128.55679864354747. 카메라 소유 상태의 body 이동과 해제 뒤 입력 중립을 기록했다. 단일 로컬 QA 연결 결과이며 네트워크 지연/다인/청크 경계 인수는 아니다.
- **저속 틱 문제는 남아 있다.**5TPS 관찰에서 BetterModel clip은 벽시계 쪽으로 진행하지만 발사는 서버7틱이므로 회복 뒤 화살이 나왔다. 이를 정상 동기화 통과로 기록하지 않는다. 먼저135 client-tick 시퀀스는15초 runner deadline을 초과했고 lease 해제/중립을 확인한 뒤33틱 시퀀스로 관찰을 완료했다. tick rate20으로 복원했다.
- 완전 draw의 cheek/nock는 정적 오차<.001단위지만, .15초 partial draw에서 당긴 모델로 교체되는 순간 약2.24모델 단위의 손/시위 차이가 남는다. 엔진 보간·후방 가림, 오프라인 QA 스킨 폴백도 추가 개선 대상이다.

실제 증거·재현 조건·버전/해시: [H19 QA](../qa/2026-10-22/h19/README.md).

## 후속 순서 — 이번 구현과 구별

1. 저속 TPS에서도 animation contact와 projectile을 같은 시간축으로 맞추고 partial draw 접점을 연속화.
2. Arc 지팡이 연속 스윕/회수, Solar 반동/총구/탄수 연동을 각각 공식 시각 근거와 비교. 이번에는 기존 clip8개를 그대로 유지했다.
3. 수류탄 던지기·투척 칼·연막·근접의 전신 예비/접촉/회복 모션과 실제 projectile contact 연결. 이번 H19가 일반 스킬까지 전면 재저작한 것은 아니다.
