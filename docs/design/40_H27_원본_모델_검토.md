## 현재 모델과 비교한 판단

### 아크 지팡이 — 보강 우선순위 높음

[원본 미리보기](https://drive.google.com/file/d/1mDv3nPHT-BEBUEX8nr51b5zKPB-y7iXo/view)를 직접 열람했다.
현재 `arc_staff_h24`는262cuboid/3,144tri이고 양끝을 부호만 달리해 반복 저작한다.
원본은 위끝의 창촉과 아래끝의 형상이 다르고, 아래쪽 칼날에 비어 있는 안쪽 윤곽이 보인다.
칼날 바로 안쪽 목/문양, 촘촘한 금속 링과 중앙 그립의 대각 패턴도 훨씬 명확하다.
따라서 "단순히 폴리곤을 더 늘리는 것"보다 다음 수정이 원작 인상에 더 중요하다.

1. 위/아래 칼날 별도 저작, 아래쪽 빈 공간과 갈고리형 안쪽 윤곽 보존.
2. 실제 링/슬리브 위치와 굵기 변화, 중앙 감긴 그립 패턴 재구성.
3. 금속의 어두운 면/밝은 날을 텍스처로 분리. 청백색 전기는 외부 VFX로 유지.
4. 기존 grip `(8,8,8)` / support `(8,12,8)` / native translation+2Y 계약을 유지하며
   형상만 새 버전으로 교체. H26 휘두름과 H25 lightning socket 회귀를 새로 검사.

### 공허 활 — 덩어리/곡률 우선

[원본 미리보기](https://drive.google.com/file/d/1bGaTG6GEqUBP_EmO_ypJkfjqc7urVt96/view)를 직접 열람했다.
원본은 가늘게 이어지는 굽은 limb와 중앙 쪽 두꺼운 에너지 덩어리, 안쪽으로
뻗는 분기 돌기가 읽힌다. 보라색 외곽 빛이 재질의 인상도 크게 만든다.
현재 H22 활은206cuboid/2,472tri로, 원본1,721tri보다 삼각형이 많다.
따라서 활이 어색한 이유를 "폴리곤 부족" 하나로 볼 수 없다. 실루엣/재질/표현방식 문제다.

1. 원본의 중앙 폭 변화·곡률·분기 위치에 맞춰 재저작.
2. FBX의 휴지 자세 시위를 그대로 복사하면 다시 안 당겨져 보이므로,
   H22의 V형 당김/뺨 anchor와 화살 방향 계약을 유지한다.
3. FBX 로컬Z → 현재 아이템Y축 전환, 왼손 context의yaw 반전/안쪽Ry180을 명시적으로
   처리한다. 예전 "활 반대로 듦" 문제가 재발하지 않게 조준/접점 검증을 재실행.
4. 원본 재질의 빛은 H25 에너지 레이어로 근사한다. 정적 이미지의 glow를
   그대로 실제 발광/bloom이나 원작 shader로 취급하지 않는다.

## 변환 방향

현재 서버사이드/바닐라 리소스팩은 FBX를 직접 로드하지 않는다.
FBX는 비례/방향/표면구조의 기준으로 두고, Blockbench cuboid와 지원되는 vanilla item
geometry로 재구성한다. normal/MRC는 그대로 꽂지 않고 색/형상/밝기 레이어에 적절히 배분한다.
원본triangle수와cuboid의12tri 환산은 렌더 성능을 직접 비교하는 벤치마크가 아니다.

원본 자체를 통째로 패키징하는 방안은 별도 변환/권리/배포 검토가 필요하다.
이번에는 **원본 FBX/텍스처/미리보기 이미지를 Git·JAR·리소스팩에 넣지 않았다.**

## H27-S2~S4 — 구현 (사용자 승인 후)

신규 선택: `arc_staff_h27`, `shadow_bow_h27_drawn`, `shadow_bow_h27`(release).
결정론적 생성기 `scripts/build_super_props_h27.py`는 이전 버전·플레이어 리그를 덮어쓰지 않는다.
322/277/273 cuboid(각3,864/3,324/3,276tri). 단순 증량보다 아래 형상 변경을 우선했다.

- 지팡이: 상부 solid spear42 slice, 하부 split rails로 실제 관통 슬롯, 서로 다른 taper.
  중앙 무발광 대각 wrap28개, sleeve/rib/collar 굵기 변화. 새 atlas는 독립 색상/브러시패턴.
  금속은 일반 shade+emission0, 기존 청백색 runtime 전기가 별도 레이어로 남는다.
- 활: 수동 곡률/폭 profile를 cubic Hermite로 연결. tangent 방향120개 strip으로 매끄럽게
  이어붙이며 급곡률 부위 틈과 coplanar 깜빡임을 방지. 안쪽 taper spur4개/각8segment.
  보라색 몸체와 밝은 rim을 분리. 원본 preview의 정지시위 대신 기존 V형 당김 유지.
- 시위2개/shaft/head/vane의 raw 좌표·회전은 H22와 동일. nock(16.24,8,8),
  tip(11.27,-4/20,8), 좌/우 ItemTransform과 +2Y hand offset 불변.
  release에만 화살을 제거하고 정지시위로 완화하며 limb 실루엣은 동일하게 유지한다.
- H25 활 전기 시작점을 새 limb의(6,13)/(6.45,3)로 조정. tip/nock 및6display budget 불변.
- H26_r2 player clip/전개11t/접점3t/회복8t는 변경하지 않았다.
- `ServerAnimationClockGameTests`가 예전 고정 element203 대신 `nocked_shaft` 이름으로
  실제 선택된 resource를 읽도록 바꿔 신규 geometry 개수에 독립적인 접점검사를 유지했다.

Blockbench MCP native import와 offscreen render를 수행했다. 생성은 deterministic authoring,
검사는 native Blockbench이며 native codec export 또는 추출 FBX 직접변환으로 혼동하지 않는다.
기존 미저장 탭을 보존하고 처음 선택 프로젝트로 복귀했다. offscreen 삭제 응답은 플러그인의
`onContextMenu` 오류를 반환했으나 후속 `list_views`에서 두 private view가 제거됐음을 확인했다.

초기 신규 JUnit이 이전 rest BB의 stale tail을 검출했다. 새 source만 runtime canonical
geometry로 맞추었으며 예전 H20 파일은 수정하지 않았다. 곡률 보정 중 float endpoint
12.000000000000002가 구간 밖으로 판정된 generate 실패는 clamp로 수정하고 `--verify` 재검사.
중간 stale generation gate는 최종인수로 세지 않는다. 최종 gate/실제픽셀 근거는
`../qa/2026-10-23/h27/README.md`에 별도 기록한다.
