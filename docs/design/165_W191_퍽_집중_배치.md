# W191 — 퍽 집중 배치

## 범위와 단계

사용자 지시에 따라 애니메이션 조사·추출·구현은 Windows 파일을 받을 때까지 보류한다. 단순 수치는 출처와 적용 경로만 확인하고, 새 처치·타이머·피해·소유권 동작에 검증을 집중한다.

1. **완료 — 작업 분할:** 현재 dirty 제품65,764파일을 해시 기준선 `6f955186ded8f006c56cfdfb4fcb1994d3ccb6d76e8eafb17eff2a3e17efadce`로 복제했다. w191-energy, w191-pugilist, w191-firing-line을 별도 worktree에 배정했다. master는 Full Auto와 공유 통합을 소유한다.
2. **완료 — 제품 구현:** Wellspring·Thresh / Pugilist / Firing Line / Full Auto Trigger System. 실제 공식 소켓만 지원하며 기본 퍽만 적용한다.
3. **완료 — 통합:** 레지스트리·실제 결제된 발사·처치 확인·근접 확인·핸들링·ADS·cleanup 경로.
4. **완료 — 검증·기록(전체 회귀 실패 별도 기록):** 새 동작의 좁은 회귀 후 통합 빌드. 서버 GameTest와 실제 클라이언트 검증은 구분해 기록했다. 이전 봉인 QA는 보존한다.

공식 소켓은 기존 제품이 고정한 manifest `245114.26.10.13.2000-1-bnet.66137` 기준이며 전체 최신 manifest를 새로 받았다고 주장하지 않는다. 각 `art/weapons/w191/*/source.json`에 원본 행·입력 해시·소켓 증거를 보존한다.

현재 능력은 단일 충전 cooldown 방식이다. 에너지는 **원래 장착 능력의 전체 cooldown** 비율로 환산하고 최종 tick 올림 후 남은 cooldown에서 차감한다. 다중 충전·Destiny 능력 tier 보정은 구현하지 않는다. 실제 처치 보상은 기존 기본 보상에 추가한다. 일반 능력 피해·궁극기·무료 월도 근접을 무기 처치로 오인하지 않는다.

## Master 통합 진행

- 레지스트리5종과 정확 소켓 조회·선택·명령 invalidation 연결. 기존40종 →45종 연결.
- DamageTraits에 원본 paid token 운반. 에너지·근접 회복은 같은 폭발 토큰을 재사용해 중복 보상을 방지하고, Firing Line 정밀 배율은 body-only splash에서 제거한다.
- Full Auto 반복 입력과 산탄총 실제 결제 간격, Lonesome Stability 합산 연결. 옵션을 바꾸지 않고 퍽 선택 변경 시 unpaid input lease만 종료한다.
- 실제 paid 처치·근접 접촉·아군2명 조건·반복 사격을 확인하는 서버 GameTest5개를 추가했다. 수치만 추가하는 퍽별 테스트는 요구하지 않는다. 아직 실행 전이다.

- 1차 컴파일·JAR·단위 회귀 통과. 서버 GameTest 최초 실행은5개 중4개 통과, Lonesome 자동사격 fixture가 한손 기본 carrier에 양손 heartbeat를 보낸 오류로1개 실패했다. 기본 carrier에 맞는 native use/continue 경로로 fixture를 수정한다.
- 코드 리뷰에서 Pugilist의 평생 세션 처치 기록을 개별 발사 token ledger로 줄였고, 회복 시 HUD 갱신을 연결했다. 다음 통합 검사에 포함한다.

## 검증 결과와 남은 범위

- 첫 targeted: 컴파일·JAR 생성·단위 회귀30개 통과. 이후 Pugilist corpse ledger를 개별 emission 수명으로 보정했다.
- 최종 focused 서버: **5/5 통과**. 실제 paid 처치의 Wellspring 분배, Thresh 추가 보상, Pugilist 회복·nonlethal 근접 적중·해제, Firing Line의 body/precision 차이와 아군 이탈, Full Auto 반복·해제·접근성 옵션 보존을 실행했다.
- 통합 JUnit: **1,862개, 실패·오류·skip 0**. 별도 단순 수치 복제 테스트는 추가하지 않았다.
- `test build`의 전체 서버 GameTest: **1,270개 중1,245통과·25실패**. `docs/qa/2026-10-27/w191/full-server-failures.json`에 전부 기록했다. W191 focused5개는 여기서도 통과했다. 과거 sight/reload/reticle/wire·Izanagi scope 기대와 ThreatDetector ADS 항목이 남아 있으므로 **전체 build 통과로 보고하지 않는다**. 전체 수정 전 baseline을 실행하지 않았으므로25건을 모두 기발생이라고 단정하지 않는다.
- Vision·native 입력·실화면·청취 검증은 이번 서버 로직 배치에서 수행하지 않았다. 애니메이션 보류를 유지한다.
- 출처 대조: 정확 무기24종의28개 weapon-perk 소켓, 신규 퍽5종. 고정 manifest와 DDC의 원문·해시를 보존했다. W190 봉인8파일 모두 변경 없음.
- 병렬 worktree 구성 점검 중 GCB의 체크아웃 폴더가 `GCB-server`에서 `gcb-server`로 바뀌면 composite 모듈 자동 대체가 실패하는 것을 확인했다. `settings.gradle`에 명시적 module→project substitution을 추가해 격리 소스 연결을 고정했다. 이 설정만 보정한 수정 전 제품 worktree에서 ThreatDetector 단독 테스트는 통과했다. 현재 코드 역시 assert 메시지에 진단 값만 추가한 재실행에서 통과했다. 입력·계산 로직 변경 없이 결과가 달라 원인을 확정하지 못했으며 간헐 실패로 기록한다. 퍽 로직의 확정 회귀 또는 해결 완료라고 주장하지 않는다.

## 배치 상태

- 퍽5종과 실제 무기 소켓28개 연결 완료. 전체 구현 퍽45종. 전체 무기/HUD 목표는 계속 진행 상태이며, 이 배치만으로 목표 완료 처리하지 않는다.
- 실제 클라이언트 검증은 수행하지 않았고, 전체 서버 회귀25실패는 남아 있다. 실패 목록과 초기 실패·수정·재실행 원문을 QA 폴더에 보존한다. 애니메이션 재개나 이전 표현 경로의 수정은 사용자 파일 전달 전까지 보류한다.
- 병렬 worker3개를 종료했고 작업 worktree는 복구·검토용으로 보존했다. 원본 변경은 commit/stash/reset/clean/push하지 않았다.
