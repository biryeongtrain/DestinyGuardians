# W53 — 검 전신 모션·지속 후방 카메라

## 범위와 보존

W51/W52 검 전투 위에 **전신 공격 8종과 검을 든 동안의 후방 카메라**를 연결한다.
황금총 W39 1인칭 조준, 일반 탄창·예비탄·재장전·3슬롯 HUD, 기존 스킬과 궁극기는 유지한다.
새 음원 매핑이나 원본 무기/황금총 542 에셋의 변경은 없다.

## 별도 모델

- `guardian_sword_w53`: 기존 Hunter H26 모델을 덮어쓰지 않는 버전별 limb.
- 편집용 `art/blockbench/animations/guardian_sword_w53.bbmodel`: H26-r2의 rig/텍스처와 기존 21클립의 원문 바이트를 유지하고 8클립만 추가한다. **합계 29**.
- 런타임 리소스 `destiny/animation/sword_w53.animation.json`은 검 8클립만 포함한다.
- 실제 설치는 BetterModel 3.5.1의 Steve 스킨/갑옷 rig에 bone 이름으로 UUID를 다시 매핑한다. 현재 설치본은 기본 `roll` 1개 + 검 8개 = **9클립, 18그룹**이다. 편집본의 29클립 전체를 설치하는 것이 아니다.
- `CREATE_NEW`로만 설치한다. 이미 있는 파일/심볼릭 링크는 열어 쓰지 않는다. 누락/변형된 artist-owned 파일은 자동 덮어쓰기하지 않는다.
- `PlayerAnimations`는 검 요청에 별도 limb만 사용하며, 다른 모델의 엉뚱한 클립을 fallback하지 않는다.

W52의 영상·공식 형태 근거를 재사용했으며 새 원작 모션 캡처로 인증하지 않는다.
약공격은 오른쪽→왼쪽→낮은 마무리, 강공격은 프레임별 형태로 구분한다.
16개 rig bone의 몸통·팔·다리·망토·item pivot을 움직인다. root X/Z=0, root Y는 발바닥 보정뿐이다.
대시 이동/중력/공중 궤적은 기존 게임 로직에 맡기고 시각 root 이동이나 카메라 회전으로 대체하지 않는다.

**중요:** 현재 HP·탄약·에너지·돌진은 기존 승인 시점에 즉시 적용한다.
모션 cue에 맞춘 지연 타격이나 연속 칼날 판정은 아직 없다. 실제 접촉 시점과 완전히 동기화했다고 주장하지 않는다.

## 소유권과 수명

`SwordPresentation`은 owner 객체·차원·정확한 주손 ItemStack identity에 binding을 둔다.
공격은 기존 비용/주기/가드 검사를 통과한 다음에만 모션을 요청한다. 표현 실패는 게임 공격의 거부 조건이 아니다.
선택 시 카메라를 시작하고, 원샷이 끝나도 검을 계속 들고 있으면 카메라는 유지한다.
공격 종료 시 limb만 닫고 기본 플레이어 스킨·live 장비 표시로 돌아간다. 전용 idle/가드/보행 loop는 후속이다.

- 일반 스킬/Arc·Void·Solar 모션이 점유하면 검이 덮어쓰지 않는다.
- 검 전용 cleanup은 검 limb/검 카메라만 해제한다. 다른 스킬·궁극기·시네마틱을 닫지 않는다.
- Solar 궁극기는 기존 1인칭을 유지하며, 아래 검을 들고 있어도 카메라를 다시 얻지 않는다.
- 아이템 교체·죽음·관전자·차원 변경·연결 종료·사용 불가 상태에서 정리한다.
- 카메라 획득은 binding당 한 번 시도한다. 40틱 회전 watchdog 해제 후 같은 검으로 자동 재획득을 반복하지 않는다. 실제 새 stack 선택이나 스킬 handoff 이후 새 binding은 다시 시도할 수 있다.

## 바닐라 서버사이드 카메라

기존 `SuperCamera`의 개인 전용 가상 seat/ItemDisplay 카메라를 재사용한다.
실제 서버 카메라는 player self, 실제 mount/관전자 전환은 없고 marker는 world에 등록/저장하지 않는다.
회전 packet과 native 입력을 받아 서버의 충돌·중력·낙하 처리를 사용한다. 매 프레임 player teleport는 없다.
끝날 때 한 번만 자기 카메라/seat 제거/위치 재동기화를 보낸다.
26.3 teleport의 known-movement 기준 문제에 대응해 서버 delta를 보관/복원하고 wire는 상대 delta=0·회전=0을 유지한다.
외부 카메라가 점유하거나 차원이 바뀌면 자기 카메라·위치 보정 packet을 새 연출 위에 보내지 않는다.
