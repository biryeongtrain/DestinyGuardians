## 원작 근거와 적용 범위

기본 Demolitionist(`3523296417`)의 **정확한 선택 무기 11종**만 지원합니다. `austringer`, `gnawing_hunger`, `bug_out_bag`, `lonesome`, `high_albedo`, `whispering_slab`, `first_in_last_out`, `stormchaser`, `retraced_path`, `salvager_s_salvo`, `nezarec_s_whisper`입니다. 강화 특성은 지원하지 않습니다.

[공식 소켓·원문·수치 근거](../../art/weapons/w103/references/CONTRACT.md)는 고정 Bungie manifest `245114.26.10.13.2000-1-bnet.66137`와 별도 커뮤니티 수치 자료를 구분합니다. Salvo의 socket3/set253은 **공식 curated 대안**이지 무작위 풀이나 최초 장착 특성이 아닙니다. 모든 새 무기는 기본 미선택이며, `/destiny perk select demolitionist`로 명시 선택합니다. 같은 소켓의 특성은 기존 정책대로 배타적입니다.

기본 처치 에너지 chunk는10%, 일반 산탄총·저격총·융합소총·월도 예외는20%입니다. 현재 선택 목록에서는 First In Last Out·Nezarec’s Whisper만20%이며 **추적소총·유탄·선형융합소총은10%**입니다. 월도 근접은 이번 qualifying ranged 경로에 포함하지 않습니다. 파동 유탄/검을 편의상 제외한 것이 아니라 정확한 선택 무기의 공식 풀에 해당 기본 특성이 없습니다.

**정확한 현재 D2 에너지 복제는 아닙니다.** 원작 ability-tier/Armor3.0 grenade-stat 보정의 최신 수치가 충분하지 않아 임의의 스칼라를 만들지 않습니다. 이번 단계는 기존 Minecraft 수류탄 기본 cooldown의10/20%를 올림한 tick만큼 남은 cooldown에서 차감하는 명시적 baseline 근사입니다. 원래 수류탄 조정값·자연 충전 속도·궁극기/근접 cooldown은 바꾸지 않습니다.

## 서버 authority

- 실제 탄약을 지불한 `WeaponRuntime` emission에서 원본 플레이어·차원·수호자 runtime/class/data·ItemStack identity·선택 소켓을 캡처합니다.
- 실제 HP/흡수 감소가 확인되고 해당 거래가 최종 처치를 만든 경우에만 에너지를 줍니다. 산탄은 기존처럼 대상별 거래이며, 한 폭발의 여러 적은 각각 인정하되 동일 corpse 재호출은 중복 인정하지 않습니다.
- hitscan/점사·활·projectile·Salvo 폭발의 공통 거래에 연결합니다. 잠자리/Firefly 등 별도 2차 능력 피해는 다시 무기 처치 특성을 발동하지 않습니다.
- 발사 후 수납해도 **원본 스택이 소유 중**이면 귀속을 유지합니다. 새로 든 무기나 동등한 복사본으로 보상을 옮기지 않습니다. 직접 API·명령의 실제 특성 편집은 같은 tick 안에서도 token을 영구 취소합니다. drop 등 관측된 소유권 무효 상태도 취소합니다. 관측 사이 같은 tick 내 drop-reacquire 같은 모든 중간 이력까지 추적한다는 주장은 하지 않습니다.

## 수류탄 → 예비탄 장전

`HunterGrenade`의 승인 시 원본 무기를 캡처하고 **T+4의 실제 유효 contact에서 projectile을 생성한 다음** 장전합니다. 누른 즉시/거절/취소된 windup에는 보상하지 않습니다. 시전 중 교체했다면 새 무기는 건드리지 않고 여전히 소유한 캡처 원본만 대상으로 합니다.

`WeaponMagazine.reload()`의 기존 예비탄/legacy-overflow 전송만 사용해 유한 총탄을 보존합니다. 무한 주무기 예비탄은 기존 규칙을 따릅니다. free ammo 생성, Kill Clip·Ace의 일반 장전 callback, 장전음의 새 재생은 없습니다. 원본의 진행 중 작업만 취소하며 다른 무기의 장전이나 발사 cadence deadline은 초기화하지 않습니다.

수류탄 장전 효과의3초(60tick) lockout은 확인했지만 원작에서 owner-wide인지 per-instance인지는 확정하지 못했습니다. 서버는 **owner-wide**를 선택해 무기 교체·특성 편집으로 우회하지 못하게 합니다. 실제 유효 release에서 시작하고, 탄창이 가득 찼거나 예비탄이 없어도 해당 기회는 소비합니다. 이는 명시적 로컬 정책입니다. 사망·접속 종료·차원 cleanup에서는 이전 생명 상태를 폐기합니다.
