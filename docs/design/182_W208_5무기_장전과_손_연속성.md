# W208 — 5무기 장전·플레이어 손 연속성 확장

W207의 Ammit/Blast/Hammer/Dust/Izanagi 이후, 은둔자·총애·갉아먹는 허기·선입후출·오스트링거를 한 배치로 진행한다. 무기별 독립 dirty-CoW worktree 5개에서 작성하고 main이 공유 라우팅과 손 합성을 통합한다.

| 무기 | 기존 표현 | 변경 목표 | source 팔 방향 자료 |
|---|---|---|---|
| 은둔자 | W101 21 pose | 탄창 교환 경로의 움직이는 구간에서 불필요한 정지 제거, 중앙 하단 교환/파지 | 80A8A192 |

61 pose는 상태 선택의 1/20 계단을 1/60으로 줄인다. 서버의 item 상태 갱신은 여전히 최대 약20Hz이며, 바닐라 item 모델의 클라이언트 연속 보간이나 60fps 애니메이션 구현을 의미하지 않는다. PCHIP/Hermite 접선은 움직이는 key 양쪽에서 공유해 구간마다 멈추는 smoothstep을 줄이고 의도된 hold는 유지한다.

추출자료의 FK wrist/elbow 위치·회전은 기존 W205 보간기로 샘플한다. 카메라는 추출되지 않았으며, 공통 그룹의 reload_full/reload_empty 이름만으로 무기별 clip 변형을 단정하지 않는다. `reload.rigAction`을 명시적으로 선택하고 source 방향과 현 리모델의 palm anchor를 결합한다. `keepMeshSupport`는 리핑 원본의 손 간격이 현 무기 그립을 덮어쓰지 않게 한다. 팔 길이는 원래 source idle 길이로 일정하게 유지하고 총과 양팔을 함께 이동한다.

선입후출의 initial/loop/return은 기존 실탄 lifecycle CMD4 0..1/2..3/4..5와6tick cosmetic return에 연결한다. 추출자료에 shell-loop 이벤트 트랙이 없으므로 held pose를 연속으로 잇는 source 방향 slice는 명시적 보정이다. 실탄 전이, 재장전 시간, 사격 승인, 오디오와 ADS 완성 행렬은 기존 동작을 유지한다.

검증은 무기별 곡선/현재 형상 분할/단계 경계 검사, main의 실제26.3 Cuboid parser·item codec·runtime 라우팅, 한 Vision 세션의 다섯 HIP/발사/장전/ADS/복귀를 취합한다. 이미 확인된 역사적 숫자 퍽 외부 fixture 누락을 이유로 이 미술 배치마다 전체 퍽 테스트를 반복하지 않는다. 실제 수행 결과와 취소/미검증 범위는 `docs/qa/2026-10-28/w208/`에 기록한다.

실행 결과: 관련 JUnit 59개와 assemble 통과. Vision 입력16개 완료·중립해제, 최초 Austringer 장전1개는 실제 사용자 입력으로 취소 후 새 fixture/r2로 수행. 시각 파지 품질은 사용자 피드백으로 W209에서 재보정하며, W208 transport 성공을 미술 수락으로 간주하지 않는다.
