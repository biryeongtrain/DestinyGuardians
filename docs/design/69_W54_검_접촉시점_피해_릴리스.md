# W54 — 검 모션 접촉 시점의 피해·이동·릴리스

## 목적

W53은 모션을 시작하면서 HP·돌진·투사체를 즉시 처리했다. 이번 단계는 **승인/비용과 접촉을 분리**하여
준비 자세가 먼저 나오고 기존 전투 효과는 authored 접촉 cue에서 한 번 처리되게 한다.
황금총 1인칭·탄약 HUD·기존 검 모델/텍스처/안료·8클립 geometry·음원 매핑은 유지한다.

## 공통 시간 계약

`SwordTiming`은 W53 manifest의 authored cue를 20Hz로 올림하고 기존 원샷 blend 1틱을 더한다.
`PlayerAnimations`의 원샷 start에도 같은 상수를 사용한다. 기존 다른 원샷의 start=1 값은 바뀌지 않는다.

| 모션 | clip cue | 최소 승인 후 기한 |
|---|---:|---:|
| 약공격1 | 0.15초 | 4틱 |
| 약공격2/3 | 0.20초 | 5틱 |
| uppercut | 0.35초 | 8틱 |
| dash | 0.25초 | 6틱 |
| slam | 0.40초 | 9틱 |
| vortex | 0.45초 | 10틱 |
| caster release | 0.30초 | 7틱 |

이는 **Minecraft용 authored 모션과 20Hz 접촉 이벤트**이며 Destiny 2의 실측 공격 시간/충돌 프레임이 아니다.
서버가 느려져도 wall-clock으로 보정하거나 누락 공격을 몰아서 발동하지 않는다.

## 승인 → 접촉 거래

1. owner/주손/사용 가능/가드/기존 pending/공통 cadence/외부 스킬·카메라 점유를 먼저 검사한다.
2. 실제 탄약과 강공격 에너지를 한 번 소모하고 combo·cadence·회복 지연을 확정한다. HUD는 실제 비용을 즉시 표시한다.
3. 기존 swing 사운드와 W53 모션을 시작한다. 이 단계에서는 HP·돌진·ring·caster projectile이 없다.
4. owner의 정확한 stack/차원 binding에 pending 하나만 둔다. entry/profile/weak 여부/공격력을 승인 시점에 보관한다.
5. 최소 서버 tick 기한과, 성공적으로 시작한 모션의 실제 BetterModel server-clock 진행을 함께 기다린다.
6. pending을 **피해 콜백보다 먼저 제거**하고 현재 시야/대상/LOS/충돌을 다시 구한다. 현재 contact의 효과를 한 번만 실행한다.

약공격은 접촉 시점의 시작/돌진 후 cleave 합집합과 총16명 cap을 그대로 사용한다.
경량 강공격은 cue에서 안전한 dash 후 근접, uppercut은 근접, slam/vortex는 기존 LOS 범위 거래,
caster는 cue에서 생성한 뒤 기존 실제 비행/충돌을 거쳐 HP가 변한다. 발사 시 projectile cap도 다시 확인한다.
기존 속도·시야·상대-zero 보정 보존은 유지한다. 연속 칼날 충돌이나 애니메이션 자체의 root 이동으로 바꾸지 않는다.

## 실제 clock을 함께 기다리는 이유

일반 native/GameTest 입력에서는 승인 후 첫 END tick부터 모션이 진행되어 표의 기한에 실제 clock도 도달한다.
하지만 같은 tick의 animation listener가 이미 끝난 뒤 입력 API를 호출하면 pose tick이 하나 적다.
실제 회귀에서 `elapsed=4`일 때 `BM=6 frame`인데 시간만 확인한 구현은 HP를 먼저 적용했다.
이 실패를 raw gate3에 보존하고, 승인 시 실제 frame 기준점을 기록해 `delay*2`개 frame도 진행했는지 확인한다.
late-phase 입력은 필요하면 한 tick 더 기다린다. 시간 assert를 느슨하게 만들어 이 결함을 숨기지 않는다.
모델이 없거나 닫힌 cosmetic 실패는 게임 공격을 영구 봉쇄하지 않으며 최소 tick 기반 fallback을 유지한다.

## 취소·재획득 정책

- 다른 stack/차원/owner, 죽음/관전자/연결 종료/장비 사용 불가 상태는 기존 binding/lifecycle 정리로 취소한다.
- 스킬 handoff, class/subclass 변경의 Ability cleanup, guard 입력, 외부 모션·카메라 점유, 한 tick에 8블록 초과 위치 변화도 취소한다.
- 승인 후 취소는 **환불하지 않는다**. 이미 시작한 공격의 cadence도 초기화하지 않는다. 이는 명시적인 로컬 정책이지 원작 실측 규칙이 아니다.
- contact는 저장된 target lock을 사용하지 않는다. windup 중 돌아선 시야·새로 진입/이탈한 대상·추가된 벽이 실제 접촉에 반영된다.
- 같은 tick의 무기 away/back 교체는 polling만으로 감지할 수 없다. 실제 native hotbar handler의 validated `setSelectedSlot` 호출 전 hook으로 검 상태를 취소한다.
- 같은 슬롯 재전송·잘못된 슬롯은 취소하지 않는다. 비Guardian의 실제 F 손 교환도 전환 전에 취소하며 Guardian의 능력 입력 우선권은 유지한다.
- native hook은 검 상태에만 적용한다. 일반 총기 사용/장전 정책을 hotbar hook으로 재정의하지 않는다.

## 검증 경계·잔여

[W54 QA](../qa/2026-10-24/w54/README.md)에 최종 gate/실제 HP·위치·탄약·BM clock·native packet-handler 결과를 기록한다.
기존 W51/W52/W53의 검37테스트는 같은 공간/HP/속도/packet 불변식을 실제 contact 대기 단계로 이관한다.
EmbeddedChannel/서버 handler 호출은 native 클라이언트 입력·수신·시각 보간 증거가 아니다.
이번 단계는 새 Minecraft framebuffer·실제 스킨/IK·다인 접속·거리/성능·HUD 픽셀 검증을 인증하지 않는다.
W47 SDL 출력 정지의 원인은 미확정이며, 외부 표시 상태 변화 확인 없이 재기동을 반복하지 않는다.

전용 idle/guard/보행·공중 변형, 정확한 양손 파지·원작 충돌/에너지/특전, 검 전용 음원 청취와 연결,
다른 무기의 추가 모션/고유 기믹과 native 검증은 여전히 전체 목표의 후속 작업이다.
