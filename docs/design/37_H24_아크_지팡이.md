## 2. 모델 제작

`scripts/build_arc_staff_h24.py` → 신규 `arc_staff_h24.bbmodel` + Java cuboid JSON +
item definition + 자체 제작 256×128 PNG. Pillow 사용, `--verify`는 바이트 단위 재현성 검사.
가늘게 다듬은 양끝 날, 링/리브, 은백색 표면, 작은 전류 가닥을 개별 편집할 수 있다.
실시간 전류/공격 잔상은 기존 서버 VFX를 유지하며 새 파티클 시스템을 중복하지 않는다.

Blockbench MCP의 read-only `get_project_info`를 8초 제한으로 시도했으나 타임아웃.
다른 사용자 탭은 변경하지 않았다. 따라서 native Blockbench 조작/codec export 성공으로
표현하지 않는다. 기존 호환 .bbmodel 스키마를 기반으로 결정론적으로 작성하고
MC26.3 native CuboidModel parser와 실제 클라이언트 렌더링을 별도로 검사한다.

## 3. 기존 모션과 호환

- 모델 중심 raw `(8,8,8)`, 봉의 축 +Y, 장착 display translation `(0,2,0)` 그대로.
- 보조손 raw `(8,12,8)` → native item local `(0,6,0)` 유지.
- 3m 길이, 중앙 손 부근은 매끈한 실제 형상이 이어진다.
- `SuperVisuals.item(ARC)`만 신규 item ID 선택. 공허/솔라/실제 인벤토리/카메라 변경 없음.
- H23 전개18틱/이동 허용/공격 접점 및 모든 기존 애니메이션은 수정하지 않는다.
- 이전 H15 모델·텍스처·manifest 및 설치된 BetterModel 파일은 보존한다.

## 4. 검증 계획/기록

1. JUnit: native parser, JSON↔BB geometry/UV/embedded PNG 일치, 단일 뾰족한 양끝,
   길이/두께/큐브 예산, 손잡이/기존 display 보존.
2. GameTest: 실제 BetterModel native display가 H24를 선택하는지 확인하고 기존
   inter-key 보조손 접점 `<0.025m` 기준 유지. 전체 회귀 실행.
3. Vision: 실제 입력으로 발동→전개→대기→공격. 본인 후방 카메라와 관찰자 화면의
   지팡이 실루엣·손잡이·양끝·텍스처 확인. fixture 서버 명령과 native 입력을 구분한다.
4. 실행 결과/실패 시도/한계/정리는 `docs/qa/2026-10-23/h24/README.md`에 기록한다.
