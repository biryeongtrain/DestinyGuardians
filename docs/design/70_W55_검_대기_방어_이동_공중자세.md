# W55 검 대기·방어·이동·공중 자세

## 범위와 기준

- 기존 W53 8개 공격과 W54 피해/contact cue는 변경하지 않는다.
- 검을 들고 있는 동안 `guardian_sword_w55`를 유지한다. 원샷 종료 후 바닐라 자세로 튀지 않고 현재 대기/이동/방어/공중 loop로 복귀한다.
- `guardian_sword_w53`/Hunter/Steve 설치본과 아티스트 파일은 덮어쓰지 않는다. 새 버전도 `CREATE_NEW`로만 설치한다.
- 원작 모션 캡처 재현이 아닌 **자체 제작 자세/주기**다. 기존 W51/W52 공식 shape·영상 자료를 재사용하며 출처 경계는 [애니메이션 노트](../../art/weapons/w55/animation-notes.md)에 기록했다.

## 네 가지 루프

| clip | 주기 | 선택 조건 |
|---|---:|---|
| `h15_sword_idle` | 2.40초 | 지상 정지/벽에 막혀 실제 수평변위 없음 |
| `h15_sword_move` | 0.80초 | 지상 실제 수평변위 제곱 > 0.000225, ≤ 64 |
| `h15_sword_guard` | 1.60초 | 서버가 계산한 실제 유효 guard 상태 |
| `h15_sword_air` | 1.20초 | guard가 아니고 onGround=false |

우선순위는 유효 guard → air → move → idle. 단순 sneak 키만으로 guard를 만들지 않는다.
NaN/음수/무한·8블록 초과 불연속은 보행으로 간주하지 않는다.
이동 방향별/속도별 gait 및 지면 foot locking은 아직 없다. 이동 루프는 제자리 보행이다.
공중 루프는 무릎/상체/망토 자세일 뿐 점프 높이·중력·게임 이동·공격 가능 지상 조건을 바꾸지 않는다.

## Tracker와 시간 소유권

1. 정확한 ItemStack/owner/level binding당 카메라 1회, stance 생성 1회만 시도한다.
2. stance priority0 아래에서 승인된 공격 priority20을 재생한다. 같은 tracker와 누적 서버 clock을 재사용한다.
3. 공격 중 stance 요청은 공격을 끊거나 clock을 진행/리셋하지 않는다. 공격 종료 뒤 그때의 서버 상태로 loop를 선택한다.
4. W54 contact는 승인된 시점 대비 실제 BM frame 차이를 계속 사용한다. 기존 1tick blend와 contact tick은 그대로다.
5. sneak로 windup을 취소하면 pending 피해를 지우고 원샷만 중지한다. 유효 underlay는 유지하며 cadence가 풀려 실제 guard가 되면 방어 자세를 올린다. 비용 환불은 없다.
6. 스킬/궁극기/외부 시네마틱은 검 loop보다 우선이다. 일반 스킬 원샷을 검 rig에 잘못 재사용하지 않는다.
7. 교체/사망/차원 등 정리는 기존 tracker를 닫는다. 취소된 공격을 되살리지 않는다. 명시적 cleanup 이후에도 검이 여전히 유효하면 후속 binding이 **새 idle**을 시작할 수 있다.
8. 카메라 watchdog/닫힌 cosmetic은 동일 binding에서 자동 재시도하지 않는다. 실제 stack 변경 또는 다음 명시적 승인 공격은 별도 요청이다.

`PlayerAnimations.swordPlaying`은 loop 포함 전체 검 playback, `swordAttacking`은 원샷 여부다.
`swordPose` telemetry는 underlay 이름이므로 공격 중 화면을 대표하지 않는다.

## 에셋 보존과 설치

- 아트 모델: W53 29clip의 원문 JSON 유지 + 새4 = 33clip.
- 런타임 sidecar: 기존8 공격 원문 유지 + 새4 = 12clip.
- 실제 설치 모델: BetterModel3.5.1의 전체 Steve rig18group + 기본roll1 + 런타임12 = 13clip.
- 기존16bone, item bind `[-90,0,0]`, item scale1 유지. geometry/UV/안료/무기 디스플레이/음원 변경 없음.
- 모든 새 loop는 각 채널 시작/끝이 동일하며 finite FK, 200Hz floor-fit 검사를 수행한다. root X/Z와 root 회전은0, Y는 skin-floor fitting만 한다.

## 검증

[현재 QA와 전체 실행 결과](../qa/2026-10-24/w55/README.md).

- 새6 GameTest: 네 루프의 실제 BM 송신 transform/누적 clock, 실제 변위 선택, 공격 후 같은 rig로 복귀, guard 취소 후 지연 피해 차단, 닫힌 cosmetic 재시도 방지, 스킬 및 타 플레이어 소유권.
- 새7 JUnit: selector/임계값/locale, 원래8clip 유지, loop seam/finite/fullbody, 원문 rig/29clip 유지, 설치 remap/별도 버전.
- 이전 검 관련46 GameTest의 HP/LOS/충돌/탄약/교체/late-END clock/카메라 검사는 그대로 유지한다.
- 새 테스트에서 전체 플레이어의 `PlayerAnimations.tick(server)`을 수동 호출하지 않는다. 공유 GameTest 배치의 다른 플레이어 clock을 중복 진행시키기 때문이다. 특정 tracker의 직접 clock 샘플은 시각 데이터 테스트로만 분리한다.

현재 native 클라이언트 렌더링/실제 파지/skin 보간/HUD pixel/다인 거리 성능은 미검증이다. 이전 SDL 정지의 원인과 외부 상태 변화가 확인되지 않아 blind 재기동을 하지 않는다. HTTP listener, GameTest EmbeddedPlayer, 설치 JSON은 실게임 화면 증거가 아니다.

황금총1인칭 방향과 장탄수 HUD는 W39부터 구현된 기존 기능이며 이번에 새로 구현한 것으로 세지 않는다. 최신 전체 회귀에 포함한다.
