# W68 — 스냅샷 조준경과 ADS

## 목표와 입력

바닐라 서버사이드의 실제 crouch 조준 진입을 기본 Snapshot Sights 특성과 연결한다.
`/destiny perk select snapshot_sights`로 실제 소유 전투무기에서만 선택한다. 기본 자동부여는 없다.
기존 조준 입력/무기 탄약·발사 간격/줌 배율/반동/ready·stow Handling은 바꾸지 않는다.

## 증거 수준과 충돌

- 공식 pinned Bungie manifest는 정확한 아이템 hash·base957782887의 존재·socket을 증명한다. enhanced4116820839는 제외한다.
- Bungie Update4.1.0(2022)의 Special ADS duration scalar는0.75, Primary는0.5이다.
  <https://www.bungie.net/7/en/News/article/51380> 및 설명 <https://www.bungie.net/7/en/News/article/51319>.
- exact-base light.gg Community Research(2024-04-12)는 Primary50% 감소/Special20% 감소로 표기한다.
  <https://www.light.gg/db/items/957782887/snapshot-sights/?_=150>.
- 현재 구현은 후자의 **0.5/0.8 측정값을 명시적으로 채택한 서버 정책**이다. 역사 공식0.75와의 차이는 미해결이며 최신 공식 확정/원작 엔진 독립측정이라고 표현하지 않는다.
- Heavy인 Edge Transit/Bad Omens도 공식 base socket을 가진다. Primary 배율을 Heavy에 임의 적용하지 않는다.
  전체 열거에는 포함하되 측정 배율 없는2개는 선택 구현 대상에서 제외한다.

[공식 전소켓 열거·생성 근거](../../art/weapons/w68/reference-notes.md).

## 시간 양자화

W44의 pinned Foundry raw `adsSeconds`에 먼저 배율을 곱한다.
`clamp(ceil(rawSeconds * scalar * 20), 1, 20)`으로 서버 tick에 올림한다.
기존 이미 올림된 base tick에 배율을 곱해 이중 올림하지 않는다.
W44 base57종/비지원6종의 값은 수정하지 않는다. 기존 곡선은 커뮤니티 모델이며 현재 원작의 frame-exact 값이라는 주장은 하지 않는다.

Snapshot은 진입에만 적용한다. 이탈은 기존 base tick을 유지한다. 이탈 단축을 입증하는 자료가 없어 채택한 서버 동작이지 원작 이탈 규칙의 확정이 아니다.
이미 진행 중인 조준에서 특성을 바꾸면 진행도를 보존하고 다음 실제 tick부터 남은 진행에 새 속도를 쓴다. 같은 tick 중복 호출은 진행하지 않는다.

## 단일 진행도와 수명

`WeaponAiming`의 기존 실제 session/state 한 개가 아래를 모두 구동한다.

1. FOV는 `base + (perspectiveZoomFov - base) * progress`를 정수 degree로 전송한다.
2. progress0.5 전 HIP, 이후 ADS/SCOPE selector로 기존 실제 아이템 모델을 바꾼다.
3. scope HUD는 같은 session의 SCOPE 판정에서 기존 노드를 만든다. 별도 타이머/가짜 특성 buff row는 없다.

모델은 기존0.5 selector 전환이며 프레임마다 손/총구가 연속 보간하는 신규 애니메이션은 아니다.
서버는 F5 시점을 알 수 없고 새1인칭 손/IK 구현을 했다고 표현하지 않는다.
shader FOV off일 때도 실제 ADS와 모델/HUD는 동작하지만 projection 변화는 없다.
다른 시스템의 FOV 소유권을 빼앗지 않으며 reload/skill suspend·수납·stack 교체·사망·관전 등은 기존 session 정리 정책을 따른다.
