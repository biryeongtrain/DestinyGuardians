# A Guardian Rises — 경험 중심 최초 미션 개발 기획

작성: 2026-11-01 · 상태: 개발 제안 / 원본 추출 자료 수령 전
범위: 미션 분석과 개발 기획. 이번 문서는 런타임 구현·인게임 검증 완료를 뜻하지 않는다.

## 1. 제품 방향과 원작 기준

플레이어는 시험장을 통과하는 학생이 아니라, 폐허에서 처음 살아난 수호자다. 이동·사격·장전은 살아남기 위해 배우고, 고스트와 함께 우주선을 확보한 뒤 탑으로 떠난다. UI의 단계 수보다 공간, 위협, 소리, 빛이 다음 행동을 알려 준다.

기준은 Destiny 2 New Light의 첫 미션이다. 같은 이름의 Destiny 1 첫 미션, 2019 도입부, Beyond Light 이후 New Light 퀘스트 전체를 혼합해 원작이라고 주장하지 않는다. 이번 요청은 첫 미션 대체이며 Schism·Cold Boot·The Disgraced 등 후속 퀘스트 제작은 범위 밖이다.

**사용자 확정 변경:** Shaw Han을 만나러 가는 결말을 제거한다. Dock 13에서 우주선을 확보하고 탑으로 출발한다. 이는 D2 도입부에 우주선 탈출 결말을 결합하는 의도적인 각색이다. Shaw Han 모델·음성은 필수 추출 목록에서 제외한다.

자료로 확인한 D2 흐름은 폐차장 부활 → 장벽 진입 → 어두운 내부 탐색 → 소총 획득 → Breach 전투와 보급품 → 야외 Fallen/Walker 교전 → 신호 추적과 Dock 13 → Shaw Han 조우다. 여기서 보존할 것은 고립감에서 무장, 첫 승리, 넓은 세계로 이어지는 감정 변화다. 정확한 지형 치수·카메라 키프레임·적 수·대사 타이밍은 아직 확정하지 않는다. 웹 공략은 순서 근거이며 영상 프레임 분석이나 실제 플레이 검증을 수행했다고 간주하지 않는다. ## 2. 플레이 흐름 — 제안 러닝타임 15~20분

시간은 제작 목표이며 원작 측정값이 아니다. 숙련자는 약 10분, 탐색하는 신규자는 25분까지 진행이 자연스러워야 한다. 대사 종료를 모든 문 개방 조건으로 삼지 않는다.

| 구간 | 플레이 경험·공간 | 자연스럽게 배우는 것 | 진행 조건·복구 |
|---|---|---|---|
| 01 부활, 1분 | 폐차장 사이 낮은 시점, 빛이 돌아오며 고스트 등장. 멀리 거대한 장벽 | 시선과 이동 | 시선 입력 또는 짧은 연출 종료 후 이동 가능. 고스트 응시 실패로 잠그지 않음 |
| 02 장벽으로, 1~2분 | 차량 잔해와 안전한 틈, 입구의 빛, 뒤편 위협음 | 걷기·질주·낮은 점프 | 입구 도착. 낙오 시 방향 힌트, 추락 시 가까운 안전점 |

| 10 탑으로, 1분 | 엔진음·빛·짧은 이륙, 탑 도착 | 다음 활동과 E 메뉴 | 탑의 안전한 착지 성공 후 완료 상태 기록 |

직업은 시작 전 짧은 선택 UI에서 고르되 기존 유저의 선택은 유지한다. ‘E에서 언제든 변경 가능’을 표시한다. 원작의 긴장감을 끊는 직업 선택 원과 속성 제단은 본편에서 제거한다. 능력은 교전 맥락에서 소개하며 모든 능력을 사용해야만 문이 열리는 방식은 피한다.

기존 요청인 무기군별 대표무기 실습은 삭제하지 않고 **탑의 후속 무기 훈련**으로 이관한다. 첫 미션에서는 자동소총·산탄총을 집중 소개한다. 중화기와 모든 무기군을 첫 탈출 중에 강제로 순환시키면 경험 중심 목표와 충돌한다. 후속 훈련에서는 일반탄·특수탄·중화기 차이, 무기군별 실사격과 E 장비 설정을 모두 제공한다. 이 이관은 개발 제안이며 기존 기능을 즉시 삭제하는 작업 지시가 아니다.

## 3. 전투·감정·화면 연출

첫 적은 한 방향에서 접근하고 충분한 반응 시간을 준다. 두 번째 교전부터 측면 이동과 엄폐를 추가한다. 초기 HP·적 정확도·증원 수는 PvP 수치와 분리한 미션 프로필로 튜닝한다. 무적 상태로 끝까지 달리는 코스 대신 관대한 피해와 명확한 체크포인트를 적용한다.

Walker는 다리 장갑 → 무력화 → 노출 약점 → 회복의 읽을 수 있는 전투를 목표로 한다. 개별 부위는 하나의 보스 상태에 피해를 전달하고 같은 발사의 중복 적중을 차단한다. 몸체를 수백 개 독립 AI 엔티티로 만들지 않는다. 일반탄만으로도 완료 가능하게 하고 특수탄은 유리한 선택으로 만든다. 유탄·로켓은 기존 투사체, 일반 총기는 현재 서버 히트스캔 경로를 사용한다.

고스트는 플레이어 정중앙과 ADS 시야를 피한다. 조사 시 목적물로 이동하고 대사 중 눈·셸 동작을 동기화한다. 플레이어가 빠르게 지나가면 필수 정보만 재배치하며 긴 음성을 연달아 쌓지 않는다. 자막은 한국어 음성에 맞춘 실제 전사로 교체하며 없는 대사를 다른 뜻의 음원으로 위장하지 않는다.

HUD는 현재 목표 한 줄, 필요한 순간의 조작 힌트, 고스트 자막을 기본으로 한다. 키 안내는 서버가 확인한 GCB 유무에 따라 기존 입력 규칙을 사용한다. GCB 사용자 좌클릭 발사·우클릭 홀드 조준, 비 GCB 사용자는 기존 조작 유지. 클라이언트 수정은 하지 않는다. 지원되지 않는 포스트 효과·카메라 기능은 어두운 공간, 조명, 화면 전환으로 대체하고 완전한 원작 렌더링 동등성을 약속하지 않는다.

Rise는 사용자 요청대로 미션당 한 번 사용한다. 현재 구현처럼 시작 시 재생하는 안을 기본으로 유지하고, 대사 구간의 음량 균형을 실제 청취 후 조정한다. 곡 길이 약 6분 15초보다 미션이 길므로 이후에는 환경음과 전투 효과음으로 이어 간다. 재접속·체크포인트 복구에서 재생 여부를 저장해 반복 시작을 막는다. 나가기·탑 전환에서 소유 음악만 정리한다.

## 4. 현재 코드와 변경 경계

2026-11-01 소스 확인 기준 `Tutorial.java`는 AWAKEN부터 ASCEND까지 ARSENAL을 포함한 15개 enum 단계를 가진다. 이전 14단계 설명을 현재 코드로 간주하지 않는다. `TutorialWorld.java`는 static handle 하나의 `destiny:tutorial` 임시 월드와 LANES/USED 목록으로 개인 코스를 나눈다. 이는 Fantasy를 이미 쓰지만 세션별 독립 차원은 아니다.

재사용: 무기 지급·반납(TutorialLoan), 고스트 표시(TutorialGhost), 음성(TutorialVoice), HUD(TutorialUi), 완료 revision, 기존 전투·장비·입력 경로. 교체: 직선 훈련용 TutorialCourse, 단계별 강제 사용 조건, 단일 월드 lane 할당. `ActivityMusic`의 튜토리얼 판정도 새 세션 레지스트리에 연결한다. `isTutorial`의 단일 handle 비교는 등록된 인스턴스 level 조회로 바꾸어 피해 보호·퇴장·로그인 복구 전 경로를 점검한다.

## 5. Fantasy 독립 인스턴스 설계

Fantasy는 서버에서 임시 차원을 생성·삭제할 수 있다. 현재 프로젝트와 공식 API는 RuntimeLevelConfig, RuntimeLevelHandle, openTemporaryLevel, handle.delete를 사용한다. 임시 차원의 종료 시 자동 정리는 정상 운영의 즉시 회수를 대신하지 않는다. [공식 Fantasy 저장소](https://github.com/NucleoidMC/fantasy)

기본은 1인 1인스턴스. 향후 1~3인 화력팀을 지원할 수 있도록 멤버 집합을 두되 첫 출시의 협동 지원은 별도 수락 항목이다. 다른 세션의 적·전리품·사운드·보스 상태를 공유하지 않는다. 여러 월드는 같은 서버 tick 예산을 쓰므로 Fantasy 자체가 병렬 CPU 처리나 무제한 확장을 제공한다고 가정하지 않는다.

제안 구성:
- MissionDefinition: 버전, 구역 연결, 템플릿 해시, 체크포인트, 목표·대사·웨이브 정의. 불변 공유 데이터.
- MissionInstance: sessionId, generation, level handle, 멤버, 현재 encounter, 소유 엔티티·작업·청크 티켓·오디오 목록.
- MissionDirector: 서버 스레드에서 사건 처리와 상태 전환. 이벤트에 sessionId/generation을 검증하여 이전 인스턴스 콜백 무효화.
- InstancePool: 입장 큐·동시 생성 제한·준비 상태·실패 정리. 월드 조작은 서버 스레드, 파일 해석만 비동기.
- MissionProgressStore: UUID별 missionVersion/checkpoint/completedRevision/rewardClaimed/musicStarted/loan 복구 정보. 월드 엔티티 ID는 영속화하지 않음.

수명은 REQUESTED → PREPARING → READY → RUNNING → DRAINING → CLOSED. PREPARING 실패도 같은 cleanup 경로를 사용한다. READY 전에는 플레이어를 넣지 않는다. 탑 귀환 성공, 카메라 원복, 소유 작업 취소, 소유 엔티티·티켓 회수 뒤 handle.delete를 호출한다. 텔레포트 실패 상태에서 플레이어가 남은 월드를 삭제하지 않는다. 재시도 횟수와 관리자 진단을 남기며 종료 루틴은 중복 호출에 안전해야 한다.

맵은 불변 구역 템플릿을 캐시하고 인스턴스별 상태만 분리한다. 초기에는 새 월드 생성·삭제를 사용하고, dirty 월드 풀 재활용은 상태 유출 테스트를 통과한 뒤 도입한다. 준비 중 블록 배치를 tick별 예산으로 나누며 플레이어 눈앞에서 생성하지 않는다. 다음 구역을 미리 준비하고 이전 구역 청크는 체크포인트·역주행 정책에 따라 해제한다.

접속 종료 후 짧은 유예(제안 120초) 동안 세션을 유지하고 이후 월드를 회수한다. 재접속은 저장된 체크포인트에서 새 세션을 복원한다. 서버 재시작도 동일하다. 기존 유저는 새 mission revision 미완료인 경우 한 번 진입하며 완료 후 강제 반복하지 않는다. 구 튜토리얼 완료를 새 미션 완료로 오인하지 않는다. 보상과 임시 무기 반환은 중복 실행·재접속·사망에서도 한 번만 적용한다.

## 6. 체크포인트와 실패 처리

저장점은 첫 무장, Breach 출구, Walker 직전, 격납고 진입이다. 사망 시 현재 교전을 초기화하고 저장점에서 재개한다. 처리 중인 적 사망 이벤트가 다음 교전의 카운터를 깎지 않게 encounter generation을 분리한다. 필수 적이 지형 밖으로 이탈하면 복귀 또는 재생성하며 단순 타임아웃으로 전투 성공 처리하지 않는다.

길찾기 막힘은 20초 후 약한 안내, 45초 후 고스트 위치 안내, 반복 추락 시 안전점 복귀를 제안한다. 대사·리소스 로드 실패는 자막으로 진행 가능해야 한다. 마지막 탑 이동 실패는 완료 보상을 중복 지급하지 않고 안전한 재시도 상태에 남긴다. 운영자는 세션·목표·남은 적·대기 작업·실패 사유를 조회할 수 있어야 한다.

1. 회색 상자 맵과 세션별 Fantasy 생성·회수: 두 플레이어의 진행/적/음성 격리, 종료·재접속 복구 통과.
2. 부활부터 첫 무장까지 수직 단면: 직접 입력으로 고스트 시야, 소총 자동 지급, 첫 전투, 음성·자막 확인.
3. 전체 미션 회색 상자 완주: Walker 약점과 우주선 시동·탑 도착, 모든 체크포인트 실패 복구 포함.

5. 연출·성능 마감: 대표 장비에서 전 구간 Vision, 실제 청취, 동시 세션 부하와 반복 회수 검증.

QA는 copper-golem-vision-client-fabric-26-3와 저장소 Mac QA 규칙을 따른다. 실제 키 입력, PNG, 서버 상태, 실제 청취를 따로 기록한다. 단순 서버 명령 발동을 사용자 조작 검증으로 보고하지 않는다. 검증 시나리오는 신규/기존 계정, GCB/비GCB, 빠른 진행/장시간 정지, 사망·낙하·로그아웃·서버 재시작, 팩 거부/재로드, 탑 텔레포트 실패, 중복 완료 이벤트, 두 세션의 같은 좌표 교전을 포함한다.

출시 수락은 ‘끝까지 도착 가능’만이 아니다. 무장 전 부당한 사망 없음, 안내 없이도 다음 공간을 찾을 수 있음, 고스트·자막·총기가 시야를 가리지 않음, 약점과 피해 원인이 읽힘, 진행 막힘·자산 누락·인스턴스 누출 없음, 성능 목표와 vanilla/GCB 조작을 각각 통과해야 한다.
