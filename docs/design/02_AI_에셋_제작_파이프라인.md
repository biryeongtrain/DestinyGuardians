# 02. AI 에셋 제작 파이프라인

AI를 어디에 쓰고, 사람이 어디서 확인하는지 정한 작업 흐름입니다.

## 1. 전체 흐름

```
① 명세 작성 → ② 레퍼런스 수집 → ③ 컨셉 시트(이미지 AI) → [검수 A]
→ ④ Blockbench 모델링(AI + Blockbench MCP) → ⑤ 텍스처 → [검수 B]
→ ⑥ 애니메이션 → ⑦ 게임 내 테스트 → [검수 C] → ⑧ 리소스팩 반영
```

| 단계 | 담당 | 도구 | 산출물 | 저장 위치 |
|---|---|---|---|---|
| ① 명세 | 사람 | 03~08 명세서, 10 요청서 | 작업 요청서 | `art/requests/` |
| ② 레퍼런스 | 사람 + AI 검색 | ArtStation, Sketchfab (보기만) | 레퍼런스 메모(링크·특징 3줄) | `art/refs/<id>.md` |
| ③ 컨셉 시트 | AI | 이미지 생성 | 정면·측면·후면 3면도, 색 지정 | `art/concept/<id>.png` |
| ④ 모델링 | AI + 사람 | Blockbench (MCP 연결) | `.bbmodel` | `art/models/<id>.bbmodel` |
| ⑤ 텍스처 | AI + 사람 | Blockbench 페인팅, 이미지 AI(패턴) | PNG | `art/textures/<id>.png` |
| ⑥ 애니메이션 | AI + 사람 | Blockbench 애니메이터 | `.bbmodel` 안의 애니메이션 | 같은 파일 |
| ⑦ 테스트 | 사람 | 테스트 서버, `/bm play`, `/posteffect` | 스크린샷·영상 | `art/qa/<id>/` |
| ⑧ 반영 | 빌드 스크립트 | Polymer 리소스팩 생성 | 리소스팩 | 09 참고 |

## 2. 단계별 상세

### ③ 컨셉 시트 (이미지 AI)

- 목적: 모델링 전에 실루엣과 색을 확정합니다. 3D가 아니라 **방향 잡기용**입니다.
- 요청에 반드시 넣을 것
  - "low-poly, blocky, Minecraft-compatible, orthographic turnaround (front/side/back)"
  - 01의 속성 색 hex 값
  - 형태 키워드(01-4) 와 강조할 포인트 1~2개
  - "no text, plain background"
- 저작권: 원작 이름(예: "Ace of Spades")을 그대로 넣으면 원작을 베끼기 쉽습니다. **특징만 설명**합니다. 예: "revolver-type hand cannon, spade-shaped engraving on the side plate, dark steel with gold trim"
- 검수 A: 실루엣이 3m 거리에서 구분되는지, 색이 팔레트 안인지

### ④ Blockbench 모델링

- Blockbench MCP(이 개발 환경에 연결 가능)로 AI가 큐브를 직접 배치할 수 있습니다.
- 진행 순서
  1. 큰 덩어리(블록아웃) – 큐브 10~20개로 실루엣만
  2. 사람이 비율 확인
  3. 디테일 추가 – 01의 큐브 상한 안에서
  4. 본 구조 정리 (플레이어·적만) – 05, 04의 본 이름 규칙
- 무기는 Java Item 형식이라 **큐브 회전이 축 1개만 가능**합니다. 비스듬한 부품은 큐브를 계단식으로 쌓거나 텍스처로 표현합니다.

### ⑤ 텍스처

- 64×64 / 128×128 픽셀 아트. 이미지 AI 결과를 그대로 축소하면 뭉개지므로, **팔레트 축소(8~16색) 후 사람이 수정**합니다.
- 발광 부위(속성 색 부분)는 별도 레이어로 그려 두면 VFX·셰이더에서 재사용하기 쉽습니다.

### ⑥ 애니메이션

- 길이는 틱으로 나누어떨어지게 (0.05초 단위)
- **서버 이벤트 지점**을 애니메이션 이름 옆에 적어 둡니다. 예: `hunter_roll` 3틱 = 무적 시작, 7틱 = 무적 끝. 서버 코드는 이 표를 보고 타이밍을 맞춥니다. (04-5 참고)
- BetterModel은 Molang을 지원하므로 반복 흔들림 같은 동작은 키프레임 대신 수식으로 넣을 수 있습니다.

### ⑦ 게임 내 테스트

| 대상 | 확인 방법 |
|---|---|
| 무기 | 손에 들고 1인칭·3인칭(F5)·인벤토리 아이콘 확인, 조준·사격 상태 모델 전환 |
| 플레이어 애니메이션 | `/bm play <limb> <animation>` 으로 본인·다른 플레이어 시점 모두 확인 |
| 적 | 소환 후 걷기·공격·피격·사망, 머리 판정 위치 |
| 포스트 이펙트 | `/posteffect add @s <id>` 로 켜고, OpenGL·Vulkan 두 렌더러에서 확인 |
| UI | DisplayHud를 16:9, 21:9, 4:3 화면에서 확인 |

## 3. 검수 게이트

| 게이트 | 통과 조건 | 실패 시 |
|---|---|---|
| A (컨셉) | 실루엣 구분, 팔레트 준수, 원작과 다름 | ③ 재요청 |
| B (모델·텍스처) | 예산 준수, 이름 규칙 준수, 비율 확인 | ④⑤ 수정 |
| C (게임 내) | 10의 QA 체크리스트 전부 통과 | 해당 단계로 되돌림 |

## 4. 파일·버전 관리

- `art/` 폴더는 Git에 넣고, `.bbmodel`·PNG는 Git LFS로 관리합니다.
- AI가 만든 결과는 **요청서 ID를 커밋 메시지에 남겨** 어떤 요청으로 만들었는지 추적합니다.
- 리소스팩에 들어가는 최종 파일은 빌드 스크립트가 `art/`에서 복사합니다. 리소스팩 폴더를 직접 고치지 않습니다.
