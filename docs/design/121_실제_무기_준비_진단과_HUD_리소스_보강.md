# W106 — 실제 준비 상태 진단·HUD particle 참조

## 목표

W105 실게임에서 은둔자의 grip 교체 직후 single-fire가41→40이 되지 않은 관측을 조사한다. 실제 무기 준비 deadline과 겉모델의 swap 표시를 혼동하지 않도록 관측 경계를 보강하고, 새샷건4종의 누락 particle texture 참조를 수정한다. 원작 수치를 새로 추정하거나 기존 발사/장전/장비 교체 gate를 제거하지 않는다.

## 확인한 소스 경계

`WeaponModels.withGrip`은 원본을 복사하고 `/destiny weapon grip`은 실제 mainhand identity를 교체한다. `WeaponHandling`은 이 교체에 기존 **stow6 + ready7 =13 server tick**을 부과한다. 은둔자에는 W91 cosmetic swap pair가 없으므로, 겉모델 query의 `swap=none`은 발사 가능의 증거가 아니었다.

다만 W105의 정확한 use packet/Handling clock 동시기록은 없다. 이 설명을 원래 실패의 확정 원인이라고 선언하지 않는다. 새 격리 native에서 pending gate 중 denial 및 ready 후 별도 fresh press, 실제 empty-trigger reload→같은 grip/같은 stack fresh-fire를 구분해 검증한다. 시간초과 후 이전 click을 replay하지 않는다.

## 관측 API와 부수효과 교정

- `WeaponHandling.readiness`는 **기존·현재 binding**에만 `Optional<Readiness(remainingTicks,phase)>`를 반환한다. 없거나 actual stack/owner/level가 다르면 `Optional.empty`이며 ready0으로 취급하지 않는다.
- `Phase.READY`는 아직 총을 꺼내는 중이다. 실제 발사 준비 완료는 관측된 `NONE:0`이다. query는 update/bind/tick/재장전·탄약·시계 진전을 하지 않는다.
- debug status의 `handling=unobserved|PHASE:ticks`, `grip=native|two_hand`로 이를 콘솔 oracle에 노출한다. 다른 status 필드는 유지한다.
- 독립리뷰는 eligibility→`AbilityService.inSuper`→`Guardians.runtime.computeIfAbsent`의 숨은 생성 부수효과를 발견했다. 교정전 소스를 보존하고 `Guardians.runtimeIfPresent`와 read-only `inSuper`로 동일 boolean만 읽도록 수정했다. 발사/장전/Handling clock은 변경하지 않는다. 새로운 GT는 runtime을 지운 상태에서도 readiness와 전체 debug query가 다시 생성하지 않는지 검사한다.

## resource overlay

네 `reticle_w105_shotgun_*` 모델의 `textures`에 `particle: #0`만 추가한다. 실제 PNG·face·geometry·UV·tint·item route는 그대로다. 원래12asset 중 item4/PNG4는 byte그대로이며, 수정4model도 particle을 제거하면 역사적W105 manifest의 원래 bytehash로 돌아간다.

재현 pipeline은 **W105 generator → W106 overlay**다. 역사적 생성기와 manifest를 덮어쓰지 않는다. `rtk proxy python3 scripts/fix_reticle_particles_w106.py --verify`는 최종 current model을 쓰기없이 검사하며 `--output-root`로 독립 재현한다. W105의 raw-model verify는 overlay 전 역사적 단계다. 기존 다른 HUD 모델의 같은 경고까지 이번4개 수정으로 모두 해결했다고 주장하지 않는다.

## 검증 계약

신규 **4JUnit +4GT**, 이전750JUnit/865GT 보존 → 예상754JUnit/869GT. 정확 레지스트리1class append다. GT는 실제 command 교체·자연서버tick·gate t0/t12/t13·대체본만 결제·pure query·같은원본의0→41 reload→별도fresh-use immediate40을 검사한다. 직접 server item callback은 native input/pixel 증거가 아니다.

Two-hand SMG는 charged-crossbow의 **6-server-tick lease** 때문에1client-tick click이라도 뒤에서 자동사격이 이어질 수 있다. immediate callback 결제1발과 client click 뒤 최종 탄수는 구분한다. 실제 버튼 release packet이 없는 이 모드에서 무조건 최종40을 기대하지 않는다. Native one-hand의 실제 release 및 두 파지의 empty-trigger 후 fresh fire는 별도 관측한다.
