# W63 — 재장전 음향의 실제 시간·소스별 취소

## 발견한 차이와 이번 변경

W62에서는 실제 장전 시간이 무법자로 줄어들어도 `DestinySounds.weapon(...,"reload")`는 같은 고정길이
one-shot을 재생했다. 탄약·HUD deadline과 소리가 달랐고, 수납·능력 취소 후에도 기존 음향은 자체 길이로 남았다.
W63은 **기존 실제 장전 시작/완료/취소**에 음향 수명을 연결한다. 장전 계산·탄창·reserve·cadence는 변경하지 않는다.

현재 별도 1인칭 장전 모션은 **Beloved만** 구현되어 있다. 그 모션은 원래 실제 phase progress를 읽으므로
시간 소유권을 유지한다. W63을 전체 무기의 원작 장전 모션 구현이나 손/IK 완성으로 표현하지 않는다.

## 적용 범위와 파일

- 63선정 무기 중 **50개 full-magazine 기본 장전 +11개 Outlaw 가속**, 61개의 `(id,ticks)` 행.
- source event+ticks 중복 제거로 **53개의 파생 mono Ogg/이벤트**. 기존99개 이벤트의 값은 그대로 보존한다.
- [런타임 계약](../../src/main/resources/destiny/sounds/w63-reload.json)
- [원본 Drive·트림·신뢰도·측정·해시](../../art/weapons/w63/audio-manifest.json)
- [생성기/재현](../../scripts/audio/build_reload_sounds_w63.py), [음향 설명](../../art/weapons/w63/audio-notes.md)

샷건·Long Arm은 점진 장전이므로 제외한다. 전체 장전 녹음을 매 shell마다 재생하지 않는다.
활은 별도 재노킹, 검은 단일탄약이므로 제외한다. 기존 매핑이 있는 점진 장전음은 그대로 두고,
자료에 없는 `weapon.bow.reload`는 기존처럼 무음이다. 소리를 새로 지어 연결하지 않는다.
알 수 없는 미래 장전 시간은 기존 one-shot으로 fallback하며 임의 pitch나 잘못된 clip으로 대체하지 않는다.

## 소리 길이와 원본 정체성

기존 사용자 Drive에서 선택·가공되어 있는 W33 Ogg를 SHA로 확인해 입력으로 삼는다. 새 다운로드는 없다.
정확한 무기 ID alias가 있으면 그것을 선택하고 없으면 기존 family representative를 사용한다.
**Duke 음원이 Duke 원작 녹음이라는 뜻은 아니다.** 파일/폴더의 출처·provisional 정체성은 manifest에 남긴다.

`targetSamples=ticks*1600` (mono32000Hz, 20tick/s)로 full-magazine 전체 clip을 맞춘다.
`atempo`를0.5~2.0 단계로 분해하고 `apad/atrim`으로 sample 경계를 정리한다.
`asetrate`나 playback pitch 증가를 쓰지 않는다. 바닐라 재생 pitch는 **1.0**이다.
ffmpeg7.1 binary SHA·generator SHA·입력 문서/메서드/선택된 음향 정의·원본 Ogg SHA를 고정한다.

기본/무법자 Duke는59tick/33tick, 약2.95초/1.65초의 별도 파생 clip이다.
PCM 검사에서 목표 길이 오차0sample, clipping0, 최악 sample peak -4.916159dBFS이다.
이는 **오프라인 파형 검사**이지 청취·native playback·스피커 출력의 증거가 아니다.
atempo는 pitch를 보존하지만 transient/질감이 달라질 수 있다.

## 바닐라 소스별 취소

`ClientboundStopSoundPacket`은 sound ID/category 단위여서 같은 event를 재생 중인 다른 플레이어까지 끊을 수 있다.
따라서 각 accepted reload에 **고유한 빈 vanilla ItemDisplay**를 client-only로 생성하고
`ClientboundSoundEntityPacket`으로 음원을 그 entity에 묶는다.

1. 실제 ammo.reload가 가능한 startReload 승인 뒤 캡처된 `reloadPhaseTicks()`로 clip 선택.
2. source eye 위치에 고유 entity ID/UUID의 empty ItemDisplay spawn → inline Holder sound 순서로 전송.
3. owner와 시작 시32블록 안 같은 차원의 연결된 청자에게 전송. 뒤늦게 범위에 들어온 청자에게 중간 재시작하지 않는다.
4. 실제 source 이동 시 absolute teleport로 음원을 따라가게 한다. 정지 상태/중복 tick은 새 음원으로 재시작하지 않는다.
5. 실제 완료/수납/실물 교체/능력·궁극기/회피/사망/차원/cleanup/server shutdown 시 해당 source entity만 remove.

이 display는 server world에 추가·저장·tracker 등록하지 않으며 빈 기본 아이템이어서 보이는 모델/상호작용을 만들지 않는다.
서버 전역 entity ID allocator를 거치므로 다른 서버/가상 엔티티 ID를 수동으로 재사용하지 않는다.
세션은 owner object/level/actual ItemStack에 묶이고 다른 owner의 cleanup은 영향을 주지 않는다.

26.3 실제 `EntityBoundSoundInstance.tick()` bytecode는 source가 removed이면 stop하고, 아니면 entity 좌표를 따라간다.
[검증한 바닐라 계약](../qa/2026-10-24/w63/vanilla-entity-sound-bytecode.txt)을 기록했다.
추가로 [실제 packet handler·source 제거·sound 생성](../qa/2026-10-24/w63/vanilla-entity-sound-handler-bytecode.txt)의
26.3 bytecode와 class SHA도 확인했다. entity lookup→playSeededSound→EntityBoundSoundInstance,
remove packet→ClientLevel.removeEntity→setRemoved의 연결이다.
이는 클라이언트 코드의 정적 근거이며 현재 네이티브 클라이언트로 들어 본 결과는 아니다.

## HUD·애니메이션과 남은 차이

장전·무법자 HUD는 기존 실제 캡처 phase를 읽는다. W63 음향도 같은 길이를 선택하므로 가속 수치만 따로 갖지 않는다.
장전 도중 무법자가 만료되어도 이미 시작한 게임플레이/clip의 시간을 바꾸거나 다시 틀지 않는다.
거절된 재장전·HUD/상태 조회·같은tick 반복 처리로 음향·탄약을 생성하지 않는다.

다만 **전체 clip을 현재 서버의 근사 장전 시간에 맞춘 자체 정책**이다. 원작의 탄약 삽입 순간/장전 후 꼬리 구간/
빈 탄창·부분 탄창 차이/원작 애니메이션 event marker와 일치함을 증명하지 않는다.
현재 원본 개별 reload clip과 손/IK는 대부분 미구현이며 server TPS와 client 오디오 wall-clock이 다르면 드리프트할 수 있다.
source removal은 다음 client sound tick에 반영되므로 sample-accurate stop을 주장하지 않는다.

[QA](../qa/2026-10-24/w63/README.md)에서 actual paid reload·entity packet/codec·source 격리·출처/재현을 구분한다.
[로컬 음원 비교](../qa/2026-10-24/w63/audio/audition.html)를 사용자 청취용으로 제공한다.
추가 Vision/일반 QA 기동·native 입력·게임 프레임버퍼·실청취는 이번 단계에서 하지 않는다.
